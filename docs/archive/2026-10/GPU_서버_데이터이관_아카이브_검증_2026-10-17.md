CPU의 별도 해석적 미분 계산과 CUDA FP64 autograd를 대조했다. 허용 오차는 `1e-10 + 1e-8 × abs(reference)`다. 가중치가 모두 1인 대조군과의 차이도 확인했다. validation은 역전파 없이 무가중 주지표와 가중 보조지표를 분리했다. 두 장치에서 반복한 같은 419행을 838개 독립 사례로 세지 않는다.

실제 행 검사는 어휘 전체 262,144개에 대한 위치 불변 bias 벡터의 CE를 사용한다. 정답 마스크·가중계수·전역 정규화의 CUDA 경로를 검증하지만 **입력 문맥을 이해하는 신경망은 아니다.** 별도 7-class 위치별 logits fixture로 한 번의 causal shift와 마스크를 확인했다. 첫 정답을 예측하는 마지막 prefix 위치의 logit에는 gradient가 있어야 한다. 입력 embedding·hidden state의 gradient가 0이어야 한다고 주장하지 않는다.

실제 31B forward/backward, BF16/FP16, DDP/NCCL, optimizer 업데이트, 체크포인트·재개, 배포 또는 기존 trainer 통합은 이번 검사 범위가 아니다. 고정 파라미터에서 누적창 gradient 평균의 일치를 확인했으며, 서로 다른 optimizer 궤적의 동일성을 주장하지 않는다.

## 6. CUDA 초기 실패와 실행 경계

최초 실행은 CUDA 오류 304와 `cuda_unavailable`로 중단됐다. 이번 작업에서 시작한 진단 프로세스만 `strace`로 확인한 결과, 검증기의 seccomp 정책이 `AF_UNIX` 소켓 생성과 CUDA의 **프로세스 내부 abstract Unix listener bind**를 차단했다. 별도 실행기 r4에서 이 내부 listener를 허용하자 CUDA 초기화·1개 원소 텐서 연산·두 GPU 전체 검사가 통과했다. 기존 실패 기록은 보존했다. 이 결과를 드라이버 고장이나 서버 전역 변경 필요로 판정하지 않는다.

실행 경계는 다음과 같다.

- Python `-I -S -B`로 사용자 site·`.pth` 자동실행과 pyc 쓰기를 피하고, 제한 적용 후 확인된 기존 venv 경로를 추가했다.
- Landlock ABI 8로 일반 파일 변경은 새 실행의 `work*` 하위로 제한했다. 기존 환경·bundle·아카이브에는 쓰기 권한을 주지 않았다. GPU 연산에 필요한 개별 NVIDIA char device와 `/dev/null`만 별도 허용했다.
- seccomp로 권한·소유자·확장속성·시간 변경, 마운트·전역 관리 syscall, 외부 연결·전송을 차단했다. r4는 `AF_UNIX` 생성만 허용하며 인터넷 소켓 생성은 차단한다. abstract Unix IPC·signal에는 Landlock scope도 적용했다.
- 캐시·임시·HF·Torch·CUDA·Triton 경로를 작업 내부로 지정했다. 오프라인 토크나이저를 사용하고 CUDA 디스크 캐시를 껐다.
- 작업 내부의 deny 시험영역에서 생성·절단·삭제·이동·링크·chmod·utime 7개 동작이 거부됐다. 기존 서버 `AGENTS.md`에는 절단·쓰기 없는 쓰기전용 open만 시험해 `EACCES`를 확인했다.

진단 중 CUDA가 `/dev/char/*` 링크 생성과 자기 thread 이름 파일 쓰기를 시도했으나 차단됐다. 해당 외부 쓰기를 허용하거나 관리 작업으로 대신 실행하지 않아도 최종 GPU 검사가 통과했다. 이 경계는 신뢰한 검증 코드의 자동 쓰기를 제한한 근거이며, 모든 드라이버 ioctl을 compute/reset별로 구분하는 완전한 보안 경계라는 주장은 아니다.

Landlock의 파일 권한·한계·IPC scope는 [Linux 공식 문서](https://docs.kernel.org/userspace-api/landlock.html), syscall 비교 규칙은 [libseccomp 공식 헤더](https://github.com/seccomp/libseccomp/blob/main/include/seccomp.h.in)를 확인했다. 실제 서버 ABI와 거부 결과를 별도로 검사했다.

**사용자 추가 규칙:** 서버 전역의 드라이버·CUDA·서비스·권한·시스템 설정 등을 관리해야 하는 문제가 확인되면 작업을 멈추고 원인·영향·미완료 검증을 보고한다. 전역 수정이나 우회를 실행하지 않는다. 이 규칙을 로컬 [AGENTS.md](../../../AGENTS.md)와 [서버 레퍼런스](../../current/GPU_서버_사용_레퍼런스.md)에 반영했다.

## 7. 남은 검증 한계

1. 서버 검증은 이관된 419행 스냅샷에 대한 검사다. 전체 v8/v2 원천 계보 재구축, 앱 JavaScript 재생성, 새 사람·임상 검토는 수행하지 않았다. 의미적 적절성과 독립 test 자격을 추가 승인하지 않는다.
2. 기존 trainer가 이 가중 정책을 실제 loss·누적·저장·재개에 연결했는지 확인하지 않았다. 학습 전에는 trainer 통합과 사용할 정밀도·장치 배치의 검증이 별도로 필요하다. 이번에는 본학습을 시작하지 않았다.
3. 기존 모델·서비스 경로의 재귀 설정 조회는 자동 승인 검토가 민감한 `.env` 및 다른 작업 내용 노출 가능성을 이유로 거절했다. 조회를 진행하지 않고, 필요한지 확정할 수 없는 모델·서비스·기존 학습 기록을 유지했다. 이 보고서는 전체 서버 정리 완료를 주장하지 않는다.
