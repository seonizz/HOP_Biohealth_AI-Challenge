# 말씨 프로젝트 수정 내역 종합 정리

작성일: **2026-10-16, Asia/Seoul**

앱 기능, 데이터 처리, 개인정보 보호, 검토·운영 도구, 발표 자료에 반영한 수정을 모았다. 2026-10-15~16의 수정·재검증 기록을 중심으로 작성했으며, 원문 상담 내용과 개별 사례 ID는 포함하지 않았다.

**최신 전체 적대적 평가는 v13의 75/90점이고, 최신 별도 데이터 구성은 v8이다.** v13은 데이터 v7까지 검증했다. 데이터 v8의 별도 검증 결과를 아래에 추가로 정리하지만, v8까지 포함한 전체 재평가 점수를 새로 부여한 것은 아니다. 모델 자체·처리시간은 평가에서 제외하고 현장 발표·Q&A 10점은 유보한다.

이 문서는 기존 변경과 검증 기록을 정리한 문서다. 이번 작성 과정에서는 제품 코드·데이터를 수정하거나 전체 회귀검사를 다시 실행하지 않았다.

혼합 입력은 `selection_status:unknown`과 작성된 사실의 활용을 함께 보존한다. 기존 저장 원문·암호문을 일괄 덮어쓰지 않고 읽기 경계에서 정규화했다. 건너뜀과 공개 거절을 실제 답변으로 바꾸지 않는다.

### 2.2 안전 근거와 검증 이력

- 안전 근거를 문항·사람·원문·출처에 결합한 ID로 선택하고, 서버가 해당 원문과 후속 답변 전체를 복원하도록 변경했다.
- 정정 전 ID, 검색 범위 밖 ID, 중복 ID와 누락을 거절한다. 근거를 짧게 잘라 성공으로 처리하지 않는다.
- 요청·생성·시도 ID를 연결하고, 실제 요청과 재시도 대기 사건을 구분했다. 불완전·빈 trace와 실패 이력을 성공 실행에 섞지 않는다.
- 이 변경은 원문·출처·실행 기록의 정확성을 위한 것이다. 안전 판단의 의미적 정확성이나 임상 효과의 인증으로 계산하지 않는다.

근거: [N1–N4 수정 v3](../../competition/결선_재평가_지적_수정_v3.md), [안전 ID·후속 출처·불완전 로그 수정 v4](../../competition/결선_재평가_지적_수정_v4.md).

### 2.3 상세 안내와 화면 통합

별도 구현에서 필요한 기능을 현재 앱에 선별 통합했다.

- 관찰 내용·관계 메모리·주장별 근거를 나누어 관리한다.
- 근거가 있는 질문 생략, 선택적 확인 질문, 현재 위험 검토를 연결한다.
- 첫마디·듣기·제안·돌봄 등의 안내를 단계별로 구성하고 문제 카드만 수정한다.
- 최종 발화와 연결된 설명·원문 근거를 저장하고 화면에 표시한다.
- 실제 완료 단계에 따른 진행 조회, 전체 폭 행동 카드, 다음 단계 카드, 접힌 대화 내역을 반영했다.
- 조기 종료 시 아직 처리되지 않은 후속 질문 때문에 이미 받은 기본 답변까지 사라지는 결함도 수정했다.

기존 입력·삭제·소유자 격리·암호화·CSRF·버전 충돌 방어를 보존했다. 불필요한 모델·학습·평가·개발 설명은 서비스 화면보다 문서에서 관리한다. [통합 기록](../../../app/docs/GROUNDED_GUIDES_INTEGRATION.md), [UI 정보 원칙](../../../app/docs/UI_CONTENT_POLICY.md).

## 3. 저장·삭제·개인정보 보호

### 3.1 삭제와 보유기간

완료·미완료 대화 삭제와 전체 삭제 경로를 보강했다. 전체 삭제 후 늦게 끝난 생성이나 응답이 과거 데이터를 다시 복원하지 못하도록 세대값과 요청 상태를 검사한다.

쿠키를 잃었을 때 사용할 **삭제 키**를 추가했다. 키는 무작위 256비트이며 서버에는 해시만 저장한다. 해당 소유자의 삭제 권한만 제공하고 조회·복구 권한은 주지 않는다. 다른 소유자의 키를 사용해도 현재 사용자의 데이터는 보존한다.

기본 **미활동 30일**, 설정 범위 1~90일의 보유기간을 구현했다. 만료 접근 차단, 시작 시·주기적 청소, 청소 실패 상태 표시·재시도, 기존 데이터 유예기간을 반영했다. 쿠키 상실·동시 저장·지연 응답·다른 소유자 보호를 DB와 일부 브라우저 시나리오에서 검증했다.

운영 DB 적용·실제 보유기간 승인·WAL·백업·외부 사본 삭제는 별도 과제로 남는다. [삭제·보유 계약](../../../app/docs/DATA_RETENTION.md), [구현·브라우저 확인 기록](../../competition/결선_재평가_지적_수정_v7.md).

### 3.2 Git 원문 유입 방지

| 지적 | 수정 내용 | 확인된 결과 |
|---|---|---|
| **G1 원문 Git 추적** | private 1,221파일과 불투명 ZIP 2개를 로컬에 보존하고 인덱스에서 제거. `.gitignore`와 커밋 전 검사 추가 | 현재 인덱스의 원문 완전 일치 파일 **174→0** |
| **G2 UTF-16 JSON 우회** | 선언된 JSON·JSONL·NDJSON을 바이너리 생략보다 먼저 검사. UTF-8·선택적 BOM 지원, 다른 인코딩·손상 입력은 오류 | gzip·Office 첨부·실제 staged blob을 포함한 기존 우회 차단 |
| **G3 중복 JSON 키 우회** | 값이 덮어써지기 전에 중복 키 거절. 중첩·이스케이프 키도 검사 | 회귀와 독립 반례에서 차단 확인 |

검사기는 작업 파일 대신 실제 Git 인덱스 blob을 읽고 10MiB 이상 파일·제외 경로·원문 일치·파싱 실패 등을 확인한다. v13에서 **1,142파일, 원문 일치 0·파싱 오류 0**을 확인했다. 지원 형식의 **80자 이상 완전 일치 단위** 검사이며, 바이너리 62파일·짧거나 변형된 발췌·이미지·과거 이력·원격 공개는 별도 확인 대상이다.

추적 해제는 로컬 자료 삭제나 원격·과거 이력 정리를 뜻하지 않는다. 관련 작업에서 커밋·푸시·이력 재작성은 수행하지 않았다. [G1](../../competition/결선_재평가_지적_수정_v7.md), [G2](../../competition/결선_재평가_지적_수정_v8.md), [G3 재검증](../../competition/결선_적대적_재평가_v10.md), [검사 도구 안내](../../../tools/README.md).

## 4. 사람 검토 인계·운영 증거 도구

### 4.1 사람 검토를 준비하는 인계 도구

접두부를 먼저 판단할 자료, 나중에 볼 응답·주석, 빈 검토 요청, 기존 원천 검토 참조, 검토 계약을 같은 단위 해시로 연결했다. 검토자·시각·판정은 실제 검토 전까지 비워 두고 `pending_human_review` 상태를 유지한다.

현재 인계본은 **`human_review_v10_20261016_r5`**이며, 검토 대기 **28단위 = 응답 24 + 전문·권리 4**다. **사람 승인 0건**, 학습·운영·독립 test 승인 false다. 원천 검토 큐 391개·작성 요청 6개와 합산하지 않는다.

| 결함·경계 | 완료한 수정 | 회귀·버전 처리 |
|---|---|---|
| **HR1** 잘못된 pending 컨테이너에서 traceback | 객체·행·접두부·판정 타입을 사용 전에 검사. 일반 오류 JSON·종료 2·stderr 없음으로 처리 | 신규 CLI 회귀, 기존 묶음 보존 후 r2 발행 |
| **HR2** 릴리스 파일 메타데이터 타입 오류 | 공통 `audit_release`에서 루트·파일 메타데이터 객체, 행 수·해시·실제 파일을 검사 | 데이터셋 3개·인계 2개 회귀 추가, r3 발행 |
| **HR3** manifest의 pin·파싱·반환 해시 불일치 | 같은 캡처 바이트로 해시·파싱·계획 비교·반환값 계산. 읽기 전후와 최종 파일 상태 대조 | 중간 수정·같은 바이트 파일 교체·정상 표현 대조 추가 |
| **HR4** 검증 의존성 누락 | 정규화 모듈·패키지 초기화·질문은행을 고정 입력에 추가 | 구현·리소스만 바뀌어도 기존 pin 거절, 최종 r5의 입력 26파일 |
| 질문은행 오류 계약 | 버전·목록·객체·탐지 문자열의 타입을 먼저 검사 | 잘못된 입력에서도 일반 오류·미승인 상태 유지 |

HR3·HR4 대응으로 인계 회귀는 **24→29메서드**가 됐다. 기존 r3·중간 r4를 보존했고 검토 내용 5파일은 그대로 유지했다. 그러나 v13에서 별도 입력 소비 경계인 **HR5**와 Unicode 파싱 **HR6**를 발견했다. 따라서 인계 전체의 결함이 모두 해결됐다는 의미는 아니다.

### 4.2 운영 증거 점검기

정책 승인·실제 설정·앱 소스 해시, DB·WAL·복제본·백업·내보내기·외부 사본의 6영역, 만료·복원·장애 대응 증거를 검사하는 읽기 전용 도구를 추가했다.

- **OP1:** 빈 JSON이 해시만 맞아도 증거로 통과하던 경로를 차단했다.
- **OP2:** 명시적 합성 증거를 actual로 선언해 통과하던 충돌을 차단했다.
- **OP3:** 잘못된 JSON을 TXT로 바꾸거나 손상된 UTF-8을 넣었을 때 파싱 실패가 일반 텍스트 성공으로 바뀌던 경로를 제거했다. JSONL·NDJSON·중복 키·제어 바이트도 검사한다.

OP3 회귀는 **22→29개**다. 정상 형식·해시 검사와 실제 승인·신원·물리 삭제 인증을 구분한다. 현재 실제 템플릿은 **pending·미완료 59항목·확인 증거 0**이다. [v10 도구·OP1·OP2](../../competition/결선_v10_감점대응_재검증_v1.md), [v11 OP3 수정](../../competition/결선_v11_감점대응_재검증_v1.md).
