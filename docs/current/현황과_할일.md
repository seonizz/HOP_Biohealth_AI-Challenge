## 실제 모델에서 확인한 것

v3.7에서는 긴 위험 부정·후속 화자 정정·현재 위험의 분석 단계만 확인합니다. 개별 실측 결과와 초기 개발 실행의 평가 helper 식별 한계는 [N1–N4 수정 v3](../competition/결선_재평가_지적_수정_v3.md)를 따릅니다. 원문 전체 보존 검사가 위험 의미 판단 전체를 인증하지 않으며, 매우 긴 입력의 생성 토큰 한도도 남은 검증 대상입니다.


로컬 `gemma4:12b`를 대상으로 기존 합성 개발 사례를 다시 호출했습니다. `v3.6`의 최신 문항 누락 실패 후 `v3.6.1`에서 최신 원문을 서버가 보존하도록 수정했고 현재 위험 사례의 최종 생성은 통과했습니다. 누적 사례는 원문에 없는 진단·성향명 때문에 다시 실패해, `v3.6.2`에 원문 보고 전용 재요청을 추가해 초기·누적 STATE 자동 조건을 통과했습니다. 4회 요청 중 거절된 2회도 분모에 남깁니다. 실패 기록을 포함한 버전별 결과와 시간은 [v2 결과](../competition/결선_적대적_평가_v2.md)에 모읍니다.

자동 검사 통과는 독립 사람 검토나 임상 효과 검증이 아닙니다. 초기·누적·정정·위험 부정·현재 위험·사람 혼동의 코드 회귀검사, 실제 모델의 제한된 합성 사례, 29턴 전체 웹 검증은 각각 다른 범위입니다. 과거 v3.5 웹 기록의 `complete:false`는 소급해서 변경하지 않습니다.
