## 1. 확인 결과

**기존의 주소가 바뀌지 않는 화면 전환에 화면별 URL과 상태 복원 기능을 추가했다. 현재 구현은 CSR을 유지하는 SPA 라우팅이다.**

예전에는 `show(id)`가 한 HTML 안의 화면을 숨기고 보여 주었다. 변경 후에는 같은 화면 전환에 브라우저 주소와 방문 기록을 연결하고, 주소로 직접 접속하거나 새로고침하면 해당 화면과 서버 저장 대화를 복원한다.

| 항목 | 확인한 상태 |
| --- | --- |
| 화면별 URL | 시작·소개·상담·결과·기록·칼럼에 구현 |
| 주소 직접 접속 | 서버가 지원 화면 경로에 `index.html`을 반환하도록 구현 |
| 새로고침 복원 | 초기 데이터 조회 후 URL을 해석해 화면·대화를 복원 |
| 뒤로 가기·앞으로 가기 | `popstate`에서 복원하도록 구현 |
| 작성 중 답변 보존 | 같은 탭·세션의 `sessionStorage` 초안으로 보완 |
| 렌더링 구조 | 단일 `index.html`과 클라이언트 JavaScript 유지 |
| 이번 재검증 | 관련 자동 검사 **128개 통과**, JavaScript 문법·JSON 검사 통과 |

따라서 “페이지마다 URL을 갖게 하기”는 구현돼 있다. SSR 전환이나 화면마다 별도 HTML을 응답하는 다중 페이지 구조로의 전환은 이 작업에서 확인되지 않았다.

## 3. 추가한 URL 구조

| 화면·상태 | URL | 복원 방식 |
| --- | --- | --- |
| 시작 | `/` | 시작 화면 표시 |
| 서비스 소개 | `/about` | 소개 화면 표시 |
| 진행 중 상담 | `/chat/{intake_id}` | 해당 상담 ID를 서버에서 조회해 대화 재개 |
| 결과 | `/result/{intake_id}` | 같은 상담을 조회하고 실제 저장 상태에 따라 상담 또는 결과 표시 |
| 기록 | `/records` | 기록 목록과 기본 선택 기록 표시 |
| 특정 기록 | `/records/{record_id}` | 숫자 기록 ID를 선택해 표시 |
| 칼럼 목록 | `/columns` | 칼럼 목록 표시 |
| 특정 칼럼 | `/columns/{article_id}` | 해당 칼럼 읽기 화면 표시 |
| 칼럼 분류·필터 | `/columns?category=마음&view=saved` | 분류와 담은 글 필터 복원. `view=unread`도 지원 |

- 칼럼 상세 주소에도 `category`와 `view`를 함께 붙일 수 있다.
- 결과 주소의 ID는 숫자 기록 ID가 아니라 **상담 UUID**다. `/records/{record_id}`와 구분한다.
- 기록이 있으면 `/records` 진입 후 선택된 기록의 `/records/{record_id}`로 주소가 정리될 수 있다.
- `/chat`은 새 상담을 만들고 서버 ID를 받기 전의 임시 주소로 사용된다. ID 없는 `/chat`·`/result`를 새로고침했을 때 특정 상담을 복원하는 계약은 없으며, 현재 클라이언트 해석에서는 시작 화면으로 정리된다.
- 상담·결과 URL에는 이름·답변·입력 초안을 넣지 않는다. URL은 화면과 서버 ID를 식별하며, 대화 열람에는 기존 세션의 접근 권한이 필요하다.

## 4. 실제로 바꾼 동작

### 4.1. 화면 전환과 브라우저 주소 연결

새 `AppRouter`가 화면 상태에서 URL을 만들고, 일반 이동에는 `history.pushState`, 상태에 맞게 주소를 정리할 때는 `history.replaceState`를 사용한다. 기존 공통 함수 `show(id)` 끝에서 라우터를 호출하므로 기존 화면 전환 흐름에 연결된다.

칼럼은 분류 변경·담은 글/미읽음 필터 변경·글 열기·닫기도 주소에 반영한다. 상담은 서버가 발급한 ID를 받으면 해당 상담 주소로, 완료 상태이면 결과 주소로 정리한다.

### 4.2. 직접 접속·새로고침·방문 기록 복원

초기 실행은 다음 순서로 처리한다.

1. `API.bootstrap()`으로 익명 세션과 서버 저장 상태를 읽는다.
2. 세션에 맞는 초안 저장소를 준비하고 화면 컴포넌트를 구성한다.
3. `AppRouter.init()`으로 `popstate` 처리를 등록한다.
4. `AppRouter.restore()`가 현재 URL을 해석해 화면 또는 대화를 연다.

상담·결과는 `resumeConversation(id)`가 `/api/intakes/{id}`를 조회한다. 결과 URL이라는 이유만으로 완료를 가정하지 않고 서버가 돌려준 실제 상태를 사용한다.

복원 중에는 이전 상담 요청과 오래된 화면 갱신을 무효화하고, 열린 칼럼 읽기 화면·이탈 대화상자·스크롤 잠금을 정리한다. 라우터의 순번 검사로 이전 복원이 뒤늦게 끝나 최신 URL을 정리하는 것을 막는다.

### 4.3. 서버에서 화면 경로 처리

서버는 `/about`, `/records[/숫자]`, `/columns[/글ID]`, `/chat[/상담UUID]`, `/result[/상담UUID]` 등 허용된 화면 경로의 `GET`·`HEAD` 요청에 공통 `index.html`을 반환한다. `index.html`에는 `<base href="/">`를 두어 깊은 주소에서도 CSS·JavaScript·이미지의 기준 경로를 루트로 유지한다.

모든 알 수 없는 주소를 HTML로 바꾸는 방식은 아니다. 허용 화면 경로 밖의 요청에는 기존 정적 파일 검사와 404 처리가 적용된다. 클라이언트에서 잘못된 경로를 해석할 때 시작 화면으로 정리하는 동작과, 서버에서 직접 잘못된 주소에 접속했을 때의 400·404 처리는 구분한다.

### 4.4. 페이지 이동 시 입력 유실 방지

URL 전환과 함께 `ConversationDrafts`를 추가했다.

- 같은 탭의 `sessionStorage`에 작성 중 답변·선택지·직접 입력·다음 질문용 선입력을 보존한다.
- 세션에서 파생한 저장 키와 상담 ID·revision·질문 ID·후속 질문 여부로 초안을 구분한다.
- 입력 변경, 화면 전환, `beforeunload`, `pagehide`, 화면 숨김 시점에 저장한다.
- 서버가 확인한 대기 답변의 이전 revision에 한해 초안을 옮겨 복원한다. 다른 질문·다른 상담에 임의로 붙이지 않는다.
- 저장된 대기 답변과 사용자가 수정한 초안을 구분해, 수정한 내용을 예전 답변으로 덮어쓰거나 자동 전송하지 않도록 처리한다.
- 전송 확인 후 초안을 제거하고, 개별·전체 대화 삭제 및 세션 변경 때 관련 초안을 정리한다.
- 보관 기간은 24시간, 최대 32개 질문이다. 저장소·암호 기능을 쓸 수 없는 환경에서는 일반 입력을 유지한다.

이는 같은 탭·세션 안의 복원 기능이다. 새 탭·다른 기기 간 미전송 답변 동기화를 구현했다는 의미는 아니다.
