# 실행과 검증

공통 명령의 기준 위치는 이 저장소의 루트(`HOP-Final/`)입니다. 앱 연결 설정과 기동 절차는 [앱 실행 안내](../../app/README.md)에만 둡니다. 검사 결과와 미완료 항목은 [현황과 할 일](현황과_할일.md)을 확인합니다.

## 준비

- Node.js는 루트와 앱의 `package.json`에 지정된 24.x 범위를 사용합니다.
- Python 테스트는 Python 3과 해당 모듈의 기존 환경을 사용합니다. 데이터 파이프라인은 NumPy가 필요합니다.
- 기존 의존성·환경 설정을 유지합니다. 폴더 정리만을 위해 새 모델이나 패키지를 설치할 필요는 없습니다.

## 로컬 검사

```sh
cd /Users/chihun/Documents/ChatGPT/HOP-Final
npm run test:evidence # 모델 식별·실패 분모·대기 집계 검사
npm run check         # 앱 JavaScript·JSON 검사
npm test              # TEST_DATABASE_URL 미설정 시 DB 검사 건너뜀
npm run test:paths    # 모듈 경로·인수인계 패키지 회귀
npm run ai:test       # 로컬 인증 게이트웨이 테스트
npm run data:test     # 데이터 파이프라인 테스트
```

기본 Python에 NumPy가 없으면 이미 설치된 런타임을 지정합니다. 이 컴퓨터에서 확인한 경로:

```sh
MALSSI_PYTHON=/Users/chihun/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 npm run data:test
```

`npm test`는 `TEST_DATABASE_URL`이 설정돼 있으면 DB 검사도 실행합니다. 최신 DB 포함 실행 여부와 검사 개수는 [현황](현황과_할일.md)을 확인합니다. 검사 통과만으로 실제 모델 연결·배포 성공을 확인한 것은 아닙니다. 게이트웨이 테스트 역시 현재 앱의 모델 응답 품질을 평가하지 않습니다.

## 실행 및 실제 연결 검사

| 목적 | 절차 |
|---|---|
| 앱 시작·개발 서버·종료 | [앱 README](../../app/README.md) |
| 별도 PostgreSQL 테스트 스키마를 사용하는 통합 검사 | 앱에서 `npm run test:integration`; [테스트 스크립트](../../app/scripts/test-integration.js) |
| v3 새 대화·결과 생성·저장 조회의 단발성 로컬 검사 | 루트에서 `node app/scripts/verify-questionnaire-v3-live.mjs --base-url http://127.0.0.1:9000`; [실행기](../../app/scripts/verify-questionnaire-v3-live.mjs) |
| 실제 모델의 합성 사례 평가·웹 흐름 확인 | [AI 평가 명령](../../ai/local_api/RELATIONSHIP_AGENT.md) |
| 데이터 처리 재현 | [데이터 실행 안내](../../data/README.md#실행) |
| 다른 장비의 앱 환경 구성 | [이동 안내](../../app/docs/DOCKER_HANDOFF.md) |

실제 모델 평가와 웹 시연은 로컬 단위 검사보다 오래 걸리며 새 합성 결과·세션을 만듭니다. 평가할 때 실행 코드와 패치 소스를 구분합니다. `ai/scripts/apply_relationship_backend.py`는 코드와 설정을 실제로 반영하는 도구로, 읽기 전용 검사 명령이 아닙니다.

v3 실행기는 로컬 앱이 시작된 상태에서 새 가상 대화를 만들고, 앱이 선택한 질문과 생략을 따라 결과 생성·저장 조회·기록 목록을 확인합니다. `app/runtime/` 아래에 진행 상태·예상 완료 시각·최종 보고서를 남기고 한 번 실행한 뒤 종료합니다. 예상 시간은 완료 보장이 아니며, 최종 `passed`/`failed`와 검사 범위를 확인해야 합니다. 암호화 DB를 직접 복호화해 대조한 별도 검사와 API 재조회 검사를 구분하며, 실제 수행 결과는 [v3 검증 기록](../../app/docs/QUESTIONNAIRE_V3_VERIFICATION.md)에 둡니다.

## 비공개 서버 자료 확인

앱 폴더에서 `npm run export:verification`을 실행하면 관리자 검증용 복호화 자료가 `app/runtime/server-verification.json`에 생성됩니다. 서버에 저장된 원문·상태·수정 이력·결과를 확인하는 용도이며 Git·웹 공개·발표자료에 포함하지 않습니다. 단순 상태 확인과 구분해 필요한 경우에만 실행합니다.

## 결과 기록

실행 날짜, 사용한 코드·모델 경로, 명령, 통과·실패·건너뜀, 실제 DB·모델 사용 여부를 함께 남깁니다. v3 결과는 [담당 검증 문서](../../app/docs/QUESTIONNAIRE_V3_VERIFICATION.md)를 갱신하고 [현황](현황과_할일.md)에서 연결합니다. 다른 README에 검사 수치를 반복해서 복제하지 않습니다.
