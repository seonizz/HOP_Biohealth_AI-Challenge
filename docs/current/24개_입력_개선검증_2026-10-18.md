## 실행 순서와 완료 기준

이번 `baseline`은 현재 서비스의 통합 Q&A(v13, 정상 답변당 2회 호출)이며, `candidate`는 여기에 관계 근거 참조 압축을 추가한 실험이다. 원래 4회 호출 방식과의 비교를 새로 완료했다는 뜻이 아니다. 그 방식의 앞선 실제 비교는 6번째 문항에서 실패했고, 공통으로 완료한 범위의 속도만 비교할 수 있었다.

1. 24개 원본 답변을 실제 서비스 문항·선택지에 대응시킨다. 누락된 선택 문항은 명시적으로 건너뛰고, 새로운 답변을 만들어 넣지 않는다. 원본 필드별 제출·조건상 미질문·미제공을 모두 추적한다.
2. 관계 근거의 중복 문자열을 짧은 참조 ID로 전달하는 후보를 준비한다. 원문 전체와 근거 범위를 유지하고, 서버에서 정확한 객체로 복원한 후 기존 검증과 독립 검토를 거친다. facts·이름·위험 판단·최종 생성의 의미 계약은 보존한다.
3. 원문 복원 동등성과 잘못된 ID·인물·문항·경로의 거절을 검사한다. 실제 모델에서 기존 방식과 후보의 완료율·재시도·입출력 토큰·시간을 비교한다. 입력 크기 감소만으로 실측 개선을 선언하지 않는다.
4. 24개 사례의 실제 실행과 독립 의미 검토를 진행한다. 사실/전언/추측, 모름, 정정, 현재 동의, 지원 가능 범위, 위험의 시점, 인물 구분을 확인한다. 실패한 사례와 미실행 사례를 성공 분모에서 숨기지 않는다.
5. 코드·프롬프트만으로 해결되지 않는 반복 오류는 별도 학습 데이터 계약과 독립 평가 분할을 마련해 추가 학습 후보로 검증한다. 실제 개선과 회귀 검증을 확인한 후보만 서비스에 반영한다.
6. 실행별 소스·모델·입력 해시를 보존하고 사용한 GPU를 반환한다. 전체 목표의 검증이 끝나기 전에는 완료로 표시하지 않는다.

## 사례 03의 실제 실패와 다음 진단

기준·후보 모두 최종 결과 전에 실패했으므로 전체 속도 개선이나 최종 품질 동등성을 주장하지 않는다. 후보의 `want`는 103.363초에서 44.133초, `mood`는 173.022초에서 66.460초로 줄었지만, `describe`는 검토 후 보정이 추가되어 153.473초에서 201.080초로 늘었다. 실패 문항과 추가 호출을 성공 응답 통계에 숨기지 않는다.

후보의 완료된 0–12번 답변을 원문과 대조한 범위에서는 인물·시점·방문 동의·수면 정보의 전언과 관찰 구분에 확정된 오류를 찾지 못했다. 12번에서도 어머니의 해석·아버지의 설명·이용자의 불확실성이 함께 보존됐다. 가설로 저장된 고립감·상실감 등이 최종 결과에서 사실로 바뀌는지는 검증하지 못했다. 기존 방식은 9번부터 성공 출력이 없어 해당 구간의 상대 품질 비교가 불가능하다.

실패 당시 문맥을 고정한 별도 진단을 새 인증으로 실행해 초안 2회에서 같은 결함을 재현했다. 첫 초안은 `state.relationship_memory.patient`에 reported 1개와 tentative 2개를 생성해 최대 2개 제한을 넘겼다. 재시도는 tentative 2개만 생성했고, 두 초안에서 같은 최신 reported fact 1개를 선택했지만 이를 보존할 자리가 없어 거절됐다. 두 번째 출력은 JSON 스키마 자체는 유효했다. 따라서 이번 실패는 응답 토큰 한도나 네트워크 문제가 아니라 사실·가설 선택과 저장 제약의 충돌이다.

진단은 180.424초·실제 모델 2회 호출로 끝냈고 서비스 답변·최종 결과를 수정하지 않았다. 소유 PID 종료와 GPU 메모리 11/30 MiB·실행 프로세스 없음으로 반환을 확인했다. 진단의 네트워크 호출 제한·재시도 본문 보존 등 5개 검사, 실행기 11개 검사도 통과했다. 다음 수정은 최신 사실을 보존할 자리를 명시하고 가설을 사실로 바꾸거나 인용을 자동 삭제하지 않는 범위로 제한한다.
