# v11 데이터셋의 실제 31B 모델 학습 가능성 검증

작성: 2026-10-17 KST · 대상: 주변인 지원 v11 419행 · 서버: RTX 4090 2대 · 출력 예산: 8,192

**판정: 현재 데이터셋과 v11 가중 정책을 사용해 Gemma 31B의 QLoRA 학습을 실행할 수 있음을 실제 서버에서 확인했다.** 5개 과업의 제한된 학습 8스텝, 체크포인트 저장·복원 5건, 과업별 최장 입력의 역전파·검증이 통과했다. 단순 모델 로딩이나 합성 gradient 검사에 근거한 판정이 아니다.

**단, 기존 학습 스크립트에 데이터 경로만 바꾸는 방식은 준비되지 않았다.** 기존 루프는 v11 행별 가중치를 적용하지 않는다. 이번에 검증한 고정 가중 소비기와 실행 경로를 본학습 실행기에 연결해야 한다. 전체 epoch·최종 어댑터·생성 품질·서비스 배포의 완료를 뜻하지 않는다.

- checkpoint는 각 약 701.5 MiB이며 서버 작업 폴더에만 보관했다. 모델 가중치나 checkpoint를 Git에 올리지 않았다. 복원은 동일 프로세스 안에서 검사했으며, 일반 PEFT 배포 형식이 아닌 전용 `.pt` 상태 파일이다. 새 프로세스로 재시작하는 복원은 미검증이다.

## 3. v11 가중 정책과 원문·맥락·분할

한 행의 평균 정답 CE에 곱한 실제 역전파 계수는 `K × w_i × n_i / Z`다. `K`는 전체 과업의 계획된 optimizer 창 수, `w_i`는 고정 행별 가중치, `n_i`는 정답 토큰 수, `Z`는 전체 과업 train의 가중 정답 총량이다. 선택한 51행으로 분모를 다시 만들지 않았고 창 크기·창 정답량으로 추가 나누지 않았다.

51행 모두 loss gradient hook에서 실제 유입 계수가 고정 유리수 계수와 맞는지 확인했다. 과업별 전체 계획은 상담 6창, 문장 11창, 단어 13창, 상태 관찰 1창, 관계 기억 1창이다. 세부 원행 ID와 분수·gradient 근거는 Git 제외 결과 JSON에 있다.

전체 입력 token ID와 attention mask를 그대로 전달했다. prefix의 불필요한 출력 logits만 줄였으며 입력을 자르거나 요약하지 않았다. 가장 짧은 실제 train 행(141토큰)에서 선택 logits CE `4.731845855713`와 모델 자체 full-logits causal loss `4.731843471527`를 비교했다. 차이는 `0.0000023842`로 사전 허용 오차 안이다.

종료 후 원본 모델 **13파일**의 SHA-256·크기·mtime·inode·device가 사전 기록과 완전히 같았다. 기존 데이터·정책·토크나이저·코드 묶음 **45파일**의 해시와 실제 token entries 해시도 그대로였다. 새 원문 작성·대표 교체·split 이동·재분할은 하지 않았다.

앞선 서버 실제 토크나이저 검사의 419행 완전 재인코딩 일치, 입력 157,668토큰·정답 17,220토큰, 집중도 90/90·총량 20/20 조건은 변경되지 않은 동일 입력·정책에 결속된다. 이번 실행에서 원천 전체를 새로 재구축하거나 의미·임상 타당성을 재승인한 것은 아니다. [이관·실제 토크나이저 보고서](GPU_서버_데이터이관_아카이브_검증_2026-10-17.md)와 [v11 정책 보고서](../competition/학습데이터_가중집중도_개선_재검증_v11.md)를 함께 본다.

## 4. 출력 8,192와 GPU 메모리의 의미

출력 8,192는 유지된 **예약 예산**이다. 현 데이터의 실제 최대 정답은 145토큰, 최대 입력 접두부는 3,806토큰, 최대 실제 시퀀스는 3,909토큰이다. 모든 실제 행은 4,096 이하이며, 이번 학습 검증도 이 실제 길이에 대한 것이다. 8,192개 정답 토큰을 생성하거나 8,192 길이의 정답으로 학습한 결과로 확대할 수 없다.

| 장치 | PyTorch peak allocated | PyTorch peak reserved |
|---|---:|---:|
| GPU 0 | 18,353.7 MiB | 19,000.0 MiB |
| GPU 1 | 14,143.7 MiB | 14,848.0 MiB |

각 GPU 총 메모리는 24,564 MiB다. 위 값은 PyTorch allocator 통계이며 드라이버·다른 프로세스를 포함한 `nvidia-smi` 최대 사용량과 같지 않다. 이번 설정에서 OOM은 없었다. 더 큰 batch·길이·rank에도 같은 여유가 있다고 보장하지 않는다.

## 5. 발견한 문제와 해결 범위

1. **기존 trainer는 v11 가중치를 무시한다.** 기존 `stage1_training_loop.py`는 누적창의 정답 토큰 비율을 사용한다. 새 데이터 경로만 지정하면 승인한 목적함수가 적용되지 않는다. 이번 검증기는 고정 `supporter_weighted_loss.py`를 실제 31B 역전파에 연결했다. 기존 trainer를 수정했다고 주장하지 않는다.
2. **첫 검증 r1은 출력 위치 tensor의 GPU 배치 오류로 실패했다.** 모델 로딩·LoRA 구성은 성공했으나 첫 causal loss에서 GPU 0 인덱스와 GPU 1 hidden state가 충돌했다. r2에서는 위치 선택 길이를 Python 정수로 전달하고, 반환된 logits의 장치에서 정확한 정답 위치를 선택했다. full input은 그대로이며, r1 코드·로그·실패 결과를 보존했다. r2의 loss 비교와 실제 역전파로 수정 효과를 확인했다.
3. **기존 드라이버의 RTX 40 P2P 경고는 남아 있다.** Accelerate가 드라이버 업데이트를 권하는 일반 경고를 출력했다. 이번 두 GPU 실행은 경고가 있는 환경에서 통과했으며, 모든 멀티 GPU 실행의 안정성이 검증된 것은 아니다. 드라이버·CUDA·서비스·전역 환경을 변경하지 않았다. 향후 전역 관리가 필요한 실제 문제가 확인되면 사용자의 지시대로 중단·보고한다.
4. **짧은 성공은 장기 학습 안정성·품질을 뜻하지 않는다.** 7/8개 창에 gradient clipping이 적용됐고, 상태 관찰의 preclip norm은 약 92.25였다. 유한 gradient와 정상 업데이트는 확인했지만 수렴이나 주변인 지원 답변 품질의 근거로 사용하지 않는다. 가중 목적함수의 개선이 optimizer 궤적·의미적 성능까지 보장하지 않는다.

## 6. 서버 경계와 종료 상태

새 실행의 `/home/slim/choieram/training_data/supporter-v11-20261017-7d1e112f/work-training-canary-r2/` 안에만 일반 파일 쓰기를 허용했다. 캐시·임시·출력도 내부로 고정하고 기존 가상환경·모델·데이터는 읽기만 했다. Landlock ABI 8, seccomp, 오프라인 설정과 기존 GPU별 잠금 파일의 read-only open·프로세스 잠금을 사용했다.

경계 시험에서 생성·절단·삭제·이동·링크·chmod·utime 7개 금지 동작과 작업 밖 기존 파일의 write-open이 거부됐다. CUDA 내부 Unix listener와 필요한 개별 장치 연산은 허용했다. 모든 드라이버 ioctl을 구분하는 완전한 보안 경계라는 주장은 하지 않는다.

전역 설치·설정 변경·GPU reset·재부팅·다른 작업 종료는 하지 않았다. 종료 후 GPU 0은 11 MiB, GPU 1은 30 MiB이고 compute 프로세스와 이번 검증 PID가 남아 있지 않다.

## 7. 본학습 전에 남은 작업

- v11 전체 계획·가중 소비기를 본학습 실행기의 데이터 로더·누적·checkpoint·연속 재개에 연결해야 한다. 이번 실행기는 first/last 창의 제한 검증용이며 그대로 전체 epoch 학습 명령으로 사용할 수 없다.
- 과업별 독립 어댑터 또는 단일 다중 과업 어댑터의 최종 운영 방식을 본학습 설정에 명시해야 한다. 이번 검증으로 임의의 과업 혼합 정책을 도입하지 않았다.
- 전체 train의 연속 epoch, 전체 validation, 새 프로세스 재시작·장기 재개·수렴·생성 품질·8,192 토큰 생성은 미검증이다. 모델 품질·크기·학습 진행률을 프로젝트 평가 점수로 환산하지 않았다.

따라서 **데이터와 실제 31B QLoRA 학습 연산은 검증 통과**, **기존 본학습 진입점의 v11 통합은 별도 남은 작업**으로 구분한다.
