# GPU 서버 사용 규칙

사용자 지정: 2026-10-17 · RTX 4090 2대(접속 후 확인).

```sh
ssh -p 20522 -L 8888:127.0.0.1:8888 slim@165.194.161.61
```

1. **접속:** 에이전트가 보이는 터미널을 열고 사용자가 비밀번호를 직접 입력한다. 비밀번호는 저장하지 않는다.
2. **절대 금지:** 서버 reset·reboot·초기화, GPU reset, 시스템 재시작·재설치·포맷을 실행하지 않는다. 장애 시에도 예외 없다.
3. **작업 위치:** 서버의 유일한 변경 허용 범위는 `/home/slim/choieram/` 하위의 요청받은 작업 대상이다. 코드·데이터·환경·캐시·임시 파일·출력도 모두 내부에 둔다. 외부 경로 변경은 금지한다.
4. **환경 격리:** 가능한 모든 작업은 가상환경 또는 기존 컨테이너에서 실행한다. 전역 설치·시스템 설정 변경은 금지한다.
5. **공유 자원 보호:** GPU 사용 상태를 먼저 확인한다. 다른 사용자의 파일·프로세스·컨테이너는 건드리지 않고, 종료는 이번 작업에서 시작한 것으로 확인된 대상에만 한다.
6. **불확실하면 중단:** 작업 경로·종료 대상·격리 가능 여부가 불명확하면 변경 작업을 멈추고 확인한다. 금지 작업으로 우회하지 않는다.
7. **전역 관리가 필요하면 중단·보고:** 서버 전역에서 해결해야 하는 문제가 확인되면 해당 작업을 즉시 멈추고 원인·영향·미완료 검증을 사용자에게 보고한다. 에이전트가 전역 수정을 실행하거나 우회하지 않는다. (사용자 추가 지정: 2026-10-17)
8. **사용 종료 후 GPU 반환:** GPU가 더 필요하지 않으면 이번 작업에서 시작한 것으로 확인된 학습·추론 프로세스만 종료하고 GPU 점유를 해제한다. 해당 PID가 남아 있지 않은지와 GPU 메모리가 실행 전 수준으로 돌아왔는지 확인·보고한다. 다른 작업의 점유는 해제하지 않으며 GPU reset으로 반환하지 않는다. (사용자 추가 지정: 2026-10-17)

사용자 재확인(2026-10-17): 이번 요청의 작업 대상만 변경하고 학습·검증은 가상환경 또는 기존 비특권 컨테이너에서 실행한다. 기존 환경은 변경 없이 재사용하며 모든 출력·캐시·임시 경로의 경계를 별도로 확인한다.

프로젝트의 Git·학습 데이터 제외 규칙은 [AGENTS.md](../../AGENTS.md)를 따른다. 확인된 작업 경로는 `/home/slim/choieram`이다.

**필수 작업 경계:** [AGENTS.md의 서버 작업 경계](../../AGENTS.md#서버-작업-경계--모든-세션과-하위-에이전트에-적용)를 모든 세션에서 먼저 따른다. 외부 경로 쓰기, 링크·마운트를 통한 우회, 호스트 설정 변경, 다른 작업 종료를 금지한다. 변경 전 실제 경로·격리 환경·출력 및 캐시 경로를 확인할 수 없으면 실행하지 않는다. SSH 접속과 `cd`만으로 파일 접근이 기술적으로 차단되는 것은 아니다.

## 접속 후 확인

인증이 완료된 원격 터미널에서 다음 읽기 전용 명령을 실행한다.

```sh
whoami

pwd -P
ls -d -- */
nvidia-smi
```

- 계정이 `slim`인지 확인하고, 현재 경로와 하위 폴더 목록에서 `choieram` 위치를 확인한다. 보이지 않으면 서버 전체를 탐색하거나 임의로 만들지 않고 위치를 확인한다.
- 확인한 `choieram`으로 이동한 후 `pwd -P`로 실제 절대 경로를 기록한다. 그 전에는 설치·파일 생성·작업 실행을 하지 않는다.
- GPU 모델·개수·메모리 사용량·실행 중인 프로세스를 확인한다. GPU 상태는 실행 직전에 다시 확인하며, GPU가 2대라는 사실만으로 둘 다 사용할 수 있다고 판단하지 않는다.
- 비밀번호 입력 대기나 SSH 실행만으로 접속 성공을 판단하지 않는다. 인증 후 출력으로 계정·호스트·경로를 확인한다.

## 다른 세션에서 접속

**같은 Mac·같은 로컬 사용자**의 다른 터미널 또는 Codex 세션에서 아래 공유 소켓을 사용한다. 다른 컴퓨터에서는 재사용할 수 없다. 비밀번호는 저장하지 않으며, 인증된 SSH 연결이 살아 있는 동안 재사용한다.

현재 소켓: `/private/tmp/hop-gpu-ssh-z0bddbnn/control`

먼저 연결 상태를 확인한다. `Master running`이 나오면 재사용할 수 있다.

```sh
ssh -S /private/tmp/hop-gpu-ssh-z0bddbnn/control \
  -O check -p 20522 slim@165.194.161.61
```

다른 세션에서 경로·GPU를 읽기 전용으로 확인하는 명령:

```sh
ssh -S /private/tmp/hop-gpu-ssh-z0bddbnn/control \
  -o BatchMode=yes -p 20522 slim@165.194.161.61 \
  'cd -- /home/slim/choieram && pwd -P && nvidia-smi'
```

작업 폴더에서 대화형 셸을 여는 명령이다. 홈 디렉터리에 셸 이력이 저장되지 않도록 설정하며, 작업용 가상환경은 별도로 활성화한다.

```sh
ssh -t -S /private/tmp/hop-gpu-ssh-z0bddbnn/control \
  -o BatchMode=yes -p 20522 slim@165.194.161.61 \
  'cd -- /home/slim/choieram && exec env HISTFILE=/dev/null bash --noprofile --norc -i'
```

현재 공유 연결은 `ControlPersist=10m`으로 설정되어 마지막 클라이언트가 닫힌 뒤 10분간 유지된다. 네트워크 단절·Mac 재시작·연결 종료 뒤에는 재인증이 필요하다. `BatchMode=yes` 명령이 실패하면 반복하지 말고 아래 절차로 새 연결을 만든다.

사용자에게 보이는 **로컬 Mac 터미널**에서 실행하고 비밀번호를 직접 입력한다. `mktemp`는 로컬에 전용 임시 폴더를 만들며 서버는 변경하지 않는다.

```sh
GPU_SSH_DIR="$(mktemp -d /private/tmp/hop-gpu-ssh-XXXXXX)" || exit 1
printf '공유 소켓: %s/control\n' "$GPU_SSH_DIR"
ssh -M -S "$GPU_SSH_DIR/control" \
  -o ControlPersist=10m -o StrictHostKeyChecking=yes \
  -o ServerAliveInterval=30 -t -p 20522 slim@165.194.161.61 \
  'cd -- /home/slim/choieram && exec env HISTFILE=/dev/null bash --noprofile --norc -i'
```

새 연결을 만들면 위 재사용 명령의 소켓 경로를 새로 출력된 값으로 교체한다. 공유 연결에는 `-L`을 추가하지 않았다. 8888 포트 전달은 기존에 연 원래 SSH 연결이 담당하므로 해당 연결을 유지하고, 같은 로컬 포트를 중복 바인딩하지 않는다.
