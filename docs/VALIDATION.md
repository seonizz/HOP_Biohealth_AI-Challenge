- 사용자 답변 예시의 전체 30문항 입력 경로는 실제 UI 이벤트를 사용하는 VM 검사로 확인했습니다. 원문에 없는 추가 답은 만들지 않았습니다. 일부 실제 브라우저 답변과 상태 갱신을 확인했지만, 학습 모델로 예시의 최종 가이드까지 완주한 검증은 아직 없습니다. API의 연결 오류·혼잡이 관측되었고 실패 시 원문을 보존합니다. 이번 질문 DB 전환 검증은 모델 생성과 별도로 수행했습니다.

## 실제 Gemma API

- 인증된 `/v1/models`: HTTP 200, `gemma4:12b` 제공 확인.
- `/healthz`: HTTP 200, 준비 상태 `ok`.
- 짧은 생성 요청: HTTP 200, 정상 종료.
- `node --env-file=.env scripts/live-check.js`: 합성 주변인 사례로 내부 상태 갱신과 최종 가이드 생성 성공. 상태·최종 결과 각각 현재 답변으로 검증된 근거 7개.
- 실제 상태 생성 약 57초, 후속 최종 생성 약 69초. 이는 이번 합성 실행 관측이며 보장된 지연 시간이 아닙니다.
- 첫 긴 생성 요청은 연결 오류로 실패했습니다. 짧은 요청과 후속 전체 호출은 성공했습니다. 실패 시 답변을 보존하고 재시도하는 경로를 검증했습니다.

## 브라우저 확인

Codex 브라우저에서 `http://127.0.0.1:9000`을 열어 기존 시작·칼럼·읽기 화면을 확인했습니다. 담기, 읽기 완료, 정원 1/10 표시, 새로고침 후 읽음·담음 보존을 실제 서버 연결로 확인했습니다. 합성 이름 입력 뒤 실제 모델 상태 갱신과 다음 문항 표시, 되돌리기로 최초 문항 복원을 확인했습니다.

익명 세션·개인 시연용 서버 저장 안내를 UI에서 제거하고 Docker 이미지를 다시 빌드했습니다. 브라우저 새로고침 후 시작 화면과 첫 질문에서 해당 문구가 사라진 것을 확인했습니다. [확인 화면](screenshots/name-question.jpg).

전체 문항을 실제 모델로 한 번씩 수동 통과하는 긴 브라우저 시나리오는 실행하지 않았습니다. 전체 문항·후속 질문·완료·기록 삭제는 PostgreSQL API 통합 테스트에서 검증했고, 실제 모델의 상태·가이드 생성은 합성 실행으로 따로 확인했습니다.
