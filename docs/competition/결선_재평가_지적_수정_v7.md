2026-10-16 · 기준: `531522f` 이후 현재 작업 트리. [원래 v7 평가서](결선_적대적_재평가_v7.md)의 **67/90점은 당시 기록으로 보존**한다. 이 문서는 수정 결과이며 재채점이 아니다. 모델 자체와 처리시간은 평가하거나 개선 효과의 근거로 쓰지 않았다.

## G1 — 로컬 자료 보존과 재유입 방지

`ai/outputs/**/private/`와 일반 압축 묶음을 제외한다. 1,223파일 모두 삭제 전 기록한 SHA-256과 로컬 내용이 일치하는지 확인했다. ZIP 2개는 내용 검사를 통과했다고 간주할 수 없는 묶음이어서 추적을 해제했으며, 내부에 원문이 있었다고 별도로 단정하지 않는다.

[검사 도구](../../tools/audit_git_privacy.py)는 작업 파일 대신 **실제 Git 인덱스의 blob과 인덱스의 `.gitignore`**를 읽는다. 10MiB 이상, 제외 경로에 남은 추적 파일, 알려진 원천의 80자 이상 완전 일치 문자열, 파싱 실패·불투명 압축을 검출한다. Office 파일은 패키지 구조와 XML·첨부를 검사하며, 일반 ZIP의 확장자만 바꾸어 검사를 통과하지 못하게 했다. 상담 원문은 출력하지 않는다.

현재 인덱스 1,142파일에서 원문 일치·정책 위반·파싱 오류는 0건이다. 비교 기준은 원천 단위 106,583개, 고유 해시 53,884개다. 텍스트·JSON·JSONL·Office XML까지 검사 범위를 넓혔지만, 짧은·변형된·부분 발췌와 이미지 문자는 배제하지 못한다. 인덱스와 별도로 변경·신규 작업 파일도 같은 원천 해시 기준으로 확인했다.

`.githooks/pre-commit`을 추가하고 이 로컬 저장소의 `core.hooksPath`를 설정했다. 다른 클론에서의 설치와 검사법은 [도구 안내](../../tools/README.md)에 있다. 이 훅은 검사를 돕는 장치이며 과거 이력을 지우거나 모든 형태의 원문을 식별하는 보증이 아니다.

## A1 — 불확실한 선택과 입력 사실 분리

`잘 모르겠어요`와 유의미한 직접입력이 함께 있으면 필드 상태는 `answered`, 선택 상태는 `selection_status:unknown`으로 보존한다. 모름만 입력하면 `unknown`을 유지한다. 공백·보이지 않는 문자만 있는 입력을 사실로 승격하지 않으며 건너뜀·공개 거절을 바꾸지 않는다. [질문·근거 계약](../../app/docs/RELATIONSHIP_AGENT.md)에 정책을 반영했다.

[회귀검사](../../app/tests/mixed-answer.test.js)는 직접입력 대조군, 혼합 입력, 현재 위험·부인 합성 문장, 수정, 저장 재조회, 검색·안전·인용과 과거 암호화 상태 읽기를 확인한다. 기존 저장 원문·암호문은 덮어쓰지 않고 읽기 경계에서 정규화한다. 실제 브라우저에서도 보기 선택과 텍스트 입력을 통해 HTTP 저장 후 근거 자격이 유지되는지 확인했다.

## O1 — 삭제 키와 보유기간 집행

[보유·삭제 계약](../../app/docs/DATA_RETENTION.md)에 API·환경변수·마이그레이션·운영 한계를 정리했다. 삭제 키는 무작위 256비트이며 서버에는 해시만 저장한다. 키는 해당 소유자의 대화 삭제만 허용하며 조회·복구 권한을 주지 않는다. 현재 세션과 다른 소유자의 키를 쓰면 현재 소유자의 화면과 데이터를 보존한다.

유효한 세션의 마지막 API 접근부터 개발 기본 30일(설정 1~90일)이 지나면 접근을 차단하고 시작 시·매시간 청소한다. 기존 DB에는 마이그레이션 시점부터 유예기간을 준다. 청소 실패는 health 503으로 드러내고 재시도한다. 자동 청소는 소유자와 연결된 대화·결과·상태·이력·칼럼 상태를 제거한다. 이용자 요청 대화 삭제는 별도의 칼럼 상태를 보존한다.

실제 브라우저에서 이전 소유자의 합성 대화 **5 → 0개**, 새 소유자의 대화 **1개 보존**을 확인했다. 새로고침 없이 쿠키만 지운 경우도 다시 확인하여 이전 대화 삭제 후 캐시가 0개이고 세션이 새로 발급되는 것을 확인했다. 테스트용 스키마는 제거했다. 삭제 후 재조회 실패는 삭제 성공과 화면 갱신 실패를 구분한다.

운영 DB에는 적용하지 않았다. SQL 삭제가 저장매체 덮어쓰기나 모든 백업의 삭제를 증명하지 않으며, 운영 정책 확정과 감시는 별도 완료 조건이다.

## D1 — 선별 편중과 사람 검토의 경계

[대표성 보고서](../../data/docs/support_agent/결선_데이터_대표성_2026-10-16.md)는 원천 → release → 원본 SFT → 내용 허용 → 4,096 후보를 같은 정의로 비교한다. 목표 발화가 원상담 전반부에 있는 비율은 내용 허용 **54.18%에서 후보 99.16%**로 증가했고, 마지막 1/4은 **9,266행에서 1행**으로 줄었다. 위치는 원문 순서이며 실제 시간이나 임상적 단계 판정이 아니다.

층화 검토 요청 391개는 298상담·180그룹을 포함한다. 원문 접두부·정답·분할·해시와 기존 주석 문맥 391개를 원천에 재대조했다. 주변인 목적 과업 6개의 정의와 독립 검토·불일치 조정·권한 게이트는 [검토 계약](../../data/docs/support_agent/결선_데이터_검토계약_2026-10-16.md)에 명시했다. 원문이 있는 검토 자료는 Git 제외 경로에만 저장했다.

이번 선별 대조를 사용 이력에 추가하여 후보 **17,236행·199그룹 전체를 `development_exposed`**로 기록하고 기존 이벤트는 보존했다. 사람 결정과 신규 주변인 정답은 **0건**이다. 원천·기존 후보 내용을 임의로 바꾸지 않았고 편중이 해결됐다는 주장도 하지 않는다. 사용 범위·수령 근거·라벨 의미 확인과 실제 사람 검토가 필요하다.

## C1·F1 — 비교 가능한 주장과 발표 자료

[대안 비교·현장 검증표](결선_대안비교와_현장검증_v1.md)에 같은 합성 과업의 메모·체크시트·말씨 결과, 수동 대조의 장점과 한계, 앱에서 실행한 원문 인용 수락·주체 혼동 거절·미입력 사실 거절 3개를 기록했다. 이는 계약의 차이이며 사용자 우월성·시장 수요를 증명하지 않는다. 참여자 관찰과 기관 역할 확인란은 미실행 상태로 남겼다.

[발표 v4](../../presentation/archive/final_v2-v5/말씨_결선_실전발표_v4.pptx)는 v3의 디자인을 유지하면서 실제 결과 화면의 첫마디·자기돌봄·행동·근거 예시 2장을 추가했다. 화면은 새로 작성한 합성 fixture를 실제 UI에 넣어 캡처했고 실제 상담 원문이나 모델 호출을 사용하지 않았다. 검사 수, 현재 소스, 대안 비교, 삭제 키·보유기간, 대표성 편중을 본문·발표 노트에 반영했다. 이전 v3는 보존한다. 전체 14장을 렌더링하고 패키지·레이아웃 검사를 수행했다.
