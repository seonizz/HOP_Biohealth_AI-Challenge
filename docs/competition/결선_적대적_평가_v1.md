## 1. 판정

**사용자가 직접 체험할 수 있는 서비스와 상당한 데이터 처리 기반은 존재한다. 그러나 ‘대회 데이터로 학습한 최종 모델이 주변인 지원이라는 목적에서 유효하고, 현장에 바로 적용할 수 있다’는 핵심 주장을 현재 자료로 방어하기는 어렵다.**

가장 큰 약점은 기능의 수가 아니다. **상담 분류 성능, 31B의 원본 상담사 응답 학습, 12B 기반 주변인 지원 앱이 서로 다른 과제·모델·검증으로 존재한다.** 이 셋을 하나의 완성된 성능 이야기로 설명하면 심사위원은 실제로 어느 기능이 어떤 데이터와 평가로 검증됐는지 다시 물을 수밖에 없다. [R02][R03][R05][R06][R08][R13]

증거가 있는 범위의 보수적 모의 점수는 **39/90점이며, 현장 발표·질의응답 10점은 평가를 유보한다.** 현장 점수를 임의로 5점이라 가정할 때만 **44/100점**이다. 이 점수는 공식 심사 결과나 수상 확률이 아니라, 아래 공개한 내부 배점으로 작성한 적대적 검토자의 판단이다. 경쟁팀 자료가 없으므로 순위·탈락·수상 여부는 예측하지 않는다.

| 우선순위 | 핵심 판단 | 근거 확신도 | 점수에 미치는 해석 |
|---|---|---|---|
| 1 | 최종 목표 31B와 현재 12B 앱, 별도 분류 기준 모델 사이에 검증 연결이 부족하다 | 높음 | 최종 완성도와 모델 목표 달성의 근거가 약하다 |
| 2 | 독립 test 및 주변인 지원 목적의 사람 평가가 확인되지 않는다 | 높음 | NLL·형식 유효율로 정확도·유용성·신뢰성을 대신 설명할 수 없다 |
| 3 | 저장된 웹 사례에 상태 갱신 정체·과도한 해석·긴 대기가 있다 | 높음 | 즉시 적용가능성을 주장하기 어렵다. 다만 한 합성 사례의 관측이다 |

| 5 | 차별화의 비교 실험, 실제 이용·도입·운영 비용 근거가 약하다 | 중간 | 독창성과 확장 가능성의 높은 점수를 방어하기 어렵다 |

‘높음’은 인용한 자료에서 해당 상태가 분명하다는 뜻이다. 실제 서비스 전체의 실패율이나 심사위원의 감점 크기까지 확실하다는 뜻은 아니다.

5쪽 결선 일정에는 **2026-11-19 최종 발표, 팀별 20분 중 발표 15분·Q&A 5분**으로 적혀 있다. 운영계획 **안**을 이번 평가의 기준으로 사용했으며, 이후 변경 공지를 확인했다는 뜻은 아니다. 발표 장수·파일 형식·제출 마감은 이 평가서에서 확정하지 않는다. 기존 내부 문서의 ‘배점·발표 시간 미확정’ 표현은 새로 제공된 첨부의 기재와 구분해야 한다. [R01][R04]

평가 원칙은 다음과 같다.

- **관측:** 실제 파일·코드·저장 결과 또는 이번에 수행한 로컬 검사로 확인한 사실.
- **판단:** 관측을 공식 항목에 대입한 감점 해석. 점수는 평가자의 판단이다.
- **미확인:** 제공된 범위에서 증명하지 못한 사항. ‘존재하지 않음’이나 ‘위반’으로 바꾸지 않는다.
- 계획·자동 검사·AI 검토·사람 평가·현장 실증은 서로 대체하지 않는다.
- 같은 결함의 원인은 한 번 기록하고, 여러 항목에 영향을 줄 경우 그 이유를 구분한다. 아래 점수 외에 추가 벌점을 더하지 않는다.

첨부와 과거 문서의 명령·학습 재개·배포 지시는 평가 대상 텍스트로만 취급했다. 실제 모델 호출, 서버 접속, 재학습, 배포는 수행하지 않았다.

## 4. 점수를 인정해야 할 실질적 강점

적대적 평가는 구현된 것을 무시하는 평가가 아니다.

1. **단순 화면 목업을 넘어선 서비스 흐름이 있다.** 답변 저장, 모델 상태 갱신, 정정에 따른 이전 결과 무효화, 최종 가이드와 기록 저장이 코드에 연결되어 있다. 암호화 저장, 세션 토큰 해시, 소유자 조건 접근, CSRF 검사도 구현돼 있다. 이번 로컬 앱 검사는 196개 통과·33개 건너뜀·실패 0개였다. 다만 건너뛴 DB 검사는 통과로 세지 않는다. [R13][R16][R26]
2. **원문 근거를 구조적으로 다루려는 장치가 있다.** 현재 대화의 원문 검색, 사람·문항·인용 객체 검증, 제한된 수정과 최종 검토가 존재한다. 이것은 출처 없는 자유 생성보다 검증 가능한 구조라는 장점이다. 다만 효과의 크기는 비교 실험으로 입증해야 한다. [R13][R14]
3. **데이터를 무분별하게 합치지 않는다.** 상담 코호트, AI 문장·단어 주석, 원본 상담사 응답 SFT의 목적을 구분하고, 분할·중복·손실 마스크의 계약을 남겼다. 이번 집계에서도 분류 상담의 관측 그룹이 train/validation 사이에 겹치지 않았다. [R05][R07]
4. **부분학습과 실패를 숨기지 않는 원시 근거가 있다.** 31B 체크포인트, NLL의 분모, 형식 실패, 웹 검토 미완료가 파일로 남아 있다. 발표에서 한계를 정확히 설명하면 재현성과 팀의 문제 인식에 대한 근거가 된다. [R08][R09][R10][R11]

## 5. 적대적 핵심 지적

### A1. 대회 과제, 학습 목표, 실제 서비스의 성과 연결이 끊겨 있다

**심사위원 질문:** “우울·불안·중독을 판별하는 모델을 만든 것인가, 상담사처럼 답하는 모델을 학습한 것인가, 가족에게 대화법을 추천하는 서비스를 만든 것인가? 어느 결과가 이번 대회 성과인가?”

**관측:** PDF 4쪽은 심리상담 데이터 1,661건을 이용한 심리 질환 판별 AI 모델을 주제 예시로 제시한다. 현재 앱은 주변인 지원 가이드를 생성한다. 분류 기준 모델은 TF-IDF + Naive Bayes이고, 31B SFT의 목표는 다음 원본 상담사 응답이다. 앱의 최종 기록 경로는 `scores:{}`, `symptoms:[]`, `risks:[]`, `protect:[]`를 구성한다. 현재 관계 에이전트 경로가 그 분류 기준 모델을 호출한다는 근거는 확인하지 못했다. [R01][R04][R05][R06][R07][R16][R29]

**판단:** 사용 목적의 전환 자체가 나쁜 것은 아니다. 그러나 별개 과제의 결과를 이어 붙이면 대회 데이터·모델이 실제 서비스에서 어떤 가치를 만드는지 설명이 약해진다. 창의성 항목에서는 목표 대비 완성도, 모델 항목에서는 목적에 맞는 분석 방법이 감점 대상이다.

**미확인:** 제출·승인된 최초 계획서와 멘토의 범위 변경 승인. PDF에는 주제가 변경될 수 있다고 적혀 있으므로, 주변인 지원을 곧바로 규정 위반이나 탈락 사유라고 단정하지 않는다.

**반박에 필요한 증거:** 승인 목표→입력 데이터→학습 목적→현재 실행 모델→평가 지표→사용자 출력의 대응표. 분류가 실제 서비스 구성요소라면 호출·출력·후속 활용을 보여 주고, 연구용 별도 구성이라면 그 범위를 분명히 설명해야 한다.

**관측:** 상담 validation 117행은 23개의 관측 ID 그룹에서 나온다. train/validation의 관측 그룹·대상자 ID 교차는 0이지만, 그 ID가 실제 인물의 완전한 유일성을 보장하는지는 확인되지 않았다. 문장 주석 1,646행은 모두 `human_verified=false`이며 별도 AI 검토는 그중 205행이다. 따라서 누수를 확정하는 것도, 전문가 정답으로 간주하는 것도 부정확하다. [R05][R21]

**판단:** 전처리와 형식 검증은 좋은 기반이다. 그러나 AI 주석에 맞춘 성능, 상담 코호트 분류, 임상 상태 판별, 주변인 지원의 유용성은 서로 다른 주장이다. 대표성·실제 인물 독립성·라벨의 목적 적합성이 남아 있다.

**반박에 필요한 증거:** 공고→수령→적재→선별 수량 대조, 실제 인물/원천 그룹을 고려한 고정 test, 라벨 기준과 독립 검토 기록. 불명확한 인물 ID를 추정으로 확정하지 않는다.

### A3. 모델 성능의 핵심 수치는 목표 달성을 입증하지 못한다

**반박에 필요한 증거:** 동일 기반 모델의 학습 전후를 같은 보류 사례·프롬프트·출력 예산으로 평가하고, 분류 성능과 가이드 유용성을 별도로 측정한다. 성공 기준은 결과를 본 뒤 정하지 말고 먼저 선언한다. 표본 수와 그룹 수, 실패 분모, 클래스별 결과, 불확실성을 함께 보고한다.

### A4. 현재 시연 모델과 최종 목표 모델이 다르며 개선 코드도 분리돼 있다

**관측:** 기준 문서는 최종 목표를 31B, 현재 앱을 임시 12B 테스트라고 명시한다. STATE 개선본은 `ai/local_api/backend_patch`에 따로 있고 미배포로 기록돼 있다. 실행본과 개선본의 `relationship-agent.js` SHA256도 서로 다르다. 같은 프롬프트 버전 문자열을 사용한다고 동일 구현이 되는 것은 아니다. [R02][R13][R23]

**판단:** 12B 데모를 잘 보여 주어도 31B 최종 시스템의 품질·지연·통합 완성도를 자동으로 증명하지 못한다. 반대로 31B 학습 손실 감소를 12B 화면의 성능 근거로 쓰는 것도 불가능하다.

**반박에 필요한 증거:** 최종 모델·체크포인트·프롬프트·앱 소스의 식별자와 해당 조합으로 실행한 초기·누적·정정·위험 부정·현재 위험 사례 및 저장·재조회 결과. 이번 평가에서 전환이나 패치 반영을 수행한 것은 아니다.

### A5. 인용과 모델 검토는 의미 정확성의 보증이 아니다

**관측:** 저장된 v3.5 합성 웹 기록은 29개 답변, 최종 7단계 생성, 저장·재조회를 수행했다. 하지만 검토 기록은 `complete:false`다. 초기 사실에 머문 관계 메모리와 인용보다 넓은 `reported` 해석이 관찰됐다. 마지막 스크립트의 특정 장면 키워드 조건도 실패했다. [R11][R12]

키워드 실패만으로 가이드가 의미적으로 틀렸다고 단정하면 안 된다. 기록에는 다른 원문 장면을 사용했고 상담 의도는 남았다고 적혀 있다. **여기서 방어할 수 없는 주장은 ‘전체 웹 의미 검증 완료’이지, 이 한 건만으로 ‘서비스 전체가 무용하다’는 결론은 아니다.**

RAG의 실제 검색 대상은 현재 대화 원문이며 방식은 `conversation_lexical_v1`이다. 외부 임상 지식이나 전문가 지침을 검색하는 시스템으로 소개하면 안 된다. `reviewed:true`도 사람 검수가 아닌 모델 검토이며, 코드 문서는 `clinically_validated:false`를 유지한다. [R13][R14]

**판단:** 한 모델이 생성과 검토를 수행하므로 검토 단계가 많다는 사실만으로 오류의 독립적인 검출력을 입증하지 못한다. 인용 문자열이 실제로 존재하는 것과 그 인용으로 해석을 뒷받침할 수 있는 것은 별도 평가 대상이다.

**반박에 필요한 증거:** 사람 혼동, 최신 답변 반영, 정정 전파, 거절·부정·시점 보존, 근거 없는 동기 추측 등을 원문과 대조한 독립 검토 결과. 오류와 모델의 검토 통과 여부를 함께 기록해 검토 단계가 놓친 사례도 공개한다.

### A6. 현재 저장된 지연은 ‘빠르게 이용할 수 있다’는 설명을 약하게 만든다

**관측:** v3.5 합성 웹 원시 결과의 29개 `duration_ms`를 재집계했다. [R12]

| 항목 | 재계산 값 |
|---|---:|
| 상태 갱신 대기 합계 | 1,126,522ms = **18.78분** |
| 턴별 대기 중앙값 | 36.926초 |
| 최소 / 최대 | 13.932초 / 135.608초 |
| 범위 | 해당 29턴의 모델 상태 갱신 대기; 사람의 입력 시간·최종 가이드 생성 제외 |

시작 화면은 질문에 답하기를 **‘약 10~15분’**으로 안내한다. 서버는 상태 갱신 모델 응답을 기다린 뒤 다음 질문을 반환한다. 따라서 이 한 시나리오에서는 질문 과정의 모델 대기만으로 표시 범위를 넘는다. [R15][R16]

**판단:** 즉시 적용가능성의 직접적인 반박 지점이다. 긴 처리 자체보다 실제 대기와 화면 기대의 차이, 실패 재시도 비용, 현장 시연 시간의 불확실성이 문제다. 이 숫자를 전체 서비스 평균이나 목표 31B 지연으로 일반화하지 않는다.

**반박에 필요한 증거:** 최종 모델·동일 하드웨어에서 여러 독립 시나리오의 전체 완료 시간, 성공률, p50/p95, 재시도 수, 동시 사용 조건을 기록한다. 사람 입력 시간과 추론 대기를 분리하고 UI 안내를 측정 범위와 맞춘다.

### A7. 실제 이용과 사업화 근거가 ‘가능성’에서 멈춰 있다

**관측:** 현재 문서와 후보 덱은 사용자 의견 확인·상담사 답변 비교를 준비 계획으로 설명한다. 검토한 현재 자료에서 완료된 사용자 연구 보고서, 도입 기관의 확인, 고객/지불 주체 검증, 세션당 비용·동시 처리 용량·운영 담당 체계를 확인하지 못했다. 기대효과 덱의 110만 명·1% 사용 가정 등은 수요 검증 자체가 아니다. [R02][R17][R19][R28]

운영 측면에서는 기본 익명 세션 만료 후 서버 데이터가 남고, 기존 익명 기록에는 접근할 수 없는 동작이 문서와 코드에 명시돼 있다. 현재 세션 소유 기록의 삭제 기능은 있지만, 세션 만료·쿠키 소실 뒤의 복구/삭제 절차와 보유 정책을 추가로 설명해야 한다. ‘삭제 기능이 전혀 없다’는 지적은 부정확하며, 여기서는 접근 수명과 데이터 보유 수명의 차이를 문제로 삼는다. [R13][R16][R26]

**판단:** 발표에서 ‘많은 사람이 필요로 한다’와 ‘이 서비스가 선택되고 지속적으로 운영될 수 있다’ 사이를 증명해야 한다. 사회적 필요는 인정하더라도 즉시 적용·보급 가능성 30점 전체를 방어하지 못한다.

**미확인:** 문서 밖의 인터뷰·협약·기관 검토. 원천 이용 조건, 제3자 정보 처리, 보관·삭제 정책의 운영 확인도 별도 증거가 필요하다. 현재 자료만으로 법적 위반 여부를 판정하지 않는다.

**반박에 필요한 증거:** 한 가지 도입 상황과 이용자·구매자·운영자를 정하고, 실제 과업 완료·이해도·부담·재사용 의향을 관찰한 기록을 남긴다. 전문가 검토 결과, 실패 시 안내·지원 흐름, 수집·전송·저장·삭제 범위, 측정된 세션 비용을 연결한다. 소규모 사용성 확인을 임상 효과 실증으로 표현하지 않는다.

### A8. 발표자료와 실제 UI에 과장으로 읽힐 여지가 남아 있다

**관측:** 이번에 원본 PPTX ZIP 내부의 슬라이드·노트 XML을 직접 추출했다. **32개 덱·60개 슬라이드**, 본문에 `37.6`이 있는 덱 **14개**, `12B` 표기가 있는 덱 **0개**, `90%`와 `95%`가 모두 있는 덱 **3개**였다. 텍스트 검사이며 전체 슬라이드의 시각적 완성도를 검증한 것은 아니다. [R17][R18][R19]

- 연구근거 덱 1쪽은 `+37.6% 학습 지표 개선`을 크게 표시한다. 노트에는 NLL 조건이 있지만 본문만 보면 상담 성능 향상으로 오해할 수 있다. 본문에 모델·분모·지표명이 필요하다.
- 같은 덱 2쪽은 90%·95%를 선행연구 평가자 일치도로 구분한다. 이를 말씨 자체 성능으로 제시했다는 지적은 부당하다. 다만 말씨 적용 효과는 따로 검증해야 한다. 논문 원문을 이번에 재검증한 것은 아니다.
- 기대효과 덱 노트는 통계 출처를 사용자 제공 PPT로만 기록한다. 원조사·연도·대상·분모가 없으므로 이 보고서에서 검증된 시장 수치로 인정하지 않는다.
- 앱 소개는 `말씨가 배우고 있는 데이터`, 1,661회기·46만여 단락·64개 항목과 증상 신호의 뚜렷함을 학습한다는 설명을 함께 제시한다. 원천 데이터의 소개와 현재 12B/31B의 실제 사용·학습·평가 범위를 구분할 필요가 있다. 원천 숫자 자체가 틀렸다고 단정하는 지적은 아니다. [R24]
- 별도 카드 실험의 `organized.md`는 Codex가 반복·오타·출처 없는 단정을 덜어낸 편집본이다. 모델의 무편집 출력이나 현재 웹 앱 성능으로 제시하면 안 된다. [R25]

**반박에 필요한 증거:** 제출 덱 한 개를 지정하고, 모든 핵심 숫자에 모델·날짜·표본·과제·출처를 붙인다. 서비스 시연 화면과 발표 본문의 현재 상태가 일치해야 한다. 발표 태도·질의응답 능력은 실제 리허설 없이 평가하지 않는다.

오프라인 앱 테스트는 `app/`에서 `TEST_DATABASE_URL`, `DATABASE_URL`, `MODEL_BASE_URL`, `MODEL_API_KEY`를 제거한 환경으로 실행했다. 비공개 원문·인증키·개인정보를 평가서에 복사하지 않았다. 실패와 오류 관측은 합성 평가 기록을 사용했다.

### 평가의 경계

- 현재 Git 저장소는 평가 시작 시 **커밋이 없는 초기 상태**였으며, 기존 프로젝트 파일은 미추적 상태였다. 평가 도중 별도 커밋 이력이 생성된 것도 확인했다. 따라서 평가 입력 전체가 단일 커밋에서 확보됐다고 주장하지 않는다. 이 작업에서는 v1 평가 파일만 버전 기록하며, 근거 JSON의 파일 해시로 검토 입력을 식별한다.
- `archive/`의 과거 계획·설계 링크 일부를 열 수 없었다. 현재 이용 가능한 실행 코드와 원시 산출물로 보완했지만, 최초 승인 계획 대비 완성도는 부분 판단이다.
- 현재 서버의 가동, GPU 체크포인트 실재·로딩, 31B 통합 상태를 원격으로 확인하지 않았다. 저장 기록의 날짜를 현재 서비스 검증일로 바꾸지 않았다.
- 완료된 사람 평가·도입 협약을 발견하지 못했다는 것은 팀이 어디에서도 수행하지 않았다는 단정이 아니다. 해당 증거가 제공되면 재평가해야 한다.
- 경쟁 서비스 조사, 외부 논문·시장 통계 원문 재검증, 법률·임상 적합성 판정은 범위에 포함하지 않았다. 그 근거가 필요한 주장을 이번 평가에서 높은 점수로 인정하지 않았을 뿐이다.
