# 결선에서 실제 사람이 확인해야 할 증거

기준일: 2026-10-16. [v10 평가](결선_적대적_재평가_v10.md)의 남은 감점 중 코드·형식 검사로 대신할 수 없는 부분이다. 담당자는 역할로 표시했으며, 실제 담당자 지정·회신·서명·관찰이 있었다는 뜻이 아니다. 모든 항목은 **대기**다. 모델 자체·처리시간은 평가하지 않고 현장 발표·Q&A 10점은 관찰 전까지 유보한다.

## 지금 준비된 자료를 쓰는 방법

- [사람 검토 인계 절차](../../data/docs/support_agent/사람검토_인계_절차_v1.md)의 로컬 묶음을 사용한다. 준비된 요청에는 승인자나 성공 결과를 미리 채우지 않는다. 검토 결과를 기록할 때도 원천 내용 해시와 연결하고, 원문이 바뀌면 이전 판정을 재사용하지 않는다.
- [원천·주변인 검토 계약](../../data/docs/support_agent/결선_데이터_검토계약_2026-10-16.md)의 과업별 기준을 사용한다. AI의 `accepted_for_experiment`는 사람의 정답 승인이 아니다. 사람의 검토 완료와 학습 사용 권한 확보도 별도 조건이다.
- [같은 과업의 대안 비교·현장 검증](결선_대안비교와_현장검증_v1.md)의 사전 과업과 기록표를 사용한다. 비교 순서를 교차 배정하고 도움·미완료·중단을 분모에서 빼지 않는다. 짧은 시연의 선호를 임상 효과나 시장 전체의 우월성으로 확대하지 않는다.
- [운영 계약](../../app/docs/DATA_RETENTION.md)의 증거 점검에 실제 기록을 연결한다. 점검 통과는 입력한 파일의 연결 확인이며, 백업 삭제나 승인자의 신원을 대신 확인하지 않는다.

## 기록 형식과 증거 보관

각 기록에는 `항목 ID / 상태 / 검토 대상 버전·SHA-256 / 실제 수행일 / 담당 역할과 확인된 검토자 / 관측·판정 / 근거 파일·SHA-256 / 남은 조건`을 남긴다. 기록을 만드는 것, 실제 검토하는 것, 승인하는 것, 운영에 적용하는 것을 다른 상태로 관리한다. 결과가 없으면 **대기**, 반려·불일치가 있으면 그대로 **보류/수정 필요**로 남긴다.

원천·학습 행·실제 사람의 신원·원문이 담긴 기록은 Git 제외 로컬 경로에 보관한다. 공개 보고서에는 원문 없는 분모·상태·검증 방법만 싣는다. 자동화 도구가 실제 참여·검토·회신을 만들어 냈다고 표현하지 않는다. 이 작업에서 사람이나 기관에 연락하지 않았다.

## 공개 공지 확인의 범위

2026-10-16에 확인한 [상명대학교 바이오헬스 사업단의 모집 공지](https://biohealth.smu.ac.kr/biohealth/board/notice.do?articleNo=768429&mode=view)는 2026-09-07 모집 안내이며 운영기간 9~11월, 결선 장소를 안내한다. 이것만으로 최종 발표 파일 규격·팀별 제출 기한·현재 과제의 승인을 확인할 수 없다. 이 공지가 연결한 대전대학교 주최 측 원문은 이번 조회에서 내용을 가져오지 못했다. 공개 검색에서 찾지 못했다는 사실을 최종 공지가 존재하지 않는다는 증거로 쓰지 않는다.

첨부 운영계획(안)의 **결선 발표 15분·Q&A 5분, 11월 19일**은 기존 준비 기준으로 유지하되, 최종 공지와 개별 통보를 대조하기 전에는 확정 제출 조건으로 표시하지 않는다. 사전 준비 배분은 앱 처리시간 채점과 관계없다.
