# v13 HR5·HR6 수정과 사람 검토 인계 재검증

확인일: **2026-10-18, Asia/Seoul**. [v13 평가](결선_적대적_재평가_v13.md)의 HR5·HR6를 수정했다. 별도 채팅에서 진행 중인 앱 전체 흐름·GPU 시험은 이 작업의 변경·검증 범위에 포함하지 않는다. 새 점수는 부여하지 않았다.

## 수정한 계약

- **HR5:** 입력 26파일을 안정적인 바이트 스냅샷으로 캡처한다. manifest의 SHA-256·길이와 릴리스 검증, 질문은행 탐지·의존성, 전문 사례 재검증, legacy 해시·참조, 계약 사본이 같은 바이트를 사용한다. 시작·종료 해시만 비교하던 구조를 바꾸고 파일의 장치·inode·형식·크기·mtime/ctime도 대조한다. 발행 직전과 별도 검증 완료 직전에 입력 안정성을 다시 확인한다.
- **HR6:** JSONL은 LF로 나누고 CRLF도 지원한다. 문자열 안의 U+2028·U+2029는 보존한다. raw/escaped 표현과 생성→외부 pin 검증 왕복을 확인했다. 빈 줄은 허용하고 공백만 있는 줄은 기존처럼 거절한다.
- 릴리스·질문은행 검사에는 선택적 바이트 인자를 추가했다. 기존 호출 방식과 사람·전문가 승인 게이트는 유지한다. 출력 payload의 파싱·내용 비교도 같은 읽기 결과를 사용한다.

변경 구현: [인계 도구](../../data/counseling_pipeline/human_review_bundle.py), [릴리스 검사](../../data/counseling_pipeline/agent_dataset.py), [질문은행·사례 검증](../../data/counseling_pipeline/agent_training.py). `agent_dataset.py`의 이 작업 이전 변경은 시작 시 파일 사본과 대조해 보존했다.

## 검증 근거

기존 인계 검사 **29개**가 통과한 상태에서 회귀를 추가했다. 수정 전 최초 추가 검사 실행은 **36개 중 실패 19·오류 8**로 결함을 재현했다. 이는 하위 조건을 포함한 실패 수이며 독립 결함 27개라는 뜻이 아니다. 최종적으로 검증 완료 직후 입력 변경도 추가해 **37개 모두 통과**했다. [회귀 검사](../../data/tests/test_human_review_bundle.py) · [수정 전 관측 요약](../../runtime/handoff-integrity-20261018-r1/hr5-hr6-red-summary.json) · [최종 인계 실행 로그](../../runtime/handoff-integrity-20261018-r1/human-review-bundle-green.log)

회귀에는 pending·계약의 A→B→A, 릴리스 9파일, legacy 7파일, 질문은행 내용 대체, 지속 변경·복원, 검증 후 입력 변경, Unicode 8조합을 포함한다. 실제 합성 파일을 변경하고 작성 동작이 실행됐는지 단언한다. 이전 `Path.read_bytes` hook이 사라졌다는 사실만으로 수정 완료를 판단하지 않는다.

독립 코드 검토는 실행 가능한 결함 0건을 보고했고, 저장된 바이트를 전달한 helper가 실제 파일을 다시 읽지 않는지와 검증 후 변경 거절을 별도 합성 검사로 확인했다. Python AST 파싱·컴파일은 통과했다. LSP·별도 타입 검사 도구는 사용할 수 없어 해당 통과를 주장하지 않는다.

전체 데이터 **38모듈·중복 없는 722개** 중 **665개 통과·실패/오류 0·57개 생략**이다. 생략은 이 Python 환경에 NumPy가 없어 43개, PyTorch가 없어 CPU autograd 검사 14개이며 설치하거나 통과로 계산하지 않았다. 인계 검사 37개는 전체 665개에 포함된다. [최종 실행 요약과 개별 생략 사유](../../runtime/handoff-integrity-20261018-r1/data-tests-final-summary.json) · [전체 로그](../../runtime/handoff-integrity-20261018-r1/data-tests-final.log). 앱·GPU·모델 실행 검사 수를 합산하지 않는다.

최초 전체 검사 명령은 namespace 테스트 디렉터리를 `discover -t`로 지정해 실행 전 import 오류가 났다. 파일은 바꾸지 않고 기존 테스트 모듈을 명시적으로 불러온 뒤 ID 중복 여부를 검사하는 실행기로 위 결과를 확인했다. 실제 인계본 생성 전 Git 제외 검사도 기존 심볼릭 링크 별칭 대신 해석된 실제 경로를 사용하도록 보완했다. 두 실행 설정 오류는 제품 결함이나 통과 수에 포함하지 않는다.

## 남은 우선순위와 한계

**기존 v9~v11의 구현 버전 결속:** 이번에 수정한 `agent_dataset.py`·`agent_training.py`는 해당 데이터의 manifest/provenance에도 고정돼 있다. 현재 코드로 기존 v9 `audit()` 또는 v11 `load()`·`verify()`를 호출하면 구현 해시 불일치로 거절되는 구조다. 두 모듈의 이전 해시는 이 작업의 시작 사본과 일치한다. 또한 현재 별도 앱 작업의 `app/src/model.js`·`app/src/relationship-agent.js`도 기존 앱 단계·v11에 고정된 해시와 다르다. v10의 저장 자료 읽기 자체와 현재 구현으로 새 측정을 수행하는 경로는 구분하며, 새 측정은 v9·앱 단계의 검증을 먼저 요구한다.

기존 manifest의 해시만 덮어쓰거나 진행 중인 앱/GPU 실행을 변경하지 않았다. 두 공용 모듈의 변경 전 사본은 `runtime/handoff-integrity-20261018-r1/before/data/counseling_pipeline/`에 보존했다. 전체 데이터 재발행은 별도 앱 작업의 코드가 확정된 뒤 새 경로에서 원행·분할·토큰·가중 정책을 대조하며 수행해야 한다. 기존 산출물은 과거 구현에 결속된 증거로 유지한다. 이번 **28단위 인계본은 이 의존성과 별개로 현재 코드에서 생성·검증 완료**다. [메타데이터 호환성 대조](../../runtime/handoff-integrity-20261018-r1/compatibility-impact.json)

이번 결과는 기존 검토 대기 자료를 신뢰할 수 있게 인계하는 선행 수정이다. 실제 사람의 판단·사용 범위 확인·개발 비노출 평가 자료가 생긴 것은 아니다. 현재 인계본은 기존 20대화의 24응답과 전문 보류 4건이며, 이후 v9의 추가 응답 48개와 앱 단계 정답쌍 24개를 포함하지 않는다. 전체 단계의 정답과 사람 검토를 마련할 때 각 버전·내용 해시·분모를 구분해야 한다.

스냅샷 검사는 관측한 파일의 일치·중간 변경을 확인한다. 운영체제 파일 잠금, 반환 이후 불변, 실행 중인 메모리·표준 라이브러리·사람 신원이나 임상 타당성 인증을 제공하지 않는다. 기존 절대 입력 경로 제약은 유지한다. 원천·학습 데이터 수정, 사람 승인 작성, 커밋·푸시, 원격 서버 작업은 수행하지 않았다.
