## 3. 학습 데이터 20점의 직접 근거

### 3.1 목적 적합성과 구성 — 3/5

분류 자료의 단위와 실제 입력–정답 관계를 구분했다.

| 자료 | Train | Validation | 실제 목표 |
|---|---:|---:|---|
| 상담 분류 | 990 | 117 | 상담 전체의 원천 코호트 라벨 |
| 문장 분류 | 1,440 | 206 | 문장 내용의 복수 의미 라벨 |
| 단어 분류 | 302 | 76 | 표현 단위 의미 라벨·어휘 그룹 |
| 원본 SFT | 40,652 | 5,322 | 원래 내담자 문맥에서 다음 상담사 응답 |
| 내용 노출 보류 후 SFT 후보 | 40,415 | 4,298 | 원본 SFT 중 보류 정책을 통과한 행 |
| 기존 4,096 길이 후보 | 15,512 | 1,724 | 위 풀의 특정 길이 선별본, 전체 후보와 구분 |

원본 SFT의 45,974행은 **1,069상담**에서 파생됐다. SFT에 부속된 문장·단어 등장 자료는 보조 출처 자료이며 독립적인 생성 정답으로 합산하지 않는다. 길이 후보는 별도 데이터 버전으로 검증했으며 길이나 처리속도로 가감점하지 않았다. [S04][S05]

원본 관점을 그대로 보존하고 내담자를 주변인으로 바꾸지 않은 점은 장점이다. 그러나 현재 서비스가 요구하는 **주변인의 관계·부담·지원 행동·첫마디에 대응하는 입력–정답쌍**은 이 자료로 직접 입증되지 않는다. 보충 AI 주석 24개도 실제 파일에서 모두 `training_allowed:false`, `human_verified:false`였고, 10개는 역할 확인 필요, 14개는 직접적인 주변인 요청 없음으로 표시됐다. 이를 사용 가능한 HOP 정답 24개로 계산하지 않는다. [S06]

### 3.2 원문·가공·라벨 품질 — 3/5

**긍정적 증거:** 원천 SQLite의 SHA가 SFT manifest와 일치했다. 분류에 채택된 1,107상담의 원본 JSON paragraph와 DB 발화 303,522개가 순서·화자·본문까지 같았고, 전달된 1,069상담의 접두 구간도 DB와 일치했다. SFT 45,974행을 이 출처로 재구성해 목표 원문, 미래 발화 미포함, 역할, 마지막 응답만의 손실 마스크, 중복 마지막 문답을 검사했다. 오류는 발견되지 않았다. 보조 문장·단어의 Unicode 좌표도 전수 대조했다. [S04][S05]

분류용 6개 분할의 행 순서·타깃·가중치·CSR 값과 특징 3,131행을 다시 계산했다. 어휘·문서빈도·IDF는 train만으로 만든 값과 일치했다. 문장 후보 **2,400=채택1,646+보류754**, 결정 통합 수정25건을 재생했을 때 원장·라벨·출처 불일치 0이었다. 단어 결정 **21,340=채택378+보류70+기타제외20,892**도 분할·제외 장부와 맞았다. [S03]

**점수 제한:** 원장과 라벨 배열이 일치하는 것과 그 라벨이 의미적으로 정확한 것은 다르다. 채택 문장 중 독립 AI 재검토 표시는 **205/1,646(12.45%)**, validation은 **18/206(8.74%)**다. 사람 검토 표시는 0이며, 후보는 관련 표현을 중심으로 선별됐다. 이 수치를 오류율이나 임상 정확도로 바꾸지 않는다. SFT도 원문을 재현한 휴리스틱 선별 자료여서 원문 응답 자체의 적합성을 전수 보장하지 않는다.

### 3.3 분할과 누출 방지 — 4/5

분류 3종의 train↔validation에서 정규화 동일 텍스트·그룹 교차는 0이며, 상담·문장 자료의 상담 ID 교차도 0이었다. 단어에는 상담 ID가 없어 상담 출처 연결은 미확인이다. 문장 분할과 반대쪽 상담 분할의 전체 문장 포함 검사도 0이었다. 문장 근접중복은 NFKC·공백 제거 후 **길이비≥0.8, 3글자 Jaccard≥0.6 후보, SequenceMatcher≥0.9** 범위에서 0쌍이었다. 전체 상담의 모든 근사·의미 중복까지 전수 제거했다는 뜻은 아니다. [S03]

SFT는 그룹 ID 교차 0만으로 종결하지 않고, 원본 풀과 실제 보류 적용 풀을 따로 공격했다.

| 분할 간 내용 노출 검사 | 원본 45,974행 | 보류 후 44,713행 |
|---|---:|---:|
| 관측 source group 교차 | 0 | 0 |
| 첫 8개 문맥 묶음 동일, 총 200자 이상 | 1개 묶음 | 0 |
| 검증 목표가 train 과거 assistant 문장 전체와 동일 | 54행 | 0 |
| 검증 목표가 train 최종 목표와 동일 | 15행 | 0 |
| 80자 이상 검증 목표 전체가 train assistant 문장 안에 포함 | 20행 | 0 |
| 위 포함 검사 중 200자 이상 | 10행 | 0 |

여러 검사는 같은 행을 중복 포함할 수 있다. 원본의 54행 노출은 기존 정책이 다루는 문제를 다시 확인한 것이며, 현재 후보에 그대로 남았다고 주장하지 않는다. **1,261행 보류 후 노출 감소를 직접 확인한 성과**를 점수에 반영했다. 3차·4차 admission 45,974행의 ID·순서·판정·사유도 일치했고, 4,096 후보 17,236행은 허용 ID 집합과 원본 내용이 정확히 같았다. [S05]

**남는 한계:** 보류 후 validation 4,298행은 97상담·21관측 그룹이며 최대 그룹588행(13.68%), 상위5그룹2,107행(49.02%)이다. 행 수가 독립 표본 수는 아니다. 실제 인물 유일성·의미 중복과 3종 결합 시 독립성은 미확인이다. 개발 및 선별 정책에 사용한 validation을 미사용 최종 test로 바꿔 부르지 않는다. 이 항목은 데이터 분할의 신뢰도를 평가하며 모델 성능 측정을 요구하는 감점이 아니다.

### 3.4 추적성과 재현 가능성 — 4/5

원천 인덱스 **1,507행은 고유 상담1,462건**에 대응한다. 인덱스 상태는 성공1,108·보류354·중복45행이며, 최종 분류는 **채택1,107+제외355**와 정확히 맞는다. 인덱스 중복 행과 고유 상담 제외를 혼동하지 않았다. SFT의 원본→보류→길이 후보가 해시와 장부로 연결되고, 재계산 가능한 코드도 확인했다. [S03][S05]

문장 3행의 부모 상담이 상담 릴리스에 없다는 후보 지적은 같은 분할의 동일본문 중복 제외로 설명됐다. 단어 manifest의 옛 절대경로3개도 현재 경로에 같은 이름·같은 SHA 원천이 모두 있었다. 최초 파일명 검색의 2/3 결과는 Python 런타임별 한글 Unicode 파일명 탐색 차이였으며, NFC로 비교한 재검사에서 3/3을 확인하고 두 결과를 보존했다. 이를 원천 소실로 감점하지 않았다.

공고 수량1,661과 로컬 고유 상담1,462의 차이199건은 수령 내역의 완전한 대응이 확인되지 않았다. 원천 사용 범위·비식별의 완전성도 이번 구조 감사만으로 확정하지 않는다. 이는 파일 손상이나 사용 위반을 발견했다는 뜻은 아니다. 원문·학습 행은 Git에 추가하지 않았다.

## 4. 모델과 구분한 앱 적대검사

### A1. [P2] 빈 서술형 Send가 건너뜀 대신 실제 답변·근거로 등록된다

현재 마이그레이션을 적용한 새 일회용 DB에서 **기본 29문항**을 읽고, 8단계 경로로 비필수 서술형 `describe`에 도달했다. 실제 `ChatInput.js`를 mock DOM에서 실행해 빈 textarea의 Send와 명시적 Skip을 각각 눌렀다. 두 버튼 모두 활성 상태였다. [S07]

| 동작 | 호출부 적용 후 skipped 값 | 저장 전 문항 상태 | 전체 답변 수 | 해당 검색문서 | 해당 안전 ID 후보 |
|---|---:|---|---:|---:|---:|
| 빈 Send | false | answered | 7 | 1 | 1 |
| 명시적 Skip | true | skipped | 6 | 0 | 0 |

두 경로 모두 건너뛰기 표시 문자열을 보내지만, 빈 Send는 `skipped` 인자를 생략해 호출부의 기본값 false를 사용한다. 서버는 이를 비어 있지 않은 텍스트 답변으로 정규화한다. 따라서 내용이 없는 문항이 답변 수와 출처 후보에 편입된다. 이는 **모델과 독립된 입력 상태 결함**이며 확신도는 높다.
