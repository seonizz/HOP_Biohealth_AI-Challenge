# 결선 적대적 평가 대응 v2

**2026-10-15, Asia/Seoul. v1을 보존하고 로컬 수정·재검증 결과를 추가한다.** [근거·파일 해시](결선_적대적_평가_v2_근거.json)

## 현재 판정

실행본에 분리돼 있던 STATE 개선, 과장된 서비스 설명, 모델명을 고정하던 평가 도구를 수정했다. 앱 전체 테스트는 **250 통과·0 skip·0 실패**이며 실제 일회용 DB에 연결했다. 평가 근거 도구 **9개 검사**도 통과했다. 독립 test·사람 평가·최종 31B 조합·현장 실증이 확보됐다는 뜻은 아니다.

이 문서는 점수를 높이기 위한 계획표가 아니라 바뀐 증거의 기록이다. v1의 39/90을 자동 상향하지 않으며, 최종 조합과 목적 평가가 확보될 때 다시 점수화한다.

## 실제 모델 재검증

로컬 Ollama가 제공하는 `gemma4:12b`를 사용했다. 체크포인트 서버의 가중치 로딩을 검증한 것은 아니며 모델 요청명과 로컬 목록 digest를 구분한다. 모든 사례는 기존 공개 합성 개발 fixture이며 독립 test가 아니다. 모델 출력 원문은 Git 제외 `ai/local_api/runtime/evaluations/`에 남긴다.

### 수정 도중 발견한 실패

v3.6은 최신 answered 문항을 모델의 선택 facts에 반드시 포함하도록 요구했다. 실제 현재 위험 사례와 누적 사례에서는 3회씩 누락해 실패했다. 실패한 요청을 분모에서 빼거나 모델 의미 검토 통과로 바꾸지 않는다.

v3.6.1은 모델이 선택한 근거의 스키마·출처 검증을 먼저 수행한 다음, 최신 answered 문항의 전체 원문과 후속 답변을 서버에서 facts에 보존한다. 10,000자 이상의 결합 답변은 Unicode 문자를 자르지 않는 연속 인용으로 나누며, 거절·모름·건너뜀을 확정 사실로 추가하지 않는다. 원문 보존을 모델에 다시 요청하지 않으므로 해당 누락 재시도는 필요 없다. 가설의 의미적 타당성까지 보장하는 변경은 아니다.

그 뒤 누적 STATE는 원문에 없는 진단·성향명을 가설에 붙여 3회 거절됐다. v3.6.2는 이 오류의 재시도에서만 원문 보고로 출력 범위를 좁힌다. 부적격 출력을 사후 삭제해 승인하지 않고, 새로 생성한 원문 보고를 축소 스키마와 기존 검증에 모두 통과시킨다. 실패 횟수·시간은 계속 집계한다. 관계 가설은 해당 복구에서 비워 두며 다음 STATE·최종 분석은 원래 계약으로 검증한다.

실측 후에는 내 기록 화면의 “상태 이력”을 쉬운 표현으로 바꿨다. 모델·프롬프트 파일은 같으며, 화면 문구와 소스 식별 파일의 끝 빈줄 정리 이후 최종 소스 해시·차이 경로를 근거 JSON에 별도 기록했다. 해당 UI 검사 43개를 다시 통과했다.

자동 기대 조건은 구조·출처·안전 flag·금지 호칭·fixture의 목적 키워드를 검사한다. 실제 사람의 의미 판단은 `pending`이다. 실행 수와 고유 사례 수를 구분하고, 앱/평가 코드/프롬프트가 달라진 결과를 하나의 성능 점수로 합치지 않는다. 전체 29턴 시연·사용자 입력 시간·최종31B 성능은 이번 호출 결과의 범위 밖이다.

## 사용자 지정 화면 원칙

사용자가 2026-10-15에 **“서비스에 불필요한 자세한 내용을 넣지 말고, 문서에 사용자 지정이라고 남길 것”**을 지정했다. [UI 정보 원칙](../../app/docs/UI_CONTENT_POLICY.md)과 루트 [AGENTS.md](../../AGENTS.md)에 기록했다.

이에 따라 모델명·데이터 수량·학습/검증 수치·연구 방법의 긴 설명을 서비스 소개에서 제거했다. 이용 방법, 대기, 진단 대체 불가, 정보 저장·삭제처럼 이용자 판단에 필요한 안내만 남겼다. 기술 상세를 숨긴 채 과장된 성능 문구를 남기지 않고, 과장된 문구 자체를 삭제했다.

## 발표자료와 검증 경계

[근거정합본 v2](../../presentation/final/말씨_결선_근거정합본_v2.pptx)를 한 개의 발표 기준본으로 지정했다. 12장·편집 가능한 표7개·발표노트15분+Q&A5분이다. 패키지·레이아웃·글꼴·표·재입력 검사와 전장 렌더·시각검수를 수행했다. PowerPoint 앱 직접 실행과 발표 리허설은 미실시다. 기존32개 후보는 보존하며 전부 수정했다고 주장하지 않는다.

현재31B API의 로컬 터널 응답을 확인하지 못했으며 기존 인증 SSH 소켓도 없었다. 원격 서버 변경·모델 교체·재학습·배포·제출·외부 메시지 전송은 수행하지 않았다. 이력·학습 데이터 삭제도 하지 않았다. 테스트는 별도 일회용 DB를 사용했다.

## 다음 재평가를 여는 증거

- 최종31B checkpoint/adapter의 로딩 기록과 동일 앱 해시의 초기·누적·정정·위험·사람 혼동·저장·재조회.
- 노출 이력이 없는 그룹 test와 독립 사람 평가의 원시 판정·실패 분모.
- 실제 이용자 과업·기관 확인·세션 비용·보유/삭제 운영 기록.
- 최신 공지·범위 승인 확인과 제한 시간 내 발표/Q&A 리허설.

위 자료가 필요한 항목은 미완료로 남긴다. 계획·합성 자동 검사·코드 테스트를 실제 이용 또는 사람 검토 결과로 대체하지 않는다.
