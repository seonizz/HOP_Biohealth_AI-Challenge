# v11 OP3·HR2 수정과 동일 기준 재검증

검증일: **2026-10-16, Asia/Seoul** · 시작: **19:35 KST** · 기준: [사용자 지정 평가 v1](05_평가범위와_학습데이터_기준.md) · 비교: [적대적 재평가 v11](결선_적대적_재평가_v11.md)

**OP3(P1)와 HR2(P2)를 수정했고, v11의 실패 변형 6개를 같은 재현 스크립트로 다시 실행해 모두 차단했다.** 새 회귀 메서드 12개를 추가했으며, 앱 **420개**, 데이터 **341개(고유 18모듈)**, 평가 근거 도구 **24개**, Git 원문 검사기 **29개**가 통과했다. 별도 독립 검토의 새 합성 경계 16조건도 통과했다.

## 1. 우선순위별 수정 결과

### P1 · OP3 — 운영 증거의 파싱 실패를 완료로 처리하던 경로 제거

[운영 증거 검사기](../../app/scripts/check-operations.js:108)는 지원 형식을 UTF-8 `.json`, `.jsonl`, `.ndjson`, `.txt`, `.md`로 명시한다. 모든 지원 형식에서 잘못된 UTF-8과 제어 바이트를 거절한다. JSONL/NDJSON은 비어 있지 않은 각 행을 파싱하며 객체·배열만 허용하고, 행마다 중복 키·내용·명시적 합성 표시를 검사한다. TXT/MD라도 JSON 형태로 시작하면 구조화 문서로 검사한다. 파싱 실패를 일반 텍스트 성공으로 바꾸던 분기를 없앴다.

| v11의 동일 반례 | 수정 전 | 수정 후 새 실행 |
|---|---|---|
| `synthetic:true`가 있는 두 행 JSONL | CLI 0, `evidence_complete` | **CLI 1, `pending`, `EVIDENCE_SYNTHETIC_CONFLICT`** |
| 닫는 괄호가 없는 JSON을 TXT로 저장 | CLI 0, `evidence_complete` | **CLI 1, `pending`, `EVIDENCE_JSON_INVALID`** |
| 잘못된 UTF-8 바이트를 TXT로 저장 | CLI 0, `evidence_complete` | **CLI 1, `pending`, `EVIDENCE_TEXT_INVALID`** |

세 경우 모두 `operational_evidence_complete:false`다. 정상 JSON·JSONL·일반 TXT/MD 대조는 유지된다. 지원하지 않는 확장자는 `EVIDENCE_FORMAT_UNSUPPORTED`로 거절하며, 해시만 맞는 PDF·이미지를 내용 검사 완료로 세지 않는다.

[회귀 검사](../../app/tests/operations-readiness.test.js:157)는 **22→29개(+7)**다. JSONL/NDJSON·BOM·대문자 확장자·다른 행의 동일 키 정상 대조, 뒤쪽 행 손상·escape 중복 키·스칼라 행, 구조화 문서의 확장자 변경, 인코딩·제어 바이트·미지원 형식을 포함한다. 새 검사를 수정 전 코드에서 먼저 실행했을 때 **29개 중 6개 실패**, 수정 후 **29개 모두 통과**했다. 이미 정상 동작하던 일반 텍스트 대조까지 포함해 회귀 메서드 수와 실패 수를 구분한다.

[운영 문서](../../app/docs/DATA_RETENTION.md:72)에도 검사 범위를 반영했다. 일반 TXT/MD는 읽을 수 있는지 확인하며 사실·승인자의 신원·실제 운영을 인증하지 않는다. `{"synthetic":false}`처럼 형식상 모순이 없는 내용만으로도 구조 검사가 완료될 수 있는 한계는 남는다. 도구의 `production_ready`, `human_approval_authenticated`, `physical_deletion_verified`는 계속 false다. **형식 검사 완료를 실제 운영 증명으로 해석하지 않는다.**

### P2 · HR2 — 공통 릴리스 감사 경계에서 타입을 먼저 검증

## 2. 실제 인계본의 버전과 사람 검토 상태

HR2 수정은 인계 manifest에 고정된 구현 해시를 바꾼다. 기존 `_r2`를 덮어쓰지 않고 Git 제외 경로 **`data/outputs/private/human_review_v10_20261016_r3`**에 새 버전을 생성한 뒤, 별도 manifest 해시를 지정해 현재 코드로 검증했다.

- 새 manifest SHA-256: **`a4f5b0aac96e870cdc88480e6352d601b39ef7d975478db9219bb6a5f0554135`**.
- 입력 23파일 중 `_r2`와 달라진 연결은 `agent_dataset.py`의 구현 해시뿐이다. 검토 내용 **5파일은 `_r2`와 바이트가 같다**. 기존 묶음과 원본은 보존했다.
- 현재 코드로 과거 `_r2` 검증이 거절되는 것은 코드 버전 고정의 의도된 결과다. 과거 묶음 손상이나 사람 판정 취소로 기록하지 않는다.
- 검토 대기는 **28단위 = 응답 24 + 전문·권리 검토 4**다. AI 초안 20에피소드·AI 검토 20기록·선언된 AI 검토자 1개를 실제 사람 수로 세지 않는다. **사람 승인 0건**, 학습·운영·독립 test 승인 false를 유지한다. 기존 원천 큐 391개와 작성 요청 6개도 별도 분모다.

[인계 절차](../../data/docs/support_agent/사람검토_인계_절차_v1.md)를 새 버전으로 갱신했다. ARCH1의 **절대 입력 경로 제약**도 명시했다. 기존 묶음의 검증에는 같은 해석된 입력 경로·바이트·구현이 필요하며, 다른 루트로 옮길 때는 새 버전과 단위 내용 해시를 대조해야 한다. 경로와 논리 입력 ID를 분리하는 이식성 기능은 아직 구현하지 않았다. 따라서 **ARCH1은 문서 보완 완료, 구조적 이식성은 WATCH**다.

## 4. 최신 데이터 v5를 포함한 연결 확인

v3·v4·v5는 HR2를 고친 `agent_dataset.py`를 manifest 입력으로 고정하지 않는다. 기존 후보를 다시 만들지 않고 고정 manifest, 연결된 입력 전부, 산출물 해시·크기를 새로 대조했다.

| 후보 | manifest SHA-256 | 입력 / manifest 포함 산출물 | 결과 |
|---|---|---:|---|
| v3 | `d105f733f80e5ee17b08cd83d52aff6903929fa504545e58ed7e4ae69a992afb` | 36 / 9 | 일치 |
| v4 | `f23d25f7a5ec4df3e0efa36e420698259905eb8fb11afba4364f45e4e2e32599` | 46 / 8 | 일치 |

이번 범위는 **연결 검증과 회귀 재실행**이다. 원천 전체 행 재구성과 v5 선택 알고리즘의 독립 적대적 검토를 이번에 다시 했다고 표현하지 않는다. v3·v4 재구성은 같은 바이트의 v11 기록, v5 실제 구성과 한계는 [별도 v5 보고서](학습데이터_4096_대안비교와_집중도완화_재검증_v5.md)의 기록을 참조한다.

최신 v5는 짧은 후보 **1,052행·1,036상담**, 긴 후보 **2,376행·1,038상담**을 보존하며 행 기준 집중도를 줄였다. 그러나 짧은 validation은 **후기 2셀·마지막 ¼ 0행**이고, 정답 토큰 기준 일부 상위 그룹 비중은 오히려 높아졌다. 긴 후보의 전기 45.58%도 50:50에 더 가까워진 수치가 아니다. 후기 패널 105행과 두 후보는 서로 겹치므로 독립 사례 수로 합산하지 않는다. 사람 승인 목표·새 독립 test·새 상담 확보를 입증한 변화는 아니며, 학습 허가·사람 검토·독립 test 플래그는 false다.

v11은 OP3를 운영 준비, HR2를 추적·인계의 기존 제한 안에 기록했으며 결함별 추가 감점을 만들지 않았다. 따라서 두 수정만으로 자동 가산하지 않는다. 이 판단은 결함 해결을 부정하는 것이 아니라 **검사 도구의 정확성과 실제 외부 증거의 확보를 구분한 결과**다. 모델 성능·크기·학습·생성 품질·로딩·앱 통합과 처리시간을 다른 항목에 옮겨 감점하지 않았다. 사용자 지정 내부 평가이며 주최 측 공식 심사 결과가 아니다.
