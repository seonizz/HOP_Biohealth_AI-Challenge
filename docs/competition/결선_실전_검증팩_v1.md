# 말씨 결선 실전 검증팩 v1

기준일: 2026-10-15. 결선 발표·시연·질의응답을 같은 근거로 준비하기 위한 문서다. [실전 발표 v3](../../presentation/archive/final_v2-v5/말씨_결선_실전발표_v3.pptx), [발표 내용·노트](../../presentation/archive/final_v2-v5/말씨_결선_실전발표_v3.json), [고도화 구현·검증](결선_고도화_v1.md)을 함께 사용한다. 이전 [재평가 v6](결선_적대적_재평가_v6.md)는 당시 소스와 검증 결과를 보존한다.

## 결선에서 전달할 한 문장

**말씨는 어려움을 겪는 사람의 가족과 친구가 관찰한 사실과 자신의 부담을 구분하고, 건넬 첫마디를 준비하도록 돕는다.**

질문 → 원문 근거 → 대화 안내 → 기록 관리의 연결을 실제 앱에서 보여준다. 데이터의 양보다 사용 목적·선별·분할·이력을 설명하고, 확인하지 않은 효과를 주장하지 않는다. 진단·치료·임상 효과, 실제 이용자 효용, 기관 도입이 검증됐다고 소개하지 않는다.

## 공식 기준과 이번 준비 범위

첨부 운영계획(안)의 **결선 평가표(7쪽)**는 아이디어의 창의성 및 차별성 30점, 모델 성능 20점, 적용가능성 30점, 발표력 20점이다. 첫 항목에는 목표·계획 대비 최종 완성도가 포함된다. 결선은 구현된 산출물과 발표·질의응답을 보여주는 단계로 준비한다. 운영계획(안)은 초안이므로 실제 제출 전에 주최 측의 최종 공지를 대조해야 한다.

사용자 요청에 따른 **내부 검증**은 모델 자체와 처리시간을 제외하고, 모델 관련 20점을 학습 데이터의 목적 적합성·품질·분할·추적 가능성으로 대체한다. 이는 공식 배점의 변경이 아니다. v6의 70/90은 이 내부 기준의 기록이며, 현장 발표·질의응답 미관측 10점은 보류했다. 이번 고도화에서 그 점수를 자동으로 올리지 않는다.

| 결선 항목 | 보여줄 산출물 | 확인 가능한 근거 | 남은 증거 |
|---|---|---|---|
| 창의성·완성도 | 주변인과 당사자의 관점 구분, 질문·정정·근거·결과·기록 흐름 | 앱 소스, 회귀검사, 삭제·동시 요청 검증 | 참여자가 그 구분을 이해하고 사용하는지 |
| 학습 데이터 — 내부 대체 기준 | 원천→내용 선별→길이 후보, 개발 노출 이력 | v6 장부 대조, 새 평가 이력 검사 | 주변인 지원 정답 구성과 사람의 의미 검토, 독립 test |
| 적용 가능성 | 기록 재조회, 미완료 대화·전체 대화 삭제, 짧은 서비스 안내 | 실제 소유자 격리·저장·삭제 계약과 UI | 실제 과업 관찰, 운영 책임자·보유 정책·도입처 확인 |
| 발표 능력 | 하나의 합성 사용 장면, 명확한 단위·한계, 근거를 찾는 Q&A | 12장 발표와 발표노트, 아래 질문·답변 | 실제 리허설과 현장 질의응답 |

## 발표 주장 장부

| 말할 수 있는 주장 | 근거 | 함께 밝혀야 할 한계 |
|---|---|---|
| 그분과 나의 답변 출처를 구분한다 | `relationship-retrieval.js`, `relationship-agent.js`, `GuideCards.js` | 의미 판단 전체의 정확성을 입증한 것은 아니다 |
| 내용 없는 필수 답변을 차단한다 | v6의 앱 295개 검사, HTTP 72사례, UI 핸들러 128사례 | 사례 수를 합쳐 고유 사용자 수나 성공률로 만들지 않는다 |
| 질문 중 되돌리면 이후 상태와 근거를 되돌린다 | `intake.js`와 API 회귀검사 | 완료된 결과에서 임의 문항을 바로 정정하는 기능은 제공하지 않는다 |
| 학습 원본은 45,974행, 내용 기준 허용은 44,704행이다 | v6 근거 JSON의 실제 장부 대조 | 행 수는 상담 수·인물 수가 아니다 |
| 4,096 길이 조건의 후보는 17,236행이다 | train 15,512 + validation 1,724, export 대조 | 내용 기준 허용 44,704행과 섞지 않는다 |
| 긴 정답 부분 노출 9행을 보류했다 | v6 독립 부분 일치 검색과 admission 전후 대조 | 그 9행은 기존 길이 조건에서도 제외돼 4,096 후보 내용은 바뀌지 않았다 |
| 개발에 사용한 validation을 독립 test로 인정하지 않는다 | `evaluation_history.py`, 합성 공격 회귀, 실제 근거 적용 | 새 독립 test를 만들거나 과거 비노출을 증명한 것은 아니다 |
| 같은 브라우저의 대화를 사용자가 삭제할 수 있다 | 고도화 v1의 서버·DB·UI 검증 | 쿠키 만료는 서버 데이터 자동 삭제가 아니며, 쿠키 분실 후 복구·삭제 경로는 별도 과제다 |

새 기능의 실제 검사 수와 실패·제외는 [고도화 v1](결선_고도화_v1.md)에 기록한다. v6 검사 수를 새 소스의 전체 검사 수로 재사용하지 않는다. 발표의 최신 회귀검사 표와 노트에 남긴 v6의 역사 근거를 구분한다.

## 합성 사례 시연 절차

다음 입력은 시연용으로 새로 작성한 **합성 상황**이다. 실제 상담 원문이나 참여자 자료를 가져오지 않는다. 현재 앱이 생성한 결과와 합성 응답으로 확인한 UI를 구분해 설명한다. 연결 실패나 기대 불일치도 그대로 기록하고 성공으로 바꾸지 않는다.

| 단계 | 조작 | 확인할 동작 | 실패로 기록할 조건 |
|---|---|---|---|
| 시작 | 별도의 시연 브라우저에서 새 대화를 시작한다 | 질문과 진행 위치가 표시된다 | 이전 이용자의 대화가 보임 |
| 입력 | “친구가 최근 약속을 미루고 연락을 줄였습니다. 저는 말을 꺼낼 때 부담을 줄까 걱정됩니다.”처럼 문항에 맞춰 답한다 | 그분의 관찰과 나의 부담을 각각 받는다 | 원문과 다른 사람이 답변 주체로 표시됨 |
| 필수 경계 | 필수 서술형에서 공백만 전송하고, 이어 정상 답변을 입력한다 | 빈 내용은 통과하지 않고 정상 문장은 보존된다 | 내용 없는 답변으로 다음 단계로 이동함 |
| 정정 | 질문 중 이전 답변으로 돌아가 관찰 내용을 바꾼다 | 이후 단계와 근거가 현재 답변을 기준으로 구성된다 | 삭제한 후속 답변이 현재 근거로 다시 등장함 |
| 근거 | 결과의 원문 인용과 ‘모르는 부분’을 펼친다 | 현재 대화 원문 및 출처와 연결된다 | 입력하지 않은 문장을 원문이라고 표시함 |
| 사용 | 첫마디와 행동 안내를 확인하고 복사 기능을 쓴다 | 화면 문장과 복사 문장이 같다 | 복사 실패를 성공으로 알리거나 다른 문장이 복사됨 |
| 재조회 | 기록 화면으로 이동해 완료 기록을 다시 연다 | 저장한 결과가 일관되게 보인다 | 다른 대화 결과가 섞임 |
| 미완료 관리 | 별도의 새 대화를 중단하고 기록 화면을 연다 | 중단한 대화가 표시되고 확인 후 개별 삭제된다 | 취소했는데 삭제됨, 삭제 실패인데 목록에서 사라짐 |
| 전체 삭제 | 시연용 데이터임을 확인하고 ‘내 대화 모두 삭제’를 실행한다 | 확인 단계 후 완료·미완료 대화가 없어지고 이전 요청이 되살리지 못한다 | 다른 소유자에게 영향, 완료 결과의 재등장 |
| 다시 시작 | 전체 삭제 후 의도적으로 새 대화를 시작한다 | 새로운 대화는 정상 생성된다 | 삭제 전 요청과 새 요청을 구분하지 못함 |

시연 실패의 대체 자료는 버전·검증 방식이 적힌 캡처와 테스트 기록이다. 합성 gateway로 만든 화면을 실제 모델 생성 성공의 증거로 제시하지 않는다. 장애가 나면 마지막으로 성공한 단계와 실패한 단계를 구분해 설명한다.

## 심사위원 질문과 답변 근거

1. **누가 어떤 문제 때문에 쓰나요?** 당사자를 걱정하는 가족·친구가 무엇을 관찰했고 어떤 부담을 느끼는지 정리하고 대화를 시작하기 위해 사용한다. 효용은 아직 실제 참여자 과업 관찰로 확인해야 한다. 근거: 질문 구성, 시작·결과 화면.
2. **서비스의 구체적인 특징은 무엇인가요?** 그분의 관찰과 나의 감정·부담을 구분하고, 현재 대화 원문과 안내의 연결을 보여주며 모르는 부분을 표시한다. 다른 모든 서비스보다 우월하다는 비교 주장은 하지 않는다. 근거: 관계 검색·안내 카드.
3. **어떤 근거를 검색하나요?** 현재 대화 안에서 답변과 출처를 검색한다. 외부 의학 지식을 검색하는 체계라고 소개하지 않는다. 근거: `app/src/relationship-retrieval.js`.
4. **답변을 고치면 예전 해석이 남지 않나요?** 질문 중 되돌리기는 이후 답변·상태·근거를 되돌리며 이를 회귀검사한다. 완료 결과에서 임의 문항을 바로 편집하는 별도 기능은 아직 없다. 근거: `app/src/intake.js`, API 검사.
5. **테스트가 많다는 것이 상담 품질을 뜻하나요?** 아니다. 입력, 출처, 저장, 삭제, 격리 같은 프로그램 계약을 검사한 수다. 실제 효용과 의미 적절성에는 별도의 사람 검토가 필요하다. 근거: v6와 고도화 v1의 검증 범위.
6. **45,974건의 독립 상담을 학습하나요?** 45,974는 SFT 행 수다. 한 상담에서 여러 행이 생긴다. 내용 선별과 길이 조건 후 후보도 별도로 집계한다. 근거: v6 데이터 대조.
7. **주변인을 돕는 서비스인데 데이터 목적이 맞나요?** 원본은 상담사의 다음 발화를 학습하는 과업이다. 주변인 지원에 맞는 정답 구성·의미 라벨 검토는 남아 있다. 데이터의 양을 목적 적합성의 증거로 대신하지 않는다. 근거: 데이터 파이프라인과 v6 미확인 항목.
8. **정답 노출은 해결됐나요?** 정한 연속 문자열 조건에서 기존 9행을 보류했고 재검색 잔존은 0행이다. 짧은·의미상·불연속 중복과 인물 독립성 전체를 해결했다고 말하지 않는다. 기존 4,096 후보는 전후 동일하다. 근거: v6 부분 일치·lineage 결과.
9. **이 validation으로 최종 점수를 제시할 수 있나요?** 개발에서 확인하고 정책을 수정하는 데 사용했다. 독립 test가 아니며 새 검사기는 그 이력을 연결해 잘못된 승격을 거절한다. 근거: 평가 이력 검사와 실제 적용 결과.
10. **사용자가 기록을 지울 수 있나요?** 같은 브라우저의 완료 기록·중단한 대화를 삭제할 수 있고, 전체 대화 삭제는 별도 확인을 받는다. 소유자 격리와 진행 중 요청의 재저장 방지도 검사한다. 쿠키를 잃은 뒤의 삭제 요청 처리와 보유 정책은 별도 운영 과제다. 근거: 고도화 v1, API 문서.
11. **이미 현장에서 효과를 확인했나요?** 아직 아니다. 합성 사례 검증과 실제 사용자 관찰을 구분한다. 아래 관찰 과제·성공 기준으로 사용성을 확인하고, 임상 효과라고 확대하지 않을 계획이다.
12. **다음 단계의 완료 기준은 무엇인가요?** 주변인 목적에 맞는 데이터 의미 검토, 개발 노출과 분리된 평가 자료, 실제 과업 관찰, 운영 책임·보유 정책 확인이다. 각 항목의 산출물이 남았을 때 완료로 표시한다. 근거: 공통 현황과 아래 기록 양식.

모델 자체의 성능·규모·처리시간을 내부 점수로 환산하지 않는다. 공식 심사에서 해당 질문이 나오면 실제 확인된 연구 기록만 설명하고 이 문서의 내부 대체 기준을 공식 규정처럼 제시하지 않는다.

## 실제 과업 관찰 설계 — 아직 실행하지 않음

목적은 가족·친구 역할의 참여자가 관점 구분, 안내의 한계, 기록 삭제를 이해하고 직접 사용할 수 있는지 확인하는 것이다. 임상적 효과 검증과 구분한다. 실제 타인의 민감한 상황을 입력하게 하지 않고 위와 같은 합성 상황을 제공한다. 참여·중단·기록 범위를 사전에 설명하고, 관찰 기록에는 신원과 상담 원문을 남기지 않는다.

| 과업 | 사전 성공 기준 | 관찰할 오류 |
|---|---|---|
| 상황 입력과 질문 중 정정 | 도움 없이 관찰과 본인 부담을 각각 입력하고 이전 답변을 수정함 | 주체 혼동, 수정 위치를 찾지 못함, 이후 답변 보존 오해 |
| 원문 근거 이해 | 안내에 연결된 원문과 모르는 부분을 자신의 말로 구분함 | 안내를 진단·사실 확정으로 이해함 |
| 문장 사용 | 원하는 첫마디를 찾아 복사하고 실제로 복사됐는지 확인함 | 복사 성공 오인, 다른 문장 선택 |
| 기록 관리 | 중단한 대화를 찾아 삭제하고 전체 삭제의 범위를 설명함 | 완료 기록만 삭제된다고 오해함, 취소 동작 혼동 |

참여자별로 ‘완료/도움 필요/미완료’를 남긴다. 사용자가 제외한 처리시간은 성공 지표로 쓰지 않는다. 전체 수와 실패 수를 함께 제시하고 실패를 제외한 성공률을 만들지 않는다. 표본 수가 작거나 모집이 편향됐다면 그 범위를 밝힌다. 목표를 미리 정한 뒤 실제 관찰 결과를 보고 목표를 바꾸지 않는다.

관찰 양식: 익명 관찰 번호 / 앱 commit·화면 버전 / 합성 사례 버전 / 각 과업 결과 / 도움을 준 지점 / 주체·한계·삭제 범위 이해 여부 / 개선 요청 / 중단 여부 / 관찰자의 해석과 직접 관측의 구분. 실제 참여자가 없으므로 현재 채워진 결과는 없다.

## 제출 전에 확인할 항목

- 발표 파일 한 개와 근거 문서의 버전을 맞추고, 슬라이드의 행 수·분모·검사 범위를 대조한다.
- 주최 측 최종 안내의 제출 형식과 결선 운영 조건을 확인한다. 첨부 초안만으로 제출 완료라고 표시하지 않는다.
- 합성 시연 계정·브라우저를 사용하고 원천 상담 데이터·키·개인정보가 화면이나 파일에 포함되지 않게 한다.
- 실제 리허설에서 질문자가 근거를 요구하면 해당 파일까지 찾아 설명한다. 리허설과 제출 완료는 실행한 뒤에만 기록한다.
