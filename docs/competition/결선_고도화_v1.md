# 말씨 결선 고도화 v1

기준일: 2026-10-15. [재평가 v6](결선_적대적_재평가_v6.md) 이후 결선 발표·시연을 위해 **대화 삭제 기능, 학습 데이터 평가 이력 검사, 발표자료와 질의응답 근거**를 구현·보강한 기록이다. 단순한 개선 제안서가 아니라 실제 변경과 실패 재현·재검증을 남긴다.

모델 자체의 성능·크기·학습 진행·생성 품질·로딩·통합과 처리시간은 [사용자 지정 기준](05_평가범위와_학습데이터_기준.md)에 따라 평가에서 제외했다. 프로젝트 모델을 호출하거나 운영 DB·배포를 변경하지 않았다. v6의 **70/90, 데이터 14/20**은 당시 점수로 보존하며, 검사 수나 자료 작성만으로 점수를 자동 상향하지 않았다.

## 앱의 저장·삭제 계약

- 완료 기록 삭제는 관련 대화도 지운다. 미완료 대화 삭제는 연결된 결과가 그 사이 생겼더라도 함께 정리한다.
- 전체 삭제는 현재 익명 브라우저 소유자의 대화·결과·상태·수정 이력을 삭제한다. 다른 소유자와 칼럼의 읽음·담음 상태는 유지한다.
- 삭제는 UI에서 두 단계로 확인한다. 실패하면 대화·미전송 입력·목록을 성공한 것처럼 지우지 않는다.
- `bootstrap`과 기록 조회가 `conversation_epoch`를 반환하고, 생성 요청은 이 값을 보낸다. 전체 삭제 이전의 epoch로 늦게 들어오는 생성 요청은 `409 CONVERSATIONS_CHANGED`로 거절한다.
- 전체 삭제 응답을 받기 전에는 같은 화면의 새 대화 시작을 차단한다. 성공 후 최신 epoch로, 실패 후 기존 epoch로 사용자가 다시 시작할 수 있다.
- 동일 소유자의 생성·저장·삭제를 DB 잠금으로 직렬화한다. 삭제 실패의 롤백과 연결 행 정리를 검사했다. 새 마이그레이션 `005_conversation_epoch.sql`은 재적용 검사를 포함한다.

API 호환 변경에 맞춰 실제 프런트엔드와 `ai/scripts/smoke_relationship_web.mjs`의 생성 요청을 갱신했다. 이 스크립트는 이번에 실제 모델을 호출해 실행하지 않았고 구문과 평가 근거 도구를 검사했다. 자세한 입력·응답 계약은 [API 문서](../../app/docs/API.md)와 [OpenAPI](../../app/docs/openapi.json)에 있다.

쿠키 만료·삭제는 서버 데이터 자동 삭제가 아니다. 쿠키를 잃은 뒤의 복구·삭제 처리, 자동 보유기간과 운영 담당자는 별도 과제로 남는다. 미완료 대화의 재개, 완료 결과에서 임의 문항으로 바로 돌아가 수정하는 기능을 추가했다고 설명하지 않는다.

## 검사 통과 후에도 다시 찾은 결함

첫 통과 결과만으로 종결하지 않았다. 아래의 수정 전 근거를 보존하고 사후 검증을 별도 파일로 남겼다.

| 식별 | 수정 전 재현 | 수정·재검증 |
|---|---|---|
| A1 / P2 | 전체 삭제의 서버 처리는 끝났으나 응답이 지연된 동안 새 epoch로 대화를 만들면, 뒤늦은 삭제 응답이 새 `S`까지 지워 빈 대화 화면을 만들었다. 서버에는 새 대화가 남았다 | 삭제 요청 수명 동안 공통 `begin()`과 시작 버튼을 막고 `finally`에서 버튼 상태를 복구. 성공·거절·`deleted:false` 3회귀를 먼저 실패시킨 뒤 수정. 실제 HTTP·DB의 성공·DB 실패 2경로로 독립 재검증 |
| D1 / P1 | 원천 파일을 읽지 않고 장부·manifest의 자체 일치만 검사해, 양쪽 장부와 export의 그룹 재지정·같은 행 누락·보류 해제를 함께 맞추면 `verified`였다 | 실제 원천 release·admission policy·선별 근거·길이 장부를 읽고 기존 선별 규칙을 재계산. 전체 행의 ID·원천 그룹·split 및 export 원문 바이트를 대조 |
| D2 / P2 | 잘못된 `policy.files` 배열이 `AttributeError`로 빠져 JSON 오류 대신 traceback과 exit 1을 냈다 | 잘못된 구조는 원문 없는 `invalid` JSON과 exit 2로 처리. 출력 파일을 생성하지 않음을 회귀검사 |

D1은 독립 test 인증을 통과시킨 결함이 아니다. 해당 판정은 이전 구현에서도 항상 거절됐다. 개발 노출·장부 완전성의 검증 주장이 우회된 것이며, 현재 실제 집계가 잘못됐다는 증거로 확대하지 않는다. 실제 이벤트에는 원래 장부 해시를 고정한 근거도 포함돼 있었다.

수정 전 [A1 HTTP 재현](../../runtime/finals-upgrade/review-app/late-delete-response-http.json), [A1 회귀 실패 로그](../../runtime/finals-upgrade/verification/delete-race-before.log), [D1·D2 독립 재현](../../runtime/finals-upgrade/review-data/independent_probe.json)을 보존했다. 사후 결과는 [A1 HTTP·DB 검증](../../runtime/finals-upgrade/review-app/late-delete-response-http-after.json), [데이터 공격 7종 재검증](../../runtime/finals-upgrade/review-data/independent_probe-after.json), [실제 원천 독립 재대조](../../runtime/finals-upgrade/review-data/real-audit-after.json)에 있다. 로컬 상세 로그는 `runtime/`에 보관하고 공개 근거 JSON에는 집계·경로·해시만 연결한다.

검사 범위가 겹치므로 합산해 하나의 고유 표본 수나 성공률을 만들지 않는다. 이전 314개 앱 통과와 91개 데이터 통과도 실패 발견 이전의 실행으로 보존했다. 최종 로그는 별도로 남겼다. 첫 앱 전체 실행의 자동 승인 검토가 시간 초과되어 실행 전 종료됐고, 허용된 한 번의 재시도로 실제 검사를 완료했다. 이를 앱 테스트 실패나 모델 결과로 세지 않는다.

검증용 서버·일회용 DB는 종료했고 임시 UI 스키마도 정리했다. 운영 데이터와 기존 원천·분할·라벨·장부는 변경하지 않았다.

## 학습 데이터 직접 검증의 의미

현재 내용 기준 허용은 train **40,415행**, validation **4,289행**이다. 4,096 길이 조건 후보는 train **15,512행**, validation **1,724행**, 합계 **17,236행**이다. 검사기는 이 수량과 실제 원천·정책·전체 장부·후보 내용을 함께 대조한다. 학습 행을 독립 상담이나 인물 수로 표시하지 않는다.

v4·v5·v6와 v6 부분 일치·계보 검사 등 **근거 5개**를 해시와 JSON pointer로 연결했다. 현재 등록한 범위는 validation이므로 그 1,724행·21개 원천 그룹은 모두 `development_exposed`다. train의 15,512행은 이번 이력 목록에서 `history_unverified`이며, 미사용 또는 미학습 판정이 아니다.

어느 행의 개발 사용은 같은 원천 그룹 전체에 적용한다. 길이 조건으로 빠진 행의 사용 이력도 같은 그룹의 남은 후보에 적용한다. 후보의 파일명·압축을 바꿔도 원래 원천과 이력 연결을 확인한다. 이력이 없다는 이유로 미사용 평가셋이라고 인정하지 않는다.

이 도구는 독립 test를 인증하지 않는다. 로컬 해시는 기록의 연결·변조를 검사하지만 기록되지 않은 사용, 작성자 신뢰성, 사람의 의미 판단을 증명하지 않는다. 현재 후보를 독립 test로 승격하지 않고, 사람 검토나 주변인 지원 정답을 완료한 것처럼 만들지 않았다.

v6에서 추가 보류한 9행은 기존 길이 조건에서도 제외돼 4,096 후보 내용은 바뀌지 않았다는 결론을 유지한다. 이번 검증도 원천·선별 규칙의 연결을 강화한 것이며, 기존 후보의 의미 품질 향상이나 모델 성능 향상을 주장하지 않는다. 실행 방법과 필수 원천 입력은 [데이터 README](../../data/README.md#평가-데이터의-과거-사용-이력)에 있다.

## 결선 자료와 남은 실제 검증

첨부 운영계획(안)의 **결선** 운영·평가를 5·7쪽에서 직접 대조했다. 공식 30·20·30·20과 사용자 지정 내부 대체 기준을 구분한다. 신청서나 본선의 자료 제한을 결선 규정으로 가져오지 않는다.

새 발표 v3는 12장과 노트, 편집 가능한 표, 실제 앱 화면으로 구성했다. 사용자 문제 → 질문·원문·안내·기록 → 데이터 선별·개발 이력 → 실제 검증 → 현장 과업 순서로 설명한다. PPTX 패키지·글꼴·레이아웃·표와 재가져오기를 검사하고 모든 최종 슬라이드를 렌더링해 확인했다. PowerPoint나 Google Slides 앱에서 직접 재생한 결과는 아니다. 원본 JSON과 검증 영수증·해시는 근거에 남긴다.

다음 항목은 코드 수정과 자료 작성만으로 완료할 수 없으므로 미완료로 유지한다.

- 주변인 지원 목적에 직접 맞는 학습 정답과 라벨의 사람 검토.
- 개발 노출과 분리된 독립 평가 자료의 확보·사용 이력.
- 실제 참여자의 과업 관찰, 운영 책임·보유 정책·도입처 확인.
- 주최 측 최종 공지 대조, 실제 발표 리허설·Q&A·제출 확인.

이 항목을 위해 [실전 검증팩](결선_실전_검증팩_v1.md)에 합성 사례·성공 기준·관찰 양식·예상 질문을 구체적으로 남겼다. 우승·임상 효과·현장 채택을 확인된 결과로 표현하지 않는다.
