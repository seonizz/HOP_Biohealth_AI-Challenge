# 모델과 웹 적대적 평가

평가일: 2026-10-27. 현재 로컬 소스, 실행 중인 웹, Mac의 Ollama `gemma4:12b`를 대상으로 했다. 이번 요청은 모델·웹의 기술 검토이며 기존 결선 총점 53/90을 임의로 재산정하지 않았다. 모델 자체도 검토 대상으로 포함했지만 처리시간은 채점하지 않는다. 제품 코드를 수정하지 않고 재현 결과를 남겼다.

**우선 수정이 필요한 모델 안전 경계 2건과 웹 결함 2건을 재현했다.** 모델 결함은 실제 생성 오류율이 아니라, 모델이 틀렸을 때 현재 코드가 그 오류를 막는지 확인한 결과다. 별도 기관 안내가 남는 경로도 있어 모든 안전 안내가 사라진다고 확대 해석하면 안 된다.

## 1. P1 — 이미 승인한 긴급 판단과 모순되는 최종 가이드가 통과한다

- 위치: [intake.js](../../app/src/intake.js)의 `applyModelUpdate` 311행, `buildContext` 401–438행; [relationship-agent.js](../../app/src/relationship-agent.js) 692·858·886–911행; [server.js](../../app/src/server.js) 343행.
- 조건: 현재 진행 중인 폭력을 보고한 합성 대화에 유효한 `current_physical_danger` 검토를 적용하면 `state.safetySignal.urgent=true`가 저장되고 대화가 ready로 바뀐다.
- 문제: 최종 생성용 문맥에는 원문은 있지만 이전에 승인한 긴급 판단이 없다. 최종 단계는 새 모델 분석의 `safety` 값을 기준으로 고정 긴급 행동을 적용한다.
- 재현: 최종 분석을 false로 바꾸고 일반 가이드와 잘못된 승인 리뷰를 주입했다. 실제 현재 `ModelGateway.respond`의 검증을 거쳐 `assessment.safety=false`, `agent.reviewed=true`, 고정 긴급 행동 버전 없음으로 수용됐다. 같은 원문에서 최종 분석을 true로 두는 대조군은 `immediate-help-v1`을 유지했다.
- 영향: 같은 원문에 대해 이미 확인된 긴급 상태와 일반적인 대화 제안 카드가 충돌할 수 있다. 리뷰가 오류를 잡을 수도 있지만, 기존 승인과의 모순을 결정적으로 막는 계약은 확인되지 않았다.
- 한계: 별도 referral 안내는 저장된 긴급 신호를 유지한다. 전체 경고 소실·실제 피해·배포 모델의 오판을 관측한 것은 아니다.
- 수정 방향: 동일한 원문 스냅샷에 결속된 긴급 승인 상태를 최종 생성·검증에 전달하고 설명 없는 하향 변경을 거절한다. 사용자의 정정으로 원문이 달라지면 기존 승인을 무조건 고정하지 말고 새 근거로 재검토해야 한다.

근거: [반례 코드](../../runtime/model-web-adversarial-20261027/model/confirmed-danger-final-probe.mjs), [결과](../../runtime/model-web-adversarial-20261027/model/confirmed-danger-final-probe.json). 부모 검토에서도 재실행했다. 네트워크·실제 사용자·실제 DB를 사용하지 않은 합성 오류 주입이다.

## 2. P1 — 최초 위험 판단이 false이면 전용 안전 검토가 실행되지 않는다

- 위치: [relationship-turn.js](../../app/src/relationship-turn.js) 606–618·626–632·651행.
- 조건: `combined_blocks` 경로에서 최초 질문 블록이 긴급 여부를 false로 반환한다.
- 문제: 전용 `safety_review`는 긴급 제안이 true이거나 같은 작업에서 이미 승인해 보존한 위험이 있을 때만 생성된다. 일반 상태 검토에는 `questions:null, safety:null`이 전달된다.
- 재현: 진행 중인 폭력 원문을 상태 근거에도 그대로 보존한 채 false 제안을 주입했다. `finish_early=false`, `safetyUrgent=false`, `stateReviewed=true`로 통과했고 `safety_review`는 **0회**였다. true 대조군에서는 안전 검토를 **1회** 수행했다.
- 영향: 초기 누락을 전용 안전 검토가 다시 판단하지 않는다. 상태 검토 완료가 위험 없음 판단의 추가 검증을 뜻하지 않는다.
- 한계: 실제 모델이 이 입력을 놓쳤다고 입증한 것은 아니다. 이후 최종 생성·referral 단계가 위험을 다시 발견할 가능성은 남아 있다.
- 수정 방향: 첫 초안의 양성 여부와 별개로 현재 원문에서 위험 신호를 검토할 수 있게 하고, 현재 위험·부정·과거 한정 상황을 대조한다. 미응답 문항을 모두 강제로 묻거나 문맥상 생략을 제거하는 해결책은 적용하지 않는다.

근거: [반례 코드](../../runtime/model-web-adversarial-20261027/model/safety-negative-probe.mjs), [결과](../../runtime/model-web-adversarial-20261027/model/safety-negative-probe.json). 부모 검토에서도 재실행했다.

## 3. P2 — 늦은 삭제 완료가 새로 연 화면을 닫는다

- 위치: [conversation.js](../../app/public/js/core/conversation.js) 35–38행; [router.js](../../app/public/js/core/router.js) 45행 이후.
- 조건: 대화 A의 삭제 요청을 보낸 뒤, 응답이 오기 전에 브라우저 경로 복원으로 서비스 소개 또는 다른 대화 B로 이동한다.
- 문제: `deleteCurrentConversation()`이 삭제 응답 후 현재 화면·요청 세대를 확인하지 않고 `show("start")`를 실행한다.
- 재현: 현재 실제 core 4파일을 VM에서 실행하고 DELETE 응답만 지연했다. 같은 화면에서 기다리는 정상 대조군은 시작 화면으로 돌아갔다. `/about`과 `/chat/<B>`로 이동한 반례 2건도 늦은 응답 뒤 `/`로 바뀌었다. B의 상태 객체는 남았지만 화면이 사라졌다.
- 영향: 사용자가 새로 열어 작업하던 화면을 이전 요청이 덮는다. B의 데이터를 삭제했다거나 다른 소유자의 기록이 노출됐다고 확인한 것은 아니다.
- 수정 방향: 삭제 대상과 요청 세대를 캡처하고, 완료 시에도 해당 대화 화면에 머무는 경우에만 시작 화면으로 전환한다.

근거: [반례 코드](../../runtime/model-web-adversarial-20261027/web/navigation-delete-probe.mjs), [결과](../../runtime/model-web-adversarial-20261027/web/navigation-delete-result.json). 부모가 재실행했다. 실제 DB 삭제 없이 지연 응답을 주입한 경계 검사다. 서버가 제공하는 해당 JS 파일과 현재 소스의 바이트가 같음을 별도로 확인했다.

## 4. P2 — 열린 칼럼 창에서 키보드 포커스가 배경으로 빠진다

- 위치: [ColumnsScreen.js](../../app/public/js/components/ColumnsScreen.js) 116–123행.
- 실제 브라우저 관측: `http://127.0.0.1:9001/columns/listen`에서 칼럼을 열면 닫기 버튼에 포커스가 간다. **Shift+Tab 3회** 뒤 독자 창은 열린 상태인데 포커스가 배경 칼럼 목록의 마지막 마음에 담기 버튼으로 이동했다.
- 코드 대조: `role="dialog"`, `aria-modal="true"`는 있으나 Tab 순환 제어나 배경 `inert`가 없다. 관측한 파일은 현재 저장소의 파일과 SHA-256이 같다.
- 영향: 화면에서 가려진 배경 조작으로 키보드 사용자가 이탈할 수 있다. 실제 스크린리더 사용자 실험이나 저장 버튼 활성화는 수행하지 않았다.
- 반대 증거: 이 상태에서 Escape는 창을 닫고 원래 칼럼 버튼으로 포커스를 돌려줬다. Escape가 고장났다고 판정하지 않았다.
- 수정 방향: 디자인을 유지하면서 열릴 때 배경의 포커스 가능성을 막고 창 안에서 순환하도록 한다. 닫힐 때 원래 활성 요소를 복원한다.

## 5. 실제 모델에서 확인한 범위

현재 `app/.env`의 작성·검토 API는 모두 로컬 `127.0.0.1:11434/v1`의 `gemma4:12b`다. 부모가 이 설정을 읽는 현재 `ModelGateway`를 사용했다. 같은 모델의 여러 검토 호출은 서로 다른 역할의 재검토일 수 있으나 독립된 모델이나 사람·전문가 검증으로 계산하지 않는다.

| 검증 | 관측 | 해석 |
|---|---|---|
| 작성 API의 합성 연결 생성 | 통과 | 실제 JSON 생성 경로가 응답함 |
| 검토 API의 합성 연결 생성 | 통과 | 현재 검토 요청 형식으로 응답함 |
| 현재 위험 상태 갱신 | 진단용 종료 조건에 의해 취소 | 최종 판단 미확보. 누락·오판으로 세지 않음 |
| 위험을 부정한 상태 갱신 | 진단용 종료 조건에 의해 취소 | 최종 판단 미확보. 오탐으로 세지 않음 |
| 과거에 한정된 위험 상태 갱신 | 완료, 정의한 계약 10조건 통과 | 이 합성 사례에서 현재 긴급 상황으로 승격하지 않음 |

각 과업에 진단 전용 120초 종료 조건을 적용했으며 서비스 설정은 변경하지 않았다. 종료된 두 과업은 원문 상태·이름·관계 블록 이후 질문 블록에서 미완료였다. 처리시간을 감점하지 않으며, 미판정을 실패율에 포함하거나 완료한 1건을 일반 정확도로 환산하지 않는다.

사용한 3사례는 이미 저장소에 있는 개발용 합성 시나리오다. 독립 test·임상 민감도/특이도·실사용 품질 측정이 아니다. **이번 근거로 실제 모델 정확도 점수는 부여할 수 없다.** GPU 서버와 목표 31B 모델은 사용자 지정 금지에 따라 접근하지 않았다.

근거: [실제 모델 진단 코드](../../runtime/model-web-adversarial-20261027/actual-model-probe.mjs), [현재 실행 결과](../../runtime/model-web-adversarial-20261027/actual-model-results.json). 허용된 별도 LAN 검토 API는 연결되지 않았고 다른 외부 서버로 내용을 보내지 않았다.

## 6. 실행 중인 웹과 검증 소스의 동일성 공백

실행 중인 `/health`의 시작 시점 소스 지문은 `7cf1d168…`이고 현재 파일의 앱 지문은 `cdae2055…`다. 두 값은 다르다. `ColumnsScreen.js`, `conversation.js`, `router.js`, `app.js`의 HTTP 응답은 현재 파일과 바이트가 같았다.

이 관측은 실행 프로세스의 시작 시점과 현재 체크아웃이 같지 않음을 보여 준다. 어느 백엔드 모듈이 달라졌는지나 모든 현재 파일이 이전 코드로 실행 중인지는 이 지문만으로 확정하지 못한다. 따라서 기존 1,722개 검사 통과를 지금 떠 있는 인스턴스 전체의 검증 결과라고 설명하면 안 된다. 현재 버전을 고정해 시작한 별도 실행과 그 지문을 확인한 뒤 시연 근거를 연결할 필요가 있다. 이번 평가에서는 기존 서비스를 재시작하지 않았다.

## 7. 통과한 검사가 보장하는 것과 남은 범위

- 모델 경계 관련 기존 검사 **153개 통과**: `relationship-turn`, `relationship-final-preservation`, `model-review-routing`, `claim-review-roles`.
- 웹 상태·경로·취소 관련 기존 검사 **131개 통과**: `ui`, `navigation-state`, `conversation-cancellation`.
- 새 모델 반례 2종은 각각 양성·음성 대조를 포함하며 부모도 재실행했다. 웹 삭제 경합은 정상 대조 1건과 경로 변경 2건을 재실행했다.
- 칼럼 포커스 이탈은 실제 브라우저에서 확인했다. DB 격리·모바일 브라우저·스크린리더·실제 사용자 관찰을 이번 검토에서 새로 전수 검증한 것은 아니다.
- 소유자 조건·revision·삭제 epoch·암호화 AAD·CSRF에서 이번 범위의 추가 재현 결함을 확정하지 못했다. 이것이 전체 보안 인증을 뜻하지 않는다.

현재 가장 큰 문제는 단순히 검사가 적다는 점이 아니다. **이미 확정한 상태를 다음 단계가 다시 무시하거나, 이전 비동기 작업이 새 상태를 덮는 경계를 기존 검사들이 놓치고 있다.** 수정 시 위 반례를 회귀로 고정하고, 실제 모델 결과와 합성 오류 주입의 증거를 계속 분리해야 한다.

평가 증거는 Git 제외 `runtime/model-web-adversarial-20261027/`에 있다. 실제 상담 데이터·비밀값을 외부로 보내거나 저장소에 추가하지 않았다. 제품 코드·카드 디자인·문맥에 따른 질문 생략 정책·기존 DB를 수정하지 않았다.
