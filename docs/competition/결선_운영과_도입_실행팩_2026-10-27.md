# 결선 운영·도입 실행팩

기준일: 2026-10-27. 현재 서비스의 **로컬 검증과 실제 기관 도입 사이에 필요한 작업**을 정리한다. 이 문서는 기관 승인·계약·실제 사용자 관찰 결과가 아니다. 기존 카드 디자인과 질문 생략 정책, 모델·시간 평가 제외를 유지한다.

## 현재 확인한 실행 범위

- 별도 PostgreSQL 16 컨테이너에서 전체 앱 회귀 **1,722개 통과**, 실패·취소·생략 0. 모델 응답은 합성 fixture이며 실제 상담 품질을 측정하지 않았다.
- `tools/rehearse_final_operations.mjs`가 합성 소유자 3명의 저장·백업·복원·삭제 재적용을 **11조건**으로 확인했다. 실제 `pg_dump`와 `psql`을 사용했고, 임시 스키마를 제거했다.
- 백업 시점 이후 삭제한 데이터는 오래된 백업을 복원하면 다시 나타났다. 합성 삭제 목록을 재적용한 뒤 연결된 상담·기록·상태·이력은 0행이 됐고, 다른 소유자의 기록은 보존됐다. 만료 접근 차단과 만료 행 청소도 확인했다.
- 삭제 목록은 이번 검사에서 메모리에 만든 합성 목록이다. **실제 삭제 이벤트의 별도 보존·진위 확인·복원 시 자동 연결은 구현·운영 완료로 인증하지 않는다.** SQL 행 삭제가 저장매체·WAL·외부 사본의 물리 삭제를 뜻하지 않는다.

실행 근거: `runtime/finals-remediation-20261027/app-tests.log`, `runtime/finals-remediation-20261027/operations/restore-rehearsal.json`. 테스트 수와 복원 조건 수를 사용자 수나 하나의 성공률로 합산하지 않는다.

## 로컬 재현

아래 절차는 **새 일회용 환경과 합성 데이터만** 사용한다. 기존 서비스의 Compose 프로젝트·볼륨·DB에 실행하지 않는다. 실행 시 동일 이름의 컨테이너가 있으면 기존 것을 지우지 말고 소유자를 확인한 뒤 새 이름을 선택한다.

```sh
docker run -d --rm --name hop-finals-remediation-20261027 \
  --label codex.task=finals-remediation-20261027 \
  --tmpfs /var/lib/postgresql/data:rw,size=1024m \
  -e POSTGRES_USER=finals_test -e POSTGRES_DB=finals_test \
  -e POSTGRES_HOST_AUTH_METHOD=trust \
  -p 127.0.0.1::5432 postgres:16-bookworm
docker port hop-finals-remediation-20261027 5432/tcp
docker exec hop-finals-remediation-20261027 pg_isready -U finals_test -d finals_test
```

포트 출력의 숫자를 아래 `<PORT>`에 넣는다. DB URL과 출력에 실제 운영 암호·키를 넣지 않는다. 임시 trust 인증은 로컬 일회용 검증에만 사용한다.

```sh
FINALS_TEST_DATABASE_URL=postgresql://finals_test@127.0.0.1:<PORT>/finals_test \
FINALS_TEST_CONTAINER=hop-finals-remediation-20261027 \
node tools/rehearse_final_operations.mjs

# 저장소 루트에서 실행. 무작위 테스트 스키마만 생성·정리한다.
TEST_DATABASE_URL=postgresql://finals_test@127.0.0.1:<PORT>/finals_test \
npm --prefix app test

# 이 실행에서 직접 만든 컨테이너임을 확인한 뒤 종료한다.
docker stop hop-finals-remediation-20261027
```

검사기는 `127.0.0.1`·전용 DB/사용자·컨테이너 라벨·포트·tmpfs를 확인한다. URL query와 fragment를 거절하고 허용 값으로 URI를 다시 구성해 `pg`의 접속 옵션 재해석을 막는다. 실제 `pg` parser 대조와 접속 우회 회귀 **17개**가 통과했고 수정 후 복원 11조건도 다시 통과했다. 출력에는 세션 토큰·암호화 키·삭제 키·상담 원문을 저장하지 않는다. 합성 복원 덤프와 삭제 목록은 메모리에서만 소비한다.

```sh
node --test tools/test_final_rehearsal_connection.mjs
```

## 기관과 확인할 최소 도입안

다음은 **제안**이며 확정된 사업모델·요금·인력 배치가 아니다. 상담·교육 현장에서 가족·친구가 대화를 준비하는 보조 과업부터 검토한다. 질환 판별·치료 효과나 위기 대응의 대체를 약속하지 않는다.

| 결정 항목 | 제안 또는 선택지 | 실제 확인할 근거 | 현재 상태 |
|---|---|---|---|
| 이용 대상·장소 | 가족·친구가 상담·교육 전후에 대화를 준비하는 장면 | 기관의 실제 업무 흐름과 이용 대상 확인 | 미확인 |
| 제공 방식 | 직원이 안내하는 제한된 시범 사용부터 검토 | 설치 위치·기기·접근 범위·중단 조건 회신 | 제안 |
| 담당 역할 | 도입 결정자, 사용자 안내 담당자, 데이터·장애 담당자 | 역할별 실제 담당자와 연락 창구 | 미지정 |
| 데이터 범위 | 시범 사용에는 새 합성 사례, 실명·실제 지인 사연 수집 제외 | 기관과 합의한 입력·보관·내보내기 범위 | 미승인 |
| 운영 비용 | 장비·유지보수·교육·관찰·보관 관리의 고정/반복 비용 구분 | 실제 견적·작업량·기관 부담 가능 예산 | 금액 미산정 |
| 확대 판단 | 사용자가 근거·모름·삭제 범위를 이해하고 과업을 수행하는지 | 완료·도움·미완료·중단 및 관측 사유 | 관찰 전 |
| 대회 범위 | 질환 판별 연구와 주변인 지원 서비스의 목적·관계를 명시 | 최종 신청서·멘토 의견·주최 측 범위 안내 | 미확인 |

기관의 관심·회신·시범 사용·정식 채택은 각각 별도 상태로 기록한다. 단순 접촉이나 의향을 실제 도입으로 표현하지 않는다. 이번 작업에서 기관에 연락하지 않았다.

## 운영 전 통과해야 할 확인

1. 실제 운영 주체가 보유기간과 책임자를 정하고, 그 승인 근거를 현재 앱 버전·설정에 연결한다. 개발 기본 30일을 운영 승인으로 대신하지 않는다.
2. 저장 위치를 DB·WAL·복제·백업·내보내기·외부 제공자로 나누어 확인한다. 미사용 위치도 확인 근거가 필요하다.
3. 삭제 요청 이후에도 보존돼야 하는 최소 삭제 이벤트 기록의 범위·접근·보유기간을 운영 주체와 정한다. 삭제된 상담 원문이나 조회 권한을 이 기록에 담지 않는다.
4. 복원 환경은 사용자 접근을 열기 전에 삭제 이벤트 재적용, 만료 접근 차단, 소유자 격리와 소스·설정 일치를 확인한다. 삭제 이벤트를 확정할 수 없으면 재개 완료로 표시하지 않는다.
5. `node app/scripts/check-operations.js <실제 근거 목록>`으로 누락과 파일 결속을 확인한다. 해당 도구의 통과도 실제 승인자 신원·증거 진실성·물리 삭제를 인증하지 않는다.

현재 기본 실제 운영 템플릿은 `pending`이다. 이 실행팩이나 합성 복원 성공으로 실제 운영 템플릿을 완료 상태로 바꾸지 않았다.

## 심사 질문에 제시할 근거

| 질문 | 현재 답할 수 있는 내용 | 아직 제시할 수 없는 내용 |
|---|---|---|
| 앱의 저장·삭제가 동작하는가 | 격리 DB의 앱 계약 검사, 합성 백업 복원 후 삭제 재적용 | 실제 운영 사본 전체의 삭제 보증 |
| 누가 사용할 수 있는가 | 가족·친구의 대화 준비라는 대상·과업 정의 | 실제 참여자의 이해·선호·효용 관측 |
| 어디에 도입하는가 | 상담·교육 현장의 제한된 시범 사용 제안 | 기관 채택·유료 수요·합의된 비용 |
| 어떤 자료를 학습·검토하는가 | 최신 데이터 버전·과업별 분모·검토 준비·개발 노출 | 사람 승인·개발 비노출 독립 test 확보 |
