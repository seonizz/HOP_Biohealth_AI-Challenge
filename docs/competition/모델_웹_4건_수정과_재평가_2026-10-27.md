# 모델 웹 문제 수정과 적대적 재평가

2026년 10월 27일. [수정 전 평가](모델과_웹_적대적_평가_2026-10-27.md)의 모델 안전 경계 2건과 웹 결함 2건을 수정했다. 같은 반례와 정정·이전 기록·화면 이동 대조군으로 확인했다. 카드 디자인과 문맥에 따른 질문 생략을 유지했다. 처리시간은 평가하지 않으며 기존 결선 총점 53/90을 이번 기술 검증으로 다시 계산하지 않는다.

최종 생성은 저장된 예전 context JSON 대신 현재 intake 상태에서 문맥을 재구성한다. 따라서 예전 버전에 저장되어 지문이 없는 긴급 신호도 재검토 경로에 들어간다. 최종 검토 결과를 intake와 기록에 함께 저장한다. 이 경계를 검증하는 [API 회귀](../../app/tests/final-safety-persistence.test.js)는 변경 없는 승인·이전 형식 승인·정정으로 비긴급이 된 사례를 각각 검사한다.

실제 모델 검사 도중에는 같은 생략 문항을 두 번 반환하는 추가 오류도 확인했다. 질문 블록 검증 안에서 중복을 거절하고 해당 블록만 재작성하도록 보완했다. 근거 있는 생략을 빈 배열로 바꾸거나, 생략한 문항의 답변을 만들어 채우는 방식은 사용하지 않는다. 중복이 계속되면 결과를 거절한다.

최종 생성에서는 `strengths`와 `boundaries`를 최상위에 잘못 출력하는 형식 오류도 반복됐다. [관계 분석 프롬프트](../../app/src/relationship-prompts.js)에 `relationship` 내부의 전체 경로를 명시했다. 스키마를 느슨하게 하거나 오류 출력을 자동 수용하지 않았다. 수정 후 실제 모델의 관계 분석은 첫 출력에서 형식 검증을 통과했고 최종 안내까지 완료했다.

나머지 제품 수정 파일은 [intake.js](../../app/src/intake.js), [relationship-agent.js](../../app/src/relationship-agent.js), [relationship-turn.js](../../app/src/relationship-turn.js), [model.js](../../app/src/model.js), [server.js](../../app/src/server.js), [conversation.js](../../app/public/js/core/conversation.js), [ChatScreen.js](../../app/public/js/components/ChatScreen.js), [ColumnsScreen.js](../../app/public/js/components/ColumnsScreen.js)다.

## 회귀와 브라우저 검증

격리된 PostgreSQL과 로컬 네트워크에서 앱 전체 **1,756개 검사 통과, 실패 0, 생략 0**을 확인했다. 수정 전 1,722개 대비 34개 회귀가 추가됐다. JavaScript·JSON 문법 검사와 `git diff --check`도 통과했다. 기존 테스트의 안전 검토 호출 수와 합성 응답은 새 계약에 맞췄으며, 위험·근거·생략 검증 규칙을 완화하지 않았다.

브라우저는 현재 소스로 시작한 별도 로컬 앱을 사용했다. 마지막 파일 지문과 서버 시작 지문은 모두 `1775dc0dcace07016efd32acf8df10ad2657003fcb5bd0c1c5b2d46ee2164f88`이다. 삭제·초점·반응형 검증 후 관계 분석 프롬프트만 추가 수정했으며 웹 파일은 같음을 바이트 비교했다. 최신 인스턴스에서도 기록 화면을 다시 확인했다. [지문과 제공 파일 대조](../../runtime/model-web-fixes-20261027/final-source-identity.json)에 그 범위를 남겼다.

삭제 경쟁을 정확히 재현하기 위해 브라우저용 합성 대화에는 지연된 삭제 성공 응답을 주입했다. 실제 DB 삭제와 격리·저장 검사는 전체 API 회귀에 포함된다. 이 두 종류의 증거를 실제 사용자 기록 삭제나 실사용 관찰로 계산하지 않는다.

## 실제 모델 검증

실제 추론은 Mac의 `127.0.0.1:11434/v1`에 있는 `gemma4:12b`를 사용했다. 작성과 검토에 같은 모델을 사용하므로 서로 다른 모델이나 전문가의 독립 검증으로 계산하지 않는다. 개발용 합성 사례를 사용한 기능 회귀이며 독립 시험셋의 정확도·민감도·특이도가 아니다.

**8개 검사 항목의 최종 결과가 통과했다. 처음부터 모든 초안이 성공했다는 뜻은 아니다.** 생략 사례에서는 이미 답한 내용을 미확인으로 반복한 초안이 반려되어 재작성됐고, 최종 안내에서도 대화 계획이 검토 후 수정됐다. 중복 생략과 중첩 형식 오류의 실패 이력도 보존했다.

앞의 7개 완료 결과는 [모델 검증 결과](../../runtime/model-web-fixes-20261027/final-model-results.json)에 있다. 이 실행의 최종 생성은 반복된 스키마 오류를 관측한 뒤 진단을 중단했다. 관계 분석 프롬프트만 보완하고 영향을 받는 최종 생성 전체를 다시 실행한 결과가 [최종 생성 결과](../../runtime/model-web-fixes-20261027/final-generation/report.json)다. 이 재실행에서는 모든 9단계가 완료됐고 형식 검증 오류는 없었다. 프롬프트 변경 전후를 합쳐 최초 성공률이나 독립 정확도를 계산하지 않는다. 진단 중단·시간 제한은 처리속도 점수로 사용하지 않는다.

## 적대적 재평가

**기존 P1 2건과 P2 2건은 이번 반례 범위에서 수정 검증 통과로 판정한다.** 같은 승인 상태를 최종 생성이 무시하는 경계와, 오래된 비동기 응답이 새 화면을 덮는 경계를 코드와 회귀로 막았다. 추가 검토에서 나온 이전 형식 기록·목록 잔상·새 확인창·질문 블록 중복도 보완했다.

모델의 전체 생성 신뢰도는 조건부다. 실제로 잘못된 초안과 반려·재작성 이력이 있고, 현재 근거는 소수의 개발용 사례다. 안전 경계를 보완했다는 사실만으로 임의의 새 입력에서도 올바른 판단이나 최종 생성 성공을 보장할 수 없다. 같은 모델의 역할별 검토를 전문가 판정 또는 독립 모델 검증으로 제시해서도 안 된다.

웹의 이번 삭제·초점·카드 유지 범위는 통과다. 실제 사용자 사용성, 별도 브라우저 엔진과 스크린리더 조합까지 전수 검증했다는 의미는 아니다. 결선에서는 수정한 동작과 실제 통과 사례를 제시할 수 있지만, 이를 근거로 일반 정확도 수치나 실사용 안전성 검증 완료를 주장하는 것은 여전히 방어하기 어렵다.

이번 검증은 현재 수정본과 지문이 일치하는 별도 로컬 인스턴스 기준이다. 기존 9001 서비스 프로세스는 재시작하지 않았다. 기존 카드·사용자 기록·Git 스테이징은 보존했고, GPU 서버에는 접근하지 않았다. 학습 데이터나 비밀값은 커밋·업로드하지 않았다. 이번 작업의 임시 앱·DB·브라우저 탭은 검증 후 정리했다.
