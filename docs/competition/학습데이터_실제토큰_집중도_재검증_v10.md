# 새 주변인 학습데이터 실제 토큰·집중도 적대적 재검증 v10

검증일: 2026-10-16. [v9 과업 정합성 구성](학습데이터_주변인지원_과업정합성_개선_재검증_v9.md)의 토크나이저 미검증을 해소하는 후속 검증이다. [사용자 지정 평가 범위](05_평가범위와_학습데이터_기준.md)에 따라 데이터의 목적·품질·분할·추적성을 다루며 모델 성능·크기·속도나 전체 프로젝트 점수를 평가하지 않는다.

**기존 서버와 바이트가 같은 토크나이저를 로컬에 복구하고 419개 파생 행을 모두 새로 인코딩했다. 전부 출력 8,192 예약 조건과 실제 시퀀스 4,096 이하 조건을 통과했다.** 전체 입력은 **157,668토큰**, 정답은 **17,220토큰**이다. 이 중 v9 신규분은 **279행·입력 129,065토큰·정답 12,014토큰**이다. 보존한 기존 v2도 같은 조건에서 다시 측정했다.

**원문·맥락·분할 보존과 토큰 예산 적격성은 통과했지만, 그룹 균형의 모든 지표가 개선된 것은 아니다.** 기존 v2 대비 raw HHI는 18개 비교 모두 낮아졌다. 그룹 수 영향을 보정한 정규화 HHI는 1개, 상대 편차 CV는 5개 비교에서 악화됐다. 기존 데이터를 줄이거나 새 대화를 잘라 이 수치를 숨기지 않았다.

## 1. 접근 문제 해결과 동일성 근거

기존 SSH ControlPath가 없고 지정 계정의 비대화형 인증은 실패했다. 서버의 비밀번호 인증·키·설정은 변경하지 않았다. 대신 기존 다운로드 기록의 고정 리비전 `8e256fc6d63003fc0ca8c91b976e6dcc38433385`에서 토크나이저 메타데이터 4개만 내려받았다. 모델 가중치나 학습데이터는 전송하지 않았다.

| 파일 | 기존 서버 검증 기록과 비교 |
|---|---|
| `tokenizer.json` | 32,169,626 bytes, 전체 SHA-256 일치 |
| `tokenizer_config.json` | 22,084 bytes, 전체 SHA-256 일치 |
| `chat_template.jinja` | 18,924 bytes, 전체 SHA-256 일치 |
| `config.json` | 5,586 bytes, 전체 SHA-256 일치 |

기존과 같은 `transformers 5.17.0`, `tokenizers 0.23.2`, `huggingface-hub 1.33.0`을 Git 제외 격리 환경에서 사용했다. 템플릿 실행용 Jinja2는 3.1.6이다. 모델·PyTorch를 로딩하지 않았으며 실제 측정은 `local_files_only=True`, `trust_remote_code=False`, 네트워크 차단 옵션으로 실행했다. vocab·설정까지 고정했으므로 템플릿 해시만 같다는 근거에 의존하지 않는다.

[고정 토크나이저 원본](https://huggingface.co/unsloth/gemma-4-31B-it-unsloth-bnb-4bit/blob/8e256fc6d63003fc0ca8c91b976e6dcc38433385/tokenizer.json) · [복구 기록·4개 전체 해시](../../runtime/data-composition-supporter-tokens-20261016/tokenizer-access-restoration.json) · [실제 실행 버전·입력·구현 해시](../../data/outputs/private/composition_v10_supporter_tokens_20261016/audit/provenance.json).

**해결된 것은 토크나이저의 로컬 접근이다. 원격 SSH 인증이 복구됐다는 뜻은 아니다.** 이후 같은 입력을 재검증하는 데 서버 비밀번호가 필요하지 않다.

## 3. 집중도: 개선과 남은 악화

각 과업·split·기존/신규 집합 안에서 **고유 source group마다 해당 행의 실제 토큰을 한 번씩 합산**했다. 모든 측정 행의 root/group은 각각 1개다. 여러 그룹에 같은 행의 토큰을 중복 귀속시키지 않는다. top1·top5·top10, HHI, 정규화 HHI, 유효 그룹 수, CV를 입력과 정답에 따로 계산했다. 전체·train·validation 및 기존·신규 구분의 상세 39개 집계는 [실측 요약](../../data/outputs/private/composition_v10_supporter_tokens_20261016/audit/summary.json)에 있다.

HHI는 그룹 토큰 점유율 제곱의 합이며 균등할 때 `1/G`다. 정규화 HHI는 `(HHI−1/G)/(1−1/G)`이고, CV는 그룹별 토큰 총량의 모집단 표준편차/평균이다. 그룹이 늘면 raw HHI가 자연스럽게 낮아질 수 있어 세 지표를 함께 본다. 상위 k에 전체 그룹이 포함되는 작은 집합에서 top-k는 불균형의 단독 근거가 아니다.

| 전체 과업 | 그룹 | 입력 / 정답 top1 | 입력 / 정답 HHI | 입력 / 정답 CV |
|---|---:|---:|---:|---:|
| 주변인 다음 응답 | 44 | 3.10% / 3.59% | 0.025585 / 0.025308 | 0.3546 / 0.3370 |
| 문장 기능 | 44 | 3.89% / 3.55% | 0.026354 / 0.025324 | 0.3995 / 0.3380 |
| 근거 span | 44 | 3.71% / 3.40% | 0.026184 / 0.024887 | 0.3900 / 0.3082 |
| 앱 관찰 | 12 | 9.25% / 10.26% | 0.083760 / 0.084560 | 0.0716 / 0.1213 |
| 앱 reported 기억 | 12 | 9.52% / 10.20% | 0.083707 / 0.084643 | 0.0670 / 0.1254 |

기존 v2→최종 v9 주변인 비교는 3과업×3split 범위×입력/정답, 총 **18개 비교**다. raw HHI 18개가 모두 감소하고 정규화 HHI 17개가 감소했다. 아래 항목은 악화가 남는다. 앱 두 과업에는 기존 대응 기준본이 없으므로 개선률을 만들지 않는다.

| 비교 항목 | 지표 | 기존 v2 | 최종 v9 |
|---|---|---:|---:|
| 주변인 다음 응답 · validation · 입력 | 정규화 HHI | 0.000192 | 0.006600 |
| 주변인 다음 응답 · validation · 입력 | CV | 0.027720 | 0.324951 |
| 문장 기능 · validation · 입력 | CV | 0.362394 | 0.374733 |
| 근거 span · 전체 · 정답 | CV | 0.303192 | 0.308243 |
| 근거 span · validation · 입력 | CV | 0.201469 | 0.358262 |
| 근거 span · validation · 정답 | CV | 0.200921 | 0.292610 |

주변인 validation은 기존 5그룹이 각각 1응답이었고, 추가 12그룹은 각각 2응답이다. 대화 과업의 그룹당 평균 입력이 기존 **251.6**토큰, 추가 **606.25**토큰으로 달라졌다. 전체 접두부·다중턴을 보존한 구성이 이 편차의 구체적 배경이다. 데이터 누락이나 split 이동으로 원인이 가려진 것은 아니다.

앱은 단계마다 전체 12그룹, 각 split 6그룹이다. validation 입력 top1이 관찰 18.31%·기억 18.80%인 점은 균등 기준 16.67%와 함께 해석해야 한다. 사례 다양성·실제 모집단 대표성이 충분하다는 뜻은 아니다.

완전히 같은 직렬화 접두부는 과업별로 중복되지 않았지만 **같은 원래 대화 맥락의 재사용은 남는다.** 주변인 파생 395행은 원래 가시 접두부 72개를 공유한다. 각 문장·span의 과업 지시가 달라 입력 문자열이 다를 뿐이다. 앱 기억 입력에는 같은 맥락에서 저작한 관찰 정답이 포함되는 teacher forcing도 유지된다. 정확 문자열 중복 0을 의미적 독립성이나 누출 0의 완전한 증명으로 쓰지 않는다.

## 4. 출력 8,192와 4,096 조건의 판정

이전 요청과 동일하게 입력 상한 65,536, 출력 예약 8,192, 합산 상한 69,632를 적용한다. 유효 입력 상한은 `69,632−8,192=61,440`이다. 모델 tokenizer의 일반 `model_max_length`나 별도 API의 더 큰 상한으로 이 계약을 느슨하게 바꾸지 않는다.

| 항목 | 실제 판정 |
|---|---|
| 정답 ≤8,192, 입력+예약 8,192 ≤69,632, 실제 합산 ≤69,632 | **419/419 통과** |
| 실제 입력+정답 ≤4,096 | **419/419 통과**, 신규 279행도 전부 통과 |
| 최장 실제 시퀀스 | **3,909토큰**, 4,096까지 187토큰 여유 |
| 최대 입력과 그 예약 합산 | **3,806 + 8,192 = 11,998** |
| 최대 정답 | **145토큰** |
| 현재 앱 두 단계의 출력 상한 1,800 | 앱 정답 **24/24** 길이 적합, 설정 변경 없음 |
| 잘라내기·패딩으로 예산 맞추기 | **0건**. 배치 패딩은 검증용이며 입력·정답을 자르지 않음 |

4,096은 **현재 정답을 포함한 학습 시퀀스의 실제 길이** 조건이다. 4,096 문맥 안에서 8,192 출력 생성을 예약할 수 있다는 의미가 아니다. 8,192만큼 정답을 늘리거나 생성 품질·긴 출력 완주를 검증한 것도 아니다. 현재 합성 후보의 길이를 실제 서비스의 더 긴 입력에 일반화하지 않는다.

## 5. 원문·맥락·분할 보존

- **파일·계보:** 기존 v9 supporter·app_stages_r2·원상담 v8을 수정하지 않고 별도 v10 토큰 장부를 만들었다. v9의 기존 20대화, 신규 24대화, 앱 12맥락의 ID·root/group·split은 유지했다.
- **실제 입력 문자열:** 앱 wire JSON의 문자열을 parse→정렬→재직렬화하지 않았다. 원래 system/user/assistant content를 그대로 사용했다. 새 측정기는 앱 nested mask의 타입·값을 확인한 뒤 adapter용 flat mask만 임시 변환한다.
- **정답 경계:** 419행 모두 prefix 토큰 ID가 full sequence의 정확한 앞부분과 일치한다. 앞부분 label은 `-100`, 마지막 정답만 정수 토큰 label이다. causal label을 미리 한 칸 이동하지 않았다. 배치 패딩에도 정답 손실을 주지 않는다.
- **직렬화 차이의 공개:** native 완료 템플릿은 빈 thought 접두부를 생략하고 생성 prefix는 포함한다. 기존 고정 adapter의 non-thinking 결합을 명시 적용했다. native full/prefix 일치는 0행, 명시 결합은 419행이다. 이는 원문 수정이 아니며 각각 decode 왕복으로 canonical 전체 문자열을 대조했다. 원문 메시지 경계 공백 trim 발생은 **0건**이다.
- **독립 확인:** 별도 검토자는 생산 측정 helper와 `encode_example`를 쓰지 않고 원래 content와 생성 prefix를 결합한 뒤 `tokenizers.Tokenizer.from_file` 저수준 경로로 다시 인코딩했다. **419행의 prefix/정답/full 토큰 ID 해시·길이·source line·group/root/split/cohort가 모두 일치**했다. 39개 집계의 1,716개 scalar를 Fraction 기반 계산과 비교해 불일치 0개였다.

기존 v9 manifest의 `tokenizer_validated:false`는 당시 기록으로 남긴다. 새 판정은 원본 해시에 결속된 **[v10 측정 sidecar](../../data/outputs/private/composition_v10_supporter_tokens_20261016/audit/manifest.json)**에서 읽는다. 토큰 적격성을 사람 승인·원천 권리·독립 test·학습 실행으로 승격하지 않는다.

## 7. 남은 제한과 사용 판정

**v9의 토큰 미검증은 해소됐다.** 새 후보 전부가 현재 출력 8,192 예약과 실제 4,096 시퀀스 조건에 맞고, 저장된 원문·맥락·분할을 유지한다. 현재 학습 데이터의 목적 적합성·의미 품질에 대한 v9의 AI 검토 기록은 보존하지만, 이번 토큰 검증을 새로운 사람·전문가 의미 검토로 세지 않는다.

남은 문제는 validation의 그룹별 입력 편차, 일부 span 정답량 편차, 작은 합성 집합의 다양성, 같은 맥락의 파생·teacher forcing, 두 앱 단계에 한정된 과업 범위다. 전체 앱의 가이드·계획·안전 판단 정답이나 독립 test가 추가된 것은 아니다. 과업 간 혼합 비율은 이번에 정하지 않았으며 원상담의 큰 분량이 주변인 과업을 압도하지 않는 별도 설계가 여전히 필요하다. 기존 보류·원천 이용 근거·HR5/HR6 제한도 해소했다고 주장하지 않는다.
