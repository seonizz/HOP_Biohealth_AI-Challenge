## 1. 새로 확인한 결함과 해결 우선순위

### HR3 · MEDIUM · P1 — 요청한 manifest 해시와 다른 해시로 검증 성공

[human_review_bundle.py:216](../../data/counseling_pipeline/human_review_bundle.py:216)은 별도 기록된 `--expected-manifest-sha256`과 파일 해시를 비교한다. 이어 217행에서 파일을 다시 읽어 JSON을 파싱하고, 223행에서 다시 해시를 읽어 성공 결과에 넣는다. **세 읽기가 같은 바이트에 결속돼 있지 않다.**

합성 묶음을 정상 생성한 뒤, 첫 해시 읽기가 끝난 직후 manifest 앞에 줄바꿈 하나를 추가하는 동시 쓰기 순서를 주입했다. 실제 해시 함수는 원래 바이트를 읽어 반환하고, 이후 파서·계획 대조·최종 해시 함수는 수정 없이 실행했다. JSON 의미는 같아 정규화된 JSON 대조를 통과했다.

| 관측 항목 | 기대 | 실제 결과 |
|---|---|---|
| 외부 pin과 성공 결과의 연결 | 성공으로 검증한 바이트의 해시가 요청 pin과 일치 | **`verified:true`, 반환 `manifest_sha256` ≠ 요청 pin** |
| 변형 범위 | 동시 변경을 탐지하거나 명시된 단일 스냅샷을 검증 | manifest에 줄바꿈만 추가, 다른 산출물 보존 |
| 승인 상태 | 자동 승격 없음 | `human_approved:0`, `training_authorized:false` 유지 |

이 재현은 **함수 수준의 결정적 동시 쓰기 일정**이며 무계측 CLI에서 우연히 경쟁을 이긴 횟수가 아니다. 다른 로컬 작성자가 해시 확인과 다음 읽기 사이에 변경할 수 있는 순서를 재현했다. 검토 의미나 사람 승인을 바꾼 성공 사례로 기록하지 않는다. 정상 pin·입력 복원 대조는 통과했다.

**완료 기준:** manifest를 한 번 캡처한 바이트로 해시·중복 키 파싱·계획 비교·반환 해시를 계산한다. 성공 결과의 해시는 요청 pin과 일치해야 한다. 검증 완료 시점의 파일 상태까지 보장하려면 캡처한 파일 식별·해시와 최종 상태를 대조해 중간 교체를 거절한다. 검증된 스냅샷과 반환 후 파일 불변을 구분하고, 동일 교체 일정·정상 pin·복원 대조를 회귀에 추가한다.

### HR4 · MEDIUM · P2 — 실제 검증 의존성의 변경이 구현 해시에 반영되지 않음

[human_review_bundle.py:128](../../data/counseling_pipeline/human_review_bundle.py:128)의 구현 목록은 5개 모듈만 고정한다. 그러나 [agent_dataset.py:21](../../data/counseling_pipeline/agent_dataset.py:21)이 가져와 175행에서 대화·접두부 중복 검사에 사용하는 **`source_selection_audit.normalize`의 구현 파일은 목록에서 빠져 있다.**

| 관측 항목 | 실제 결과 |
|---|---|
| 정규화 동작 변화 | 합성 문자열의 결과가 `A`에서 공백을 포함한 전각 `Ａ`로 달라짐 |

이는 코드가 바뀌면 새 버전으로 인계하며 같은 구현으로 검증한다는 [인계 절차](../../data/docs/support_agent/사람검토_인계_절차_v1.md:34)의 보장 범위가 실제 구현보다 넓다는 증거다. 경로를 옮긴 문제가 아니며, 기존 실제 데이터에 중복·누출이 발생했다는 증거도 아니다.

**완료 기준:** `source_selection_audit.py`를 인계의 명시적 구현 입력에 포함하고 다른 판단 의존성·리소스의 결속 범위도 확인한다. 이 의존성만 바뀌어도 과거 묶음을 거절하는 회귀를 추가한다. 변경된 구현 목록은 새 버전·별도 manifest pin에 기록하고, 과거 묶음이나 사람 판단을 소급 덮어쓰지 않는다.

현재 `_r3`에 별도 pin을 적용해 `verify`를 새로 실행했다. manifest **`a4f5b0aac96e870cdc88480e6352d601b39ef7d975478db9219bb6a5f0554135`**에서 검토 대기 **28단위 = 응답 24 + 전문·권리 4**, 실제 사람 승인 **0건**을 확인했다. AI 20에피소드·AI 검토 20기록·선언된 AI 검토자 1개, 원천 검토 큐 391개·작성 요청 6개는 다른 분모이며 합산하지 않는다. 학습·운영·독립 test 승인은 false다.

## 6. 검토 판정과 보존 한계

코드 검토는 핵심 8파일과 필요한 의존성 7파일을 확인했다. **CRITICAL 0 · HIGH 0 · MEDIUM 2 · LOW 0, REQUEST CHANGES**다. JS 구문 2파일·Python AST 4파일·해당 diff 검사는 통과했다. LSP wrapper 8호출은 `tsconfig` 부재로 모두 생략됐고 ast-grep은 사용할 수 없었다. 타입 검사 통과로 표현하지 않는다.

아키텍처의 초기 WATCH는 새로운 재현 근거를 독립적으로 검토한 뒤 **BLOCK**으로 변경됐다. 초기 21조건은 HR3·HR4를 다루지 않았으므로 인계 전체의 무결성 증거로 확대하지 않는다. “manifest 바이트 전체 비교”는 정규화된 JSON 비교로, “동일 구현 결속”은 열거된 구현 파일로 설명 범위를 좁힌다. 최종 판정은 [후속 아키텍처 기록](../../runtime/adversarial-review-v12/architecture/review-summary.json)을 따른다.
