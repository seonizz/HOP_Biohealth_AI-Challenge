# 재평가 v2의 N1–N4 수정 기록

기준일: **2026-10-15, Asia/Seoul**. 기준 커밋 `738594d`, 앱 프롬프트 `relationship-v3.7-complete-safety-evidence`.

[재평가 v2.1](결선_적대적_재평가_v2.md)의 새 코드 결함 네 건을 수정했다. 평가서와 과거 근거는 보존한다. 이 기록은 재채점이 아니며 48/90점을 자동으로 올리지 않는다. 처리시간·속도는 평가 항목으로 다루지 않고 제한시간은 요청 집계 결함의 재현 조건으로만 사용한다. 서비스 화면에 기술 상세를 추가하지 않는 [사용자 지정 원칙](../../app/docs/UI_CONTENT_POLICY.md)을 유지했다.

## 수정과 검증

| 지적 | 변경 | 확인한 결과 |
|---|---|---|
| N1 긴 위험 인용의 부정·시점 누락 | 안전 근거를 문항 원문 전체로 제한. 별도 직접 입력·후속 답변도 함께 요구. 일반 사실의 160자 발췌를 안전 근거로 사용할 수 없게 분리 | 재현의 319자 원문 전체를 후보로 유지하고 기존 159자 발췌는 거절. 160자·1,000자 경계와 10,000자 원문, 화자·정정·모름의 회귀검사 통과 |
| N2 요청 수 중복 | 실제 fetch마다 `attempt_id`, 생성 호출마다 `generation_id`. 재시도 대기 종료는 별도 사건으로 기록 | HTTP 503 후 대기 제한시간 재현에서 fetch 1·요청 1·실패 1·재시도 0·대기 종료 1. 요청 ID 중복도 한 번만 집계 |
| N3 다른 서버의 결과 혼합 | endpoint와 선택적 배포 선언의 해시를 실험군 키에 포함 | 같은 모델 alias로 서로 다른 서버를 지정한 두 실행이 두 그룹으로 분리. 주소·키·배포 선언 원문은 결과에 노출하지 않음 |
| N4 웹 재실패 기록 덮어쓰기 | 재개 세션과 실행별 UUID를 분리. 시도별 시작·결과 파일을 배타적으로 생성 | 같은 세션의 실패 2회 후 성공 1회를 모두 보존. 중단·ID 충돌·중복 완료·권한 검사 통과 |

N1의 전체 원문 후보는 문장 하나, 선택 보기 하나 또는 위험 단어 주변만 남기지 않는다. 다른 구성요소 안에 완전히 포함된 중복 원문만 생략한다. 인용한 사람·문항에 별도 후속 정정이 있는데 그 정정을 빼면 서버에서 거절한다. 현재 위험을 보고한 긴 원문은 계속 허용하므로 과거 부정 단어가 있다는 이유만으로 위험을 낮추지 않는다.

**N1은 인용 계약의 수정이다.** 전체 원문을 인용하면서도 `urgent`의 의미를 잘못 판정하는 가능성은 남는다. 결정적 프로브에서도 전체 인용 자체가 판단의 의미를 인증하지 않는다는 것을 확인했다. 가설·가이드 전체의 의미 정확성이나 임상 안전성을 해결했다는 주장을 하지 않는다.

또한 안전 인용은 원문 길이를 그대로 보존하지만 분석·수정 생성 한도는 2,400토큰이다. 10,000자 회귀검사는 validator의 보존·거절 계약을 검증한 것이며, 그 길이의 실제 생성 성공을 검증하지 않았다. 긴 입력에서는 출력 한도로 실패할 수 있다. 실패를 피하기 위해 안전 근거를 다시 자르거나 자동 승인하지 않는다.

## 이전 기록과 호환성

- ID 없는 이전 trace는 대기 종료 행과 실제 요청을 확실하게 나눌 수 없으므로 새 집계에서 요청·실패·재시도·토큰을 `null`, `attempt_count_verified:false`로 남긴다. 원시 기록과 당시 집계는 보존한다.
- endpoint가 없는 이전 실행은 각각 별도 그룹으로 취급한다. endpoint 해시는 userinfo·query·fragment를 제외하며 경로를 포함한 주소 원문도 저장하지 않는다. 같은 주소 뒤에서 모델 배포가 바뀔 때는 `MODEL_DEPLOYMENT_ID` 선언을 바꿔 구분해야 한다. 이 선언은 실제 가중치 로딩 증명이 아니다.
- 웹 시도 이력은 `ai/local_api/runtime/relationship-smoke-attempts/<attempt_id>/started.json`과 `result.json`에 남는다. 재개 파일은 현재 세션 위치를 담고, 시도 이력을 대신하지 않는다. 시작만 남은 시도는 미완료로 식별한다. 실제 운영 웹 세션을 일부러 실패시키지는 않았으며 반복 실패 검증은 로컬 파일 도구 검사다.
- 이번에 UI와 PPT는 수정하지 않았다. 기존 발표 기준본은 v3.6.2 관측을 보존한 자료이며 v3.7 결과가 반영된 덱이라고 표시하지 않는다.

## 여전히 필요한 증거

최종 31B checkpoint·adapter의 실제 로딩과 전체 서비스 흐름, 독립 test·사람 검토, 학습 전후와 단순 프롬프트 비교, 이용·운영 실증은 미완료다. 이번 코드 수정과 세 합성 사례를 그 증거로 대체하지 않는다. 긴 최대 입력의 실제 생성 가능성도 별도로 확인해야 한다.
