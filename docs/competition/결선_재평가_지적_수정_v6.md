# 재평가 v5 대응 수정 v6 — 입력 경계와 부분 노출 보류

기준일 2026-10-15. [엄격 재평가 v5](결선_적대적_재평가_v5.md)의 A2 입력 결함과 D1 데이터 부분 노출에 대응했다. 기준 커밋은 `ae1e1ef`이며, 이 문서는 수정·검증 기록이다. 기존 68/90점·데이터 13/20점을 새로 채점하거나 덮어쓰지 않는다.

## 입력 A2

UI와 서버가 같은 내용 판정 함수를 사용한다. 판정용 사본에서 control·format·Unicode 기본 무시 문자를 제외하고 빈값 또는 건너뛰기 표시인지 확인한다. 실제 내용이 있는 원문은 정규화하거나 문자를 삭제하지 않는다. ZWJ 가족 이모지, 결합 악센트, 한글 자모, 실제 “모름”과 “없음”도 보존한다.

- 필수·`noSkip` 서술형과 필수 후속 질문은 내용 없는 입력을 기존 `400 answer_required`로 거절한다.
- 선택적 서술형은 건너뜀으로 처리하며 답변 수·검색·안전 근거 후보에서 제외한다.
- 선택형 직접 입력도 같은 판정을 적용한다. 이미 선택한 보기와 “네” 뒤 선택적 부가 설명을 구분한다.
- 원문 이력에 남는 내용 없는 부가 설명은 검색·안전·상태 근거로 제시하지 않는다. 내용 있는 입력의 결합문자는 유지한다.

실제 HTTP·일회용 PostgreSQL에서 상태 불변·저장·재조회·후속 답변을 검사했다. UI 검사는 실제 핸들러를 mock DOM에서 실행한 범위다. 같은 작업 디렉터리의 병행 재평가에서 생성한 전체 앱 294개·평가 도구 24개 통과 로그와 검증 시점 146파일의 현재 해시 일치를 확인했다. 별도 신규 브라우저 전체 E2E나 실제 모델 실행 결과로 표현하지 않는다.

## 데이터 D1

기존 admission이 허용한 train 40,415행의 과거·최종 assistant 메시지와 validation 4,298행의 정답을 대상으로 부분 노출을 검사했다. 기존 전체 목표·문맥 검사에 200자 연속 부분 일치 검사를 추가했다. NFKC·연속 공백 정규화, 100자 검색 창·50자 간격·마지막 창, 실제 문자열 포함 확인과 `SequenceMatcher(autojunk=False)` 최장 일치를 사용한다.

확인된 9행을 새 정책 `malssi-source-admission-v2`에서 추가 보류했다. 같은 사람이라고 단정하거나 source group 전체를 추가 격리하지 않았다. 9행의 보류는 검토 전 보수적 처리이며 반복 양식/실질 정답의 의미 판정 완료가 아니다.

운영 코드를 import하지 않은 독립 재검사도 기존 후보의 9행을 재현하고 새 후보에서 같은 200자 기준 노출 **0행**을 확인했다. 독립 검출·새 정책·장부에서 변경된 ID는 모두 같은 9개다. 원본 45,974행의 식별자와 기존 보류 결정을 대조했고, 감시한 입력·출력 20파일의 해시가 검사 전후 동일했다.

| 단계 | Train | Validation | 합계 |
|---|---:|---:|---:|
| 기존 내용 보류 후 | 40,415 | 4,298 | 44,713 |
| 긴 부분 노출 9행 추가 보류 | 40,415 | **4,289** | **44,704** |
| 새 정책 + 기존 4,096 길이 조건 | 15,512 | 1,724 | 17,236 |

추가 9행은 기존 4,096 후보에 포함되지 않았으므로 마지막 단계의 행 수는 변하지 않았다. 새 token policy·전체 행 장부·원문 바이트 보존 export를 별도로 생성해 새 내용 정책에 연결했다. 새 export는 압축 해제 후 기존 후보와 바이트가 같고 추가 보류 9행을 포함하지 않는다. 구버전 정책/장부와 학습 kit·기존 발표 집계는 덮어쓰지 않았다. 기존 길이 장부를 재사용했으며 모델이나 토크나이저를 실행하지 않았다.

로컬 산출물은 `data/outputs/private/malssi_partial_exposure_20261015/`에 있다. 전체 원문과 기존 보류를 보존하고 validation을 train으로 옮기거나 미사용 최종 test로 이름을 바꾸지 않았다. 세부 ID·좌표·해시·보류 사유는 로컬 정책에 두며 Git에는 올리지 않는다. 재현 명령은 [데이터 README](../../data/README.md#sft-부분-노출-보류)에 기록했다.

## 검증과 한계

데이터 회귀는 **총 345개 중 337 통과·8 제외·실패 0**이다. 8건은 기존 torch 의존 검사다. 새 경계·전파 검사 10개는 199/200/201자, 검색 창 정렬 위치, Unicode 정규화, 원문 보존, 기존 격리 유지, 새 보류의 token/export 전파와 장부 불일치 거절을 확인한다. 집중 검사 72개는 전체 데이터 검사에 포함하며 합산하지 않는다.

소스·로그·로컬 산출물 해시와 독립 재검증 범위는 [검증 근거 JSON](결선_재평가_지적_수정_v6_근거.json)에 기록한다. 원시 로그는 Git 제외 `runtime/adversarial-fixes-v6/`에 보존한다. 과거 v5 평가·근거와 데이터 원본은 보존한다.

[사용자가 지정한 UI 원칙](../../app/docs/UI_CONTENT_POLICY.md)에 따라 서비스에 개발·평가 상세를 추가하지 않았다. [새 평가 기준](05_평가범위와_학습데이터_기준.md)에 따라 모델 자체와 처리시간은 채점 근거로 삼지 않았다. 짧은·의미·불연속 중복, 실제 인물 독립성, 주변인 지원 정답 구성과 의미 라벨의 충분한 검토는 계속 남아 있다.
