## 1. 개선 방법과 유지 조건

기존 주 후보의 모든 행을 유지하고, 빠져 있던 후반부 상담×위치 구간에서 원래 행 하나씩을 추가한다. 전반부 행을 삭제하거나 후기 두세 행을 반복해 비율을 맞추지 않는다. 같은 상담의 다른 시점이 추가되는 것이며 독립된 사람이나 새 상담을 확보한 것은 아니다.

출력 조건은 이전과 같은 **8,192토큰**이다. 기록된 RTX 4090×2 서버 예산은 입력 65,536·출력 4,096·합산 69,632로 보존하고, 이번 요청 평가 조건은 출력 8,192·합산 69,632이므로 **유효 입력 상한은 61,440**이다. 서버 설정·모델 실행을 변경한 결과가 아니다.

```text
입력 접두부 ≤ 65,536
관측 정답 ≤ 8,192
입력 접두부 + 최대 출력 예약 8,192 ≤ 69,632
따라서 입력 접두부 ≤ 61,440
전체 학습 행 길이 = 입력 접두부 + 관측 정답
```

선택은 다음 조건을 함께 지킨다.

1. v3의 주 후보 2,365행을 원래 ID·JSONL 바이트 그대로 포함한다. 전기·후기 모두 삭제하지 않는다.
2. 원래 내용 보류·문맥 보류와 출력 8,192 예산을 통과한 풀에서, 아직 선택되지 않은 후기 상담×구간마다 한 행을 추가한다.
3. 추가 대표는 고정 seed와 ID의 해시 순서로 선택한다. 정답의 질이나 짧은 길이로 재정렬하지 않으며 선택한 원문을 요약·절단하지 않는다.
4. 한 상담×구간당 최대 1행을 유지한다. train과 validation은 원래 분할에 남고, 그룹·상담·주체 앵커도 유지한다.
5. 기존 전체 4,096 이하 후보 1,743행은 보존한다. 새 보강본을 4,096 이하 후보로 다시 이름 붙이지 않는다.
6. 새 validation에서 후기 행만 모은 `validation_late_audit.jsonl.gz`를 제공한다. 주 validation의 부분집합이며 독립 test나 추가 사례가 아니다.

위치 구간은 0부터 시작하는 정답 끝 발화 순번을 `max(1, 원상담 전체 발화 수−1)`로 나눈 값이다. `>0.5`는 후기, `>0.75`는 마지막 ¼이다. 임상 단계·회복·상담 종료의 의미 라벨이 아니다. 전체 과거 접두부를 유지하므로 **정답 위치 비율의 개선을 입력 텍스트의 전후반 노출 비율 개선으로 해석하지 않는다.**

## 2. 4,096 이하 validation의 불가능 조건

원래 내용·문맥 보류를 유지한 짧은 validation 풀에서 후기 후보는 셋째 ¼ **3행·2개 상담×구간**, 마지막 ¼ **0행**이다. v3는 그 두 셀을 이미 모두 포함했다. 선택만으로 새 후기 셀을 만들 수 없다.

출력 8,192 예산을 통과한 원래 validation의 마지막 ¼ 풀은 **636행**이다. 저장된 전체 길이의 최솟값이 **6,932**, 입력 접두부의 최솟값이 **6,833토큰**이므로 전체 4,096 조건에 들어갈 수 없다. 두 최솟값이 같은 행에서 나온다고 가정하지 않는다.

따라서 이번 개선은 **긴 원문 맥락을 보존하는 주 후보와 validation 보완본**에 적용한다. 기존 짧은 후보의 전반부 **97.13%**, 후기 **50셀**, 마지막 ¼ validation **0행**은 그대로다. 새 보강본의 수치와 섞어 “4,096에서도 해결”이라고 보고하지 않는다.

## 3. 구성 변경의 비용

v3의 그룹당 최대 16행을 그대로 적용하면 당시 제외된 후기 셀 일부를 다시 잃는다. 새 보강본에서는 **기존 16행 이하의 핵심 후보 + 그 그룹에서 빠져 있던 후기 셀당 1행**이라는 규칙을 명시한다. 기존 후보의 상한을 몰래 바꾸거나 최종 후보에도 16행 상한이 적용된다고 표시하지 않는다.

모든 후기 셀을 채우는 선택은 출처 그룹의 반복 기여를 증가시킬 수 있다. 원래 후보의 분포와 새 후보의 그룹별 최대·상위 5개 그룹 점유율을 함께 공개한다. 후기 위치 수량의 증가만으로 데이터 전반의 대표성이나 목적 적합성이 입증되지는 않는다.

| 출처 집중도 | v3 주 후보 | v4 후기 보강본 |
|---|---:|---:|
| 전체 그룹별 최대 행 수 | 16 | **25** |
| 16행을 넘는 그룹 수 | 0 | **71** |

| validation 그룹별 최대 행 수 | 16 | **20** |

이 선택은 후기 구간 누락을 해소하는 대신 출처 집중을 일부 높인다. 기존 사례를 보존하고 후기 셀을 모두 포함하는 우선순위를 택했으며, 그룹 16행 상한과 정확한 50:50을 동시에 달성했다고 주장하지 않는다. 이전 제한이 필요한 비교에는 보존된 v3 주 후보를 사용한다.

## 4. 원문·맥락·분할의 검증 계약

원상담 SFT의 원래 JSONL 바이트를 직접 복사한다. 별도 독립 감사에서는 원 발화 ordinal 0부터 정답 끝까지 역할·순서를 재구성하고, 인접한 같은 역할 발화만 기존 줄바꿈으로 합친다. 원문 바이트 비교와 원 발화 재구성을 따로 검사한다.

정답 시작·끝 좌표, 발화 ID 순서, 마지막 assistant만의 정수 손실 마스크, 화자·그룹·상담·주체·split 앵커를 대조한다. 미래 발화 추가나 앞·중간 맥락 삭제는 허용하지 않는다. 분할 보존은 원래 식별자 결속에 대한 검사이며 실제 사람의 신원 확인을 대신하지 않는다.

저장된 토큰 길이는 원문·기존 adapter·템플릿·토큰 감사 파일의 해시를 연결해 사용한다. 새 토크나이저 실행은 하지 않는다. 기존 직렬화의 생성 접두부 경계 조정 및 정답 양끝 공백 제거는 원문 파일 보존과 별도로 기록한다. 파일 원문이 같다는 사실을 모델 입력 문자열까지 바이트가 같다는 주장으로 확대하지 않는다.

추가형 선택도 적대적으로 검사한다. 기존 행 삭제, 이미 채운 후기 셀 중복, 전기 행의 후기 라벨 위조, 원래 train 행의 validation 이동, 보류 해제, 4,096 조건을 만족하지 않는 행의 짧은 후보 위장, 후기 패널에 전기 행 삽입, 설정·장부·해시를 함께 바꾸는 공격을 검증 대상에 포함한다.

**분할 누출 검사의 범위도 제한한다.** 선택된 train의 과거·정답 assistant 메시지에서 중복을 제거한 고유 메시지 66,033개와 validation 정답을 대조해 정규화된 연속 200자 이상 부분 노출은 0행이었다. validation 247행 중 검색한 긴 정답은 119행이고 128행은 길이가 짧아 이 부분 노출 검색 대상이 아니다. 의미 유사·불연속 중복·train user 발화와의 중복·실제 동일인 여부는 이 결과로 배제하지 않는다.

검토 표시도 삭제하지 않았다. 새 후보 1,281행에는 기존 과거 assistant의 절차 표현 검토 표시가 남고, 그중 추가한 행은 146행이다. 의료 문맥 보류를 해제하거나 이러한 표시를 사람 검토 완료로 바꾸지 않았다.
