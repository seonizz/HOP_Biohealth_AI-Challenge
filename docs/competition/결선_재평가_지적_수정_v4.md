# 재평가 v3 대응 수정 기록

기준일: **2026-10-15, Asia/Seoul**. 기준 커밋 `31b6b3f`, 현재 프롬프트 `relationship-v3.8-safety-source-selection`.

[강화 재평가 v3](결선_적대적_재평가_v3.md)의 장문 출력 계약, 후속 답변 출처, 불완전 로그 검증을 보완했다. 이 문서는 수정 기록이며 재채점이 아니다. 이전 58/90점과 평가 원문·실패 기록은 보존한다. 처리시간·속도는 채점하지 않는다. 기술 상세를 서비스 화면에 추가하지 않는 [사용자 지정 원칙](../../app/docs/UI_CONTENT_POLICY.md)을 유지했다.

## 변경

| 재평가 관측 | 변경 | 검증 범위 |
|---|---|---|
| 허용 10,000자 원문을 안전 분석 출력에 복사하다 2,400토큰 한도 초과 | 모델은 문항 단위 근거 ID만 선택. 서버가 해당 문항의 원문·직접 입력·후속 답변 전체를 복원하고 검증 | 출력 예산과 입력 상한을 늘리거나 원문을 자르지 않음. 초기·일반 수정·후반 수정에서 동일 계약 |
| 포함 문자열인 후속 답변이 후보에서 생략되고 입력의 출처가 평탄화 | 포함 관계로 원문을 삭제하지 않음. 모델 입력·검색 문서에 답변 출처와 실제 후속 질문을 보존 | 동일 문자열이어도 후속 답변은 별도 출처. 짧고 상충하는 답변의 의미는 여전히 모델·사람 검토 대상 |
| 연결된 요청 없는 retry wait만으로 verified=true | 사건 연결·generation·시도 순서·종료 상태를 검사하고 누락·빈 trace를 미검증 처리 | 실행별 검사 후 합산. 전체 generation 유실을 증명했다고 표시하지 않음 |

안전 ID는 사람·문항·원문·출처·질문에 결합한다. 잘못된 ID, 정정 전 ID, 검색 밖 ID, 중복 ID와 기존 quote 형식은 새 모델 출력으로 허용하지 않는다. 선택한 문항의 후속 원문을 빠뜨리는 선택지는 없다. 복원한 인용의 현재 출처를 다시 확인한 뒤 분석 검토·가이드 검토에 전달한다. 최종 기록에는 기존 전체 `safety.evidence`, 선택 ID·계약 버전과 재현 가능한 대화 context가 남는다.

현재 저장 필드의 `text/custom`은 후속 답변을 병합한 값일 수 있으므로 이를 최초 발화라고 표시하지 않는다. 입력은 `answer_snapshot`과 `follow_up`, 필드 이름·질문·전체 텍스트를 구분한다. 같은 snapshot 내부의 완전히 같은 텍스트만 별칭으로 묶는다. 저장용 인용의 완전일치 문자열은 합칠 수 있지만 출처별 구성은 모델 입력·검색·기록 context에 보존한다.

**서버는 근거를 복원할 뿐 `urgent`의 의미 판단을 바꾸지 않는다.** 후속 답변이 있다는 이유로 위험을 낮추거나, 위험 단어가 있다는 이유로 높이지 않는다. 재평가의 짧은 후속 답변 사례는 기대 불일치와 확정된 의미 오류를 구분한 기존 판단을 유지한다.

10,000자 현재 위험의 분석 출력은 **572토큰**, 안전 선택 JSON은 **66자**였다. 서버 복원 뒤 안전 인용은 **10,000자 전체**와 일치했다. 분석·가이드 검토와 긴급 행동 계약을 거친 최종 결과다. HTTP·DB·브라우저까지 거친 전체 웹 E2E는 아니다.

같은 길이의 위험 부정 사례는 세 응답 모두 출력 한도 안에서 끝났지만 동일한 `strengths` 항목을 두 번 생성해 기존 중복 해석 검증에서 거절됐다. 원시 출력의 `urgent:false`는 승인된 분석 결과가 아니므로 안전 판정 통과로 세지 않는다. 이 실패는 별도 생성 품질 한계로 남기며 서버가 중복을 삭제해 승인하거나 검증을 완화하지 않았다.
짧은 후속 답변 사례에서는 기본 답변과 후속 답변을 모두 안전 근거로 복원했지만 최종 위험 판정은 기대 false와 달리 true였다. 8개 모델 요청의 성공은 사례 통과가 아니다. 후속 문장이 대상·시점·철회 이유를 명시하지 않는다는 기존 재평가의 한계를 유지하며, 의미 판정 문제가 해결됐다고 기록하지 않는다. 이번 출처 보존 변경의 인과적 효과도 이 한 실행만으로 주장하지 않는다.

네 실행은 같은 앱·평가 코드 해시와 요청 모델 `gemma4:12b`를 사용했다. 모드가 다른 실행을 묶어 정확도를 산출하지 않는다. 실제 가중치 로딩 확인은 false, 독립 사람 검토는 pending이다. 원시 합성 응답·실패는 Git 제외 `runtime/adversarial-fixes-v4/`에 보존한다.

## 로그 검증의 뜻

`attempt_count_verified:true`는 **받은 trace의 사건 구조와 연결**을 확인했다는 뜻으로 한정한다. `attempt_count_scope=validated_trace_events`, `trace_completeness_verified:false`를 함께 기록한다. 요청 없는 대기·서로 다른 생성의 연결·누락된 시도·완료 후 재시도·미완료 대기·누락/빈 trace가 있으면 정확한 요청 수는 `null`이다. 다른 실행의 사건으로 이를 메우지 않는다. 같은 이벤트의 반복 전달은 한 번 집계한다.

외부 완료 기록 없이 생성 호출 전체의 유실 여부를 확인할 수는 없다. 기존 원시 실행과 당시 집계는 소급해서 고치지 않으며 [동반 근거 JSON](결선_재평가_지적_수정_v4_근거.json)에 이번 검사·코드·실행 파일의 해시를 남긴다.

## 남은 범위

- ID 선택은 안전 원문 재출력 요구를 제거한다. 전체 누적 입력의 문맥 한도와 다른 생성 필드의 출력 한도까지 없애지는 않는다. 한도를 넘으면 원문을 줄여 승인하지 않고 실패를 보존한다.
- 출처 일치와 모델 검토 통과는 가이드의 의미 정확성·임상 효과를 인증하지 않는다. 장문 부정 사례의 반복된 중복 해석으로 인한 생성 실패는 남아 있다. 합성 사례를 전체 오탐률이나 안전성으로 일반화하지 않는다.
- 최종 31B checkpoint·adapter의 실제 로딩과 동일 조합의 웹 흐름, 학습 전후·단순 프롬프트 비교, 독립 사람 평가·실사용 관찰은 미완료다.
- 서비스 화면과 PPT는 변경하지 않았다. 발표 기준본은 v3.6.2 근거를 보존한 자료이며 이번 결과가 반영된 덱으로 표시하지 않는다.
