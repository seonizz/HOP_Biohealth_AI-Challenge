# 학습데이터 가중 집중도 개선·적대적 재검증 v11

검증 시각: **2026-10-17 00:03 KST**. 검증 대상은 v9의 주변인·앱 후보 419행과 v10의 실제 토큰 장부다. 사용자가 **“419행 모두 보존하고 가중 정책 적용 — 원행 지표는 함께 공개”**를 선택한 범위를 따른다. 원문 없는 집계만 이 문서에 기록한다.

**선택한 가중 정책에서 남은 정규화 HHI 1항목·CV 5항목 악화를 해소했다.** train의 주변인 3과업에도 정책을 적용했고, 419행·정답 17,220토큰 및 과업×split별 정답 총량을 정확히 보존했다. 실제 토크나이저로 재인코딩한 결과는 v10과 일치하며 출력 8,192 예산과 실제 시퀀스 4,096 이하 조건을 전부 통과했다.

**원행의 HHI·CV는 변하지 않는다.** 원문과 행 수, 그룹, 길이가 동일하므로 원행 지표의 6개 악화는 그대로 공개한다. 개선한 것은 가중 손실 목적함수의 토큰 질량과 보조 집계다. 기본 validation은 무가중으로 유지한다. 가중 입력 질량 감소를 실제 입력 토큰·연산량 절감으로 계산하지 않는다.

## 2. 적용한 가중 정책과 실제 소비 경로

그룹은 원래 `과업 × split × source_group_id`를 그대로 사용한다. 그룹 내 모든 파생 행에는 같은 양수 가중치를 부여한다. `P_g`는 그룹 입력 토큰 합, `T_g`는 정답 토큰 합, `G`는 그룹 수, `T`는 해당 과업·split의 정답 총량이다.

```text
A = T / Σ_g(T_g / P_g)
입력 균형 성분: u_g = A / P_g
정답 균형 성분: v_g = T / (G × T_g)

주변인 train:      w_g = (u_g + v_g) / 2
주변인 validation: w_g = u_g
앱 두 과업:        w_g = 1
```

각 성분에서 `Σ_g w_g T_g = T`이므로 혼합 후에도 정답 총량은 정확히 같다. **395개 주변인 행에는 비단위 가중치, 앱 24행에는 1**을 적용했다. 범위는 **0.581151–5.013606**이다. 0·음수·NaN·bool·실수 분수 항·기약분수가 아닌 표기는 거절한다. Fraction으로 계산하고 조건을 판정하며, 보고서 표시 때만 반올림한다. 입력 총량 비증가나 모든 집중도 개선은 일반 정리가 아니므로 실제 입력마다 다시 검사하고 실패하면 게시하지 않는다.

기존 stage-1 trainer는 사용자 가중치를 읽지 않는다. 그래서 행에 무시될 필드를 넣는 대신 [가중 정책 로더](../../data/counseling_pipeline/supporter_group_weighting.py)의 `prepare_view()`와 [별도 손실 소비기](../../data/counseling_pipeline/supporter_weighted_loss.py)를 추가했다. 원본 JSONL·기존 trainer·v9/v10은 그대로다. 기존 trainer에 원래 JSONL만 넣는 실행은 v11 정책 적용 실행이 아니다.

소비기는 한 과업의 train 전체에 대해 `Z=Σ_i(w_i n_i)=원래 정답 총량`, 계획된 누적 window 수를 `K`로 고정한다. 각 행의 마지막 정답 평균 CE `ℓ_i`에 **`K × w_i × n_i / Z`**를 곱해 `.backward()`를 호출한다. 마지막 부분 window에서도 같은 분모를 유지한다. 매 window에서 다시 가중합으로 나누면 1행 window에서 가중치가 상쇄되므로 사용하지 않는다. token ID·label·순서 원문에 가중치를 섞지 않는다.

같은 파라미터에서 모든 window 기울기의 평균이 전체 가중 목적함수 기울기와 같음을 NumPy CE·해석 기울기·유한차분으로 검증했다. 실제 옵티마이저 변경·clipping·학습 궤적 동등성까지 뜻하지 않는다. optimizer·window 진행·중단/재개는 호출자가 소유하며, 이 helper만으로 전체 학습 완료를 선언하지 않는다. Torch 역전파나 31B 학습은 실행하지 않았다.

## 3. 남았던 6개 항목: 원행과 가중 지표 병행 공개

| 비교 항목 | 지표 | 기존 v2 원행 | v10 = v11 원행 | v11 가중 |
|---|---|---:|---:|---:|
| 주변인 다음 응답 · validation · 입력 | 정규화 HHI | 0.000192 | 0.006600 | **0.000000** |
| 주변인 다음 응답 · validation · 입력 | CV | 0.027720 | 0.324951 | **0.000000** |
| 문장 기능 · validation · 입력 | CV | 0.362394 | 0.374733 | **0.000000** |
| 근거 span · 전체 · 정답 | CV | 0.303192 | 0.308243 | **0.125120** |
| 근거 span · validation · 입력 | CV | 0.201469 | 0.358262 | **0.000000** |
| 근거 span · validation · 정답 | CV | 0.200921 | 0.292610 | **0.109444** |

표의 가중 validation은 **개발 중 설계한 보조 집계**다. 원래 무가중 validation을 대체하거나 독립 test로 승격하지 않는다. `CV² = G×HHI−1`, `정규화 HHI = CV²/(G−1)`이므로 고정 그룹 수에서 이 셋은 연결된 수치다. **54개 조건 통과를 54개의 독립적인 품질 증거로 합산하지 않는다.**

전체 확인 범위는 주변인 3과업 × train/validation/전체 × 입력/정답 × HHI/정규화 HHI/CV², 총 54조건이다. 모두 `min(v2, v10)` 이하이며 모두 v10보다 엄격히 낮다. 앱 2과업의 같은 36조건은 원래와 동일하다. 신규 데이터 때문에 그룹 수가 달라지는 비교에서는 raw HHI만으로 균형을 판단하지 않았다.

## 5. 주변인 목적·기존 대표·원문·맥락·분할

기존 v2의 20대화·140파생행, v9의 신규 24대화·255파생행, 앱 12맥락·24정답쌍을 전부 보존했다. 주변인 **44대화·72응답·395파생행**이며, 문장과 span을 독립 사람·상담으로 세지 않는다. 원상담 v8의 상담·후기 대표·보류·원문·정답 시점까지 전체 맥락도 기존 파일과 anchor 해시가 그대로다. 학습 데이터나 후기를 교체하지 않았다.

원래 group/root/split, 파일·행 위치, episode 계보, message 문자열, 원문 해시, 마지막 정답 손실 마스크를 확인한다. 소비 전에는 장부 해시뿐 아니라 **419행 전체를 실제 원천 행에서 다시 파생한 ID·group/root/cohort와 대조**한다. source inventory와 맞지 않는 삭제·추가·복제, 그룹 재명명, split 이동, task/file 혼입은 거절한다. train↔validation root/group 중복 0과 기존 분할을 유지한다.

관계·행동·coverage tag·safety scope의 **579개 비어 있지 않은 과업/split 범주 셀**은 모두 양수 영향량으로 남았다. 같은 태그가 여러 행에 나타나므로 이 수는 독립 사례 수가 아니다. 사용자 관점의 지원, 거절 존중, 한계·자기돌봄, 모름·정정·전언, 종료의 기존 정답과 annotation은 그대로다. 앱의 관찰·reported 기억 입력·JSON 구조도 그대로이고 기존 내용 결속 AI 검토를 보존했다. 이번 가중치 변경을 새로운 의미 검토로 세지 않는다.
