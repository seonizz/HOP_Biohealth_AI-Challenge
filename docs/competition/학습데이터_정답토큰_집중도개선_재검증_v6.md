# 정답 토큰 집중도 개선 대안 비교와 재검증 v6

기준일: **2026-10-16, Asia/Seoul**. [v5 구성](/Users/chihun/Documents/ChatGPT/HOP-Final/docs/competition/학습데이터_4096_대안비교와_집중도완화_재검증_v5.md)에서 남은 정답 토큰 집중도 악화를 대상으로 한다. 과거 원천·코드·v3/v4/v5 산출물은 그대로 보존하며, 별도 v6 후보의 선택을 검증한다. 모델 성능·크기·학습 진행률·처리시간은 [사용자 지정 평가 범위](/Users/chihun/Documents/ChatGPT/HOP-Final/docs/competition/05_평가범위와_학습데이터_기준.md)에 따라 채점하지 않는다.

**결과: 기존 상담·선택 구간·후기 대표와 split별 정답 토큰 총량을 유지한 쌍 교체를 적용했다. 기존 악화 7지표를 해소했고, 전체 18개 정답 토큰 지표가 v5와 이전 기준 모두 이하임을 실제 파일로 검증했다.** 원문·새 정답까지의 전체 맥락·원래 분할 검사도 통과했다. 짧은 validation 부족, 일부 입력 접두부 집중도 악화, 의미 동등성·사람 검토는 남은 제한이다.

## 1. 원인과 성공 조건

v5는 출처 그룹별 **행 수**의 상위 5·10그룹 점유율과 HHI를 제어했다. 하지만 정답 한 행의 길이는 서로 다르므로 행 분산이 정답 토큰 분산을 보장하지 않았다. 여기서 토큰 집중도는 그룹별 관측 정답 토큰 합을 전체 정답 토큰 합으로 나눈 값이다. 최대 출력 예약 8,192를 각 정답의 실제 길이로 세지 않는다.

짧은 후보는 v3, 긴 맥락 허용 후보는 v4와 비교했을 때 v5의 정답 토큰 집중도 **18지표 중 7지표**가 악화했다.

|---|---|---:|---:|
| 짧은 train | 상위 5그룹 | 8.62% | 9.67% |
| 짧은 train | 상위 10그룹 | 15.95% | 16.96% |
| 짧은 validation | 상위 10그룹 | 70.78% | 71.87% |
| 짧은 전체 | 상위 5그룹 | 7.81% | 8.73% |
| 짧은 전체 | 상위 10그룹 | 14.46% | 15.31% |
| 긴 맥락 train | 상위 5그룹 | 9.42% | 9.71% |
| 긴 맥락 전체 | 상위 5그룹 | 8.44% | 8.67% |

[기준 비교 근거](/Users/chihun/Documents/ChatGPT/HOP-Final/runtime/data-composition-token-balance-20261016/baseline-comparison.json). 반올림한 표는 설명용이며 선택·통과 판정에는 정수 토큰 합과 정확한 분수를 사용한다.

개선 조건은 train·validation·전체 각각의 상위 5·10그룹 비중과 `HHI=Σ(그룹 정답 토큰 합/전체 정답 토큰 합)²`가 **v5와 이전 기준 모두보다 커지지 않는 것**이다. 기존에 좋아졌던 지표를 다시 악화시키면서 7개만 고치지 않는다. 행 수 기준 집중도, 모든 기존 상담·후기 대표, 원문·전체 이전 맥락·원래 분할은 별도 보존 조건으로 둔다.

출력 한도와 예약은 **8,192**, 기록된 입력 한도는 **65,536**, 합산 한도는 **69,632**, 따라서 유효 입력 한도는 **61,440**이다. 짧은 후보의 **4,096 이하**는 입력 접두부와 관측 정답을 합친 길이다. 실제 서버 설정 변경이나 새 토크나이저·모델 실행을 뜻하지 않는다.

## 2. 비교하는 대안과 보존 범위

| 대안 | 개선 방식 | 비용·제약 |
|---|---|---|
| 그룹별 행 상한을 더 낮춤 | 선택 정답 수를 줄임 | 긴 정답이 남으면 토큰 점유율은 오를 수 있다. 후기 대표나 유일한 상담 대표를 제거할 위험이 있다. |
| 전기 행을 추가해 분모를 키움 | 비집중 그룹의 토큰량을 늘림 | 전기 편중·행 수·반복 접두부·그룹 행 집중도를 함께 다시 검토해야 한다. |
| 그룹별 손실 가중치 | 같은 데이터에 다른 가중치를 부여 | 원시 정답 토큰 집중도는 그대로다. 가중된 목적함수의 변화는 실제 학습 소비 경로 검증과 구분해야 한다. |
| v5 선택행 안에서 동일 셀 대표 교체 | 원래 선택 범위를 유지 | v5에는 상담×구간당 1행뿐이어서 같은 셀의 대체 행이 없다. |
| 원천의 적격 전기 대표를 같은 셀에서 교체 | 상담·구간·행 수를 그대로 두고 정답 길이 분산을 바꿈 | 정답 시점과 정답 내용은 달라진다. 선택한 새 정답까지의 전체 원래 맥락을 검사해야 한다. |
| 같은 split에서 토큰량이 상쇄되는 대표 쌍 교체 | 큰 그룹에서 줄인 토큰량만큼 작은 그룹에서 늘림 | 적격 원문으로 정확한 토큰량 쌍을 만들 수 있는지 확인해야 한다. 총량을 줄여 비율만 개선하는 것을 피할 수 있다. |

후기 대표의 ID는 고정한다. 같은 상담×구간을 유지한다는 것은 정확히 같은 정답 순번·문장·prefix 길이를 유지한다는 뜻이 아니다. 원문을 잘라 길이를 맞추거나 다른 상담의 문장을 섞지 않고, 새로 선택한 원천 행 전체를 그대로 사용하는 범위에서 비교한다. 위치 구간은 원상담 내 정답 끝 순번의 사분위이며 임상 단계나 의미상 동등성을 보증하지 않는다.

같은 셀의 새 대표를 선택하면 v5의 **행 ID 부분집합** 조건은 바뀔 수 있다. 이를 숨기지 않고 원천 적격 풀, 보존한 셀 집합, 바뀐 전기 대표, 고정한 후기 대표를 각각 대조한다. 이전 v5 파일의 행을 수정하거나 삭제하는 방식은 아니다.

## 3. 적용 정책과 통과 판정

v5에서 출발해 같은 프로파일·같은 split의 서로 다른 두 그룹을 선택한다. 현재 그룹 정답 토큰 합이 `a>b`일 때 큰 그룹의 전기 대표를 같은 셀의 **d토큰 짧은 원행**, 작은 그룹의 전기 대표를 같은 셀의 **d토큰 긴 원행**으로 함께 바꾼다. `d`는 양의 정수이며 `2d≤a−b`를 만족해야 한다. 문장을 잘라 d를 만드는 것이 아니라, 실제 원행 길이 차이가 정확히 맞는 쌍만 사용한다.

각 쌍은 총량 `T`를 보존하고 그룹 질량을 균등한 쪽으로 이동시킨다. 그룹 제곱합 변화는 `−2d(a−b−d)<0`이다. 따라서 해당 split과 전체의 HHI는 감소하고 상위 5·10그룹 비중은 증가하지 않는다. 다른 split은 변하지 않는다. **그룹별 현재 합**을 매번 다시 계산하며, 한 행만 바꾼 중간 상태나 다른 split 사이의 상쇄는 허용하지 않는다.

합격선은 지표별 `min(v5, 이전 기준)`이다. 정확한 분수로 `Σ max(0, 현재 지표/합격선−1)²`를 계산하고, 이 값이 엄밀히 감소하는 쌍만 적용한다. train·validation·전체의 9개 지표가 모두 합격한 최초 지점에서 멈춘다. 다음 세부 규칙도 고정한다.

- 큰 그룹 후보는 현재 split과 전체의 상위 10그룹 합집합으로 제한한다. 순위 동률은 `정답 토큰 합 내림차순, 그룹 ID 오름차순`으로 결정한다.
- 같은 그룹 쌍에서는 가능한 d를 정렬하고, 그 쌍의 최선 점수에 도달하는 가장 작은 d를 고른다.
- 최종 동률은 점수, 최초 v5 대비 추가 변경 대표 수, d, 현재 대표 대비 정규화한 정답 순번 거리, 고정 seed 순서로 결정한다.
- 후기 ID·선택 셀·행 수·그룹별 구간 수·상담·원래 split·기존 보류는 고정한다. 해를 찾지 못하면 실패하며 제약을 자동 완화하지 않는다.

이 방식은 가능한 해 하나를 재현하는 결정적 경로다. **전역 최소 교체 수·최적 의미 보존**을 증명하지 않는다. 상위 10그룹 제한, 같은 d의 2행 쌍, 점수가 같은 중간 이동을 허용하지 않는 조건 때문에 가능한 다른 해를 놓칠 수 있다. [독립 설계 검토](/Users/chihun/Documents/ChatGPT/HOP-Final/runtime/data-composition-token-balance-20261016/audit/design_review.md)에 수학적 전제와 반례를 기록했다.

## 4. 실제 v6 산출물의 정답 토큰 집중도

아래는 시뮬레이션이 아닌 새 JSONL 파일을 읽어 원행 해시와 대조한 집계다. 각 칸은 **이전 기준 → v5 → v6** 순서이며, 짧은 후보의 이전 기준은 v3, 긴 후보는 v4다. 정답 토큰 지표 **18개 모두** 두 기준 이하이고, v5 대비 **17개 개선·1개 동일**이다. 같은 것은 긴 후보 validation의 상위 10그룹 점유율이다.

| 후보 | split | 상위 5그룹 | 상위 10그룹 | HHI |
|---|---|---:|---:|---:|
| 짧은 | train | 8.6219% → 9.6700% → 8.6064% | 15.9503% → 16.9638% → 15.8928% | 0.00865702 → 0.00858685 → 0.00833263 |
| 짧은 | validation | 43.8576% → 40.3074% → 39.7905% | 70.7787% → 71.8678% → 70.6979% | 0.06547701 → 0.06256751 → 0.06175903 |
| 짧은 | all | 7.8142% → 8.7251% → 7.7654% | 14.4561% → 15.3062% → 14.3398% | 0.00768563 → 0.00758812 → 0.00737345 |
| 긴 맥락 | train | 9.4161% → 9.7069% → 9.3752% | 16.6176% → 16.3396% → 16.0010% | 0.00859229 → 0.00849988 → 0.00841247 |
| 긴 맥락 | validation | 50.2288% → 49.2606% → 48.1930% | 75.5196% → 74.4925% → 74.4925% | 0.07302819 → 0.07191444 → 0.07023763 |

1. **짧은 후보의 전반부 편중은 남는다.** 전기 행 95.25%, 후기 50셀이다. 짧은 validation 후기는 2셀·마지막 ¼은 0행이다. 적격 후기 원행은 전체 134행/50셀, validation 3행/2셀뿐이다. 기존 원문·전체 맥락·4,096 제한을 함께 유지한 마지막 ¼ validation의 적격 행은 없으며, 긴 적격 풀의 해당 구간 636행도 최단 전체 길이 6,932·접두부 6,833이다. 이번에는 이 구조적 부족을 해결했다고 주장하지 않는다.
2. **입력 접두부 집중도까지 개선한 것은 아니다.** v5 대비 해당 18지표 중 6개가 소폭 악화했다. 짧은 전체 HHI는 0.00660403→0.00660708, 긴 전체 HHI는 0.00698765→0.00698811, 긴 validation 상위 10그룹 비중은 73.3347%→73.3688%다. 입력 총량도 1,809·2,589토큰 늘었다. 새 정답까지의 전체 원래 맥락을 보존한 결과이며 이번 정답 토큰 합격 조건과 구분한다.
3. **구간 보존은 의미 보존을 대신하지 않는다.** 교체한 전기 정답의 정확한 순번은 모두 달라졌다. 새 대표의 절차성 문맥 플래그는 짧은 후보 **387→388행**, 긴 후보 **1,198행 유지**다. 원래 상담사 응답 SFT 과업을 유지했으며 주변인 지원 정답으로 변환한 것이 아니다. 원래 허용·검토 정책은 유지했지만 목적 적합성·답변 유형·상담 효과·사람 승인까지 입증한 것은 아니다. 의미 비교를 마친 검토본이 필요한 상태다.
