# 결선 시연·질의응답 검증팩 v2

2026-10-16. [v10 적대적 평가](결선_적대적_재평가_v10.md)와 [감점 대응 재검증](결선_v10_감점대응_재검증_v1.md)에 연결하는 발표 준비본이다. [v1](결선_실전_검증팩_v1.md)의 과거 검사 수·쿠키 상실 후 삭제 설명은 당시 기록으로 보존한다. 현재 발표 파일은 [실전발표 v5](../../presentation/final/말씨_결선_실전발표_v5.pptx)다.

## 준비 기준

첨부 운영계획(안)의 결선 **발표 15분·Q&A 5분**을 준비 기준으로 삼는다. 본선의 10분 발표와 구분한다. 최신 제출 형식·기한·과제 범위 승인과 실제 리허설·제출 여부는 [외부 증거 목록](결선_외부증거_확인목록_v1.md)에 대기로 남긴다. 모델 자체·처리시간은 내부 채점에서 제외하며 현장 발표·Q&A 10점은 관찰 전 유보한다.

| 발표 구간 | 계획 배분 | 전달할 내용 |
|---|---:|---|
| 1~2장 | 1분 30초 | 누구의 어떤 대화 준비를 돕는가. 합성 상황임을 명시 |
| 3~5장 | 3분 30초 | 입력→근거→첫마디→기록. 실제 UI 예시와 실제 효용의 구분 |
| 6~7장 | 2분 | 메모·체크시트와 구현 계약 비교, 모름+직접입력·주체·원문 보존 |
| 8~10장 | 3분 | 원상담과 주변인 과업, 자료별 분모·개발 노출·사람 미승인 |
| 11~12장 | 2분 | 재현된 검사 범위, 삭제 키·보유기간·운영 증거의 한계 |
| 13~14장 | 1분 | 실제 사람·기관 검증 계획과 마무리 |
| 화면 전환·여유 | 2분 | 실패 시 검증된 캡처와 해당 근거로 전환 |

합계는 15분이다. 이는 **발표 계획**이며 실제 수행 시간·전달력·질의응답 평가 결과가 아니다.

## 현재 상태를 설명하는 답변

| 질문 | 근거에 맞는 답변 | 확인할 자료 |
|---|---|---|
| 테스트가 많으면 상담 효과도 검증된 것인가? | 입력·출처·저장·삭제 등의 프로그램 계약을 검사한 결과다. 실제 이용자와 사람의 의미 검토는 별도로 필요하다. | v10 검사 범위, 이번 재검증 기록 |
| 주변인 서비스에 맞는 정답이 있는가? | 합성 20에피소드·24응답의 실험 초안이 있다. AI 검토 기록 20건이며 사람·전문가 승인 정답은 아직 0건이다. | 구성 v2, 사람 검토 인계 묶음 |
| 2,365행과 1,023행을 더해도 되는가? | v2의 1,023행은 2,365행의 부분집합이다. 기존 17,236행과도 다른 구성이다. 별도 v3의 두 프로파일 역시 독립 사례로 합산하지 않는다. | 데이터와 연구, 구성 v2·v3 |
| 후반부 편중이 해결됐는가? | v2 전체 구성과 짧은 부분집합의 결과가 다르다. v3는 짧은 풀에서 먼저 선택해 누락되던 후기 셀을 보존하지만, 허용 풀 자체의 마지막 ¼과 validation 부족은 남는다. | v3 실제 완료본 검증 결과 |
| 검증 자료를 독립 test로 제시할 수 있는가? | 개발·선별·검토에 노출된 후보다. 원래 split을 보존했다는 사실이 비노출 독립 평가를 뜻하지 않는다. | 평가 이력·분할·원천 연결 |
| Git의 원문 업로드가 전부 해결됐는가? | 현재 인덱스의 정한 완전 일치 범위에서는 0파일이다. G2 인코딩·G3 중복 키 우회는 차단했다. 과거 커밋·원격 공개·이미지·짧거나 변형된 발췌까지 확인한 결과는 아니다. | v10 29개 검사·13조건·독립 5조건 |
| 쿠키가 없어도 지울 수 있는가? | 접근 가능한 동안 별도로 보관한 삭제 키로 해당 소유자의 대화를 지울 수 있다. 키가 없으면 기본 보유기간 정책이 적용된다. 조회·복구 권한을 주는 키는 아니다. | API·DATA_RETENTION 계약 |
| 백업에서도 곧바로 지워지는가? | 앱 SQL 행 삭제가 백업·WAL·외부 사본 삭제를 입증하지 않는다. 실제 운영 정책·적용·만료·복원 후 삭제 재적용 증거가 필요하다. | 운영 증거 점검과 외부 증거 목록 |
| 실제 사용자나 기관이 선택했는가? | 실제 참여자 0명이고 기관 채택 근거는 아직 없다. 현재 비교는 같은 합성 과업의 로컬 메모·체크시트와 앱 계약 비교다. | 현장 검증 프로토콜 |

질문에 답할 때 검증된 버전과 분모를 먼저 밝힌다. 실제 모델 연구에 대한 질문이 오면 해당 연구 기록만 설명하고 내부의 모델·시간 제외 기준을 주최 측 기준이라고 말하지 않는다.

## 시연 확인표

새 합성 상황만 쓰고 실제 상담 원문·실명·키를 화면에 노출하지 않는다. 기존 합성 시연 입력을 쓰되 원천 상담에서 복사하지 않는다. 다음 표는 실행 전 **대기**이며 체크된 실사용 결과가 아니다.

| 순서 | 조작 | 기대 동작·실패 기록 |
|---:|---|---|
| 1 | 새 시연 세션에서 상황 입력 | 그분의 관찰과 나의 부담을 분리. 다른 소유자 기록이 보이면 실패 |
| 2 | 모름 선택과 직접입력, 질문 중 정정 | 사실을 근거에 보존하고 정정 뒤 후속 상태를 재구성. 과거 근거가 남으면 실패 |
| 3 | 안내의 원문과 모르는 부분 확인 | 입력한 주체·문장과 연결. 합성 UI 예시는 모델 생성 성공이나 실제 효용으로 제시하지 않음 |
| 4 | 완료·미완료 기록 재조회와 개별 삭제 | 취소는 보존, 성공은 삭제, 다른 소유자는 보존 |
| 5 | 별도 삭제 키 발급 후 접근 상실 상태에서 삭제 | 키는 관람객에게 보여주지 않고 조회·복구 수단으로 설명하지 않음. 발급하지 않은 키를 소급 복원하지 않음 |
| 6 | 전체 삭제 뒤 새 대화 시작 | 삭제 전 늦은 응답이 기록·화면을 복원하지 않고 새 대화는 정상 생성 |

실패하면 마지막 성공 단계와 실패 단계를 남기고 버전·검증 방식이 적힌 캡처로 전환한다. 모델 응답·대기시간은 이 내부 재검증의 점수 항목으로 쓰지 않는다. 실제 리허설은 관찰자·버전·성공/실패·Q&A 기록이 생겼을 때만 완료로 바꾼다.
