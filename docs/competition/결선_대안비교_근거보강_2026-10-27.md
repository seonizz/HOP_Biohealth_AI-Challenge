# 결선 대안 비교의 근거 보강

확인일: **2026-10-27, Asia/Seoul**. 기존 [합성 대안 비교](결선_대안비교와_현장검증_v1.md)를 보완한다. 실제 공개 대안 3종의 공식 문서 조사, 현재 앱 함수의 합성 계약 검사, 앞으로 사람이 실행할 비교 절차를 구분한다. 실제 참여자는 **0명**이며 선호·채택·임상 효과·모델 품질·처리시간을 평가하지 않았다.

## 1. 실제 존재하는 대안과 공정한 비교 범위

| 대안과 공식 근거 | 확인한 기능·내용 | 말씨와 비교할 때 인정할 점 | 이번에 확인하지 않은 것 |
|---|---|---|---|
| [NHS Every Mind Matters: Helping others](https://www.nhs.uk/every-mind-matters/supporting-others/helping-others/) | 걱정을 전하며 대화 시작하기, 열린 질문과 경청, 대화 강요하지 않기, 지원자의 자기 돌봄을 안내 | 첫마디 준비와 지원자 돌봄은 이미 공개 가이드가 다루는 과업이다 | 실제 이용자의 이해·선호, NHS 서비스 전체 기능, 말씨 대비 결과 |
| [Mind: Helping someone else](https://www.mind.org.uk/information-support/helping-someone-else/), [친구·가족을 위한 안내](https://www.mind.org.uk/information-support/types-of-mental-health-problems/mental-health-problems-introduction/for-friends-family/) | 원하는 도움을 묻기, 비판하지 않고 듣기, 지원자의 경계와 자기 돌봄을 안내. 허브는 대화 교육도 소개 | 주변인과 자기 돌봄을 함께 다룬다는 사실만으로 독창성을 주장할 수 없다 | 교육 과정 수강·사용자 실험·국내 적용 검증. 상세 안내에는 2017년 발행·현재 검토 중 표시가 있다 |
| [Obsidian: Internal links](https://obsidian.md/help/links), [Manage notes](https://obsidian.md/help/manage-notes) | 노트와 특정 블록 연결, 파일 이름 변경 시 링크 갱신, 파일 삭제 및 휴지통/영구삭제 설정 | 원문 연결과 기록 관리는 기존 노트 도구에서도 가능하다. 작성자가 정확히 대조하고 갱신할 수 있다 | Obsidian UI 실행, 설치 버전·플러그인 조합, 전체 기능·사용자 결과, 저장 매체·백업의 물리 삭제 |

공식 문서에서 찾지 못한 기능은 **미확인**이다. 기능이 없다고 판정하거나 제품 전체의 열등함으로 바꾸지 않는다. NHS·Mind는 영국의 안내 자료이고 Obsidian은 범용 노트 도구다. 국내 주변인 지원 서비스의 대표 경쟁군 전체를 조사한 결과는 아니다. 위 내용은 각 제공자의 공식 문서를 확인한 범위이며 임상 권고의 국내 타당성을 새로 인증한 것이 아니다.

공식 문서의 확인 위치·짧은 근거 구절·조회일은 [출처 장부](../../runtime/finals-remediation-20261027/comparison/official-sources.json)에 남겼다. 전체 웹페이지를 재배포하거나 공식 자료를 그대로 복제하지 않았다.

## 2. 이번에 설명할 수 있는 차이

말씨의 확인된 차이는 **입력 주체·질문·원문·미응답 상태를 연결한 검사와 정정 시 상태 갱신을 사용 흐름에 묶었다는 것**이다. 이 차이가 사용자의 이해나 선택을 개선하는지는 아직 관찰하지 않았다.

| 과업 | 가이드와 수동 정리 도구로 가능한 방법 | 이번 말씨 코드 관측 | 결과 해석 |
|---|---|---|---|
| 현재 원문 찾기 | 원문을 적고 문단·블록 출처를 연결 | 현재 문장 인용 수락, 검색 자료에 원문 보존 | 수동으로도 가능하며 앱의 자동 연결을 확인 |
| 주체 구분 | 관찰한 사실과 나의 감정을 별도 항목에 기록 | 지원자 문장을 지원자 근거로 수락, 당사자 근거로 제시하면 거절 | 주체 검사 계약. 사람의 관점 이해도는 미관찰 |
| 모름과 직접 입력 | 모르는 부분과 직접 들은 사실을 각각 기록 | 모름 선택 유지, 직접입력 문장 보존 | 불확실성 처리 계약. 사용성 우위는 미관찰 |
| 모름만 있는 답변 | 사실을 덧붙이지 않고 모름을 유지 | 사실 근거로 거절, 검색 근거에 넣지 않음 | 새 사실을 만들지 않는 상태 경계 |
| 정정 | 이전 문장을 폐기 표시하고 관련 메모 갱신 | 이전 질문 복원, 파생 상태 무효화, 새 인용 수락·옛 인용 거절 | 현재 입력에 대한 근거 계약. DB 이력은 별도 검사 |
| 미응답·생략·거절 | 상태를 표시하고 사실과 구분 | `not_asked`, `auto_skipped`, `skipped`, `refused`를 사실·검색 근거로 승격하지 않음 | 문맥상 질문 생략 자체는 정상 기능으로 유지 |
| 없는 원문 인용 | 작성자가 원문을 대조해 제외 | 입력하지 않은 문장 인용 거절 | 이 검사만으로 생성 내용 전체의 적절성을 판단하지 않음 |
| 삭제 범위 | 관리 중인 문서·첨부·사본의 범위를 확인해 삭제 | 실제 삭제 메서드가 두 SQL에 같은 소유자 인자를 전달 | **SQL 호출 계약만** 관측. DB 삭제·복원·물리 삭제와 구분 |

수동 대안은 올바르게 작성하면 위 내용을 표현할 수 있다. 자동 검사기가 없거나 이번 조사에서 실행하지 않은 것을 오답·실패로 세지 않는다. **수동 대안의 성공률, 말씨 대비 향상률, 사용자 선택률은 계산하지 않는다.**

## 3. 새 실행 결과와 재현

새로 작성한 합성 상황 **8개**, 계약 조건 **23개**가 통과했다. 이 수치는 23명의 사람이나 23개의 독립 대화가 아니다. 8개 상황 중 하나에 미응답 상태 네 종류가 포함된다. 비교 도구 자체의 회귀 **5개**도 통과했다. 검증을 무조건 수락하는 대체 함수, 혼합 직접입력 누락, 소유자 없는 삭제, 예상 밖 예외를 넣으면 정상 통과로 표시하지 않는 반례를 포함한다.

```sh
node --test tools/test_final_workflow_comparison.mjs
node --check tools/final_workflow_comparison.mjs
node --check tools/test_final_workflow_comparison.mjs
node tools/final_workflow_comparison.mjs \
  --output runtime/finals-remediation-20261027/comparison/result.json
```

[비교 코드](../../tools/final_workflow_comparison.mjs) · [회귀 검사](../../tools/test_final_workflow_comparison.mjs) · [실행 결과](../../runtime/finals-remediation-20261027/comparison/result.json)

실행 대상 앱 소스 지문은 `cdae2055900c5611865c59ec94db3b8568f2fbf51d1ff464535031c454ebfad5`다. 실행 전후 지문이 같아야 결과를 발행한다. 실제 앱 함수 `validateEvidence`, `normalizeAnswerField`, `sourceDocuments`, `backIntake`, `buildContext`, `Store.removeConversations`를 호출했다. 마지막 함수의 query 기록기는 DB가 아니며 서버·트랜잭션·CASCADE·백업 동작을 흉내 내 검증한 것으로 세지 않는다.

같은 작업의 [별도 합성 복원 리허설](../../runtime/finals-remediation-20261027/operations/restore-rehearsal.json)은 일회용 PostgreSQL에서 11조건을 관측했다. 비교 도구의 23조건과 독립 사용자 수로 합산하지 않는다. 실제 운영 승인·생산 백업·물리 삭제의 검증으로 확대하지 않는다.

## 4. 실제 사용자 비교를 실행할 준비

[진행용 워크시트](../../runtime/finals-remediation-20261027/comparison/human-comparison-worksheet.md)와 [빈 관찰 기록 양식](../../runtime/finals-remediation-20261027/comparison/participant-template.json)을 준비했다. 상태는 `not_started`이며 실제 참여 결과는 들어 있지 않다.

- **비교 조건:** 같은 한국어 과업 안내를 제공하고, A는 구조화 메모, B는 말씨를 사용한다. 공식 대안 조사는 설계 근거다. Obsidian 브랜드 사용성 비교라고 발표하려면 실제 앱 버전과 실행을 별도로 기록해야 한다.
- **순서:** A→B와 B→A를 번갈아 배정하고 합성 사례의 X/Y 순서도 교차한다. 사례의 동등성은 사람 검토 전까지 가정으로 남긴다. 반복 학습과 관찰자 도움을 기록한다.
- **판정:** 과업마다 완료·도움 필요·미완료·중단을 남긴다. 각 과업의 근거 위치를 설명하는지 관찰하고, 기록되지 않은 추측을 관찰 사실로 채우지 않는다.
- **동등한 기준:** 수동 대안에서 정확히 작성한 결과도 완료다. 같은 안내를 양쪽에 제공한다. 언어 이해·도구 친숙도를 기록한다. 속도·모델 생성 품질·임상 효과는 결과 지표에 넣지 않는다.
- **분모:** 사람 수, 조건별 시행 수, 과업 수, 반복 실행 수를 분리한다. 실패·중단·제외 사유를 포함하고 자동화 실행은 참여자로 세지 않는다.

이 보완으로 확보한 것은 실제 대안의 공식 설명, 넓어진 합성 계약 검증, 실행 가능한 관찰 절차다. **사용자 선호·실제 효용·시장 독창성·기관 도입 증거는 여전히 미확인**이다. 그에 해당하는 점수를 자동으로 회복하지 않는다.

## 5. 대회 공개 안내의 추가 확인

2026-10-27의 제한된 공개 검색에서 [상명대 사업단의 9월 7일 모집 안내](https://biohealth.smu.ac.kr/biohealth/board/notice.do?articleNo=768429&mode=view)와 [대학이 호스팅한 참가신청서](https://www.smu.ac.kr/flexer/out/_attach/file/2026/09/nEcQwmkAbwOkEfGCblVG.hwp.files/Sections1.html)를 확인했다. 신청서에는 심리 질환 판별 데이터 1,661건의 선택란과 팀 소개·프로젝트 수행 전략 최대 10쪽 조건이 있다. **모집 단계 양식의 분량 조건이며 결선 발표자료 규격으로 전용하지 않는다.**

안내가 연결한 [대전대 주최 측 공지](https://www.dju.ac.kr/biohealth/na/ntt/selectNttInfo.do?nttSn=553741&bbsId=2328&mi=5702)와 공지목록은 사용한 웹 도구에서 접근되지 않았다. 조회한 범위에서 최신 결선 제출 규격이나 말씨의 과제 범위 승인은 확인하지 못했다. 상업적 입찰 재게시 자료를 참가팀의 심사 조건으로 사용하지 않았다.
