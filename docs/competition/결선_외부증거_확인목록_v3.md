## 검토에 사용할 버전과 준비물

1. [인계 절차](../../data/docs/support_agent/사람검토_인계_절차_v1.md)의 **`human_review_v10_20261016_r5`**를 사용한다. manifest SHA-256은 **`738ab873a2a1b3f569827619bb666857395be1b678dbd5d84df080ac4b112691`**다. 이전 `_r3`·중간 `_r4`와 검토 5파일은 같으며, 입력 26파일의 코드·리소스 연결만 갱신했다. 28단위 모두 대기이며 학습·운영·독립 test 승인은 false다.
2. `blind_inputs.jsonl`의 접두부 독립 판단을 먼저 별도 기록하고, 이후 `target_packets.jsonl` 응답·근거와 [검토 계약](../../data/docs/support_agent/결선_데이터_검토계약_2026-10-16.md)을 대조한다. 검토 큐 391개·작성 요청 6개와 전문 보류 4개를 새 사람 승인 수로 합산하지 않는다.
3. [v6 구성 보고서](학습데이터_정답토큰_집중도개선_재검증_v6.md)의 manifest **`961217d542ad3a9e39d47b06c81e35cb8538b03ddb9e1f0129562b55372c549f`**에 연결된 교체 대표를 검토한다. 원행·새 정답까지의 전체 맥락·split 보존과 의미 동등성은 구분한다. 정답 집중도 18지표 통과가 목적 적합성·임상 타당성·사용 허가를 대신하지 않는다.
4. [현장 검증 계획](결선_대안비교와_현장검증_v1.md)의 사전 과업·기록표를 사용하고 도움·실패·중단 전체를 분모에 남긴다. 기관의 도입 의향과 실제 도입도 구분한다.
5. [운영 증거 계약](../../app/docs/DATA_RETENTION.md)에 실제 승인·설정·사본 위치·복원 기록을 연결한다. 구조 검사 통과는 신원·사실·물리 삭제 인증이 아니다. 지원 형식의 기록과 PDF·이미지 원본을 대조한 근거를 보관한다.

인계는 여전히 같은 해석된 절대 입력 경로·바이트·구현을 요구한다. 다른 작업 루트로 옮길 때는 새 버전과 단위 내용 해시를 대조해야 한다. 검증은 관측한 바이트의 스냅샷 판정이며 반환 후 파일 불변이나 사람 신원·자격을 보증하지 않는다.

## 기록·보관

실제 기록마다 `항목 ID / 상태 / 대상 버전·내용 SHA-256 / 수행일·시간대 / 확인된 수행자·역할 / 판정·사유 / 근거 파일·SHA-256 / 남은 조건`을 남긴다. **준비 → 실제 수행 → 검토 → 승인 → 운영 적용**을 구분하고, 수정된 내용에 이전 판단을 자동 재사용하지 않는다. 사람 판단은 별도 접근 통제된 이력으로 남기며 초기 pending 묶음을 승인 상태로 덮어쓰지 않는다.

상담 원문·학습 행·실제 신원·개별 검토 내용은 Git 제외 경로에서 접근을 통제한다. 공개 문서는 원문 없는 집계·버전·방법·한계만 담는다. 이번 작업은 사람·기관에 연락하거나 실제 검토·승인·회신을 만들어 내지 않았다. 최종 공지·개별 통보도 새로 확인하지 않았다.
