# 4,096 이하 구성 대안 비교와 그룹 집중도 완화 재검증 v5

기준일: **2026-10-16, Asia/Seoul**. 비교 기준은 [v3의 전체 4,096 이하 후보](/Users/chihun/Documents/ChatGPT/HOP-Final/docs/competition/학습데이터_4096_후반부_구성_재검증_v3.md)와 [v4의 긴 맥락 보강본](/Users/chihun/Documents/ChatGPT/HOP-Final/docs/competition/학습데이터_전후반균형과_validation_보완_재검증_v4.md)이다. 과거 파일을 고쳐 비율을 바꾸지 않고, 원래 행을 그대로 선택한 별도 후보를 만든다.

**판정: 원문·전체 맥락·분할과 모든 기존 상담·후기 대표의 보존 검사는 통과했다.** 짧은 후보의 전기 비중은 **97.13%→95.25%**, 그룹 최대는 **16→10행**으로 낮췄다. 긴 맥락 후보도 그룹 최대 **25→19행**으로 낮췄다. 다만 짧은 validation 후기 **2셀·마지막 ¼ 0행**은 해결되지 않았고, 정답 토큰 기준 상위 그룹 비중 일부는 높아졌다. 따라서 **구성 일부 개선**으로 판정하며 의미 품질·독립 평가·사람 검토 완료로 확대하지 않는다.

## 1. 이번 선택에서 보존하는 것

우선순위는 원문·전체 과거 접두부·정답 좌표·원래 train/validation·기존 내용 보류, 후기 대표, 출처와 상담의 범위다. 전기 비율만 맞추기 위해 기존 상담 대부분을 새 후보에서 제외하는 방안은 우선하지 않는다. 이미 선택한 전기 시점 일부를 새 후보에서 제외하는 것과 원천 상담의 발화·맥락을 잘라내는 것은 구분한다. 원천·v3·v4 산출물은 그대로 보존한다.

평가 예산은 기록된 RTX 4090×2 환경의 입력 65,536·출력 4,096·합산 69,632를 기준으로 출력 한도와 예약을 요청 조건 **8,192**로 평가한다. 합산 69,632를 유지하므로 유효 입력은 **61,440**이다. 실제 서버를 변경하거나 새 모델·토크나이저·학습을 실행한 결과는 아니다.

여기서 **4,096 이하**는 입력 접두부와 관측 정답을 합친 전체 학습 행 길이다. 위치는 `정답 끝의 0-based 순번 / max(1, 원상담 발화 수−1)`이며 후기 `>0.5`, 마지막 ¼ `>0.75`를 뜻한다. 의미상 상담 종료나 임상적 단계라는 뜻은 아니다.

## 2. 구조적으로 만들 수 없는 사례와 선택 정책

고정 원천과 보류·분할에서 짧은 validation 후기는 **3행·2개 상담×구간**, 마지막 ¼은 **0행**이다. 기존 후보는 후기 2셀을 이미 포함했다. 마지막 ¼의 적격 validation 636행은 전체 길이 최솟값이 **6,932**여서 원문 전체 맥락을 유지한 채 4,096에 넣을 수 없다.

따라서 같은 상담·정답을 복제하거나, train을 validation으로 옮기거나, 앞부분을 절단·요약해 짧은 후기 사례 수가 늘었다고 표시하지 않는다. 실제로 짧은 마지막 ¼ validation을 늘리려면 처음부터 짧고 완결된 추가 원상담이 필요하다. 이번 작업에서 그러한 새 원상담을 만들거나 확보한 것으로 처리하지 않는다.

전체 짧은 풀에는 서로 다른 후기 원문 **134행**이 있지만, 상담×위치 구간은 **50셀**이다. 이번 구성은 기존처럼 **한 상담×구간당 대표 1행**을 선택한다. 이는 원문 보존에서 자동으로 따라오는 불변 조건이 아니라 반복 노출과 사례별 비중을 제어하는 선택 정책이다. 같은 셀에서 다른 원문 정답을 더 선택하는 방법은 동일 행 복제와 다르지만, 새 후기 셀이나 마지막 ¼ validation을 만들지는 않는다.

그룹 집중도는 최대 행 수뿐 아니라 상위 5·10그룹 점유율과 `HHI = Σ(그룹 행 수 / 전체 행 수)²`로 비교한다. HHI가 작을수록 행이 더 고르게 분산돼 있다. `1/HHI`는 이 비율의 유효 그룹 수이며, 사람 수나 독립 사례 수가 아니다. train·validation·전체를 각각 확인하고, 행 집중도와 정답 토큰 집중도를 구분한다.

## 4. 적용한 선택 규칙

1. 기존 v3와 v4를 원천·기존 보류·길이·이력 근거로 재검증한다. 원문 45,974행의 장부를 유지하고 새 선택 결과는 `selection_v5`에 별도로 기록한다.
2. 각 후보에서 기존 후기 대표를 전부 남긴다. 전기에는 각 출처 그룹×구간마다 1행을 두되, 기존 후기에서 빠진 상담을 더 많이 포함하는 조합을 우선한다. 동률은 고정 seed와 행 ID 해시로 정한다.
3. 짧은 후보에는 아직 없는 기존 상담을 한 번씩 추가한다. 그룹 상한은 `max(10, 필수 core 행 수)`이고, train·validation·전체 각각의 상위 5·10그룹 비중과 HHI가 기준보다 커지지 않아야 한다. 실제 core 1,052행은 9조건을 바로 만족해 추가 채움이 0행이다. 실제 그룹 상한 예외도 없다.
4. 긴 후보는 `max(16, 필수 core 행 수)`까지 전기 후보를 채운다. 빠진 상담, 적은 그룹 행 수, 적은 그룹×구간 행 수, 고정 해시 순서로 우선한다. 마지막에 모든 기존 상담·그룹 구간·후기 대표와 9개 집중도 조건을 다시 검사한다. 이번 6그룹의 상한 예외는 숨기지 않고 장부와 집계에 기록한다.
5. 후기 validation 패널은 한 셀당 1행으로 두고, 같은 셀에 짧은 대표가 있으면 먼저 사용한다. 따라서 짧은 후기 2행과 긴 후기 103행을 길이별로 구분한다. 패널은 두 후보와 겹치며 독립 test나 105개의 신규 사례가 아니다.

모든 선택은 기존 후보의 원래 JSONL 행을 바이트 그대로 복사한다. 미래 발화나 다른 상담의 문장을 붙이지 않고, 선택된 정답 이전의 전체 접두부를 유지한다. 전기 시점 수는 줄지만 원천 파일이나 과거 후보에서는 삭제하지 않는다. 조건을 만족할 수 없는 입력은 실패 처리하며 비율·상한을 조용히 완화하지 않는다.

## 5. 검증 범위

기존과 같은 원문 바이트 대조와 원 발화 재구성으로 전체 과거 접두부·화자 순서·정답 좌표·정수 손실 마스크·미래 발화 제외를 검사한다. 저장된 길이는 원문·adapter·템플릿·감사 장부 해시에 결속하며 새 토크나이저를 실행한 것처럼 표현하지 않는다.

새 선택은 기존 후보 내부의 부분집합인지, 후기 대표와 모든 기존 상담·그룹×구간이 보존되는지, 전기 시점만 제외됐는지 검증한다. 집중도 조건은 반올림한 수치가 아니라 정확한 분수로 비교한다. 고정된 선택 순서를 재현하고 첫 통과점 또는 core 자체 통과를 구분한다. 이를 전역 최적화의 증명으로 표현하지 않는다.

이번 평가도 [사용자 지정 평가 범위](/Users/chihun/Documents/ChatGPT/HOP-Final/docs/competition/05_평가범위와_학습데이터_기준.md)를 따른다. 모델 성능·크기·학습 진행률·처리시간을 채점하지 않으며, 행 선택과 구조 검사를 의미·임상 적합성이나 사람 검토의 대체 근거로 삼지 않는다.
