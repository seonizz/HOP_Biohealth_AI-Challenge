# 같은 과업의 대안 비교와 현장 검증

2026-10-16. v7의 C1을 보완한다. 아래는 **로컬 합성 과업과 구현 계약의 비교**이며, 실제 이용자·기관 채택이나 특정 상용 서비스의 우열을 입증한 결과가 아니다. 모델 품질·처리시간은 평가하지 않는다.

## 같은 합성 과업으로 비교한 범위

`SYNTH-C1-01`: 친구가 약속을 미루고 연락을 줄인 상황에서, 이용자는 부담을 줄까 걱정하며 대화를 준비한다. 원천 상담을 복사하지 않았다. 비구조화 텍스트 메모와 ‘관찰한 사실 / 나의 부담 / 모르는 부분’ 체크시트를 실제 로컬 파일로 작성하고, 같은 문장을 말씨 근거 검증 함수에 넣었다.

| 과업 | 자유서술 텍스트 메모 | 관점 구분 체크시트 | 말씨의 현재 구현 |
|---|---|---|---|
| 관찰과 내 부담을 나눠 적기 | 작성자가 구분해 작성 | 별도 항목에 수동 기재 | 질문과 저장 필드의 주체를 구분 |
| 사실·모름을 함께 기록 | 둘 다 적을 수 있음 | 둘 다 적을 수 있음 | 모름 선택은 남기고 직접입력도 근거로 사용 |
| 안내의 원문 찾기 | 작성자가 수동 대조 | 작성자가 수동 대조 | 질문 ID·주체·원문 일치 검사 |
| 잘못된 주체/없는 문장 인용 | 이 로컬 텍스트 파일에는 검사기가 없음 | 이 로컬 체크시트에는 검사기가 없음 | 다른 주체 문장과 미입력 사실 인용을 거절 |
| 정정 후 후속 상태 처리 | 관련 내용을 직접 고침 | 관련 항목을 직접 고침 | 질문 중 되돌리기로 이후 상태·근거 재구성 |
| 저장·삭제 범위 | 해당 파일과 사본을 직접 관리 | 해당 파일과 사본을 직접 관리 | 소유자별 조회·삭제·삭제 키·보유기간 집행 |

**이번에 관측한 결과:** 같은 입력의 정상 원문 인용은 수락, 이용자 부담을 당사자 관찰로 바꾼 인용은 거절, 입력하지 않은 사실 인용은 거절했다. [재현 코드](../../runtime/remediation-v7/compare-workflow.mjs) · [3사례 결과와 기준 파일 해시](../../runtime/remediation-v7/workflow-comparison.json). A1와 O1의 실제 브라우저 경계는 [별도 결과](../../runtime/remediation-v7/browser-regression.json)로 연결한다.

이 비교로 말할 수 있는 차이는 **수동 대조하던 출처·정정·기록 계약을 앱이 검사한다**는 점이다. 단순 메모의 적은 입력 부담, 사용자가 양식을 바꿀 자유도 역시 장점이다. 말씨의 질문 부담과 결과 이해도는 사람 관찰이 필요하다. 메모 사용자도 출처를 정확하게 관리할 수 있으므로 ‘메모는 틀린다’고 일반화하지 않는다. 특정 상용 앱의 전체 기능, 시장의 독창성, 선택 선호를 조사했다는 주장도 하지 않는다.

## 사람 관찰에 바로 사용할 사전 기록표

합성 사례는 위와 같은 내용으로 고정하고, 양식 순서에 따른 영향을 줄이기 위해 메모→말씨와 말씨→메모를 번갈아 배정한다. 동일 참여자의 반복 과업은 학습 영향을 기록한다. 각 과업은 **완료 / 도움 필요 / 미완료 / 중단**으로 남긴다. 실제로 모집하거나 관찰한 사람은 현재 0명이다. 에이전트·브라우저 자동 실행은 참여자로 세지 않는다.

| 과업 | 사전 성공 기준 | 관찰 중 남길 기록 |
|---|---|---|
| 상황과 나의 부담 입력 | 두 주체를 구분해 입력 | 주체 혼동·도움을 준 내용 |
| ‘모름 + 직접입력’ | 모르는 부분과 알고 있는 사실을 설명 | 사실이 사라졌다고 오해했는지 |
| 정정 | 앞선 관찰을 바꾸고 후속 상태를 설명 | 이후 답변 재입력 부담·옛 근거 오인 |
| 안내와 원문 연결 | 안내의 근거와 확인되지 않은 부분을 각각 지목 | 추측을 사실·진단으로 이해하는지 |
| 첫마디 사용 | 원하는 문장을 고르고 복사 상태 확인 | 선택 이유·복사 성공 오인 |
| 삭제 | 미완료 삭제와 키 삭제의 범위를 설명 | 다른 세션 자료까지 자동 삭제된다고 오해하는지 |

참여자별 기록 필드: 익명 번호, 동의·중단 의사, 도구 순서, 앱 소스 해시, 합성 사례 버전, 과업별 상태, 도움을 준 지점, 이해한 내용, 혼동·개선 요청, 직접 관측과 관찰자 해석의 구분. 원천 상담·실제 지인의 사연·개인 신원은 관찰표에 넣지 않는다. 성공률은 분모와 미완료·중단 수를 함께 제시하며 시간은 성공 기준으로 사용하지 않는다.

## 기관 도입 확인표

아래는 요청할 내용이 구체화된 확인표이며 기관의 답변이나 계약을 대체하지 않는다. 이 작업에서 기관에 연락하거나 메시지를 보내지 않았다.

| 확인할 조건 | 남겨야 할 근거 | 현재 상태 |
|---|---|---|
| 누구의 어느 업무에 쓰는가 | 이용 대상·사용 장소·직전/직후 절차를 적은 회신 또는 면담 기록 | 미확인 |
| 운영 주체와 담당자는 누구인가 | 운영·접근 상실·삭제·장애 대응 담당자 지정 | 미확정 |
| 어떤 데이터를 보관하는가 | 입력·모델 전송·서비스 DB·백업·내보내기별 보유 범위 | 개발 구현 외 미확정 |
| 어떤 비용·설치 조건을 수용하는가 | 사용 빈도·기기·설치·교육·예산 조건 | 미확인 |
| 도움과 실패를 어떻게 판단하는가 | 위 과업 기준과 중단/문의 조건에 대한 합의 | 미확인 |
| 대회 과제와 변경 범위가 승인됐는가 | 신청서·멘토 기록·주최 측 최종 안내와 기능 연결 | 미확인 |

완료는 회신·관찰·승인 근거가 생긴 항목에만 표시한다. 현재 C1은 **구현 차이의 재현 근거 보강**, 실수요·비교 우위·기관 도입은 **검증 대기**다.
