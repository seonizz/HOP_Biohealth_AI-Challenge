## 1. 우선순위별 수정과 회귀 근거

### P1 · HR3 — 동일 바이트의 pin·파싱·성공 결과

[인계 검증기](../../data/counseling_pipeline/human_review_bundle.py)는 manifest의 바이트를 캡처하고, 그 바이트로 SHA-256·중복 키를 거절하는 JSON 파싱·계획 비교·반환 해시를 계산한다. 파일을 읽기 전후의 장치·inode·파일 형식·크기·mtime/ctime과, 산출물 검사 뒤의 manifest 내용·식별자를 대조한다. 재읽은 다른 해시를 성공 결과에 섞지 않는다.

| 결정적 변경 순서 | 수정 전 | 수정 후 |
|---|---|---|
| 첫 전체 읽기 직후 줄바꿈 추가 | 성공하며 다른 해시 반환 | 변경 거절 |
| 첫 전체 읽기 직후 같은 바이트의 다른 파일로 교체 | 변경 탐지 없이 성공 | 파일 식별자 변경 거절 |
| 마지막 검토 payload를 읽은 뒤 manifest 변경 | 성공하며 다른 해시 반환 | 마지막 안정성 검사에서 거절 |
| 공백 표현만 다른 JSON을 미리 저장하고 그 바이트의 pin 제시 | 정상 대조 | 성공·반환 해시가 제시한 pin과 일치 |

회귀의 작성자 동작은 실제 임시 파일 바이트/파일을 바꾸며 반드시 실행됐는지 검사한다. 원래 스트리밍 해시와 새 캡처 읽기에 모두 적용되는 일정으로 수정 전 실패와 수정 후 통과를 확인했다. v12의 과거 `source.sha_file` hook이 더는 호출되지 않는다는 사실만으로 해결을 주장하지 않는다. 각 실패 뒤 원본을 복원하면 정상 pin 검증이 다시 통과한다.

검증은 관측한 스냅샷의 일치와 중간 변경 탐지를 보장한다. 운영체제 파일 잠금이나 마지막 확인·반환 이후의 불변을 보장하지 않는다. 의미가 같은 JSON을 정규화 비교하더라도 외부 pin은 실제 바이트에 적용한다.

### P2 · HR4 — 실제 판단 의존성과 리소스 결속

인계 입력에 **`source_selection_audit.py`·패키지 `__init__.py`·질문은행**을 추가했다. 중복 검사에 쓰는 정규화 구현뿐 아니라 패키지 초기화와 질문 탐지 리소스도 현재 사례의 일치 여부와 무관하게 고정한다. 직접·간접 호출을 확인했으며 현재 범위는 프로젝트 코드 7파일과 질문은행을 포함한 총 26입력이다. 실행 중 메모리나 Python 표준 라이브러리까지 인증한다고 표현하지 않는다.

제품 코드를 복사한 격리 경로와 합성 fixture만 사용해 정상 묶음을 만들었다. 같은 경로에서 정규화 함수, 패키지 초기화, 일치하지 않는 질문 항목을 각각 바꾸면 기존 pin의 CLI가 **2·`invalid`·빈 stderr**로 거절한다. 정상·각 원상복원 대조는 0·pin 일치 성공이며, 모든 경우 기존 묶음의 바이트와 미승인 상태를 보존했다.

v12의 HR4 원래 재현 스크립트도 바이트 그대로 복사해 다시 실행했다. 정상 생성·변경 거절·복원 검증 **3조건 통과**이며, 원래 정상으로 통과하던 정규화 변경은 이제 거절된다. [동일 스크립트 재실행](../../runtime/remediation-v12/original-replay/implementation-binding-results.json)

### 함께 수정한 질문은행 오류 계약

독립 검토에서 질문은행의 `questions`에 잘못된 컨테이너나 객체가 아닌 행이 들어가면 `AttributeError` traceback을 내는 인접 결함을 재현했다. 승인 성공이나 실제 상담 내용 노출 사례는 아니지만, 일반 오류 JSON·비공개 경로 비노출 계약을 위반했다.

입구에서 버전의 비어 있지 않은 문자열, 질문 목록과 각 객체, 탐지에 읽는 문자열 필드의 타입을 검사하도록 수정했다. 광범위한 `AttributeError` 무시를 추가하지 않았다. **12가지 형태**의 `main()` 경계 회귀와 독립 검토자의 동일 격리 CLI 공격 4조건·정상/복원 5조건을 통과했다. 기존 인계본을 바꾸지 않고 `invalid`·종료 2·승인 0·학습 false·빈 stderr를 유지한다.

## 3. 데이터 v6까지 포함한 새 검증

즉시 수정 대상이었던 HR3·HR4와 질문은행 오류 계약은 해결됐다. 후속 로컬 개선 **ARCH1**은 논리 입력 ID와 경로를 분리해 다른 루트에서도 같은 내용을 검증하는 기능이다. 현재 동일 해석 경로 제약을 명시한 **WATCH**로 유지하며 이번 범위에서 형식을 바꾸지 않았다. v6의 입력 집중도 개선은 전체 맥락·후기 보존과 새 정답의 의미 검토를 함께 고려해야 하므로 수치만 다시 맞추지 않았다.

[외부 증거 확인 목록 v3](결선_외부증거_확인목록_v3.md)에 담당 역할·실제 기록·보관 조건을 별도로 정리했다. 준비 도구의 통과를 사람 승인·기관 도입으로 기록하지 않는다. 이번에 최신 외부 공지·개별 통보를 새로 조회하거나 사람·기관에 연락하지 않았다.

## 6. 검토·보존·검증 한계

독립 검토자는 HR3·HR4와 질문은행 결함의 수정 후 재현·정상/복원·중복 키·심볼릭 링크·파일 교체 경계를 확인했다. 최종 열린 제품 결함은 0건이다. 코드 검토의 **COMMENT**는 LSP가 `tsconfig` 부재로 생략되고 ast-grep을 사용할 수 없었던 정적 진단 한계를 남긴 판정이며, 타입 검사 통과나 무결점 보증이 아니다. [독립 검토](../../runtime/remediation-v12/code-review/review-summary.json)

현재 Git 인덱스 **1,142파일**의 지원 형식에서 상담 원문 완전 일치 0·파싱 오류 0을 확인했다. **80자 이상 완전 일치 단위** 검사이며 미지원 바이너리 62파일·짧거나 변형된 발췌·이미지·과거 커밋·원격 공개까지 안전하다고 증명하지 않는다. 수정·추가 공개 파일도 별도 원문·크기·링크 검사를 했다.

시작 시 기존 비제외 **1,198파일**을 고정했다. 이 작업의 변경은 인계 도구·회귀·절차, 현재 안내 2문서, 새 결과·외부 증거 문서 2개다. 별도 v7 추가는 위 관측 기록으로 구분했다. 원천·학습 후보·v6 제품 코드/검사/산출물·이전 인계본·발표본·과거 평가서와 사용자 HEAD·인덱스·스테이징을 보존했다. 새 `_r4`·`_r5`는 Git 제외 로컬 경로이며 커밋·푸시·배포하지 않았다.
