# PR #3 직전 프런트 복원

> 현재 배포 화면은 이 원본 소스를 디자인 참조로 사용하면서 `frontend/src/`의 말씨 v2 API 클라이언트를 실행합니다. 아래 내용은 원본 복원 당시의 기록입니다. 원본 30문항·`localStorage`·`mockModel`은 `frontend/js/`에 참조용으로 남아 있고 배포 빌드에는 포함되지 않습니다. 실제 질문과 기록은 백엔드 24문항 계약과 PostgreSQL을 사용합니다.

## 기준과 원인

- 복원 기준: 최이람 프런트의 칼럼 추가까지 포함한 `ea9c607519ce2269d8da14a166a7b99d7e287233`.
- 통합 커밋: `2620dedffb872b77a44f903cc1d96f85681cdc42`, PR #3의 main 병합 `d3397b48bb398b6f41107ec7e12dc8283a6a9d07`.
- 통합 때 프런트는 `frontend/src/`로 재작성되고, 기존 백엔드 24문항 카탈로그(`backend/docs/MALSSI_QUESTIONNAIRE_V1.json`)를 렌더링하도록 변경되었습니다. 카탈로그는 통합 이전 백엔드에 이미 있던 내용으로, 원본 프런트 30문항의 순서를 그대로 옮긴 것이 아닙니다.
- B가 수치 JSON을 평가하고 A가 답변하는 구조는 `backend/docs/DUAL_MODEL_PIPELINE_DESIGN.md`에 설계로 존재하며, PR #3의 실행 경로에 연결된 기능이 아닙니다. 이 설계가 원본 30문항이나 화면을 바꿔야 할 기술적 이유는 확인되지 않았습니다.
- 사용자 확인: PR #3 직전 프런트를 기준으로 질문·결과 가이드·위기 신호·칼럼 및 원래 동작 전부 복원.

## 변경 범위

원본 `index.html`, `js/**`, `css/**`, `assets/**`의 36개 파일을 내용 변경 없이 `frontend/`로 복사했습니다. `frontend-original-manifest.json`에 원본 경로와 SHA-256을 기록했습니다. 브라우저에 제공하는 파일은 이 원본 집합입니다.

빌드는 원본의 일반 스크립트, 7개 CSS, 마스코트를 포함하도록 변경했습니다. Caddy CSP에는 원래 글꼴을 제공하는 Google Fonts의 스타일·폰트 출처를 추가했습니다. API와 DB는 변경하지 않았습니다. 통합 UI의 `frontend/src/`는 이력 확인용으로 남아 있지만 빌드에서 제외됩니다.

복원되는 동작:

- 30문항 정의와 원래 순서, 필수 8개(`want`, `rel`, `mood`, `dur`, `freq`, `concern`, `need`, `moment`), 건너뛰기를 제공하지 않는 네/아니요 문항 4개.
- 연락이 드물 때 질문 문구 변경, 변화가 없을 때 기간·빈도 생략, 선택에 따른 후속 문항, 문항별 최대 1회 보충 질문.
- 직전 질문으로 돌아갈 때 답변·태그·대화 기록 복원.
- localStorage `malssi.records.v1` 기록 저장·조회·삭제. 기존 같은 출처의 기록을 덮어쓰거나 이관하지 않음.
- 원본 mockModel 맥락 추출·임시 점수·결과 가이드 및 돌봄 문구.
- 대화 중 즉시 보류하지 않고 대화 완료 후 결과 화면에 원본 안전 카드 표시. 원본 코드상 카드 위치는 결과 카드 묶음의 맨 위이며, 대화가 끝난 뒤 표시됩니다.
- 칼럼 목록·분류·요약·원문 링크, 마스코트와 화면 구성.

## 실행 범위

화면은 실제 서버 모델이나 PostgreSQL에 답변을 전송하지 않습니다. 원본의 임시 점수를 실제 정신건강 평가 결과로 간주하지 않습니다. B→A 모델 설계, API 동작, 기존 DB 데이터는 이번 복원 범위에서 그대로 보존합니다.

원본 CSS는 1920×1080 화면을 기준으로 작성되어 390px 모바일 화면에서 상단 버튼의 줄바꿈과 가로 넘침이 있습니다. 원본의 한계도 그대로 보존하며 이번 복원에서 반응형 디자인을 새로 수정하지 않습니다. 모바일에서는 기본 대화 진행과 버튼 동작만 확인합니다.

서버의 정적 프런트 경로만 새 복원본으로 교체하면 됩니다. 변경 전 웹 설정과 배포 디렉터리를 유지해 이전 통합 화면으로 되돌릴 수 있습니다. localStorage는 출처별로 분리되므로 기존 주소의 호스트·포트를 유지합니다.

## 검증 결과 (2026-10-09)

- JavaScript 구문 검사 통과, 단위·원본 계약 검사 7개 통과.
- 브라우저 검사 3개 통과: 위험 보기를 포함한 30문항 완주와 결과·기록·삭제, 조건부 생략과 필수 후속 질문, 칼럼·원문 링크·소개·모바일 기본 조작.
- 로컬 정적 서버와 실제 SSH 배포의 8088 포트에서 브라우저 검사를 각각 통과.
- 배포 주소에서 받은 36개 파일의 SHA-256이 원본 커밋과 모두 일치.
- 구형 `/src/app.js`와 `/css/app.css` 및 서버 비공개 파일 경로가 웹 루트에서 제공되지 않는지 확인.
- API·DB 상태 정상. 웹 프로세스만 교체했고 기존 API·보관 정리 프로세스는 재시작하지 않음.
- 검증 브라우저에서 `/api/` 요청이 발생하지 않으며 완료 기록은 localStorage에만 저장됨.
