## 중복 처리 기준

파일 내용의 SHA-256을 비교했습니다. Git·OMX·설치 의존성·Python 캐시를 제외한 원래 파일 집합에서 현재 **961개 동일 내용 그룹, 추가 사본 1,939개**를 확인했고, 그중 388개 그룹은 보관 위치에 사본을 포함합니다. [중복파일 검증 목록](중복파일_검증목록.csv)에 실제 경로와 처리 상태를 기록했습니다.

중복 내용을 무조건 제거하지 않았습니다. 학습 패키지·검증 manifest·배포본은 내부 파일이 모두 있어야 재현할 수 있고, 데이터 필드가 우연히 같은 바이트여도 서로 다른 계약의 출력일 수 있습니다. 패키지는 통째로 분리하고 현재 도구가 참조하는 평가·발표 사본은 유지했습니다. `HOP_agent/서비스_문서`와 `HOP_data/서비스_문서`의 대응 문서 13개는 모두 내용이 달라 유지했습니다. `local_api/backend_patch`도 적용·패키징에 사용하는 미커밋 변경이 있는 소스이므로 유지했습니다.

## 경로와 원문 보존

- [이동 기록](폴더정리_이동기록.json): 원래 경로, 새 경로, 분리 사유, 이동 전 SHA-256, 수정 전 원문의 위치.
- [현재 경로 분류표](전체파일_현재경로.csv): 최초 파일 7,204개의 현재 위치. 기존 분류표와 최초 복사 목록은 역사 기록으로 보존.
- [정리 전 원문](../../archive/99_%EC%A0%95%EB%A6%AC%EC%A0%84_%EC%9B%90%EB%AC%B8): 안내·문서 링크·보관 도구를 수정하기 전 원문.
- `HOP_data/deliverables`, `HOP_agent/outputs/handoff`와 배포 ZIP 2개는 기존 경로에 상대 심볼릭 링크를 남겨 도구의 참조를 유지했습니다. 실체는 보관 폴더에 한 번만 존재합니다.
- 이동한 문서의 상대 링크를 갱신하고, 과거 문서 검증 도구 3개의 기준 폴더 탐색을 새 구조에 맞췄습니다. 과거 운영·성능 주장이나 패키지 내부 manifest는 새 결과로 바꾸지 않았습니다.

복구가 필요하면 이동 기록의 `new`를 `old`로 되돌리고, 호환 링크가 있는 위치는 링크를 제거한 뒤 되돌립니다. 수정 파일은 각 `backup` 경로의 원문으로 복원할 수 있습니다.

## 검증 결과와 범위

- 이동한 1,022개 파일의 원문 SHA-256 보존 확인. 링크·도구를 수정한 파일은 정리 전 원문과 비교했습니다.
- 최초 복사 목록 7,204개 파일 모두 추적 가능. 비교 차이 7개는 Finder `.DS_Store` 4개와 Git index 3개뿐이며, 코드·데이터·패키지 원문은 일치합니다.
- 기존 심볼릭 링크 7개와 새 호환 링크 4개 정상 확인.
- 변경 문서 등의 로컬 링크 803개 검사에서 이번 이동으로 새로 깨진 링크 0개. 수정 대상 문서에 원래 있던 미해결 링크 29개는 별도 기록했습니다. 전체 과거 문서를 최신화한 작업은 아닙니다.
- 보관 검증 도구 3개 Python 구문 검사 통과.
- [검증 JSON](폴더정리_검증결과.json)의 `errors`는 빈 배열입니다.

현재 서비스 코드의 동작을 변경하지 않았으므로 앱·모델 실행 테스트는 수행하지 않았습니다. 기존 과거 운영 검증기는 당시 코드 해시를 검사하고 증거 파일을 다시 쓰므로 이번 정리에서 실행하지 않았습니다. 원격 서버와 실제 모델 상태도 재검증하지 않았습니다.
