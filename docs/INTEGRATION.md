# 통합 변경 및 API 계약

## 기준

프론트 main과 백엔드 별도 브랜치를 새 통합 폴더로 구성했습니다. 기존 작업 폴더와 서버 데이터는 변경하지 않았습니다. 첨부 명세의 예전 “설계만 작성” 범위나 SSH 실행 안내를 현재 사용자 요청 대신 실행 지시로 취급하지 않았습니다.

## 변경

| 영역 | 이전 | 통합본 |
| --- | --- | --- |
| 소스 구조 | main 루트의 정적 프론트, 별도 백엔드 브랜치 | `frontend/`, `backend/`, 루트 Compose |
| 저장 | 프론트 localStorage | 쿠키 인증 후 v2 PostgreSQL 저장 |
| 질문 | 프론트 내부 질문과 순서 | 서버 question snapshot의 문구·스키마·리비전 |
| 모델 | 프론트 규칙 점수·mock 가이드 | worker 큐 → 추출/가이드/검증 → 저장 결과 조회 |
| 위험 흐름 | 마지막 결과 카드 | 즉시 SAFETY_HOLD, 복원 후 명시 재개 |
| 개인정보 제어 | 브라우저 기록 | 동의 분리, 기억 확인/정정/잊기, 원문/프로젝트/계정 삭제 |
| 배포 | 연결되지 않은 정적 페이지와 API | 한 origin의 Caddy·API·DB·worker·retention |

## 추가 API

`GET /api/v2/projects/{id}/conversations?limit=50&cursor=<uuid>`

현재 사용자가 소유하고 만료되지 않은 프로젝트의 대화를 반환합니다. `{conversations, next_cursor}` 형식이며 항목은 `conversation_id`, `resource_revision`, `state`, `run_id`, `goal`, `created_at`을 포함합니다. 커서는 UUID 정렬에 기반합니다. 화면에서는 생성 시각으로 정렬합니다.

`GET /api/v2/conversations/{id}`에 다음 필드를 추가했습니다.

- `questionnaire_version`, `question_history`: 실제 제시했던 문항 스냅샷으로 답변과 정정 폼을 복원합니다.
- `safety_episode_id`: 보류 상태에서만 노출하여 새로고침 후에도 명시적 재개가 가능합니다.
- `latest_guidance`, `plans`: 검증된 최신 가이드와 선택한 계획을 복원합니다.

모든 읽기는 기존 소유권 검사·RLS·동의·보관 만료 검사 안에서 수행합니다. 기억/원문 삭제 후 파생 가이드가 제거되면 snapshot에서도 사라집니다. 이 계약은 `backend/openapi-v2.json`, 생성 스크립트와 TS 클라이언트에 반영했습니다.

`GET /health/service`는 API와 DB의 가동 상태를 검사합니다. `/health/ready`는 원래의 공개 카탈로그 정책 확인을 유지합니다. 서비스 health 성공을 콘텐츠 승인으로 표시하지 않습니다.

## 프론트의 상태 관리

쓰기마다 UUID를 만들고 현재 snapshot의 revision을 보냅니다. 네트워크 실패 또는 재시도 가능한 오류에서는 같은 본문과 UUID를 메모리에 유지하며 다른 쓰기를 먼저 진행하지 않습니다. 성공 응답을 받으면 최신 snapshot을 다시 읽습니다. 새로고침으로 아직 확인하지 못한 요청을 잃을 수 있으므로 전송 결과가 미확정인 경우 떠나기 안내를 띄웁니다.

토큰은 API가 설정한 HttpOnly cookie로만 사용하고 응답의 bearer token을 브라우저 저장소에 보관하지 않습니다. 대화 내용·프로젝트 ID·동의 상태는 서버에서 복원합니다. 현재 대화의 무작위 UUID만 URL fragment로 유지합니다.

가이드 요청은 202 응답의 run ID를 조회합니다. 완료 전 생성 중 문장을 노출하지 않으며, 완료·실패·취소 결과를 분리합니다. 화면 이동·로그아웃 시 폴링을 정지합니다. 기존 서버 SSE 계약도 유지하지만 이 프론트는 2초 간격 폴링을 사용합니다.

## 남은 제품 검증

원본 draft의 권리·콘텐츠 검토, 실제 모델 품질/안전 평가, 독립적인 지역별 도움 디렉터리, 대규모 부하·다중 인스턴스 운영, 공개 TLS·외부 백업 복구는 실제 운영 환경에서 결정해야 합니다. B→A 수치 평가 파이프라인은 이번 코드에서 새로 실행 기능으로 구현하지 않았습니다. 사용자 화면에는 임의 진단 점수를 표시하지 않습니다.
