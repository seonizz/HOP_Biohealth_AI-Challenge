# 말씨 프론트엔드 기능 명세서

> 기준 커밋: `b883420` (2026-10-09) · 대상: `index.html`, `css/`, `js/`, `assets/`
> 이 문서는 현재 구현된 프론트엔드 프로토타입의 기능을 정리합니다. 모델(맥락 추출·수치화·가이드 생성)은 아직 규칙 기반 목업으로 대신하고 있습니다.

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 서비스 | 우울·불안·중독을 겪는 사람의 **주변인**이 건넬 첫 마디를 준비하도록 돕는 대화형 웹 앱 |
| 흐름 | 시작 → 질문 대화(최대 30문항 + 후속 질문) → 결과 가이드 → 기록 저장 |
| 기술 | HTML·CSS·바닐라 JavaScript. 빌드 도구·외부 라이브러리 없음 (글꼴만 Google Fonts: Jua, Gowun Dodum) |
| 실행 | `index.html`을 브라우저로 열기. 일반 `<script>` 태그로 불러와 파일로 바로 열어도 동작 (스크립트 순서 변경 금지) |
| 화면 기준 | 1920×1080 한 화면 앱. 너비 900px 이하에서는 2단 배치를 1단으로 바꿈 |
| 저장 | 기록은 브라우저 `localStorage`에만 저장 (서버 전송 없음) |

## 3. 화면

### 3.1 시작 (`#start`)
- 상단: 로고, **서비스 소개**, **내 기록 (n)** (저장된 기록 수), 위기 상담 번호(109 · 1577-0199)
- 본문: 소개 문구, 3단계 안내(질문에 답하기 *약 10~15분* / 상황 정리 / 말하는 방법), **말씨와 시작하기** 버튼
- 오른쪽: 마스코트 무대(가운데 마스코트가 위아래로 움직이는 애니메이션 + 주변 마스코트 3개 + 말풍선)
- 안내: "말씨는 진단이나 치료를 대신하지 않아요. 이름 같은 개인정보는 묻지 않아요."

### 3.2 대화 (`#chat`)
- 상단: 로고, 진행 막대, 현재 단계 이름(예: "관계", "당신의 마음"), **처음으로**
- 대화창: 말씨 말풍선(마스코트 표정 + 질문 + 회색 설명 `why`), 사용자 말풍선, 입력 중 점 애니메이션
  - 후속 질문 말풍선에는 "조금 더 알려 주세요" 표시
  - 메시지가 추가되거나 크기가 바뀌면 자동으로 맨 아래로 스크롤
- 입력 상자: 질문 형식에 맞는 입력 UI (§5)

### 3.3 결과 (`#result`)
- 왼쪽: 마스코트, `호칭 · 관계 · ○○ 경향` 표시, "이렇게 마음을 건네 보세요"
- 오른쪽 카드 (위에서부터)
  1. **안전 카드** — 위기 신호가 있었을 때만 표시 (§9)
  2. **당신의 마음도 소중해요** — 주변인에 대한 공감 + 팁 1개
  3. **이렇게 시작해 보세요** — 바로 쓸 수 있는 첫 문장, **문장 복사** 버튼 (클립보드 실패 시 문장 선택)
  4. **이렇게 해 보세요 / 피하면 좋아요**
  5. **다음 단계** + "당신을 위해서도" 팁
  6. 저장 결과 안내, **내 기록 보기**, **처음부터 다시**
- 상단에 위기 상담 번호(109 · 1577-0199 · 112/119) 상시 표시

### 3.4 내 기록 (`#records`)
- 왼쪽 목록: 기록 카드(제목=호칭, 관계 · 날짜). 위기 신호가 있던 기록은 다른 마스코트 표정으로 표시
- **삭제**는 두 번 눌러야 확정 ("삭제" → "정말 삭제")
- 오른쪽 상세: 관계 · 경향 · 후속 질문 횟수, 안전 카드(해당 시), 공감, 첫 문장, 해 보세요/피하면 좋아요, 다음 단계, **대화 기록 전체** (후속 질문은 점선으로 구분)
- 기록이 없으면 빈 화면 안내
- **처음으로**, **새 대화**

### 3.5 서비스 소개 (`#about`)
- 서비스 설명, 도와드리는 방식 3가지, 학습 데이터 소개(1,661회기 등), 말씨의 약속 4가지, 대회 출품 표기
- **처음으로**, **말씨와 시작하기**

### 4.1 문항 속성

### 4.2 보기 메타
보기는 `"라벨"` 또는 `["라벨", 메타]` 형식입니다.

| 메타 | 의미 | 프론트에서 쓰는 곳 |
| --- | --- | --- |
| `d`·`a`·`x` | 우울·불안·중독 가중치 | 계산하지 않고 모델에 그대로 보냄 (목업만 사용) |
| `s`·`r`·`p` | 증상 라벨 · 위험 요인 · 보호 요인 (데이터셋 라벨) | 모델에 그대로 보냄. `s:"suicidal"`은 위기 신호 안전장치에도 사용 |
| `t` | 흐름 태그 | 질문 분기, 결과 가이드 (§11) |
| `none` | 다른 보기와 함께 고를 수 없음 | 입력 UI |
| `input` | 고르면 글 입력창이 열림 ("네 [직접 입력]") | 입력 UI |
| `g` | 묶음 이름 (자동으로 붙음) | 입력 UI |

## 5. 입력 방식 (`js/components/ChatInput.js`)

| 형식 | 동작 |
| --- | --- |
| 글 (`text`) | 입력창 + **보내기**. Enter로 보내기, Shift+Enter 줄바꿈 (한글 조합 중 Enter는 무시) |
| 하나 고르기 (`one`) | 보기를 누르면 바로 답이 됨. **직접 입력** 칸에 적고 보내기도 가능 (`noOwn`이면 칸 없음) |
| 네 [직접 입력] | `input` 보기를 누르면 글 입력창으로 바뀜. 비우고 보내면 "네"로, 적으면 "네, …"로 기록 |
| 여러 개 고르기 (`multi`) | 보기를 켜고 끈 뒤 **다 골랐어요**. 묶음이 있으면 묶음 제목 표시. 보기 목록은 화면 높이의 46%까지, 넘치면 스크롤 |
| 단독 보기 (`none`) | "없어요"류 보기를 켜면 다른 보기가 꺼지고, 다른 보기를 켜면 단독 보기가 꺼짐 |
| 직접 입력 | 하나·여러 개 고르기 문항 모두 보기에 없는 내용을 적을 수 있음 |
| **건너뛰기** | `required`·`noSkip`이 아닌 문항에 표시. 답은 "(건너뛰었어요)"로 기록되고, 후속 질문을 하지 않음 |
| **필수 확인** | `required` 문항에서 빈 글을 보내거나 아무것도 고르지 않고 "다 골랐어요"를 누르면 "이 질문은 꼭 답해 주세요…" 안내 |
| **← 이전 질문으로** | §8 |

## 6. 조사 자동 처리 (`josa`, `nm`)
- 질문 문구의 `{name}`은 호칭으로, `{name:은}`·`{name:이}`·`{name:을}`·`{name:와}`는 호칭 + 받침에 맞는 조사로 바뀝니다.
  - 예: 엄마 → 엄마는·엄마가·엄마를·엄마와 / 민준 → 민준은·민준이·민준을·민준과
- 마지막 글자가 한글이 아니면 둘 다 표시합니다 (예: Tom은(는)).
- 호칭을 건너뛰면 "그분"으로 부릅니다. 호칭은 최대 20자.

| 6번에서 "특별히 관찰된 변화가 없음"만 고르고 직접 입력도 없음 | 7번 dur, 8번 freq를 묻지 않음 |
| 27번에서 변화를 하나라도 골랐거나 직접 입력함 | 28번 cgchange_more를 물음 |
| 5번 contact = "그보다 드물게" | 6·7·8·10번을 "마지막으로 보거나 연락했을 때", "처음 알게 된 지", "보거나 전해 들었나요", "전해 들은 이야기도 괜찮아요" 문구로 바꿔 물음 |

## 8. 이전 질문으로
- 바로 **직전 질문 1개까지만** 돌아갈 수 있습니다. 돌아간 질문에서는 버튼이 다시 나오지 않습니다.
- 각 질문을 보여 주기 직전 상태(답변, 흐름 태그, 호칭, 후속 질문 횟수, 대화 기록)를 저장해 두고, 돌아가면 통째로 복원한 뒤 그 질문을 다시 묻습니다. 그 뒤에 쌓인 말풍선과 대화 기록도 지웁니다.
- 직전 질문에 후속 질문이 있었다면 함께 취소됩니다.
- 첫 질문, 후속 질문, "네" 입력창에서는 버튼이 없습니다.

## 9. 위기 신호
- 대화 중에는 흐름을 끊지 않고, **결과 화면 맨 위 안전 카드**로 안내합니다.
  - 카드 내용: "대화보다 안전이 먼저예요", 자살예방 상담전화 109(24시간), 정신건강위기 상담전화 1577-0199, 112/119
  - `role="alert"`로 화면 읽기 프로그램이 바로 읽음. 기록 상세 화면에도 같은 카드 표시
- 판단: **모델 판단(`ctx.safety`) 또는 프론트 안전장치(`safetyFlag`)** 중 하나라도 해당하면 표시
  - 안전장치: "죽고 싶다…" 보기 선택, 또는 답한 글에 "죽고 싶·사라지고 싶·없어지고 싶·자살·자해" 표현
- 위기 신호가 있으면 공감 문장과 다음 단계도 위기 상담 연락을 먼저 권하도록 바뀝니다.
- 시작·결과 화면 상단에는 위기 상담 번호가 늘 보입니다.

## 10. 후속 질문 (`FOLLOW`, `gapCheck`)
문항당 최대 1회. 건너뛴 문항은 다시 묻지 않습니다.

| 문항 | 조건 | 후속 질문 | 합치는 방식 |
| --- | --- | --- | --- |
| name | 비었거나 모호함 | 부르기 편한 호칭 하나만 정해 주세요 | 다시 비면 "그분" |
| rel | 직접 입력이 2자 미만·모호 | {name}와는 어떤 사이인가요? | 답하면 관계를 바꿈 |
| mood | 아무것도 고르지 않고 직접 입력도 짧음 | '평소와 다르다'고 느낀 순간 하나 | 직접 입력으로 추가 |
| concern | 8자 미만·모호 | 마음이 덜컥했던 장면 하나 | 답하면 바꿈 |
| feeling | 4자 미만·모호 | 가까운 마음 고르기 (속상·무서움·미안함·지침·화남) | 고른 내용으로 바꿈 |

- **마무리 전 보충 질문(`gapCheck`):** 보이는 모습을 하나도 고르거나 적지 않았고, 가장 걱정되는 부분도 비어 있으면 한 번 더 묻습니다.
- "모호함" 판단: 비었음, "(…)"로 시작, 최소 글자 수 미만, "몰라·글쎄·그냥·별로·없어" 등.
- 모델이 붙으면 이 규칙을 맥락 추출 모델의 판단으로 바꿀 예정입니다.

## 11. 모델 연결 지점 (`js/core/mockModel.js`)

프론트는 **점수를 계산하지 않고** 원래 답과 흐름 태그만 모아 보냅니다. 모델이 준비되면 `Model`의 세 함수 안만 `fetch` 호출로 바꾸면 됩니다 (주석에 예시 있음, 엔드포인트 이름은 예시).

| 함수 | 역할 | 연결할 모델 |
| --- | --- | --- |
| `Model.extractContext(payload)` | 증상·위험·보호 요인, 위기 신호 추출 | 모델 1: 맥락 추출 |
| `Model.scoreAnswers(payload, ctx)` | 우울·불안·중독 점수 | 모델 2: 수치화 |
| `Model.guide(profile)` | 결과 가이드 생성 | 가이드 생성 |

### 11.1 보내는 데이터 (`buildPayload()`)
```js
{
  name: "엄마",
  tags: ["freq_high", "goal_near", ...],          // 흐름 태그
  answers: [{
    id: "mood",
    question: "요즘 엄마에게서 보이는 모습을 모두 골라 주세요.",  // 실제로 보여 준 문구 (문구 변경 반영)
    type: "multi",                                   // text | one | multi
    freeText: true,                                  // 신호를 읽을 자유 서술 문항인지 (cue)
    text: "자주 우울하거나 가라앉아 보여요, ...",     // 화면에 기록된 답
    custom: "",                                      // 직접 입력
    skipped: false,
    selected: [{ label: "자주 우울하거나 가라앉아 보여요", meta: { d: 2, s: "depressive_mood" } }]
  }, ...]
}
```
보충 질문 답은 `id: "gap_obs"`로 함께 보냅니다.

### 11.2 받는 데이터
```js
// extractContext
{ symptoms: [...], risks: [...], protect: [...], safety: false, textSignals: [...] /* 목업 전용 */ }
// scoreAnswers
{ 우울: 0.8, 불안: 1.3, 중독: 0 }   // 0~3
// guide
{ top: "불안", script: "...", doList: [...], avoid: [...], next: "...", care: { feel: "...", tips: [...] } }
```

### 11.3 목업 규칙 (모델 대체 전 임시)
- **맥락 추출:** 고른 보기의 `s`/`r`/`p` 라벨을 모으고, 자유 서술 문항의 글(글 문항은 답, 보기 문항은 직접 입력)에서 신호어를 찾음
- **수치화:** 보기 가중치 + 신호어 가중치 합계를 우울 ÷5, 불안 ÷4, 중독 ÷5로 나누고, 최근 2주 빈도로 보정(절반 이상·거의 매일 ×1.3, 거의 없었어요 ×0.6)한 뒤 0~3으로 자름. 가장 높은 영역이 "경향"
- **가이드:**
  - 첫 문장: 경향별 시작 문장 + 전하고 싶은 말 + 3번 goal에 맞는 문장(곁에 있음·걱정·상담 권유·줄이기·화해)
  - 해 보세요: 경향별 3개 + 21번 barrier에 맞는 팁 최대 2개
  - 피하면 좋아요: 기본 2개 + 거부·부정(진단명 붙이기), 중독(감시), 화해 목적(잘잘못 따지기)
  - 공감: 24·26번 답의 감정(서운·무서움·미안함·지침), 거의 매일이면 쉼 권유, 위기 신호 시 문장 추가
  - 당신을 위한 팁: 27번 변화(잠·몸·시간·고립·가족 갈등), 중독이면 가족 상담, 30번에서 기댈 곳이 없으면 정신건강복지센터
  - 다음 단계: 위기 신호 → 109/1577-0199 / 이미 치료 중 → 이어 가도록 응원 / 점수 1.5 이상·빈도 높음·6개월 이상 → 전문 기관 제안 / 그 외 → 다음 만남 약속

## 12. 기록 저장 (`js/core/store.js`)

## 13. 접근성·기타
- 대화창 `aria-live="polite"`, 안전 카드 `role="alert"`, 필수 안내 `role="status"`
- 키보드 포커스 표시(`:focus-visible`), 기록 카드는 Enter로 열기
- `prefers-reduced-motion` 설정 시 모든 애니메이션 끔
- 사용자 입력은 화면에 넣기 전에 모두 `esc()`로 이스케이프

## 14. 남은 작업
- `Model` 세 함수를 실제 모델 API로 교체. 응답 대기 중 표시, 실패·시간 초과 시 목업 규칙으로 돌아가기
- 후속 질문(`FOLLOW`)과 질문 선택을 맥락 추출 모델 판단으로 교체
- 모델 응답이 정해진 형식에 맞는지 확인한 뒤 화면에 그리기
- 답변이 서버로 가게 되면 "기록은 이 브라우저에만 남아요" 안내 문구와 개인정보 안내 수정
- 휴대폰 화면 점검, 대화 화면 상단 위기 상담 번호 검토
