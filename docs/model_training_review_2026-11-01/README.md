## 수치와 상태를 읽는 기준

- **현재 구성:** 최신 파일과 실제 학습 행·토큰 인덱스에서 확인한 데이터 수량이다. 데이터 준비를 학습 완료로 표시하지 않는다.
- **과거 결과:** 해당 날짜·모델·입력·소스에 대한 기록이다. 현재 배포 상태나 다른 데이터의 성능으로 확대하지 않는다.
- **합성 검사:** 고정 응답·테스트 서버를 사용한 소프트웨어 계약 검증이다. 실제 모델 품질이나 속도 개선율과 구분한다.
- **실제 모델 검사:** 문서에 명시된 로컬 사례의 결과다. 이어받은 생성 단계, 실패·중단, 전체 작업 호출 수를 별도로 표시한다.
- **남은 실험:** 코드가 있어도 실측·역할 평가가 없으면 후보로 표시한다. 제안한 실험을 실행 완료로 보지 않는다.

현재 문서 작성에서 네 데이터 묶음의 실제 행 수·task·인덱스 수를 대조했고, 출력 검증 집중 회귀 **135개 통과, 실패·건너뜀 0개**를 확인했다. 기존 전체 2,352개 검사 결과는 이전 실행 기록으로 인용했으며 이번에 전체를 재실행한 것은 아니다.

## 실제 코드·데이터 재검토 반영

재검토 이후 요청한 코드 수정은 [앱·학습 계약과 완료 판정의 우선순위 및 로컬 수정](../../최신/앱_학습계약과_완료판정_로컬수정_2026-11-01.md)에 정리했다. 아래는 최초 재검토 기록이며 이후 구현 상태는 해당 수정 기록과 04 문서의 후속 반영 내용을 함께 본다.

같은 날 후속 요청으로 네 문서를 다시 대조해 다음을 수정했다.

- 데이터의 실제 파일 위치, 메모리 검토의 state 전용 범위, 카드 필드별 수량·누락, 평가 사례 행과 요청 수를 바로잡았다.
- 최신 데이터에 고정된 앱 파일과 현재 코드의 해시 불일치, 새 검토 단계가 없는 종료 정책·기존 평가의 한계를 추가했다.
- 저장된 GPU 최적화 실험의 성공·탈락·미배포를 추가하고, 카드 학습 최적화의 최종 미채택을 명시했다.
- 미확인·안내 전용 판정값, 제한된 근거/배열 정규화, 수정 시점별 재검토와 턴/최종 묶음 복구의 차이를 설명했다.
- 31B의 실제 baseline 진행 스냅샷과 최종 평가 대기 이후 자동 전이 미구현을 구분했다.

재검토에서 데이터·평가 **verify 6개 모두 통과**, 출력 검증 회귀 **210개**, 호출·설정 회귀 **84개**, CPU 학습 실행기 회귀 **30개**가 통과했다. 검사 집합은 서로 겹치므로 합산하지 않는다. 전체 재토큰화·의미 전수검수·실제 모델 학습·원격 현재 상태 확인은 수행하지 않았다.

## 보관·접근 범위

상담 원문·학습 정답·개별 라벨 행렬·실제 생성 출력은 이 폴더에 복사하지 않았다. `training_data/`, `data/데이터셋/`, `runtime/` 등 Git 제외 자료로 연결되는 링크는 로컬 전용이며 공개 저장소 사본에는 없을 수 있다.

기존 코드·데이터·실행 서비스·카드 디자인은 변경하지 않았다. GPU 서버 접속·학습·배포도 수행하지 않았다. 이 폴더는 요청 시점의 종합 스냅샷이며 향후 변경 시 각 문서의 기준일과 근거를 함께 갱신해야 한다.
