## 사례와 학습 행의 차이

신규 대화는 200개 가상 사례이며 학습 160개, 검증 40개입니다. 각 사례의 첫 발화·첫 응답·후속 발화·후속 응답, 현재 사실의 원문 인용, 미확인 정보, 정정 전 정보, 중복 질문과 필요한 질문을 작성하고 독립 AI 검토를 거칩니다. 한 사례에서 아래 8개 학습 행을 만듭니다. 1,600행은 1,600개 독립 사례를 뜻하지 않습니다.

| 단계 | 사례당 행 | 내용 |
|---|---:|---|
| `02_supporter_dialogue` | 5 | 첫 응답, 후속 응답, 질문 선택, 근거 있는 질문 검토, 반복 질문 반려 |
| `03_state_memory` | 3 | 보고 사실 추출, 화자별 메모리, 상태·질문 통합 초안 |

대화 응답은 전체 대화 원문을 입력으로 받습니다. 상태·메모리·질문 작업은 작성자가 구분한 원문 조각을 앱의 구조화된 입력으로 변환합니다. 후자는 아무 전처리 없이 긴 원문에서 모든 사실을 발견하는 과제와 다릅니다. 상태 사실에는 patient/supporter만 넣고 이용자의 목적은 user_goal 입력으로 구분합니다. 앱 계약상 생략 대상이 아닌 목표 질문을 억지로 생략하지 않으며, 중복 추가 질문 반려 과제로도 반복을 다룹니다.

| 12B 단계 | train | validation |
|---|---:|---:|
| 원상담 워밍업 | 37,065 | 3,618 |
| 주변인 대화·질문 선택/검토 | 843 | 229 |
| 상태·메모리·통합 초안 | 492 | 132 |
| **합계** | **38,400** | **3,979** |

기존 역할 자료 train 55 / validation 41에 신규 train 1,280 / validation 320을 추가합니다. 역할 자료는 최종적으로 **1,335 / 361행**입니다. 학습 단계별 과제와 연결된 원천 사례의 가중치를 균형화하므로 단순 복제 횟수나 긴 답변의 토큰 수가 손실을 지배하지 않습니다. 마지막 assistant 응답만 학습하며 절단·패킹·분할 재배정은 하지 않습니다.

31B는 원상담 37,065 / 3,618, 카드 수정 20 / 5, 카드 생성 688 / 170으로 합계 **37,773 / 3,793행**입니다. 신규 카드 원천 150개는 이전에 준비한 자료이며 이번 신규 대화 200개와 구분합니다.

## 역할 평가

새 평가 원천은 **60개**입니다. 두 모델이 같은 사례의 서로 다른 역할을 평가받으므로 모델별 60건을 더해 120개의 독립 원천이라고 세지 않습니다.

| 모델 | 개발 평가 | 최종 확인 | 요청 수 |
|---|---:|---:|---:|
| 12B | 40사례군 / 320요청 | 20사례군 / 160요청 | 480 |
| 31B | 40사례군 / 200요청 | 20사례군 / 100요청 | 300 |

여기서 사례군(family)은 같은 원천 사례에서 파생된 모든 요청을 묶은 단위입니다. 12B는 사례당 8개 요청, 31B는 script/doList/avoid/next/care 5개 요청을 평가합니다. 한 사례군의 관련 요청이 모두 통과해야 해당 항목을 사례군 통과로 셉니다.

각 분할은 가족·친구·직장·지역 모임·성인 학습의 5개 영역과 정정·부정·모름·거절·동의·도움 범위·화자·기답·목표 변경·모호함의 10개 난점을 균형화합니다. 개발 40개는 체크포인트 선택에 사용하고 test 20개는 후보 확정 뒤 최종 확인에만 사용합니다. test에 맞춰 수정하면 해당 test는 더 이상 최종 독립 확인으로 취급하지 않습니다.

모델별·분할별 파일은 다음과 같습니다.

- `SUITE.json`: 사례 ID, 원천 계보, 입력·평가 참조 해시. 종료 정책과 해시로 연결합니다.
- `INPUTS.jsonl`: 모델에 전달할 요청과 출력 형식. 정답은 포함하지 않습니다. 후속 대화 평가에는 앞선 기준 응답이 대화 이력으로 들어갑니다.
- `REFERENCES.jsonl`: 평가자만 보는 원문·현재 사실·정정·미확인·질문 근거 및 12B 기준 출력. 같은 뜻의 다른 문구를 허용합니다. 31B는 단일 카드 정답 대신 원문 사실과 필드별 기준으로 평가합니다.
- `RUBRIC.json`: 항목별 판정 기준과 적용 범위.
- `OUTPUTS.template.json`, `JUDGMENTS.template.json`: 실제 출력·체크포인트·판정을 기록할 빈 양식. 판정에는 평가자가 실제로 본 후보·기준 출력 파일의 SHA-256도 기록하며, 이후 출력이 바뀌면 기존 판정을 사용할 수 없습니다. null은 미측정이며 성공으로 간주하지 않습니다.

| 모델 | 반드시 오류 0건이어야 하는 항목 | 사례군별 95% 이상인 품질 항목 |
|---|---|---|
| 12B | 스키마, 답변 날조 방지, 화자, 근거 없는 위기·진단 금지, 질문 생략 근거, 동의·범위 | 불필요한 재질문 방지, 최신 맥락 반영 |
| 31B | 스키마, 사실 근거, 화자, 동의·범위, 부적절한 조언 금지, 직접 발화, 행동 목록, 피할 말/이유/대안 역할, 다음 행동 조건, 이용자 돌봄 | 맥락 적합성, 실행 가능성 |

개발 평가 40사례군 기준 품질 항목별 최소 38사례군 통과가 필요합니다. 모든 항목은 학습 전 기준 모델보다 후퇴하면 안 됩니다. 자동 검사는 응답 누락·JSON·스키마·원문 인용 참조를 검사합니다. 의미적 적합성은 실제 출력을 본 독립 평가자의 항목별 판단과 이유가 필요하며, 이 도구가 정답과 문구가 비슷하다는 이유로 자동 승인하지 않습니다.

## 성능에 따른 학습 종료

새 종료 정책은 새 12B 묶음, 기존 31B 묶음, 고정된 개발/test 평가 해시에 연결됩니다. 첫 학습 전에 원래 모델의 평가 결과와 체크포인트 해시도 고정해야 합니다.

각 단계의 현재 체크포인트가 단계 시작 모델보다 전체 validation 평균 손실을 `max(0.001, 기준 손실 × 0.005)` 이상 줄여야 합니다. 최종 단계는 **같은 현재 체크포인트**의 역할 평가도 위 기준을 통과해야 합니다. 횟수 상한·정체·악화만으로 완료가 되지 않습니다. 평가 증거가 없으면 평가 대기이고, 성능 목표 없이 자원 한도에 도달하면 미완료 종료입니다.

`training_stop.py`는 기록된 증거로 판단하는 도구입니다. 실제 학습기의 옵티마이저·검증 기록·체크포인트 저장과 연결된 실행기는 아직 설치하지 않았습니다. 데이터 준비나 검증 통과를 모델 학습 완료로 표시하지 않습니다.

## 검사와 재현

프로젝트 루트에서 다음 명령을 실행합니다. 인코딩/수치 재검증은 기존 tokenizers/transformers 환경을 사용하며 새 의존성 설치는 필요하지 않습니다.

동결 묶음 안의 `scripts/` 사본을 직접 실행할 때는 `python3 -B`를 사용합니다. Python 캐시 파일도 동결 파일 목록을 바꾸기 때문에, 일반 검증은 아래처럼 프로젝트의 `ai/scripts/`에서 실행하는 방식이 편합니다.

```sh
python3 ai/scripts/expanded_chat_dataset.py verify --root training_data/gemma4_12b_expanded_20261031
python3 ai/scripts/role_evaluation_data.py verify --root training_data/role_evaluation_20261031
python3 -m unittest discover -s ai/scripts -p test_chat_role_expansion.py -q
python3 -m unittest discover -s ai/scripts -p test_training_stop.py -q
node --test ai/scripts/validate_role_outputs.test.mjs
```

실제 모델 출력 검사:

```sh
node ai/scripts/validate_role_outputs.mjs training_data/role_evaluation_20261031 chat_12b development /absolute/path/model_outputs.json
```

실제 후보·기준 출력과 판정 양식을 채운 뒤 `role_evaluation_data.py score`에 `--root`, `--role`, `--policy`, `--candidate`, `--baseline`, `--judgments`를 전달하면 기존 종료 판단기가 소비할 evidence와 역할 점수를 만듭니다. 요청·응답 전체를 API에 보내는 실행이나 GPU 학습은 이 명령에 포함되지 않습니다.

해시 매니페스트, 현재 사례 해시에 연결된 독립 검토, 블라인드 오류 삽입 사례, 정확한 원문 인용, 고정 분할, 전 학습/validation 계보·정확 입력 충돌, 신규 가상 사례 간 4글자 조각 유사도를 검사합니다. 문자 유사도 검사는 의미적 독립성을 증명하지 않으며 원상담 전체와의 유사도 검사를 대신하지 않습니다.

최종 데이터의 정확한 채택 수·검사 결과는 각 묶음의 `COURSE.json`, `VERIFICATION.json`, `COVERAGE.json`, `NUMERIC_AUDIT.json`이 기준입니다.
