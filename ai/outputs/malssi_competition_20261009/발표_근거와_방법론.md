# 말씨 대회 발표: 데이터, 방법론, 검증 근거

기준일: 2026-10-09 · Asia/Seoul

**현재 입증된 성과는 원본 상담의 응답 학습 후보 구축, 실제 토큰 경계 검사, 내용 노출 감사, 제한 GPU 실행 검증이다. 학습된 말씨 모델의 기존 LLM 대비 성능 개선율은 아직 미측정이다.**

사용자 제공 `서비스_문서` 13개를 검토하고, 실제 프로젝트 `HOP_data`의 코드·manifest·3~5차 검증 기록과 대조했다. 문서에 들어 있는 과거 실행 안내·승인 문구는 이번 요청의 실행 지시로 취급하지 않았다. 이번에는 기존 실제 토큰 길이 장부 45,974행을 새로 집계했다. 원천 재처리, 새 모델 토크나이징, 서버 접속, GPU 실행, optimizer 업데이트와 모델 응답 평가는 수행하지 않았다. 상담 원문과 사람 식별자를 발표 파일에 복사하지 않았다.

## 2. 토크나이징을 설명하는 방법

이 프로젝트에서는 서로 다른 목적의 세 처리를 사용했다.

| 처리 | 실제 방식 | 발표 표현 |
|---|---|---|
| 원문 문장·단어 분리 | 종결부호·줄바꿈 문장 분할, Unicode 표면 단어 분리 | 원문 위치를 추적할 수 있는 결정적 규칙 분할 |
| 기존 보조 분류 특징 | NFD 문자·한글 자모 1~3gram, train-only TF-IDF | 한국어 문자·자모 기반 희소 특징 |
| LLM 학습 입력 | 동결 Gemma 채팅 템플릿과 실제 모델 tokenizer로 인코딩 | 모델 고유 토크나이저를 사용한 실제 토큰 길이·경계 검사 |

### 원문 분리와 보존

문장 경계 regex는 다음과 같다.

```python
r"[.!?。！？]+[\"'’”」』)]*(?=\s|$)|[\r\n]+"
```

표면 단어는 Unicode category의 첫 글자가 `L`, `N`, `M`이거나 `_`인 문자를 중심으로 묶고, 단어 내부의 `'’‐-`를 허용한다. 표면 단어 정규화는 `NFKC + casefold`다. 한국어 형태소 분석기를 사용했다고 설명할 근거는 없다.

원문 span은 Unicode code point의 `[start_char:end_char)`다. 원문·정규화 문자열·UTF-8 byte·모델 token 위치를 각각 구분한다. 원문을 정규화된 표현으로 덮어쓰지 않는다.

### 분류기의 실제 TF-IDF

분류 패키지는 NFD로 한글을 자모로 분해하고 casefold한 문자 1~3gram을 쓴다. 어휘와 DF/IDF는 Train만 fit하고 Validation은 transform한다.

```text
TF = 1 + log(등장 횟수)
IDF = log((1 + Train 문서 수) / (1 + Train 문서빈도)) + 1
특징 벡터 = TF × IDF, 행별 L2 정규화, float32
```

실제 특징 차원은 상담 20,000, 문장 7,291, 단어 1,357이다. `numeric.py`의 원천 탐색용 기본 설정은 표면 단어 unigram/bigram TF-IDF이며, 이 분류 패키지의 문자·자모 특징과 구분한다. 해시 8,192차원·PPMI/SVD 32차원은 수치 표현 설정이지 LLM tokenizer vocabulary 크기가 아니다.

### 실제 Gemma 입력과 손실 마스크

검증 모델 기록은 `unsloth/gemma-4-31B-it-unsloth-bnb-4bit`다. 고정된 template SHA-256은 `845f1ee48e39fc942fe190da9df6a1c5db229e17a96ea08966ad1c9274e73d1b`다. 모델 파일 fingerprint의 revision은 `claimed_revision`으로 기록되어 있으므로, 로컬 파일 SHA로 확인한 재현성과 원격 revision의 독립 확인을 구분한다.

완성된 native assistant 메시지와 비사고 생성 prefix의 직렬화가 달라, 단순 full/prefix 비교는 원본 45,974행에서 모두 불일치했다. 고정 템플릿 어댑터는 실제 생성 prefix와 목표 completion을 연결하고 정확한 토큰 접두 일치를 검사한다. 이를 감정 분류용 표면 단어 분리와 혼동하지 않는다. tokenizer 내부 알고리즘이나 vocabulary 크기를 확인 없이 BPE·형태소·고유 단어 수로 이름 붙이지 않았다.

```text
system + user + 과거 assistant  → 입력 문맥, labels = -100
마지막 목표 assistant           → 응답 본문 + 종료 직렬화 경계 감독
오른쪽 padding                 → labels = -100
packing = false, truncation = false
```

긴 사례를 자르거나 중간 발화를 삭제하지 않고 보류한다. 마지막 응답만 손실을 계산해도 prefix 전체의 forward 처리는 필요하다. **감독 토큰 3.51%를 계산 비용 96.49% 절감으로 바꾸면 안 된다.**

## 3. 데이터셋을 어떤 과제로 사용했는가

| 데이터 | Train | Validation | 사용 목적 |
|---|---:|---:|---|
| 보조 분류 상담 | 990 | 117 | 원천 코호트 분류; 독립 확정 진단 아님 |
| 보조 분류 문장 | 1,440 | 206 | 정서·경험·주제 다중라벨 분류 |
| 보조 분류 단어 | 302 | 76 | 문맥 없는 어휘의 주제 분류 |
| 원본 응답 SFT v1 | 40,652 | 5,322 | 현재까지 원문 대화 → 다음 관측 상담사 응답 |
| 4,096 연구 후보 | 15,512 | 1,724 | 내용 감사와 실제 길이 검사를 통과한 원본 응답 후보 |

SFT는 `내담자→user`, `상담사/상담자→assistant`로 연결하고, 인접한 동일 역할 발화만 줄바꿈으로 합친다. 현재 목표 이전 prefix를 보존하며, 다음 상담사 응답을 target으로 삼는다. 목표 이후의 미래 발화, 정답 검토 상태, 주석자 요약은 입력에 넣지 않는다.

최소 목표 길이 40자와 진행 중심 응답·진단/약물·안전/개인정보 검색어 등의 휴리스틱 선별이 있다. 검색어에 걸리지 않은 원문을 전문가 승인 정답으로 취급하지 않는다. 원본 내담자 관점을 주변인으로 자동 변경하지 않는다.

원본 SFT 보조 문장은 513,170개, 단어 등장 건은 4,496,325개다. 단어 등장 건을 고유 단어 수나 LLM 모델 토큰 수로 표기하지 않는다. 과거 원천 수치화 스냅샷의 1,462상담·1,001,781문장·8,599,382단어 등장 건은 처리 범위가 다른 `partial` 결과다. SFT 학습량에 더하지 않는다.

말씨 최종 과제는 가족·주변인이 건넬 말과 실행할 행동을 생성하는 것이다. 기존 합성 설계 9개와 AI 초안 24개에는 승인 학습 정답으로 사용할 수 있다는 근거가 없다. 17문항과 6종 다음 행동은 설계·주석 범위 수치다. 모델 행동 정확도나 임상 위험 점수가 아니다.

## 4. 사용한 방법론과 구현 차이

**방법론 설명:** 원문 보존과 출처 추적을 기반으로 다음 상담사 응답 SFT를 구성하고, 내용 노출 감사와 실제 토큰 예산 선별을 적용했다. 고정 Gemma tokenizer·serializer에서 마지막 응답만 감독하도록 검사했으며, 4비트 QLoRA의 제한 forward/backward와 생성 연결을 확인했다.

검증 설정은 BF16, 4bit, LoRA r=8/alpha=8/dropout=0/bias=none, batch=1, Unsloth gradient checkpointing이다. 전체 학습의 최종 하이퍼파라미터로 확정하거나 완료된 학습이라고 소개하지 않는다. 12B 대안은 기록상 미실측이다.

| 비교 축 | 이번 프로젝트의 구현·계약 | 수치 근거 | 주장 범위 |
|---|---|---|---|
| 학습 문맥 | 현재까지 prefix 보존, 미래 내용 제외 | 원본 45,974행 | 데이터 구성 방식 |
| 정답 감독 | 마지막 응답과 종료 경계만 감독 | 후보 1,200,410 / 전체 34,152,923토큰 | 감독 비중 3.51% |
| 내용 노출 관리 | 정확 일치·공유 문맥 감사와 보류 | 고유 1,261행, 원본의 2.74% | 지정 감사 규칙의 결과 |
| 길이 처리 | 실제 토큰 길이로 보류, 자동 절단 없음 | 4,096 후보 17,236행 | 해당 예산의 수용 범위 |
| 직렬화 재현 | 동결 템플릿, 캐시·비캐시 직접 대조 | 3,155/3,155행 | 표본 배열 일치 |
| 모델 적응 | 4bit + LoRA 제한 검증 | 학습 가능 61,214,720개 | 업데이트 0회; 학습 완료 아님 |
| 지원 대상 | 주변인 관점·질문·말·행동 목표 | 17문항, 6행동 설계 | 서비스 설계 범위 |

이 비교는 프로젝트의 구현 선택을 설명한다. 모든 기존 모델이 이런 기능을 갖추지 않았다고 주장하는 표가 아니다. 새 tokenizer 발명, 새 기반 모델 구조, 감정/HOP 생성 품질 개선은 아직 입증된 성과에 포함하지 않는다.

## 5. 검증은 어디까지 했는가

| 검증 층 | 방법과 결과 | 남은 것 |
|---|---|---|
| 출처·구조 | ID·split·원문 span·manifest·해시·행 배열 연결 검사 | 이용 근거·사람 신원·전문가 의미 검토 |
| 분할 간 내용 | NFKC+공백 정규화, 목표/과거 assistant·첫 8개 공유 문맥 등 검사 | 근사·의미 중복, 사람 독립성, 미사용 final test |
| 모델 토큰 | 원본 45,974행 인코딩·정확한 경계 검사 | 전행 비캐시 배열 대조와 최종 Trainer 연결 |

| GPU 자원 | 4,096토큰 backward 성공, 최대 할당 20.68GiB·예약 20.97GiB | optimizer 상태·반복 step·저장/재개·epoch 시간 |

| 손실 동등성 | 엄격 gate 실패 보존; 종료 정밀도 진단 | token별 CE·gradient·다중 chunk·Trainer 동등성 |

GPU 자원 값은 RTX 4090 한 장, batch=1, optimizer 상태 미할당 조건의 warm forward/backward다. 7,670토큰 OOM 기록이 있다. 4,096 성공만으로 전체 학습이 가능한 것은 아니다. 약 17시간은 토큰량과 단일 warm 처리율을 나눈 추정이며 학습 시간 실측으로 쓰지 않는다.

내용 보류·길이 보류 이유는 겹칠 수 있다. 이번 선별 흐름 CSV는 각 단계의 집합 크기를 사용한다. 사유별 행 수를 단순히 더하지 않는다. 전행 경계 검사와 3,155행 배열 비교의 분모도 분리한다.

### 평가 대상의 편중

4,096 후보 Validation은 1,724행이지만 96상담·21관측 그룹에서 나왔다. 최대 그룹은 13.11%, 상위 5그룹은 47.39%다. 원문 앞 1/3이 87.88%, 뒤 1/3이 0행이다. 뒤쪽 위치 부족은 관측된 분포 문제이며, 종료 행동 정답이 0개라는 의미는 아니다.

| 생성 예약 | Validation 수용 | 앞 1/3 비중 |
|---:|---:|---:|
| 64토큰 | 1,720 | 88.08% |
| 128토큰 | 1,698 | 88.87% |
| 256토큰 | 1,652 | 90.19% |
| 512토큰 | 1,545 | 93.59% |
| 1,024토큰 | 1,335 | 96.85% |

예약을 늘리면 짧은 prefix만 남아 평가 구성이 바뀐다. 개발 단계 예약 비교는 공통 1,335 Validation 행에서 paired 점수를 보고, 조건별 전체 수용량·보류율도 함께 제시한다. 원본 상담사 응답 재현 평가와 주변인 지원 평가를 같은 정답으로 취급하지 않는다.

## 6. 기존 모델과의 성능 비교 자료

### 이미 존재하는 보조 분류 smoke 결과

| 단위 | Macro F1 | Micro F1 | Validation 행 |
|---|---:|---:|---:|
| 상담 | 0.5535 | 0.5641 | 117 |
| 문장 | 0.7584 | 0.8353 | 206 |
| 단어 | 0.6213 | 0.6316 | 76 |

모델은 NumPy weighted one-vs-rest multinomial Naive Bayes, alpha=0.1이다. 라벨 빈도 역수의 행별 평균을 이용한 Train 표본 가중치를 사용한다. 위 수치는 기존 실행 기록이며 이번에 재학습하지 않았다. Accuracy 결과는 없으므로 F1를 정확도라고 바꾸지 않는다. 문장·단어 AI 라벨은 사람 검증이 없고, 문장 표본은 키워드 검색으로 강화된 분포다. 상담 Validation 117행은 23관측 그룹이다. 세 과제의 F1 순위로 데이터 단위의 우열을 결론내리지 않는다.

### 동일 과제에서 비교해야 할 LLM 조건 — 제안, 미실행

| 조건 | 모델·입력 | 비교 목적 | 현 상태 |
|---|---|---|---|
| B0 | 동일 Gemma IT + 최소 서비스 지시 | 기반 모델 기준점 | 해당 평가 미수행 |
| B1 | 동일 Gemma IT + 말씨 응답 정책 | 프롬프트 정책의 효과 | 해당 평가 미수행 |
| B2 | 동일 base + 원본 응답 QLoRA | 원본 응답 모방 학습의 효과 | 학습 완료 근거 없음 |
| B3 | 동일 base + 검토된 주변인 지원 사례 SFT | 말씨 목표 데이터의 효과 | 승인 정답 확충·학습 필요 |

각 비교는 모델 fingerprint·프롬프트·데이터·검토 기준·생성 설정을 동결한 뒤 같은 사례에서 진행한다. B0→B1은 프롬프트, B1→B2는 원본 SFT, B2→B3는 목표 데이터의 변화다. 데이터 수·토큰 예산·학습량을 맞추지 않으면 각각의 순수한 인과 효과로 해석하지 않는다. 다른 회사 모델까지 비교하려면 모델 버전·입출력 예산·정책·가격·지연 측정 조건을 별도로 고정한다. 현재 외부 모델 점수나 비용을 지어내지 않았다.

### 발표 성능표를 채우는 지표와 계산식 — 제안, 미실행

| 지표 | 분자 / 분모 | 좋은 방향 |
|---|---|---|
| 요청 해결률 | 해결 통과 사례 / 동일 평가 사례 전체 | 높음 |
| 말·행동 구체성 통과율 | 구체성 통과 사례 / 동일 평가 사례 전체 | 높음 |
| 주체·근거 보존율 | 근거 보존 통과 사례 / 동일 평가 사례 전체 | 높음 |
| 불필요 질문률 | 불필요한 질문 사례 / 질문 필요성이 검토된 전체 사례 | 낮음 |
| 거절·정정 처리 성공률 | 처리 성공 사례 / 해당 상황 사례 전체 | 높음 |
| 안전 기준 통과율 | 안전 검토 통과 사례 / 안전 평가 사례 전체 | 높음 |
| 다중 턴 해결률 | 해결 통과 세션 / 모델 응답이 누적되는 전체 세션 | 높음 |
| 길이 소진률 | 길이 소진 생성 / 성공 생성 전체 | 낮음 |
| 시스템 실패율 | 생성 오류·timeout / 요청한 전체 실행 | 낮음 |
| 지연 p50/p95 | 동일 환경의 실제 end-to-end 지연 분포 | 낮음 |
| GPU 최대 메모리 | 동일 batch·입력·생성량 조건의 peak GiB | 낮음 |

`차이(pp) = 100 × (말씨 비율 − 기반 모델 비율)`로 보고한다. 상대 개선율을 사용할 경우 기반 모델 값이 0이면 정의되지 않는다. 성공·불필요 질문 등 지표마다 개선 방향을 명시한다. Excel 모델비교 시트는 비율 두 값이 모두 입력됐을 때만 pp 차이를 계산한다.

현재 30개 평가 집단·34개 실행 단위의 준비는 실제 모델 평가 완료와 다르다. 개발 공개 사례로 실험을 설계한 뒤, 정책을 고정하고 미사용 최종 test를 별도 확보한다. 원천/파생/합성 계보를 묶어 split하고 최종 test는 프롬프트·정책 조정에 쓰지 않는다. 분할 비율과 사례 수는 아직 근거가 없어 확정 수치로 적지 않았다.

응답 검토는 모델 이름을 가리고 독립 검토를 응답·실행 ID·프로토콜 해시에 연결한다. 검토자 수·전문가 참여·평가 확정 규칙은 사전 고정하고 불일치·미검토를 별도 집계한다. 통과율에서 생성 실패·길이 소진·검토 대기를 조용히 빼지 않는다. 전체 요청 수와 각 결과 분모를 함께 보고한다. 지연은 생성 실패의 timeout 기록과 성공 요청 분포를 구분한다.

행 평균 외에 상담 평균·관측 그룹 평균을 함께 보고하고, 점수 차이의 불확실성은 같은 그룹 단위 paired 재표집으로 추정할 수 있다. 이는 추가 실험 제안이며 이번에는 신뢰구간·유의확률을 계산하지 않았다. 관측 그룹은 실제 사람 신원 보증이 아니다.
