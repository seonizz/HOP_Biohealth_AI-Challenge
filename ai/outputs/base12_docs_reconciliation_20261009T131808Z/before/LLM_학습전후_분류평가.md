# 말씨 LLM 학습 전후 분류 평가

**원본 31B·원본 12B·학습 후 31B의 분류 정확도**를 비교한다. 우리는 상담 답변 생성 모델을 학습하며, 이 평가는 주제 이해·대응 선택 능력을 보는 **보조 평가**다. 기존 Naive Bayes F1은 사용하지 않는다.

작성일: 2026-10-09. 아래 내용은 평가 프로토콜이며, 평가 사례·정답 라벨·실제 점수는 아직 `[미확인]`이다.

**비교 조건**

| 구분 | 모델 | 조건 ID |
|---|---|---|
| 원본 · 현재 사용 모델 | Gemma 4 31B IT · 학습된 adapter 없음 | `BASE31` |
| 원본 · 한 단계 낮은 모델 | Gemma 4 12B IT 후보 · 정확한 ID·revision [미확인] | `BASE12` |
| 학습 후 · 현재 사용 모델 | Gemma 4 31B IT + 본학습 완료 adapter | `FT31` |

12B는 기존 프로젝트의 대안 기준이며 실측·설치 여부는 [미확인]. 학습 완료·성능도 근거 확보 전까지 [미확인].

**Δ학습 = FT31−BASE31**: 같은 모델의 파인튜닝 효과. **Δ소형 = FT31−BASE12**: 크기·학습 효과가 함께 반영된 비교.

BASE31/FT31은 기반 가중치·tokenizer·채팅 템플릿이 동일하다. BASE12는 자체 tokenizer·템플릿을 사용하고 식별자·해시를 별도로 기록한다. 의미상 동일한 입력·정책·라벨 설명·생성 예산을 3개 모델에 적용한다.

기존 `validation_B0/B1.json`은 BASE31/FT31의 검증 손실 기록이다. 시험 학습·용량 검사 adapter는 FT31으로 사용하지 않는다. 보존된 원본 모델은 학습 이후에도 평가할 수 있다.

**평가할 과제**

| 우선순위 | 과제 | 정답·출력 |
|---|---|---|
| 주 평가 | 상황에 맞는 다음 대응 행동 | 아래 6개 중 주된 행동 1개 |
| 선택 평가 | 상담의 중심 주제 | 불안·우울·중독·기타 중 1개 |

두 과제의 정확도와 F1은 별도로 보고한다. 상담 주제는 질환 진단이 아니며, 기존 원천 집단 라벨을 모든 발화의 정답으로 자동 복사하지 않는다.

분류 정답은 평가 전용이다. 이 정답을 추가 학습에 사용하면 기존 상담 응답 SFT와 다른 실험으로 기록하고, 별도의 미사용 test를 확보한다.

| 행동 코드 | 정답 기준 |
|---|---|
| `ASK_CFI` | 질문은행 Q01~Q17의 특정 정보가 있어야 현재 도움을 정할 수 있음 |
| `CLARIFY` | 질문은행 밖의 표현·의도·대상을 먼저 명료화해야 함 |
| `SUPPORT` | 현재 요청에 답할 정보가 충분함 |
| `SUPPORT_LIMITED` | 미확인 정보가 제공 가능한 도움의 범위를 실제로 제한함 |
| `SAFETY_SUPPORT` | 현재 입력에 근거 있는 급박한 안전 우려가 있음 |
| `END` | 급박한 안전 우려 없이 종료를 요청함 |

급박한 안전 우려와 종료 요청이 함께 있으면 `SAFETY_SUPPORT`를 우선한다. 모름·거절만으로 `SUPPORT_LIMITED`를 붙이지 않는다. `SUPPORT` 안의 보조 질문과 주된 행동을 구분한다. `ASK_CFI`의 질문 ID 정확도는 이번 6종 분류 점수에 포함하지 않는다.

주제 코드는 `ANXIETY`(불안), `DEPRESSION`(우울), `ADDICTION`(중독), `OTHER`(세 주제 외)다. `OTHER`를 정보 부족·복수 주제·판단 불가의 대체 라벨로 쓰지 않는다.

**평가 데이터와 정답 만들기**

1. 실제 전체 학습 목록·개발용 자료와 겹치지 않는 **별도 상담**을 확보한다. 같은 상담의 다른 발화, 파생 문장, 동일 출처 그룹도 교차하지 않도록 검사한다.
2. 현재 검증 4,298건은 NLL·개발용 자료다. 새 독립 test로 자동 승격하지 않는다. 기존 공개·합성 예시도 최종 test로 자동 사용하지 않는다.
3. 입력에는 현재 시점까지의 대화만 넣는다. 다음 상담사 정답·미래 발화·라벨·검토 메모·원천 집단명이 담긴 파일명은 넣지 않는다.
4. 동일 입력을 **2명이 독립 검토**해 라벨과 근거를 기록한다. 이는 이번 프로토콜의 검토 규칙이며, 검토자가 확보됐다는 뜻은 아니다.
5. 불일치는 합의 검토한다. 단일 정답으로 확정하기 어려운 사례는 모델 출력 전에 별도 보류한다. 보류 수·사유도 보고한다. 모델 출력을 본 뒤 정답을 고치거나 어려운 사례를 제외하지 않는다.
6. 과제별·라벨별 건수, 상담 수, 출처 그룹 수, 중복 검사 결과, 보류 수를 기록한다. 사람 신원 독립성은 그룹 ID만으로 보증하지 않는다.
7. 사례·정답·프롬프트·설정 해시를 고정한다. 이후 test로 프롬프트·checkpoint를 고르지 않는다. 수정이 필요하면 새 평가 버전과 미사용 test를 마련한다.

사례 수는 아직 `[미확인]`이다. 라벨별 표본을 충분히 확보하고 실제 건수를 공개한다. 동일 수로 균형 표집했다면 실제 서비스 발생 비율을 대표한다고 주장하지 않는다. 모델에 보내는 파일은 `case_id`, `task`, `messages`만 포함하고 정답·메타데이터 파일은 분리한다.

**실행 설정**

| 설정 | 이번 평가 기본안 |
|---|---|
| 샘플링 | `do_sample=false`, `num_beams=1` |
| 사고 모드 | `enable_thinking=false` |
| 출력 | 허용 코드 1개, 설명 없음 |
| 생성 예약 | `max_new_tokens=32` |
| 전체 예산 | 입력 직렬화 + 생성 예약 ≤ 4,096토큰 |
| 배치·seed | 1 / 3407 |
| 종료 | 강제 EOS·추가 stop string 없음, 종료 토큰과 실제 병합 설정 기록 |
| 반복 | 조건별 사례당 1회. 실패도 그대로 기록 |

위 값은 새 비교 실험의 기본안이며 실행 검증 완료값이 아니다. 개발용 사례에서 라벨 출력·토큰 수를 점검한 뒤 고정한다. 출력은 디코딩 후 양끝 공백만 제거하고 허용 코드와 정확히 일치할 때 유효하다. 설명·코드 블록·복수 코드·빈 출력은 형식 오류다. EOS 전 길이 제한으로 중단된 출력도 별도 실패로 기록한다.

긴 입력은 조용히 자르지 않는다. 모델 출력 전에 각 tokenizer로 길이를 확인해 하나라도 초과한 사례를 공통 test에서 보류하고 건수·비율을 공개한다. 장문 평가가 필요하면 3개 모델이 지원하는 동일 예산으로 별도 test 층을 만들고 결과를 분리한다. 학습 전은 짧은 입력, 학습 후는 긴 입력으로 비교하지 않는다.

공통 서비스 정책을 포함하려면 3개 모델 모두에 동일하게 적용한다. 모두 `eval` 모드에서 실행한다. 모델·adapter·환경·토크나이저·템플릿·프롬프트·입력 해시와 실제 생성 설정을 저장한다. 프롬프트 효과를 보려면 파인튜닝 비교와 별도 실험으로 분리한다.

BASE31/FT31의 4비트 양자화·계산 정밀도·GPU 배치를 동일하게 맞춘다. BASE12도 같은 정밀도를 목표로 하되 실제 설정·차이를 기록한다. 속도를 비교하려면 사용 GPU 수·동시성·측정 구간도 같아야 한다. 현재 구성과의 호환성은 실행 전에 점검한다.

**채점 규칙**

평가셋 고정 후 확정 정답이 있는 test 사례 수를 N으로 둔다. 모든 사례는 BASE31/BASE12/FT31 각각 기록이 있어야 한다. 해당 모델에 미실행이 남아 있으면 그 점수를 확정하지 않는다. 완료된 두 조건의 비교는 별도 보고할 수 있지만 3개 모델 평가 완료로 표시하지 않는다. 실행을 시도한 오류·timeout·형식 오류·길이 소진은 주 정확도에서 오답으로 센다.

| 지표 | 계산 |
|---|---|
| 정확도 | 정답과 일치한 유효 출력 수 ÷ N × 100 |
| Macro F1 | 라벨별 `2TP / (2TP + FP + FN)`의 평균 × 100 |
| 라벨별 재현율 | 해당 정답 라벨을 맞힌 수 ÷ 해당 라벨 사례 수 × 100 |
| 유효 출력률 | 정상 종료한 허용 코드 출력 수 ÷ N × 100 |
| 실행 실패율 | 오류·timeout 사례 수 ÷ N × 100 |
| 정확도 변화 | FT31−BASE31(Δ학습), FT31−BASE12(Δ소형)의 정확도 차이, 단위 **%p** |
| Macro F1 변화 | FT31−BASE31, FT31−BASE12의 점수 차이, 단위 **점** |

형식 오류·실행 실패·길이 소진은 해당 정답 라벨의 FN에 포함한다. 혼동행렬에는 6개 행동 또는 4개 주제 열과 별도 `INVALID` 열을 둔다. Macro F1 평균에 `INVALID`를 추가 라벨로 넣지 않는다. 고정 라벨 중 정답 사례가 없는 라벨이 있으면 전체 Macro F1을 확정하지 않고 표본 부족을 표시한다.

과제별 점수와 각 라벨의 실제 건수를 함께 제시한다. 같은 상담의 여러 사례가 있으면 상담별 평균도 함께 보고하고, 과도하게 많은 발화가 한 상담의 영향력을 키우지 않았는지 확인한다. 안전 행동은 정밀도·재현율을 별도로 보고한다. 이것만으로 실제 안전한 상담 답변을 생성한다고 해석하지 않는다.

차이의 95% 신뢰구간을 계산한다면 비교 쌍마다 동일 출처 그룹을 함께 재표집하는 paired bootstrap을 사용한다(기본 2,000회, seed 3407). 그룹 수·방법을 명시한다. 계산하지 않았거나 표본이 부족하면 `[미확인]`이며 통계적 우위를 주장하지 않는다.

**실행 순서와 전달 파일**

`정답 검토 → 개발용 사례로 형식 확인 → test·설정 고정 → BASE31 실행 → BASE12 실행 → FT31 실행 → 자동 채점 → 상담·라벨별 점검 → 결과표 작성`

- [평가설정.json](평가양식/평가설정.json): 모델·평가셋·설정 식별. 미확정 식별자·수치의 `null`은 `[미확인]`이며 실행 전에 채운다. BASE31/BASE12의 adapter와 비활성화한 생성 옵션의 `null`은 의도된 미사용 값이다.
- [기록양식.json](평가양식/기록양식.json): 사례, 검토, 모델별 실행, 집계 결과의 빈 양식. 양식 자체를 실제 사례로 실행하지 않는다.
- [행동분류_프롬프트.txt](평가양식/행동분류_프롬프트.txt), [주제분류_프롬프트.txt](평가양식/주제분류_프롬프트.txt): 3개 모델 공통 시스템 지시문. 주제 과제는 선택 사항이다.

실제 실행기는 `messages`를 한 개의 직렬화된 대화 자료로 사용자 메시지에 넣는다. 원문 안의 역할·명령이 평가용 시스템 지시문으로 승격되지 않게 한다. 이 입력 변환도 3개 모델에서 동일하게 고정한다.

실행 전 필수 확인: 정답 승인·검토자 확보, 실제 train/dev와의 중복 검사, test 동결·건수, BASE31/FT31 기반 모델 해시 일치, BASE12 정확한 모델 식별·파일 검증, FT31 본학습 완료 증거·adapter 해시, 활성 과제의 프롬프트·입력 변환·환경·생성 설정 지문, 개발용 생성 점검. 이 필수 근거가 미확인이면 실행 준비 완료로 표시하지 않는다. 비활성 과제와 의도된 미사용 옵션은 값을 억지로 채우지 않는다.

모델 추론·채점은 이번 문서화 작업에서 실행하지 않았다. 실제 실행기와 채점기 구현은 후속 작업이다.
