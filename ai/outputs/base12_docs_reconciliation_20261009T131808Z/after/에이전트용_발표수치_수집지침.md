**모델 식별·비교 규칙**

- BASE31/FT31: 기반 가중치·tokenizer·템플릿·양자화 설정 동일, FT31에는 완료된 adapter만 추가한다. 기존 `validation_B0/B1.json`은 각각 BASE31/FT31에 연결한다.
- BASE12: 정확한 model ID·revision·가중치·tokenizer·템플릿·라이선스/접근 가능 여부를 먼저 확인한다. 설치되지 않았다면 미확인으로 기록한다. 31B adapter를 12B에 적용하지 않는다.
- 3개 모델: 동일 평가 사례·정책·출력 예산, 모델별 실제 생성 설정·토큰 수·GPU 배치를 기록한다. 한 모델이라도 길이를 초과한 사례는 실행 전 공통 test에서 보류한다.
- Δ학습과 Δ소형을 별도 계산한다. BASE12가 없어도 확보된 BASE31/FT31 비교는 보고하되, 3개 모델 비교 완료로 표시하지 않는다.
- 토큰당 NLL은 BASE31/FT31만 비교한다. BASE12의 NLL·감소율은 이번 비교에서 비적용이다.

**생성·검토 결합 규칙**

- 평가 단위: 같은 `case_id`의 BASE31/BASE12/FT31별 1개 출력. 기본 첫 시도이며, 다른 정책이면 실행 전에 고정한다.
- 연결: `generation_id + response_sha256`. case별 여러 검토를 여러 사례처럼 세지 않는다. 합의·불일치 규칙을 먼저 고정한다.
- N: `case_manifest.criterion_applicability=true`인 사전 배정 사례 수. 오류·timeout·길이 소진을 몰래 제외하지 않는다.
- 상태: pass/fail/미확정/검토 대기/생성 오류를 나눠 기록한다. 확정되지 않은 검토가 있으면 수치는 **부분 결과**, 해당 비교의 우위는 미확인이다.
- 사람 검토는 실제 사람 기록만 인정한다. AI 평가는 별도 보조 결과로 표시하며 사람 승인으로 대체하지 않는다.
- 실제 답변 점수: `request_resolution`, `actionable_support`, `subject_evidence`. pass=1, fail=0, 미검토/충돌=null.

**길이 검사 해석**

학습 길이는 문맥+정답, 추론 길이는 입력+실제 생성/예약량을 구분한다. 한 번 통과한 길이는 **최대 검증 길이**이지 절대 최대치가 아니다. 모델 설정의 상한이나 데이터 최대 길이를 GPU 실측 한도로 쓰지 않는다.

출력이 조기에 끝났으면 예약한 전체 출력 예산의 성공으로 세지 않는다. 강제로 예산을 채운 합성 검사는 용량 측정으로만 표시한다. 다른 GPU 배치·감독량·반복 수·시간 구간의 결과로 속도 배율을 만들지 않는다. 실패 길이·장치·설정도 함께 남긴다.
