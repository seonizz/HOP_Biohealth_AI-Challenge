# 말씨 학습 담당자에게 전달할 수집 작업

이번 모델 학습에서 대회 발표에 사용할 수치를 재계산할 수 있도록 실제 실행 증거를 함께 수집해 주세요. 상세 계약은 같은 폴더의 `학습_데이터수집_지침.md`, 필드 양식은 `templates/record_templates.json`을 따릅니다.

1. `collection_tools.py init`으로 새 run 폴더를 만들고 모델·tokenizer·template·코드·데이터·split·환경·최종 학습 설정을 hash와 연결합니다. 원본 응답 SFT와 주변인 지원 SFT의 목적을 명시합니다.
2. 학습 전 고정 Dev에서 같은 기반 모델과 말씨 정책 프롬프트(B1)의 실제 응답을 저장합니다. 최종 Test는 학습·프롬프트·checkpoint 선택이 끝난 뒤 비교합니다.
3. 실제 Trainer/collator의 마지막 응답 마스크, prefix·padding·종료 경계, 엄격 CE 비교, 첫 optimizer 업데이트, 연속 step, 저장·재개를 pilot에서 확인합니다. 이전 손실 gate 실패를 자동으로 통과 처리하지 않습니다.
4. 매 optimizer 시도에 update/skip/OOM/failure, LR, loss의 reduction, 유효 token 수, gradient 상태, 실제 시간과 성공 update 누적을 남깁니다. 평균 loss와 정확한 token CE 합을 혼동하지 않습니다.
5. 데이터 split별 행·상담·관측 그룹·행동 분포·보류 사유 합집합·실제 token 합/p50/p95/p99/max를 저장합니다. 학습 데이터와 Dev/Test 원천 계보의 교차를 확인합니다.
6. 정해진 주기로 고정 Dev를 평가하고 사전에 정한 기준으로 best checkpoint를 선택합니다. optimizer/scheduler/RNG 상태와 실제 재개 결과를 기록합니다.
7. CUDA 정밀 시간·peak 메모리는 측정 구간을 명시합니다. optimizer 상태 미할당 측정, warmup, 일반 학습, 평가, 저장 시간을 구분합니다. 입력 tokens/s와 감독 tokens/s를 각각 남깁니다.
8. 기반 모델 B1과 학습 모델을 같은 사례·프롬프트·generation 조건으로 비교합니다. 모든 생성 시도에 상태·지연·실제 token 수·종료 이유를 기록합니다. 실패와 길이 소진을 삭제하지 않습니다.
9. 비공개 원장에 응답, 후처리 전 suffix token IDs, prefill, 최종 generation config·override·EOS/강제 EOS·stop 설정을 저장합니다. 발표용 자료에는 hash와 집계만 둡니다.
10. 모델 이름을 가린 독립 검토를 generation/response/rubric hash에 연결합니다. 사람·전문가·AI 검토를 구분하고 pass/fail/uncertain/검토 대기를 보존합니다. 원본 이력 재생과 모델 응답 누적 다중 턴 평가를 별도로 기록합니다.
11. 종료 후 네 JSON 설정, 다섯 JSONL 로그, 설정·환경·checkpoint 지문·손실 검증·재개 근거를 모읍니다. `collection_tools.py check --run <폴더> --phase after_eval`의 오류를 확인하고, 누락 항목은 미실행 이유와 함께 남깁니다.

학습량·기존 대비 성능 향상·시간·VRAM은 실제 기록으로만 보고합니다. 미측정은 `null`, 실제 0은 숫자 `0`으로 저장합니다. 실패한 run도 보존합니다. 기존 17,236 후보·4,096 길이·r=8 등의 값을 이번 실행값으로 미리 채우지 않습니다.
