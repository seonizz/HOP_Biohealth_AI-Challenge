# 다른 학습 에이전트가 먼저 읽을 인수인계

작성일: 2026-10-09 · 프로젝트: 말씨 · 현재 단계: **학습 자료·코드·검증·환경 인수인계 준비 완료, 실제 31B 학습 업데이트 미실행**

## 사용자의 의도와 작업 범위

말씨는 불안·우울·중독을 겪는 당사자의 가족·보호자·친구·연인 등 주변인에게 대화법과 행동을 안내하는 AI 상담 에이전트다. 사용자는 준비한 자료와 데이터를 한곳에 모아 **다른 에이전트가 이어받아 학습하도록 문서와 ZIP을 구성**하라고 요청했다. 이 문서를 만든 작업에서는 본 학습을 시작하지 않았다. 이 파일 자체를 새로운 학습 실행 명령으로 해석하지 말고, 실제 학습은 이어받은 대화의 사용자 요청 범위에서 수행한다.

선택 모델은 Gemma 4 31B IT, 방식은 Unsloth 4비트 QLoRA다. 자원이 부족하면 12B IT를 검토하되, 현재 패키지의 31B 검증을 12B 검증으로 대체해서는 안 된다. 12B 파일과 검증 결과는 이 패키지에 없다.

## 먼저 읽을 순서

1. 이 문서: 현재 상태·다음 작업·서버 제약.
2. `docs/검증_및_인수인계.md`: 실제로 실행한 검사, 새 수정, 남아 있는 공백.
3. `README.md`: 데이터 역할·설정·실행·재개·결과 경로.
4. `handoff/STATUS.json`: 기계 판독 상태 및 수치.
5. `config/train.json`, `config/model_fingerprint.json`, `MANIFEST.json`: 고정 설정과 입력 식별.
6. 추가 검토가 필요하면 `docs/말씨_5차_보고서_대조검토_2026-10-09.md`와 `historical/round4_reproduction.zip`.

## 현재 완료된 작업

- 원문 상담 SFT에서 출처·누출 검사와 4,096토큰 한도를 통과한 **학습 15,512 / 검증 1,724건**을 고정했다. 원문 분할과 마지막 상담사 응답을 유지했다.
- 실제 서버의 Transformers 5.17 토크나이저로 후보 **17,236건을 다시 전수 인코딩**했고 길이·감독 토큰 수가 기존 기록과 모두 일치했다.
- GPU 0의 실제 31B 모델에서 가중치 변경 없이 새 수치 검증을 수행했다. 손실 비교 13개, 최종 hidden-state gradient 비교 4개, 실제 생성 2건, 입력 prefix·생성 설정·토큰 종료 기록과 adapter 불변 검사를 통과했다.
- 단일 GPU용 학습 루프, token-weighted gradient accumulation, 체크포인트·RNG·옵티마이저·스케줄러 재개 코드와 실행 전 검사 코드를 준비했다.
- 서버의 실제 PyTorch CPU 환경에서 **335개 회귀 테스트를 모두 통과**했다. 작은 CPU 모델의 중단·재개 결과는 연속 실행의 가중치/옵티마이저/스케줄러와 일치했다.
- 상담·문장·단어 데이터, 이전 검증 자료, 고정 환경 목록, 새 검증 JSON·로그를 이 ZIP에 함께 모았다.

## 아직 실행하지 않은 작업 — 다음 에이전트의 범위

1. **31B 실제 optimizer canary**: 긴 학습 후보 24건, microbatch 1 × accumulation 8로 2회 업데이트·저장, 새 프로세스에서 복원 후 1회 추가 업데이트. 4,096토큰 행을 포함한다. 옵티마이저 상태까지 넣었을 때의 VRAM 적합성과 실제 PEFT 저장·재개는 여기서 처음 확인한다.
2. **본 학습**: canary 통과 후 초기 모델에서 15,512건 1 epoch, 1,939회 업데이트. canary 가중치는 본 학습에 이어붙이지 않는다.
3. **검증 손실 B0/B1**: 같은 검증 1,724건에서 학습 전후 토큰 가중 NLL을 비교한다. 아직 이 31B 모델의 전체 B0/B1 수치는 없다.
4. **말씨 최종 과업 평가·추가 감독**: 보호자 관점의 근거 있는 감정 설명과 HOP 지원 행동, 별도 행동 평가. 이 단계는 원문 상담사 응답 모방과 구분한다. AI 초안을 임의로 정답으로 승격하지 않는다.

학습 자료 준비, 제한된 GPU 수치 검증, CPU 재개 테스트, 실제 31B 옵티마이저/학습, 서비스 배포 품질 검증을 서로 같은 상태로 보고하지 않는다.

## 이어받는 에이전트의 실행 순서

사용자가 해당 대화에서 실제 학습을 요청했다면 다음 순서로 진행한다. 상세 명령과 의미는 `README.md`에 있다.

```bash
cd /home/slim/choieram/malssi_stage1_training_20261009
bash run.sh prepare  # 업데이트 없이 환경·전수 토큰·수치·생성 검증
bash run.sh start    # canary를 통과한 뒤 B0 → 본 학습 → B1
```

`start`는 준비 검사를 다시 확인하므로 `prepare`를 먼저 실행하지 않아도 순서는 보장된다. 인수인계만 받은 상태라면 파일·환경·상태를 읽어 다음 작업을 파악하고 실제 학습 실행 요청과 구분한다.

모든 작업을 실행 스크립트가 자동 보장하는 것으로 가정하지 않는다. 먼저 `evidence/qualification.json`을 고정 코드·설정·데이터 해시와 대조하고, 현 서버의 데이터와 모델 지문을 다시 확인한다. 수정이 필요하면 기존 증거를 보존하고 변경한 범위를 다시 검증한다. 과거 실패 보고서를 통과로 고치지 않는다.

## 중단 조건과 복구

- 고정 GPU가 사용 중이거나 모델·환경·데이터·코드 해시가 다르면 중단하고 원인을 보고한다.
- OOM, NaN/Inf, 손실·gradient 기준 실패, prefix 변경, 잘못된 생성 설정, canary 저장·재개 불일치가 있으면 본 학습으로 진행하지 않는다.
- 31B 자원이 부족하면 12B 전환을 위한 별도 파일 지문·토큰·수치·canary 검증을 수행한다. GPU를 임의로 추가하지 않는다.
- 중단된 본 학습은 `bash run.sh resume`. 마지막 확정 체크포인트부터 이어간다. 체크포인트가 없는 실패를 임의로 완료 처리하지 않는다.
- 이번 자료의 4,096토큰 한도 때문에 학습 후보는 상담 초반에 편중돼 있다. 이 분포를 모든 상담 상황의 대표성으로 해석하지 않는다.
