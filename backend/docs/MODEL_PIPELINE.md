# 모델·인터뷰·검색 흐름

## 역할과 데이터

사용자는 환자의 주변인입니다. 프로젝트별 구조화 프로필은 주변인이 전한 관찰·발언·해석·모르는 정보를 저장합니다. 생성되는 코칭의 대상도 주변인이며, 환자의 내면이나 진단을 추정하는 페르소나가 아닙니다.

17개 질문은 사용자 제공 인터뷰 문항입니다. 이 문항을 임상 검사 점수로 환산하지 않습니다. `depression/anxiety/addiction/other`는 현재 발화에서 근거를 찾은 잠정적인 대화 주제이며 확진·중증도·확률이 아닙니다. 라벨 값 0–3도 범주 식별자입니다.

## 한 메시지의 처리 순서

1. 인증·소유권을 확인하고 request_id와 본문 해시를 검사합니다.
2. 완료된 동일 요청은 저장 결과를 반환합니다. 진행 중 동일 요청은 같은 결과를 기다립니다. 다른 요청은 project_busy로 거부합니다.
3. 명시적인 긴급 신호는 일반 모델 흐름보다 먼저 안전 응답을 반환합니다.
4. 추출 역할이 현재 메시지에서 여러 문항의 정보를 한 번에 구조화합니다.
5. 서버가 문항 상태와 준비 조건을 계산합니다. 질문이 필요하면 우선순위에 따라 하나만 반환합니다.
6. 코칭 단계에서는 프로필+현재 입력으로 로컬 지식 검색을 수행하고 초안을 생성합니다.
7. 서버의 구조·인용 검사와 별도 검토 호출을 수행합니다. 거부 시 수정 초안을 한 번 생성하고 재검토합니다.
8. 통과한 턴만 사용자 메시지·응답·프로필·revision·재전송 결과를 PostgreSQL 트랜잭션으로 저장합니다.

추출·코칭·검토는 분리된 프롬프트 역할입니다. 기본적으로 같은 메인 모델을 호출하며 서로 다른 세 개의 물리 모델을 요구하지 않습니다. 별도 소형 제목 모델은 설정된 경우에만 사용하며 제목 생성 실패는 날짜 기반 제목으로 처리합니다. 긴급 응답은 제목 모델을 기다리지 않습니다.

## 인터뷰 준비 조건

필수 항목 `Q1/Q2/Q4/Q15`가 모두 `answered`이고, 맥락 항목 `Q7/Q8/Q12/Q14/Q17` 중 하나 이상이 `answered`이면 `readiness.ready=true`입니다. 답변 길이·총 토큰 수·모델의 임의 확신도는 사용하지 않습니다.

질문 우선순위: `1 → 2 → 4 → 15 → 7 → 8 → 12 → 17 → 14 → 5 → 13 → 9 → 10 → 11 → 6 → 16 → 3`.

이미 answered/unknown/skipped인 항목을 자동으로 다시 묻지 않습니다. 사용자의 새 정보로 갱신할 수 있습니다. 문항을 모두 처리했지만 필수 정보가 부족하거나 `coach_now:true`로 코칭을 요청하면 `limited_profile:true`로 진행합니다. 기존 코칭 프로젝트는 새 정보를 반영하여 대화를 이어갑니다.

## 프로필의 근거와 정정

추출 결과에는 `question_id/value/status/source/evidence`가 필요합니다. `evidence`는 현재 메시지에 그대로 존재하는 연속 문자열이어야 합니다. 이전 메시지를 새 발언의 근거로 대체하지 않습니다. `unknown` 상태와 `unknown` 출처는 함께 사용합니다.

프로필에는 근거 메시지 ID와 갱신 시간을 저장합니다. 같은 질문이 갱신되면 이전 보고는 최대 8개 보존합니다. 모델 컨텍스트에는 이전 보고 중 최신 2개와 현재 정보가 들어갑니다. 전체 메시지는 PostgreSQL에 저장하고 모델에는 최근 6개 메시지와 구조화 프로필을 전달합니다. 모든 과거 원문을 매번 통째로 모델에 넣는 구조는 아닙니다.

## 모델 연결과 제한

| 항목 | 동작 |
| --- | --- |
| 연결 | 설정된 로컬 Ollama 또는 OpenAI 호환 HTTP 엔드포인트 |
| 출력 | JSON schema 기본; 호환성 필요 시 명시적인 json_object 모드 |
| 디코딩 | temperature=0, 생각 출력 비활성 요청, 비스트리밍 |
| 추출/코칭/검토 | 출력 토큰 상한 2048/1536/512 |
| 제목 | 64토큰, 최대3초; 별도 모델/주소는 별도 동시성 슬롯 |
| 호출 제한 | 설정된 HOP_LLM_TIMEOUT_MS; 모델 슬롯 대기 시간 포함 |
| 전체 턴 | 최대300초; 같은 AbortSignal을 모든 모델 호출에 전달 |
| 응답 크기 | 모델 HTTP 본문을 읽는 중1MiB 제한; 결과 문자열262144자 제한 |
| 재시도 | 자동 전송 재시도 없음; 검토 거부 시 초안 수정은 최대1회 |

HTTP 리다이렉트는 따라가지 않습니다. 모델 주소에 URL 인증정보·query·fragment를 허용하지 않습니다. API 키는 헤더로 전달하고 오류에 모델 원문을 출력하지 않습니다. JSON 중복키, 비정상 숫자, 추가 필드, 길이·배열 한도 위반과 출력 중단 응답은 거부합니다.

모델 실패는 `503`과 원인 code 및 `message_saved:false`로 반환합니다. 이미 완료된 요청은 재전송으로 모델을 다시 호출하지 않습니다. 브라우저가 대기를 중단했다고 서버 트랜잭션이 취소된 것은 아니므로 최초 request_id와 본문을 유지해야 합니다.

## 검색과 인용

[지식 데이터 계약](../data/README.md)에 맞는 JSONL 파일만 읽습니다. 한국어 문자2/3-gram과 단어의 TF-IDF 코사인 검색이며 임베딩 모델은 호출하지 않습니다. 상위3개 결과를 모델에 전달합니다. 검색 점수는 임상 지표나 확률로 제공하지 않습니다.

자료와 사용자 메시지는 모두 신뢰할 수 없는 입력으로 취급합니다. 자료에 지시문이 있어도 시스템 명령으로 따르지 않도록 역할 프롬프트에 명시합니다. 문서 ID는 이번 검색 결과의 부분집합만 인용할 수 있습니다. 인용 ID 일치 자체가 답변의 임상적 정확성을 증명하지 않으므로 별도 검토 역할이 문장과 자료의 대응도 확인합니다.

`validation`의 의미:

| 필드 | 의미 |
| --- | --- |
| approved | 해당 응답의 서버 검사/모델 검토 통과 여부 |
| clinical_validation | 항상 false; 임상 검증 완료를 의미하지 않음 |
| retrieved_count | 이번 턴에 찾은 문서 수 |
| cited_count | 초안에서 실제 인용한 문서 ID 수 |
| grounding | retrieved_reference_used 또는 no_reference_used |
| limited_profile | 필수 정보가 충분하지 않은 상태에서의 코칭 여부 |

자료를 찾지 못했거나 사용하지 않았다면 인용은 빈 배열이며 `grounding=no_reference_used`입니다. 일반적인 소통 제안을 할 수 있지만 연구 근거가 있다고 주장해서는 안 됩니다. 실제 상담 원문·선정표·manifest는 공개 저장소에 포함하지 않습니다.
