# 프론트 연결 전 점검

현재 점검 화면은 백엔드의 `/`에서 제공합니다. 로컬 SSH 포워딩을 사용한다면 `http://127.0.0.1:9000`으로 접속합니다. 이 주소는 접속하는 컴퓨터 자신을 가리키므로 팀원 각자 사용할 포워딩 또는 공통 API 주소가 필요합니다.

팀 초대 코드는 서버가 가입 요청에서 확인하는 공용 비밀값입니다. 점검 화면의 **계정 만들기 → 팀 초대 코드**에 입력합니다. 비밀번호는 12~128자입니다. 초대 코드 실제 값은 이 공개 문서에 넣지 않습니다.

## 먼저 확인할 상태

- `GET /health`가 200이면 API가 응답합니다.
- `GET /ready`는 DB와 설정된 모델을 함께 확인합니다. 모델 중지 시 503이므로, 이를 API 전체 장애로 해석하지 않습니다.
- 모델이 중지된 상태에서도 아래 계정·저장·건너뛰기·접근 권한 테스트는 가능합니다. 정상 추출과 코칭 품질은 모델이 준비된 뒤 별도로 확인합니다.
- 현재 상태를 확인하는 테스트만을 위해 모델을 시작하거나 다운로드하지 않습니다.

## 지금 화면에서 할 순서

테스트용 계정과 프로젝트에 가상 내용만 입력합니다.

| 순서 | 조작 | 통과 기준 |
| --- | --- | --- |
| 1 | 계정 만들기에서 잘못된 초대 코드 입력 후, 전달받은 코드로 가입 | 잘못된 코드는 거부되고 유효한 입력만 가입됨 |
| 2 | 로그아웃 후 잘못된 비밀번호, 올바른 비밀번호로 각각 로그인 | 잘못된 비밀번호는 거부됨. 올바른 경우 자신의 계정 표시 |
| 3 | `테스트-친구 A`, `테스트-가족 B` 프로젝트 생성 | 두 프로젝트가 구분되어 목록에 표시 |
| 4 | 친구 A에서 질문 건너뛰기를 2회 누름 | 다음 질문으로 진행하며 skipped 상태. 확보된 답변 수를 증가시키지 않음 |
| 5 | 페이지 새로고침, 로그아웃·재로그인 후 친구 A 조회 | 프로젝트와 건너뛴 기록이 보존됨 |
| 6 | 가족 B로 전환 | 친구 A의 프로필이나 메시지가 섞이지 않음 |
| 7 | 다른 브라우저 프로필/시크릿 창에서 별도 계정 가입 | 첫 계정의 프로젝트가 목록에 나오지 않음 |
| 8 | 모델 중지 상태에서 아래 짧은 입력을 전송 | 503 모델 오류. 새 메시지·프로필·revision이 저장되지 않음 |

모델 중지 상태의 입력 예시:

```text
저는 대상자의 친구이고, 일주일에 두 번 정도 연락합니다.
```

실패 전후의 `GET /api/projects/{id}`, `GET /api/projects/{id}/messages`를 비교하면 미저장을 확인할 수 있습니다. UI에 남아 있는 작성 중 입력은 서버에 저장된 메시지와 다릅니다. HTTP 응답을 아예 받지 못한 경우에는 저장 여부를 단정하지 말고 최초 request_id와 같은 본문으로 재시도합니다.

건너뛰기를 17번 끝까지 반복하면 마지막에는 제한적 코칭을 시도합니다. 모델이 꺼져 있으면 그 마지막 요청은 성공하지 않습니다. 모델 없는 저장 테스트에는 첫 2~3번만 사용합니다.

## API 클라이언트로 추가할 검사

비밀번호 변경, 프로젝트 삭제, 같은 request_id 재전송, 잘못된 UUID/본문은 [OpenAPI](../openapi.json) 또는 [TypeScript 클라이언트](../client/index.ts)로 검사합니다. 내장 화면에 모든 API의 버튼이 있는 것은 아닙니다.

| 검사 | 요청/조건 | 기대 |
| --- | --- | --- |
| 로그인 전 보호 경로 | `GET /api/projects` | 401 |
| 다른 사용자의 프로젝트 | 두 번째 계정으로 첫 번째 프로젝트 ID 조회 | 404, 내용 노출 없음 |
| 저장 중복 방지 | 아직 질문이 남은 새 프로젝트에 `skip:true`와 같은 UUID·본문을 두 번 전송 | 같은 결과, 저장된 메시지는 한 턴만 증가 |
| 요청 ID 오용 | 성공한 request_id를 다른 본문에 재사용 | 409 |
| 잘못된 입력 | UUID 형식 오류, 빈 일반 메시지, skip와 text 동시 입력 | 422, 상태 변경 없음 |
| 비밀번호 변경 | `POST /api/auth/password` | 새 비밀번호 적용, 기존 다른 세션은 무효 |
| 프로젝트 삭제 | 자신이 만든 테스트 프로젝트만 삭제 | 프로젝트와 연결된 메시지는 조회 불가 |
| CORS/Origin | 명시적으로 허용하지 않은 origin의 변경 요청 | 403 |

건너뛰기 중복 검사 본문:

```json
{
  "request_id": "2f3d8bcc-9630-4bde-8e6f-7c4d6cedd082",
  "skip": true
}
```

새 검사에는 새 UUID를 사용합니다. 동일 요청 재전송 검사에만 UUID와 본문을 그대로 유지합니다. 쿠키 인증의 변경 요청은 허용된 Origin이 필요합니다. 자세한 인증·오류 계약은 [프론트 연동 가이드](FRONTEND.md)를 따릅니다.

## 모델이 준비된 뒤 붙여넣을 입력

각 독립 시나리오는 새 프로젝트에서 시작합니다. 기대 문장과 똑같이 답하는지를 검사하기보다, 저장된 근거와 정보 출처 및 요청한 코칭이 일치하는지 확인합니다.

### 1. 한 번에 충분한 정보 제공

```text
저는 대상자의 10년 된 친구이고 주 2회 정도 연락합니다.
친구는 지난 2주 동안 모임에 나오지 않았고, 직접 “일 때문에 지쳐서 대화할 힘이 없다”고 말했습니다.
제가 가장 걱정하는 것은 계속 연락해서 친구에게 부담을 주는 일입니다.
친구는 산책할 때는 조금 편하다고 했고, 답장을 재촉하지 말아 달라고 했습니다.
부담을 주지 않으면서 곁에 있다는 뜻을 전할 짧은 문자와 제가 할 수 있는 행동 하나를 알고 싶습니다.
```

기대: 관계·어려움·걱정·필요한 도움·맥락이 실제로 추출되면 17문항 전체를 요구하지 않고 코칭 가능. 대화 부담과 답장 경계를 존중함.

### 2. 모르는 정보

```text
저는 직장 동료입니다. 요즘 점심을 혼자 먹는 모습만 봤습니다.
왜 그러는지, 잠은 잘 자는지, 치료를 받고 있는지는 모릅니다.
```

기대: 모르는 내용을 사실처럼 채우지 않음. 관찰을 질환이나 점수로 확정하지 않고 추가 질문.

### 3. 관찰과 추측 분리

```text
제가 직접 본 것은 친구가 두 번 약속을 취소한 일입니다.
“나를 싫어하나 보다”는 제 추측이고 친구에게 확인한 말은 아닙니다.
```

기대: 약속 취소는 관찰, 싫어한다는 생각은 주변인의 해석으로 구분.

### 4. 같은 프로젝트에서 정정

```text
앞서 매일 술을 마신다고 말한 것은 제 추측이었습니다.
본인에게 확인하니 지난달 모임에서 두 번 마셨다고 합니다.
매일 마신다는 내용을 현재 사실로 사용하지 말아 주세요.
```

기대: 이전 보고가 있으면 이력을 보존하면서 최신 정정과 출처를 반영. 이전 보고가 없는 새 프로젝트에서는 그런 이력을 만들지 않음.

### 5. 주변인의 감정 구분

```text
친구가 아프다고 한 것은 아닙니다. 친구에게 답장이 없으면 제가 불안해서 잠을 못 잡니다.
친구의 실제 상태는 잘 모르겠고, 제가 연락을 어느 정도로 해야 할지 도움받고 싶습니다.
```

기대: 주변인의 불안·불면을 대상자 증상으로 저장하지 않음. 관계와 필요한 도움을 구분.

### 6. 정보가 적어도 도움 요청

```text
상대의 자세한 사정은 모릅니다. 부담을 주지 않고 안부를 물을 문자 한 문장이 필요합니다.
```

입력 후 **현재 정보로 코칭**을 요청합니다. 기대: 정보가 충분하다고 바꾸지 않고 제한적 코칭. `validation.limited_profile:true`.
