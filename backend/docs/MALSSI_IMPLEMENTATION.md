# 말씨 v2 백엔드 구현 및 검증

기준: 2026-10-09. 개발 명세 원본은 `MALSSI_BACKEND_SPEC_V1.md`, 문항 계약은 `MALSSI_QUESTIONNAIRE_V1.json`입니다. 원본의 ‘설계 문서만 작성’ 문구는 당시 작성 범위를 설명합니다. 이 문서는 현재 구현 범위와 검증 상태를 별도로 기록합니다.

## 실행 범위

기존 Node.js·TypeScript·PostgreSQL 인증과 `/api/*`를 유지하고 `/api/v2/*`를 추가했습니다. 프론트엔드 구현은 포함하지 않습니다. 기존 `public/index.html`은 v1 점검 화면이며 신규 v2 화면으로 표시하지 않습니다. 프론트 연동 계약은 `openapi-v2.json`과 `client/v2.ts`입니다.

v2는 기본 비활성화입니다. 내부 합성 테스트에는 명시적으로 draft 카탈로그를 허용할 수 있습니다. 공개 게시에는 루트 권리·콘텐츠 승인과 검토 증빙이 필요합니다. 현재 제공 카탈로그는 draft이므로 `/health/ready`는 출시 준비 완료를 반환하지 않습니다. 실제 모델 smoke 성공과 콘텐츠·임상 검토 완료는 다릅니다.

DB 테이블의 민감 상세 필드는 버전별 서버 검증을 거친 `encrypted_payload` 안에 있습니다. 조회/잠금에 필요한 소유권·리비전·상태·시각만 평문 열입니다. 명세의 모든 필드를 평문 열로 옮긴 형태는 아닙니다. 기존 001 마이그레이션은 변경하지 않고 002~004를 추가했습니다. 기존 사용자 기록을 자동으로 장기 기억으로 승격하지 않습니다.

## 개발 실행

Node 24.19.0 이상과 PostgreSQL 16 이상을 사용합니다. 기존 모델·데이터·DB를 초기화하지 않습니다.

1. migration 계정으로 `npm run migrate`를 실행합니다.
2. `HOP_RUNTIME_ROLE`을 지정해 `npm run db:grant`를 실행합니다. API 계정은 테이블 소유자, superuser, BYPASSRLS가 아니어야 합니다.
3. 32바이트의 독립 난수 키를 base64로 설정합니다. `HOP_CONTENT_KEY`를 저장소, 로그, DB 비밀번호와 공유하지 않습니다. 키가 없거나 잘못되면 v2가 시작되지 않습니다.
4. 내부 개발에서만 `HOP_V2_ENABLED=true`, `HOP_V2_ALLOW_DRAFT=true`를 명시합니다.
5. `npm start`로 API를 시작합니다. 모델을 사용하려면 별도로 `HOP_V2_MODEL_ENABLED=true`를 설정하고 `npm run worker:v2`를 실행합니다. API 기동이 모델을 시작하지 않습니다.

모델은 기존 로컬 HTTP 어댑터 규격을 사용합니다. `HOP_LLM_BASE_URL=http://127.0.0.1:18011/v1`, 실제 모델 ID, 내부 API 키 및 검증된 `HOP_MODEL_CONTEXT_SIZE`를 설정합니다. `/tokenize`를 제공하는 llama.cpp 호환 서버가 필요합니다. 네트워크 장애에서 클라우드로 전환하지 않습니다.

GPU launcher는 `node scripts/serve-gpu1.mjs`입니다. `HOP_MODEL_BINARY`, `HOP_MODEL_WEIGHTS`, `HOP_MODEL_KEY_FILE`, `HOP_MODEL_LIBRARY_PATH`, `HOP_STATE_DIR`에 `/home/slim/choieram/ys` 내부의 기존 경로를 지정합니다. nvidia-smi의 물리 GPU 1번을 UUID로 해석하고 해당 장치만 노출합니다. 장치가 없으면 중단하며 GPU 0번으로 대체하지 않습니다. 모델 슬롯은 1개입니다. 다운로드·학습·기존 모델 변경은 하지 않습니다.

`/api/v2/capabilities`는 모델 실행 설정과 출시 검증을 구분합니다. 이 PR에서는 `personalized_guidance=false`, `model_validation=not_release_validated`입니다. `model_execution_enabled=true`는 개발 추론을 허용한다는 의미입니다.

## 프론트 연동

기존 `/api/auth/register`, `/api/auth/login` 인증을 사용합니다. 쿠키 쓰기는 허용된 Origin을 필수로 전송합니다. 명시적으로 선택한 동의를 `/api/v2/consents`에 저장한 다음 프로젝트와 상담을 생성합니다.

쓰기 응답은 `request_id`, `saved`, `resource_revision`, 자원 ID와 `next_actions`를 반환합니다. 민감 데이터를 멱등 원장에 복제하지 않기 위해 질문 본문을 쓰기 응답에 중복 저장하지 않습니다. 이어서 `GET /api/v2/conversations/{id}`로 질문·선택지·답변·준비 조건을 읽습니다. 이는 명세 예시에서 질문을 즉시 반환하는 방식과의 명시적인 구현 차이입니다.

202의 `run_id`로 결과를 조회합니다. 모델 실패도 입력이 저장되었으면 `input_saved=true`입니다. 네트워크 단절에는 같은 `request_id`와 같은 본문을 다시 보내세요. revision 충돌 시 새 스냅샷을 읽고 새 요청을 작성합니다. 안전 보류에서는 일반 질문·가이드로 이동하지 않습니다.

SSE는 검증 전 토큰을 보내지 않으며 자원 참조만 보냅니다. 최종 결과는 run 조회에서 읽습니다. Bearer 토큰을 URL에 넣지 마세요. `EventSource`는 쿠키 인증을 사용하고 Bearer 사용자는 fetch 기반 SSE 클라이언트를 사용합니다.

DELETE는 JSON 본문 또는 `Idempotency-Key`·`If-Match` 헤더를 사용합니다. 계정 삭제에는 현재 비밀번호 재인증이 필요합니다. 반환된 단기 receipt를 `Authorization: Deletion <receipt>`로 보내면 세션 폐기 후에도 해당 삭제 상태만 읽을 수 있습니다. receipt를 URL이나 로그에 기록하지 마세요.

## 보관·백업·복원

보관 비동의 프로젝트는 24시간 기한의 별도 프로젝트 암호화 키를 사용합니다. 해당 키 원장은 UNLOGGED 테이블이고 백업에서 제외합니다. **암호문 행 자체는 일반 DB dump에 포함될 수 있지만, 복호화에 필요한 임시 키는 포함되지 않습니다.** 명세의 물리적으로 분리된 임시 저장소와는 차이가 있으며 공개 전 별도 저장소/백업 필터 정책을 확정해야 합니다. 원본 본문을 일반 로그나 새 학습 데이터로 내보내지 않습니다.

`npm run retention:v2`는 만료 프로젝트, outbox, 실행 메타데이터와 감사 기록을 정리합니다. 기존 사용자 공간 supervisor에서 시간 단위로 호출하도록 배치해야 합니다. 이 PR이 운영 스케줄을 자동 등록하지는 않습니다. 현재 프로젝트 보관 만료는 생성 시 90일이며 활동 기반 연장 UI/정책은 출시 전 보완 대상입니다.

삭제 원장은 백업과 독립적으로 보관해야 합니다. `node scripts/malssi-deletion-ledger.ts export <새 절대경로>`는 원문 없이 무작위 ID·삭제 범위를 인증 암호화해 내보냅니다. 복원 시 먼저 `HOP_RESTORE_PENDING=true`로 API 시작을 차단하고, 복원 대상 백업보다 최신이며 마지막 삭제까지 반영한 원장을 `apply`로 재적용합니다. 적용 검증 후에만 차단 설정을 해제합니다. 오래된 삭제 원장을 최신으로 간주하지 마세요.

기존 backup CLI는 임시 키를 제외하도록 보완했습니다. FORCE RLS 전체 백업에는 API와 분리된 적절한 backup 역할이 필요합니다. 백업 파일 전체 암호화·30일 회전·외부 보관·실제 pg_restore 복구 연습은 운영 담당 환경에서 검증해야 하며 이 PR의 테스트 결과로 완료를 주장하지 않습니다.

## 검증과 남은 인수 항목

검증 기록은 `MALSSI_VALIDATION.md`에 정리합니다. 단위 테스트, 실제 PostgreSQL 통합 테스트, 모델 응답을 주입한 worker 회귀와 GPU 1번 실제 추론을 구분합니다. 원문·실사용자 데이터·키·모델 가중치·비공개 실행 로그는 커밋하지 않습니다.

다음은 구현 또는 출시 검증이 아직 필요한 범위입니다.

- 기존 v1 원자료의 검토 가능한 v2 이관 도구와 동의 후 전환 절차. 기존 자료는 원본 그대로 보존합니다.
- 카탈로그 게시/퇴역 레지스트리와 콘텐츠 검토 워크플로. 현재 버전은 파일로 고정되어 있습니다.
- 선택과 자유문 사이의 의미 충돌 확인, 항목별 확인 1회 제한, 목표별 설명 로그의 세부 정책.
- 검토 증빙이 있는 지식·지역 자원 디렉터리. 현재 v2는 빈 근거/지역 자원으로 제한 안내만 허용합니다.
- 임시 기록의 물리적 분리, 활동 기반 보관 연장, 독립 백업 암호화·회전·복구 실측.
- 토큰별 비용·지연 집계, half-open 회로의 독립 합성 회복 판정, 장기 대화 요약의 저우선 작업자.
- 연령·지역 이용 자격 확인, 관리자/검토자 권한과 MFA, 공개 HTTPS·부하/SLO 검증.
- 명세 21.2의 240개 콘텐츠 회귀군, 60개 안전군 평가와 독립적인 한국어 콘텐츠 검토. 현재 문자열 규칙은 전체 위험 탐지기로 검증된 것이 아닙니다.

이 항목을 충족하기 전에는 운영 배포나 전체 명세 인수 완료로 표시하지 않습니다. 신규 기능은 기본 off이며 검토용 PR로 제공합니다.
