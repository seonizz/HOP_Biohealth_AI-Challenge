# 서비스 화면의 정보 범위

- **지정자: 사용자**
- **지정일: 2026-10-15**
- 사용자 요청: “서비스에 불필요한 자세한 내용은 들어가지 않도록 해. 문서에 남겨, 내가 지정했다고.”

서비스 화면에는 이용자가 서비스를 이해하고 사용 여부·다음 행동을 결정하는 데 필요한 정보만 간결하게 표시한다. 개발자가 설명하기 위해 필요한 세부사항을 화면이나 접힌 상세 영역에 쌓지 않는다.

## 화면에 남기는 내용

- 무엇을 도와주는지, 질문에 어떻게 답하면 되는지, 생성한 안내를 어떻게 활용하는지.
- 처리 대기·실패·재시도·삭제 등 현재 행동에 필요한 안내.
- 진단·치료를 대신하지 않는다는 서비스 범위.
- 입력 정보의 저장·모델 전송, 기록 삭제와 접근 상실처럼 이용자의 판단에 영향을 주는 사항. 상세한 운영 구성 대신 쉬운 문장으로 설명한다.

## 문서에 보관하는 내용

모델명·규모·체크포인트·프롬프트 버전·소스 해시, 원천/적재/학습 데이터의 수량 대조, 학습 진행량, NLL·F1·표본 수, 검증 설계·테스트 개수·미완료 목록, 면담 방법의 연구 상세와 운영 설정값은 문서에 둔다.

- 현재 모델과 검증: [현황과 할 일](../../docs/current/현황과_할일.md)
- 데이터·학습·연구 수치: [데이터와 연구](../../docs/current/데이터와_연구.md)
- 사전 평가·운영 계약: [제출 범위와 검증 계약](../../docs/competition/04_제출범위와_검증계약.md)
- 구현과 모델 계약: [관계 에이전트](RELATIONSHIP_AGENT.md)

발표자료·개발 문서는 이 사용자 화면 제한의 대상이 아니다. 필요한 근거를 명확히 남긴다. UI 과장 문제를 해결할 때도 검증 내역을 전부 화면에 노출하는 방식 대신, 과장된 표현을 제거하고 설명 범위를 실제 기능에 맞춘다.
