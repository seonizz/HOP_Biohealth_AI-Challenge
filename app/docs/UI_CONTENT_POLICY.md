서비스 화면에는 이용자가 서비스를 이해하고 사용 여부·다음 행동을 결정하는 데 필요한 정보만 간결하게 표시한다. 개발자가 설명하기 위해 필요한 세부사항을 화면이나 접힌 상세 영역에 쌓지 않는다.

## 화면에 남기는 내용

- 무엇을 도와주는지, 질문에 어떻게 답하면 되는지, 생성한 안내를 어떻게 활용하는지.
- 처리 대기·실패·재시도·삭제 등 현재 행동에 필요한 안내.
- 진단·치료를 대신하지 않는다는 서비스 범위.
- 입력 정보의 저장·모델 전송, 기록 삭제와 접근 상실처럼 이용자의 판단에 영향을 주는 사항. 상세한 운영 구성 대신 쉬운 문장으로 설명한다.

## 대화와 불씨 안내 (2026-10-18 사용자 지정)

평소 질문은 일상적인 관찰과 사용자가 전하고 싶은 말에서 시작한다. 병원·상담 또는 위험한 답변으로 유도하지 않는다. 답변의 맥락에서 상담을 권할 근거가 확인되면 대화 종료 후 불씨가 안내하되 위험 점수·등급을 드러내며 사람을 단정하지 않는다. 비긴급 안내는 짧은 제안과 선택해서 펼치는 기관 정보로, 즉시 위험 안내는 필요한 행동을 분명히 보여 준다. 서비스의 진단 한계와 데이터 처리 안내는 계속 유지한다.

### 종료 후 원문 인용 카드만 사용 (2026-10-23 사용자 지정)

- 불씨는 버전 2만 사용한다. 대화 중에는 불씨를 요청하거나 표시하지 않으며 대화가 끝난 결과 화면에서만 추가 카드를 확인한다. 버전 선택 화면은 두지 않는다. 이 지침은 이전의 대화 중·종료 후 통합 표시 지침을 대체한다.
- 모델은 일시적인 스트레스·기분 변화·잠 부족·갈등이나 주변인의 막연한 걱정만으로 일반 상담 근거를 만들지 않는다. 일반 정서·음주·약물 관련 어려움은 지속·반복과 생활 지장이 함께 보고된 경우에만 분류한다. 전문가 상담·진료·기관 연결을 명시적으로 원하는 경우도 안내할 수 있으며, 친구를 위로하거나 말을 걸 방법을 알고 싶은 서비스 이용 목적은 전문 상담 요청으로 간주하지 않는다.
- 일반 상담 근거는 현재·최근의 실제 보고이고 대상이 명확하며 두 번의 독립 분류가 같은 근거에 동의한 경우에만 카드에 포함한다. 불확실성·정보 부족·과거의 일반적인 어려움 또는 단독 분류 결과만으로 카드를 띄우지 않는다. 이름만 입력했거나 부정·가정뿐인 상황에서도 근거를 만들어 내지 않는다.
- 카드는 서버가 현재 저장한 원문과 상담을 권하는 이유를 함께 제시하고, 비긴급 안내에는 “혼자 감당하지 않아도 괜찮아요. 가까운 시일 안에 도움을 받을 수 있도록, 상담할 곳을 함께 살펴볼까요?”를 사용한다. 모델이 재작성한 원문이나 위험 점수·등급을 표시하지 않는다. 결과 화면 새로고침 시 같은 정책으로 저장된 근거를 복원한다.
- 자해·자살·폭력·신체 응급상황·학대·방임·심각한 기본 생활 기능 저하에 대한 기존 안전 분류는 유지한다. 일반 상담의 지속·반복 요건으로 명시적인 안전 근거를 누락하지 않는다. 대화의 기존 긴급 안전 종료 흐름은 유지하며 불씨는 그 결과 화면에서 표시한다.

### URL 복원과 단계 표시 (2026-10-22 사용자 지정)

- 새로고침 뒤에도 같은 대화·결과·기록·칼럼 화면을 열 수 있게 URL을 구성한다. 대화 내용이나 인증값은 주소에 넣지 않는다.
- 작성 중 입력은 같은 탭에서 잠시 보관하고, 저장 기능을 사용할 수 없는 경우에만 보내지 않은 입력의 이탈을 확인한다. 전송한 답변은 서버 저장 상태를 사용한다.
- 불씨·로딩·대화·입력 영역이 서로 가리지 않도록 배치한다. 진행바는 실제 완료된 단계에 맞춰 채우고, 결과 저장 전에 완료로 표시하지 않는다.
- 대화 상단의 진행바는 칸 구분 없는 연속 진행바로 유지한다. 다음 질문과 결과를 기다리는 동안에는 기존 점 세 개 애니메이션을 표시한다. `0 / 29단계 완료` 같은 숫자 문구와 단계별 목록·박스는 표시하지 않는다(2026-10-23 사용자 추가 지정).
- 다음 질문을 준비하는 동안에도 미리 입력할 수 있다. 작성한 내용은 다음 질문의 입력란으로 이어지고, 전송은 질문이 준비된 뒤 가능하다. 선택만 가능한 질문에서는 초안을 별도로 보관하며 전송한 답변과 섞지 않는다.
- 저장의 기술 상세와 검증 내역은 이 문서와 개발 문서에 두고, 화면에는 복원·대기·다음 행동에 필요한 짧은 안내만 남긴다.

- 최종 카드들은 검토를 통과한 순서대로 표시한다. 아직 준비 중인 영역에는 점 세 개 애니메이션을 유지하며, 부분 카드에는 저장 완료 문구를 표시하지 않는다. 전체 검토와 기록 저장이 끝난 뒤 저장 완료를 안내한다(2026-10-23 사용자 추가 지정).

## 카드 디자인 복구 및 변경 제한 (2026-10-23 사용자 지정)

사용자의 후속 요청 “깃에 있는 내용으로 복구해 최종출력”에 따라 Git 기준은 `85fe360`의 결과 카드 표시와 스타일로 고정한다. 이 기준은 표시 영역에 적용하며, 이후 추가된 실제 모델 호출·병렬 생성·부분 출력·비동기 입력·저장 기능을 되돌리는 근거로 사용하지 않는다.

사용자가 첨부한 두 이미지의 카드 형식을 기준으로 복구한다. 사용자 요청은 “원래 저런 형식이였어 작업하는 에이전트가 마음대로 수정 못하도록 지침 만들어”와 “해당 카드 이미지처럼 다시 복구”이다. 이후 명시적으로 요청한 디자인 변경만 허용한다. 일반적인 개선·수정·검증 요청은 재디자인 허가가 아니다.

| 당신의 마음도 소중해요 | 연한 초록색 둥근 카드, 왼쪽 마스코트, 오른쪽 제목·공감 문단·작은 초록색 도움말. 도움말은 목록 기호 없이 표시한다. |

- 병렬 생성 중에도 완성된 내용은 기존 카드 모양으로 즉시 보여 준다. 두 실천 카드가 모두 준비되면 같은 두 열 배치를 사용한다. 생성 완료 순서 때문에 카드 디자인을 새로 만들지 않는다.
- 결과 화면과 저장된 기록 화면에 같은 형식을 적용한다. 복사되는 값은 표시된 전체 발화와 같아야 한다.
- 이 제한은 화면 형식에 관한 것이다. 실제 모델 출력이나 저장 결과를 이미지와 똑같은 예문으로 바꾸거나, 긴 출력을 임의로 자르거나, 검증을 생략해서 맞추지 않는다.
- 검토용 `conversation_detail` 등 기존 데이터의 저장·읽기 계약은 보존한다. 저장된 상세 정보가 있다는 이유로 화면에 새로운 설명 영역을 노출하지 않는다.
- 작업 에이전트와 하위 에이전트는 UI 수정 전 이 기준을 읽고, 수정 후 결과·기록·생성 중 화면 및 좁은 화면을 확인한다. 사용자가 승인하지 않은 디자인을 통과시키기 위해 기준 또는 회귀 검사를 완화하지 않는다.

첨부 원본은 상담 문구가 포함될 수 있으므로 Git에 넣지 않는 로컬 `runtime/ui-layout-reference-20261023/`에 보관한다. 형식 계약은 위 표와 공용 카드 컴포넌트의 회귀 검사로 유지한다.
