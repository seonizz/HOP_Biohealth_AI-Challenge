# 말씨 v3 질문 계약

2026-11-13 제공된 「말씨 질문셋 강화구조 v3」의 질문 체계를 새 대화에 적용합니다. 질문셋 식별자는 `malssi-intake-3.0.0-rc1`입니다. 원본은 기본 질문 9개와 필요한 경우에만 사용하는 확인 질문 1개입니다. 이후 2026-11-17 사용자의 “추가 질문 + 답변에 맞춘 질문셋” 요청으로 새 대화에 맞춤 추가 질문을 최대 2개 허용했습니다. 현재 상한은 12개이며 모두 답하도록 요구하는 개수가 아닙니다. 이름 필수 입력과 예전 후속·마무리 질문은 사용하지 않습니다. 원본은 설계 참조 자료이고, 실행 연결은 아래 앱 어댑터와 회귀검사로 관리합니다.

목적·관계 등 선택형 질문에는 보기와 직접 입력을 함께 보낼 수 있습니다. 전송 전 단일 선택은 같은 보기를 다시 눌러 해제할 수 있어 직접 입력만 남길 수 있습니다. 모름은 ‘없음’, 가능한 도움은 ‘약속’, 제안은 ‘합의/실행’으로 바꾸지 않습니다. 관계 유형만으로 말투를 정하지 않습니다.

## 질문 수와 목적별 필요성

새 대화는 **목적(Q3-01) → 상황(Q3-03)**을 먼저 묻고 보통 총 **2~4개**에서 마칩니다. 목적 답변에 상황까지 있으면 실제 근거로 상황 질문도 생략할 수 있습니다. 이후 모델이 꼭 필요한 질문을 명시적으로 선택하지 않으면 결과 생성으로 넘어갑니다. 남은 문항을 순서대로 자동 발행하지 않으며 4개를 채우도록 요구하지 않습니다.

9개는 질문 후보 은행입니다. 추가 질문은 아직 없는 정보가 요청한 결과를 실질적으로 바꾸고, 그 정보 없이는 정확한 답을 만들 수 있을 때만 선택합니다. 내부 이유에는 부족한 정보와 결과에 미치는 영향을 함께 적습니다. 4개 이후에는 미확인·조건부 표현으로 마치는 것이 기본이며, 잘못된 사람·행동·시간·동의를 전제하게 되는 핵심 모호함에 한해 예외를 둡니다. Q10 한 번·맞춤 질문 두 번·전체 12개 상한은 유지합니다. 모델 판단의 품질과 실제 질문 수 분포는 실모델 평가 대상이며 상한만으로 입증하지 않습니다. [구현과 회귀 범위](COMPACT_QUESTIONS_2026-11-17.md)를 참고하세요.

| 원하는 도움 | 필요한 정보의 중심 | 항상 요구하지 않는 정보 |
| --- | --- | --- |
| 거절·경계 표현 | 거절하려는 범위와 본인 의사 | 상대 감정, 대안 시간, 상대 동의 |
| 가능한 시간을 넣은 제안 | 제안할 행동과 실제 가능한 시간 | 이미 합의했다는 전제 |
| 약속·합의 정리 | 정리할 항목과 확인된 합의 상태 | 모르는 반응·합의를 추측해 채우기 |
| 상황 정리 | 이용자가 보고한 장면 | 모든 사람의 감정·지원 계획 |
| 내 생각·마음 정리 | 이용자가 표현한 경험 | 상대의 도움 선호·본인의 지원 여력 |
| 도움·말 걸기 선택 | 목적·상황과 선택에 필요한 의사·여력 | 결과 선택을 바꾸지 않는 추가 세부 정보 |

원본 `tasks.json`의 과업 정의는 유지합니다. 현재 앱이 원본 참조 엔진의 과업별 완료 상태와 출력 모드 전체를 구현했다는 뜻은 아닙니다. 맞춤 질문은 실제 원문의 인용을 붙여 기존 문항을 먼저 고르거나, 기존 문항으로 확인할 수 없는 중요한 정보에 한해 추가합니다. 기존 질문 문구·보기·ID는 유지하며 동적 질문은 해당 대화에만 저장합니다. [맞춤 질문 계약](PERSONALIZED_QUESTIONS_2026-11-17.md)을 참고하세요.

## 진행과 근거

- 필수 이름과 최소 답변 수는 없습니다. 새 대화에서는 목적·상황을 우선하고 그 밖의 질문 번호를 순차 진행 명령으로 사용하지 않습니다.
- 모델은 원문과 요청 목적을 근거로 이미 다룬 질문(`already_covered`)과 불필요한 질문(`not_needed`)을 구분합니다. 생략으로 답변이나 사실을 만들어 저장하지 않습니다.
- `answered`, `unknown`, `skipped`, `refused`, `not_understood`, `stop`을 구분합니다. 첫 설명은 등록 도움말을 보여 주며 같은 질문 인스턴스와 작성 중인 보기·직접 입력을 유지합니다. 초안은 새 응답 revision에 연결하여 같은 탭의 새로고침에도 복원합니다. 반복해서 이해하기 어렵다고 하면 건너뛰며 지난 질문 초안을 다음 질문에 옮기지 않습니다.
- 목적뿐 아니라 일반 답변을 정정해도 기존 생략 결정을 무효화하고 아직 제시하지 않은 질문의 필요성을 다시 판단합니다. 이미 답한 질문을 반복하거나 Q10 사용 예산을 되돌리지 않으며, 이미 표시했으나 아직 답하지 않은 질문은 같은 인스턴스로 이어갑니다.
- 새 대화의 일반 추가 답변은 원문이 바뀌지 않은 `already_covered` 결정을 유지하여 같은 내용을 다시 묻지 않습니다. 문맥에 따른 `not_needed`는 다시 판단합니다. 선택하지 않고 종료한 문항은 `not_asked`이며 생략 근거나 답변을 만들지 않습니다.
- 건너뜀·모름·거절을 다른 표현으로 다시 묻지 않습니다. 종료와 거절에 동반된 원문은 일반 사실 확장에 쓰지 않고 기존 안전 검토에 전달합니다.
- 종료 접수 뒤에는 일반 질문과 새 일반 결과를 생성하지 않습니다. 모델 확인이 실패해도 종료 의사를 유지하고 같은 제출의 재시도만 허용합니다. 현재 원문으로 확인된 긴급 안전 안내는 기존 안전 경로로 제공합니다.
- Q10은 행동자·실행·출처·시점·동의·양태 중 한 축만 확인합니다. 실제 원문 ID·revision·구성요소·정확한 인용·Unicode 위치·사건 ID에 결합하며, 한 선택으로 다른 축을 확정하지 않습니다. 사람 확인은 역할, 합의 확인은 항목 ID도 필요합니다.
- Q10은 한 대화에 한 번입니다. 정정·재시도·새로고침으로 사용 예산을 되돌리지 않으며 오래된 원문에 대한 선택은 거절합니다.
- 질문이 어느 사람에 관해 묻는지와 답변 안의 사건 주체를 구분합니다. Q1과 Q5 등 복합 답변도 실제 원문을 근거로 각 사람의 말·행동을 해석해야 합니다.

## 판본·DB·기존 기록

실행 기본값은 [questions.json](../seeds/questions.json), 원본 묶음은 [questionnaire-v3](../seeds/questionnaire-v3/bundle.json)입니다. 원본 manifest의 `reference_only`, `active_reference_candidate`, `production_approved:false`는 첨부 묶음의 지위를 그대로 보존한 값입니다. 앱 적용이 원본의 운영 승인이나 임상 검증을 뜻하지 않습니다. 원본 질문·과업·정책·의미 정의의 SHA-256을 읽을 때 검증하며, 새 대화는 `bundle_id`와 이 정의 전체를 질문 스냅샷에 보관합니다. 일부 질문만 다른 판본과 섞거나 등록 문구를 임의 수정하면 `QUESTION_BANK_INVALID`로 거절합니다. 판본 변경은 묶음 정의와 어댑터·검사를 함께 갱신해야 합니다.

`010_questionnaire_v3.sql`은 이전 질문 행을 `question_bank_archive`에 보관하고 비활성화한 뒤 새 9문항을 등록합니다. 사용자 대화·기록·선택 번호는 다시 쓰지 않습니다. 이전 대화는 저장된 질문 스냅샷을 쓰며, 스냅샷이 없는 초기 대화만 [이전 시드](../seeds/questions-legacy.json)를 사용합니다. [이전 질문 운영 문서](QUESTIONS_LEGACY.md)는 호환성 기록입니다.

짧은 진행 정책은 새 intake의 `v3.compact_flow.version=1`에 저장합니다. 이 표시가 없는 이전 저장 대화에는 재개 시 소급 적용하지 않습니다. 질문 문구·번들 해시·DB 질문 행을 바꾸는 마이그레이션은 필요하지 않습니다.

조회 명령은 계속 사용할 수 있습니다.

```sh
npm run --silent questions -- list
npm run --silent questions -- get q3_01
```

현재 묶음은 부분 `set/disable/delete` 대상으로 관리하지 않습니다. 새 질문은 서버 시작 시 마이그레이션이 실행된 DB에서 사용됩니다.

## 적용 범위

이 교체는 질문 수집·생략·확인·근거 출처·저장·입력 화면에 적용합니다. 원본 ZIP의 별도 출력 모드·임상 평가·과업 성공률은 이 변경의 구현 또는 검증 결과가 아닙니다. 기존 최종 카드의 디자인·저장 형식과 승인된 안전 정책은 유지합니다. 과거 29문항으로 생성한 정적 결과 예시는 과거 예시로만 보관합니다.

새 묶음의 모델 처리는 `MODEL_PROTOCOL=relationship_agent`를 사용합니다. 검토 방식은 관리자 실행 설정을 따릅니다. 검토를 사용하는 경로는 질문·안전을 독립 검토하며, 기본 단독 1회 경로는 질문 처리 중 별도 검토 호출을 하지 않고 최종 결과 검토는 유지합니다. 상세 호출·역할 설정은 [모델 실행 설정](MODEL_EXECUTION_SETTINGS_2026-11-17.md)을 따릅니다. 이전 `json_schema`/`json_prompt` 프로토콜로 새 묶음을 처리하려 하면 모델 호출 전에 `MODEL_PROTOCOL_UNSUPPORTED`로 알립니다. 이전 대화는 해당 프로토콜의 기존 계약을 유지합니다.

미전송 초안은 기존과 같이 같은 탭의 `sessionStorage`에 최대 24시간/32개까지 보관하고, v3에서는 묶음과 질문 인스턴스까지 연결합니다. 제출·삭제·세션 변경에 따른 기존 정리 규칙도 유지합니다.

검증 결과와 실제 모델 호출의 한계는 [v3 교체 검증](QUESTIONNAIRE_V3_VERIFICATION.md)에 기록했습니다.
