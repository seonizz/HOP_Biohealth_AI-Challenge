# 실제 앱의 불씨 자동 안내 통합 검증

검증일: 2026-10-18. 역할 분담: 다른 담당자는 모델 개발, 이 작업은 UX/UI와 앱 내부 연결을 담당한다.

## 구현

- 실제 대화 화면에서 서버의 `referral_available`과 최신 revision을 기준으로 위험 분류를 자동 요청한다. 즉시/빠른 도움이나 별도 안전 경고가 있으면 불씨 안내를 표시한다.
- 안내 문장은 `app/seeds/referral-messages.json`에서 개발자가 등록한다. 모델이 문장을 생성하거나 수정하지 않으며, 응답의 `message_id`와 원문을 그대로 사용한다.
- 캐릭터 설정은 기존 `guide-characters.js` 레지스트리로 분리했다. 이름과 이미지 경로를 교체할 수 있다. 불씨 전용 이미지 자산과 음성 출력은 이번 구현에 포함하지 않았다.
- 기관 링크는 등록된 디렉터리에서만 제공한다. 실제 전화·예약은 사용자가 링크를 선택하는 방식이며, 기관에 대화 내용을 자동 전송하지 않는다.
- 답변 수정·화면 이동·삭제·revision 변경 시 이전 결과와 늦게 도착한 응답을 무효화한다.
- 일반 대화 생성이 실패하더라도 서버에 저장된 검증된 pending 답변은 독립적인 위험 분류에 사용할 수 있다. 기록 화면의 `이어가기`로 미완료 대화를 복구한다.

주요 구현: `app/public/js/components/ReferralGuide.js`, `app/public/css/referral.css`, `app/public/js/core/conversation.js`, `app/public/js/components/RecordsScreen.js`, `app/src/referral-guidance.js`, `app/src/referral-runtime.js`, `app/src/referral-messages.js`, `app/src/server.js`.

## 실행 환경과 실제 화면 검증

- 새 실행본: <http://127.0.0.1:9001/>. 실제 `app/src/server.js`와 `app/public`을 사용하며 기존 DB와 암호화 키를 재사용한다.
- 기존 9000 앱과 18080 모델 연결은 중단하지 않았다. 과거 v9·v11 두 배포본을 재발행했다는 의미는 아니다.
- 로컬 Ollama `gemma4:12b`를 명시적으로 선택했다. 원격 모델 실패 시 자동으로 공급자를 전환하는 기능은 아니다.
- 합성 대화 `검증용 친구`를 실제 앱에서 생성하고, 저장된 대화의 `이어가기`를 눌렀다. 별도 경고 버튼 없이 실제 로컬 모델 분류 후 불씨의 즉시 도움 안내와 등록된 기관 링크가 표시됐다.
- 화면 문장과 개발자 등록 문장의 정확한 일치를 확인했다. 미전송 답변을 수정하자 경고가 사라졌고, 다시 대화를 열자 자동 안내가 재현됐다.
- 화면 증거: `runtime/referral-app-20261018/actual-app-warning.png`. 최종 브라우저 콘솔 오류·경고는 없었다.
- 실제 전화 또는 예약 링크는 실행하지 않았다. 일반 대화 생성은 해당 합성 사례에서 `MODEL_INVALID_RESPONSE`가 발생했으며, 독립 경고 경로의 성공과 구분한다. 임상 성능 검증 결과가 아니다.

## 검증 및 데이터 보존

- 최종 관련 테스트: **294개 통과, 실패 0, 생략 0**. API·저장·보존·UI·위험 분류·기관 연결·고정 문장 관련 테스트를 포함한다.
- `npm run check`의 JavaScript 문법 및 JSON 검사, `git diff --check` 통과. 전체 프로젝트 테스트를 통과했다는 주장은 아니다.
- 기존 대화 9개, 기록 2개, 상태 이력 260개, 질문 31개, 마이그레이션 6개의 기존 행 해시와 암호화 키가 유지됐다.
- 합성 검증 후 대화 10개, 기록 2개, 상태 이력 264개다. 기존 행의 삭제·덮어쓰기는 없으며, 검증 대화는 남겨두었다. 브라우저 활동 시간 등 DB 전체의 바이트 동일성을 의미하지 않는다.
- 증거: `runtime/referral-app-20261018/focused-final.log`, `preservation-before.json`, `preservation-after.json`.
- 별도 테스트 화면 서버와 해당 테스트 DB 컨테이너는 종료했다. 로컬 모델은 검증 후 메모리에서 내려두었고 다음 호출 시 다시 로드된다. 실제 앱 9001과 기존 앱 9000은 실행 상태로 유지한다.

설정과 API 계약의 상세는 `app/docs/REFERRAL_GUIDANCE.md`를 참고한다.

## 후속 변경: 자연스러운 관찰과 조용한 개입

사용자가 위험한 답변을 유도하지 않고 자연스러운 답변을 살펴 안내하도록 요청했다. 비긴급 안내의 등급 배지·제목을 없애고 짧은 고정 제안과 기관 정보 펼치기로 바꿨다. 연결 실패는 위험 판정처럼 표현하지 않는다. 즉시 위험은 문장과 전화 링크를 그대로 펼쳐 보여 준다. 인물이 다른 경고는 일상적인 문장으로 대상 구분을 유지한다.

기본 질문 `want`, `others_why`, `burden`, `need`, `others_help`의 예시·전제를 중립적으로 다듬었다. `007_natural_prompts.sql`은 기존 기본 정의 및 설정이 모두 일치하는 경우만 바꾸며 새 대화부터 적용한다. 기존 대화의 질문 스냅샷, 사용자 답변·기록·이력과 관리자 수정은 유지한다. 모델의 분류 기준과 생성 프롬프트는 수정하지 않고 담당자에게 요구를 전달했다.

최종 관련 테스트는 **298개 통과, 실패·생략 0** (`runtime/referral-app-20261018/subtle-tests.log`). 독립 리뷰에서도 긴급 경고 유지와 데이터 보존의 차단 문제는 발견되지 않았다. 실제 DB에서 직전 기준의 대화 10개·기록 2개·이력 264개의 기존 행 해시와 키가 유지됨을 확인했고, 기본 질문 5개 외에는 질문 행이 바뀌지 않았다. 이번 합성 일상 대화가 추가되며 전체 행 수는 증가할 수 있다. 보존 증거는 `preservation-subtle-before.json`, `preservation-subtle-after.json`이다.

후속 실제 화면 검증: `일상 대화 확인`이라는 합성 대화에서 친구에게 부담 없이 안부를 묻고 산책을 제안하는 답변을 입력했다. 일반 대화 모델은 `MODEL_INVALID_RESPONSE`를 반환했지만 저장된 답변의 독립 분류 2회는 정상 응답했고, 불씨 위험 경고는 표시되지 않았다. 다음 질문 생성의 성공이나 분류 정확도 전반을 입증한 것은 아니다. 새 중립적인 입력 예시와 위험 경고가 없는 실제 화면은 `runtime/referral-app-20261018/natural-conversation.png`에 저장했다. 모델 담당자에게 일반 답변의 형식 오류를 전달했다.
