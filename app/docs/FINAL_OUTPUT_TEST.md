# 최종 출력 테스트 페이지

`/test-runner.html`에서 답변을 일괄 전달하고 서비스의 최종 생성·검토 경로로 결과를 만듭니다. 기존 `/test-result.html`은 이전 질문지로 만든 정적 합성 예시 화면으로 유지하며, 새 v3 대화·모델 생성·DB 저장의 검증 증거가 아닙니다.

1. 예시 불러오기, JSON 붙여넣기 또는 파일 불러오기로 답변을 준비합니다.
2. 최종 출력 생성을 누릅니다. 여러 사례는 입력 순서대로 하나씩 실행합니다.
3. 검토를 통과한 부분 카드는 즉시 표시합니다. 사례 선택으로 결과를 확인하고 결과 JSON 내려받기로 입력·결과를 함께 내려받습니다.
4. 중단은 현재 모델 요청을 취소하고 남은 사례를 실행하지 않습니다.

## 입력

한 사례는 `{ "title": "사례 이름", "answers": { "문항 ID": "답변" } }`, 여러 사례는 `{ "cases": [사례, 사례] }`입니다. 최대 20개 사례, 전체 JSON 256 KiB 이내입니다. 화면 문항 목록은 현재 DB 설정을 읽으며 문항 수를 고정하지 않습니다.

- 글: 문자열. 공백·줄바꿈을 보존합니다.
- 선택: 정확한 보기 문구 배열 또는 0부터 시작하는 보기 번호 배열. 단일 보기 문구도 지원합니다.
- 직접 입력: `{ "custom": "답변" }`. v3의 단일·복수 선택과 함께 넣을 때는 `{ "selected": [0], "custom": "추가 답변" }`.
- 상세 입력이 있는 단일 보기: `{ "selected": [0], "text": "상세 답변" }`.
- 명시적 건너뛰기: `null` 또는 `{ "skipped": true }`. 기존 필수·건너뛰기 불가 검증을 적용합니다.
- API 형식 `answers: [{ "question_id": "q3_03", "text": "…" }]`도 지원합니다. 예시 불러오기는 현재 DB의 v3 ID를 사용합니다.

누락한 문항은 필수 여부와 무관하게 `not_asked`로 남깁니다. 최종 출력 실험은 부분 입력도 허용하며 임의 답변이나 자동 생략 결정을 만들지 않습니다. 현재 v3 일괄 입력은 활성 기본 문항 `q3_01`~`q3_09`만 받습니다. 동적으로 원문에 결합하는 `q3_10`은 이 페이지의 입력 대상이 아니며 정상 대화에서 확인합니다. 이전 질문 스냅샷의 조건부 기본 문항은 명시한 답변을 포함합니다. 일반 대화의 모델 질문 선택·문맥에 따른 생략·후속 질문은 변경하지 않습니다. 그 흐름의 검증은 기존 서비스 화면을 사용합니다.

## 실행과 격리

`POST /api/test-runs/:uuid`에 `{ "answers": [...] }`를 보내면 `createTestIntake`가 기존 답변 검증을 적용하고 `buildContext`로 문맥을 구성합니다. `gateway.respond(context, null)`은 같은 최종 상태 분석·원문 근거 검토·가이드 생성 경로를 실행합니다. 문항별 `updateState` 호출은 하지 않습니다.

`GET /api/test-runs/:uuid/progress`는 실행 중 승인된 카드와 진행 상태를 반환합니다. `DELETE /api/test-runs/:uuid` 또는 생성 연결 종료는 요청을 취소합니다. 세션당 하나, 인스턴스당 최대 네 개 실행을 허용합니다. 세션 쿠키·CSRF·Origin 검사와 HTTP 256 KiB 제한을 공유합니다. 다른 세션에서는 조회·중단할 수 없습니다.

입력·결과는 실행 중 메모리에만 존재하고 일반 intake·기록 테이블에는 저장하지 않습니다. 모델에는 서비스와 동일하게 전송됩니다. 완료·오류 시 서버 실행을 제거하며 새로고침 후 복원되지 않습니다. 사용자가 내려받을 때만 파일을 만듭니다. 내려받은 입력·출력은 상담 원문을 포함할 수 있으므로 Git 추적 대상이 아닌 `runtime/` 등에 보관합니다.

출력은 기존 `ResultScreen`, `GuideCards`, `base.css`, `result.css`를 재사용합니다. 돌봄·발화·두 열 실천 카드와 복사 동작은 동일합니다. 테스트의 저장 안내만 “내 기록에 저장하지 않았어요”로 표시합니다. 별도 기록 저장과 불씨 기관 안내 요청은 실행하지 않습니다.

검증: `node --test tests/test-intake.test.js tests/test-runner.test.js tests/test-runner-api.test.js`. HTTP·DB 검사는 `TEST_DATABASE_URL`과 임시 스키마·합성 모델 응답을 사용하며 실제 모델 품질 검증과 구분합니다.
