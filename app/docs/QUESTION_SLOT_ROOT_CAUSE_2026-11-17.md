## 새 출력 계약

외부 API와 저장되는 논리적 판단은 기존 `skip` 배열이다. 모델 전송에서만 다음처럼 현재 허용된 문항별 칸을 사용한다.

```json
{
  "skip": {
    "q3_02": null,
    "q3_03": {
      "reason": "already_covered",
      "evidence": ["e0"],
      "explanation": "해당 문항을 생략하는 원문 기반 설명"
    }
  },
  "clarify": [],
  "safety": {"urgent": false, "evidence_ids": []}
}
```

위 예시는 형식 설명용이며 생략 판단의 승인 예제가 아니다. `null`은 이번 판단에서 그 문항을 생략하지 않는다는 뜻이다. 생략·미응답을 실제 답변이나 사실로 채우지 않는다. 다음 답변에서는 현재 원문으로 다시 판단한다. 후보가 없으면 `skip:{}`, 긴급 안전 신호이면 모든 칸을 null로 두고 기존 긴급 처리로 전달한다.

- 문항과 이유마다 기존에 허용된 근거 분기를 그대로 유지한다. 다른 문항·이유의 근거를 합치지 않는다.
- 스키마의 모든 문항 키가 필수이고 추가 키는 금지한다. 미지원 스키마는 모델 호출 전에 거부하며 이전 배열로 몰래 되돌아가지 않는다.
- 근거 ID 압축을 꺼도 고정 문항 구조는 적용한다. 정확한 원문 복원과 기존 의미 검증은 계속 실행한다.
- 선택된 항목만 원래 배열로 복원한다. 배열 순서는 스키마 문항 순서로 정규화하며, 생략 적용은 문항 ID를 기준으로 한다. 임의 순서까지 byte-identical이라고 주장하지 않는다.
- 논리 입력에 중복 ID가 있으면 인코딩도 거부한다. 중복 제거, 설명을 보고 문항 ID를 추정하는 보정, 검증 완화는 하지 않는다.
- JSON 키의 이스케이프 표기가 달라도 같은 키면 중복으로 거부한다. 문법을 무시하는 공급자의 응답도 파서에서 거부된다.
- 근거 레지스트리는 슬롯 구성까지 성공한 뒤에만 반영한다. 근거 표의 모든 스키마 경로는 새 구조의 실제 분기를 가리킨다.

판단 출처의 `prompt_version` 접미사는 `question-slots-v2`로 구분한다. 일반 모델 설정과 12B 기본 경로를 일괄 전환하지 않는다.
