# 안전 판단과 원문 표현의 일관성

2026-11-01 로컬 수정. 기존 독립 검토·품질 검토·질문 생략·암호화 저장·카드 디자인을 유지한다.

## 수정 내용

### 동일 원문의 안전 검토 보존

기존에는 `buildContext`와 최종 모델 입력이 검토된 `urgent=true`만 전달했다. 검토된 `false`는 누락돼 최종 분석이 같은 원문을 다른 분기로 분류할 수 있었다.

`currentReviewedSafety`는 두 판단 모두 다음 조건으로 검증한다.

- 분류 `basis`와 `urgent`가 일치하고 검토 이유가 존재한다.
- 전체 답변 출처의 스냅샷이 현재 원문과 일치한다.
- 근거가 현재 원문의 허용된 출처이며 중복이 없다.

검토된 결과는 최종 입력의 `reviewed_safety`와 저장 provenance에 보존한다. 같은 원문에 대한 생성 단계의 제안으로 독립 안전 판단을 뒤집지 않는다. `false`는 안전 확인이나 위험 부재의 증명으로 설명하지 않고 검토의 분류·이유·불확실성을 유지한다. 기존 긴급 판단용 `currentApprovedSafety`는 호환성을 유지한다.

답변이 변경됐거나 스냅샷이 없는 이전 기록이면 `buildContext`는 `safety_review_required`로 표시한다. 최종 생성 전 전체 현재 원문을 독립적으로 다시 검토하며, 새 판단에 따라 긴급·비긴급 모두로 변경할 수 있다. 이후 분석·계획·품질·최종 독립 검토는 그대로 수행한다.

### 발신자와 사실의 범위

공통 `SOURCE_FIDELITY_CONTRACT`를 각 모델 요청에 한 번 전달한다. 작성된 문장뿐 아니라 질문 생략 이유와 검토자의 `reason`·`repair`에도 적용한다.

- 메시지·전화·발언의 발신자와 수신자를 구분한다.
- 시점·지속 시간·빈도·수량·강도를 원문보다 늘리지 않는다.
- 공감이나 미확인 내용에 확인되지 않은 행동·희망을 전제하지 않는다.
- 검토자가 제안한 수정 예문도 새 사실의 근거로 취급하지 않는다.
- 원문에 실제 보고된 표현과 의미를 보존하는 바꿔쓰기는 허용한다.

추가 원문 대조에서 확인한 지원 방향 역전은 제한된 표현 검사로 반려한다. 강조 부사가 있는 형태도 포함하되 감사·과거 전언·피할 예문을 구분한다. 또 혼자 보내는 시간이 길다는 정적 보고를 시간이 늘었다는 변화로 바꾸지 않도록, 같은 대상자·활동에 대한 실제 증가 보고를 확인한다. 질문·조건·부정은 증가 사실의 근거로 사용하지 않고 후속 명시적 정정을 반영한다. 두 검사 모두 기존 카드 수정과 독립 재검토로 연결되며 자동 문장 교정이나 자동 승인은 하지 않는다.

질문 검토에는 받은 연락만으로 이용자가 먼저 건넨 말까지 확인됐다고 설명하지 않도록 경계를 추가했다. 실제로 질문·응답이 보고됐다면 그 범위를 인정하며 문맥에 따른 질문 생략은 유지한다. 품질 검토는 사실을 확장하는 완성 예문보다 원문 근거와 보존할 의미를 지목하는 최소 수정 지시를 요구한다.

최초 수정 버전은 `relationship-v3.23-source-fidelity`·`combined-turn-v52`다. 후속 호출 최적화까지 포함한 현재 버전은 `relationship-v3.25-source-attribution`·`combined-turn-v56`다. 의미 검토를 특정 표현의 일괄 금지로 대체하지 않는다.

## 수정 지시의 원문 경계

실제 후속 검증에서 해결된 미확인 항목을 제거하라는 검토 지시가 “확인되지 않음”을 붙인 설명문으로 재생성됐다. 블록 수정 지시가 중요한 미확인을 보존하라고 하면서 모든 항목이 이미 해결된 예외를 충분히 명시하지 않은 점을 보완했다. 같은 사람·시점·범위의 항목 전체가 답변됐으면 제거하고 모두 해결되면 `[]`가 정상이다. 명시적인 부정과 모름을 구분하며, 검토 이유·삭제 지시·수정 경과는 미확인 정보가 아니다. 실제 남은 미확인과 거절·상충은 계속 보존하고 새로운 독립 검토를 받는다.

## 검증

- `safety-consistency.test.js`: 같은 원문에서 상충하는 최종 생성 제안, 변경 후 독립 재검토와 긴급 전환, 이전 비긴급 기록, 판단 계약 검증.
- `final-safety-persistence.test.js`: 검토된 비긴급 판단의 저장·재조회·원문 보존.
- `source-fidelity-prompts.test.js`: 작성·검토·수정 요청에 공통 규칙 한 번 전달, 발신자·시간 원문 투영, 독립 검토와 질문 생략 유지.
- 최초 안전·원문 수정 당시 전용 로컬 PostgreSQL을 사용한 전체 회귀 검사: 2,067개 통과, 실패·건너뛰기 0개. JavaScript 구문·JSON 검사 통과.
- 구현 후 독립 코드 검토에서 확정 결함 없음. 별도 지정 Ollama 코드 검토 API는 연결 시간 초과로 결과를 얻지 못했다.
- 후속 저장 출력의 별도 원문 대조에서 발견한 도움의 귀속, 노력 정도 단정, 무제한 응답 약속을 추가 검증한다. `guidance-source-attribution.js`는 공식 질문과 같은 도움의 출처를 구분하고, `knownSpeechIssues`는 제한된 표현 검사를 수행한다. 위반은 기존 카드 수정·독립 재검토로 돌려보내며 자동 수정하거나 승인하지 않는다.
- 후속 수정까지 포함한 전체 앱 회귀 검사: **2,352개 통과, 실패·건너뛰기 0개**. 도움 귀속 검증 62개와 최종 검토 묶음 40개 검사, 독립 재현 9개에서 미해결 결함이 없었다. 실제 요청, 다른 사람의 요청, 요청 철회, 이름 표기·조사를 구분하는 반례를 포함한다.
- 지지 방향 검사 57개 회귀와 독립 경계 사례 21개가 통과했다. 중간 수식어·소유어 생략이 있는 잘못된 권장 발화를 반려하면서 감사·과거 전언·금지 예문은 구분한다. 모델 검토가 승인한 경우에도 기존 카드 수정과 새로운 독립 검토를 거치며, 반복 오류는 원래 시도 제한을 따른다.

실제 사례 입력·모델 요청·출력·저장 검증 증거는 Git에서 제외된 `runtime/haeun-source-fidelity-20261101/`에 보관한다. 첫 실제 실행은 발신자·기간 과장과 안전 분류 보존은 개선됐으나 피할 말 카드 수정 단계에서 중단돼 최종 저장에 도달하지 못했다. 동등한 제목(`피할 말:`)을 잘못 반려하던 검사를 고치고, 대안 발화의 발신자와 근거 경계를 보완했다. 후속 최적화 실행과 최종 저장 증거는 `runtime/haeun-call-optimization-20261101/`에 보관하며 [호출 최적화 기록](REVIEW_CALL_OPTIMIZATION.md)과 함께 확인한다. 원문·출력을 추적되는 문서나 테스트에 복사하지 않는다.

최신 로컬 검증에서는 안전 분류와 근거가 최종 저장까지 일치했고 지원 방향·도움 귀속·시간 추세 오류를 모델이 수정한 뒤 새 독립 검토를 통과했다. 최종 카드와 저장된 상세를 별도로 원문 대조했으며 저장·재조회 기록 전체가 정확히 일치했다. 실제 작성 결과를 이어받고 모든 승인을 새로 검토한 마지막 실행은 11 POST, 형식 재시도 0회, 내용 수정 2회였다. 상세 실행 범위와 실패 실행을 포함한 계수는 위 호출 기록에 구분했다.

## 한계

안전 판단 보존과 저장 일치는 소프트웨어 계약 검증이다. 임상 판단의 정답이나 모든 생성 문장의 정확성을 보장하지 않는다. 제한된 표현 검사는 모든 발신자·시간 표현을 판별하지 않는다. 프롬프트와 기존 독립 검토도 함께 유지하며 실제 생성 결과와 원문을 대조해야 한다.

앞선 승인 상태를 이어받은 실제 검증에서는 중간 미확인 정보가 받은 도움·지지 인물·주변의 권고를 충분히 구분하지 못했고, 질문 생략 이유가 원문의 미언급을 명시적인 모름처럼 설명하는 문제가 남았다. 최종 카드의 문장 수정과 구분해 추적한다. 문맥에 따른 질문 생략은 유지하며, 생략 사유의 근거 정확성은 후속 보완 대상이다.
