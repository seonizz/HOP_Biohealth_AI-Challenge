## 입력 중복 제거와 검토 경계

- 독립 상태·질문·안전 검토를 하나의 요청에 묶되 각 task의 원래 입력·스키마·validator와 모든 승인 조건을 유지한다. 작성 요청과 검토 요청은 분리한다.
- 최종 검토에서는 일부 검토가 필요로 하지 않는 필드를 제외한 답변 묶음이 다시 복제되고 있었다. `shared_input_projections`는 공통 객체에서 원래 task에 실제 존재한 필드만 참조한다. 다른 task의 추가 원문이나 과거 기록을 가져오지 않는다.
- 전송 전 정확한 역복원 비교와 실제 바이트 절감 검사를 수행한다. 잘못된 참조·충돌·순환·누락·중복 키·미사용 projection은 거부한다. 요청 바인딩은 실제 전송 요청에 고정한다.
- 공유 테이블의 별칭으로 옮겨진 retrieval도 명시적인 retrieval 참조에 한해 처리한다. 일반 documents 필드를 임의로 출처로 바꾸지 않는다.
- 전체 초안이 한도를 넘거나 형식 복구가 필요해 블록 경로로 내려갈 때도 기존 opt-in 입력·지시 범위 최적화를 적용한다. 원문 절단·출력 예약 축소·독립 승인 생략은 하지 않는다.
- Q3-09 검토 기록에서 전체 인용과 그 일부가 겹친다는 이유로 재작성이 발생했다. 이런 형식만으로 의미 오류를 단정하지 않도록 지시를 명확히 했다. 원문 불일치·근거 없는 주장·주체/시점/범위 왜곡·정정 누락과 실제 의미 거절은 계속 차단한다. 프롬프트 버전은 combined-turn-v57이다.

compact review 출력 옵션도 비교했다. 큰 검토의 출력 표현은 줄일 수 있지만 입력 설명·슬롯 스키마가 늘어난다. 이전 최종 검토를 새 중복 제거와 함께 전송할 때 일반 출력은 입력 29,356토큰, compact 출력은 31,937토큰으로 측정됐다. 후자는 출력 예약 포함 여유가 831토큰에 그쳐 이번 프로필에서는 사용하지 않는다.
