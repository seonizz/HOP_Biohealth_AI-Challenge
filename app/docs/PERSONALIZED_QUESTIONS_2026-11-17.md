# 답변에 맞춘 질문셋과 추가 질문

2026-11-17 사용자 요청: “추가 질문 + 답변에 맞춘 질문셋”. 새 v3 대화에서 활성화한다. 공통 질문 DB·질문 번들·기존 카드 디자인은 유지한다.

## 동작

- **기존 질문셋 조정:** 모델이 아직 표시하지 않은 관련 문항을 먼저 선택한다. 서버는 실제 답변의 짧은 인용을 질문 앞에 붙이고 원래 문항·선택지·주체·ID를 보존한다. 근거에 따른 생략도 유지한다.
- **맞춤 추가 질문:** 기존 문항으로 확인할 수 없는 중요한 정보가 있을 때 짧은 자유서술 질문을 최대 2개 만든다. 상황·행동·감정·관계·변화·지원범위·목적 중 한 범위를 확인한다. 추가 질문은 의무가 아니다.
- 새 대화의 상한은 기본 9개 + 사건 확인 Q3-10 한 번 + 맞춤 질문 2개 = 12개다. 이전 저장 대화는 기존 10개 계약을 유지한다. 모름·거절·건너뜀·취소된 추가 질문도 횟수를 소비한다.
- 31B 질문 전용 경로는 `question_plan` 한 번에서 생략·순서·맞춤 질문·안전 제안을 처리한다. 추가 생성 호출과 자동 재시도는 넣지 않았다. 최종 분석·결과 생성·독립 검토 호출은 이 질문당 1회와 별도다.

## 저장과 검증 경계

`personalization`은 null 또는 단일 `next`/`follow_up` 결정이다. 다음 기본 문항 선택과 추가 질문을 한 응답에서 동시에 발행하지 않는다. 기존 Q3-10과도 동시에 발행하지 않는다.

결정은 `source_question_id`, `source_revision`, `component`, 정확한 인용과 Unicode 코드 포인트 구간에 연결한다. 서버가 현재 답변과 다시 대조한다. 모름·거절·건너뜀·종료 원문은 맞춤 질문의 출처로 사용할 수 없다. 인용은 최대 160 코드 포인트, 추가 질문·내부 이유는 각각 최대 240자로 제한한다. 근거의 존재만으로 자유 질문의 의미가 자동 승인되는 것은 아니다.

실제 표시 문구는 `asked_question`, 원래 문항은 `canonical_question`으로 보관한다. 사용자별 동적 정의와 이력은 `v3.personalization`에 저장하고, 추가 답변은 `clarificationAnswers`에서 기존 암호화 intake·결과 record 경로로 전달한다. 사용자가 답하기 전에는 질문 문장이나 생성 이유를 보고된 사실로 만들지 않는다. 기존 문항과 정확히 같은 추가 질문 및 같은 출처·주체·확인 범위를 반복하는 질문은 차단한다. 의미만 유사한 재질문 여부는 모델 지침과 검토 경로의 독립 검토 대상이다.

원문 정정은 연결된 추가 답변을 연쇄 무효화한다. 중간 Q3-10이 이미 무효화되어도 자식 질문까지 전파한다. 뒤로 가기는 실제 답변 순서를 따르며, 답변된 Q3-10 편집에서 그냥 떠나면 마지막 저장 답변과 상태를 복원한다. 모델 실패·재시도는 미표시 질문의 발행 수를 늘리지 않는다. 종료·긴급 위험·도움말 재표시 중에는 새 맞춤 질문을 발행하지 않는다.
