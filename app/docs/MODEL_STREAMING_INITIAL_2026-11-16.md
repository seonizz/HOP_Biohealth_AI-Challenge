> 이후 웹 연결 요청으로 현재 새 대화 기본 모델은 31B다. 단일 호출 승격 없이 독립 검토를 유지한다. 현재 주소·관리자 기능·GPU 유휴 종료 조건은 [웹 서버 접속 안내](WEB_SERVER_ACCESS_2026-11-16.md)를 따른다. 아래 검증 종료·GPU 반환 설명은 이전 실행의 기록이다.

> 이 문서는 최초 스트리밍 소스 구현 시점의 기록이다. 이후 관리자 재개 작업에서 현재 로컬 앱에 실제 적용했다. 최신 적용·검증·남은 31B 항목은 [관리자 작업 재개 결과](ADMIN_MODEL_PARALLEL_HANDOFF_2026-11-16.md)를 따른다.

## 구현 결과

사용자의 재개 요청에 따라 관리자 연결 편집 staging을 본 소스에 선별 통합하고, 질문 답변·최종 결과 API에서 앱 화면까지 SSE를 연결했다. 현재 소스의 구현·로컬 검증 결과이며 기존 실행 앱의 배포 완료 기록은 아니다. 기존 앱·`.env`를 변경하거나 재시작하지 않았고 Git 커밋·푸시도 하지 않았다.

- 질문 `POST .../answers`: 같은 요청에서 진행 상태를 받고 검증·저장된 다음 질문 view로 종료한다. SSE 사용 때문에 모델 호출을 추가하지 않는다.
- 결과 `POST .../result`: 진행 상태·검토된 완성 카드를 준비 순서대로 전달한다. 전체 검토와 DB 기록 저장이 끝난 뒤 `result`를 전송한다. 첫 SSE 진행 이벤트를 받으면 기존 폴링을 취소한다. 이전 JSON 서버에는 폴링 호환 경로를 유지한다.
- 원시 모델 JSON·추론·미검토 문장을 사용자에게 전송하지 않는다. 글자 단위로 미검토 문장을 보여주는 기능은 추가하지 않았다. 기존 카드 배치·색상·복사 버튼·점 세 개 대기 표시를 유지한다.
- 기존 모델 스트림 재구성 코드는 그대로 사용한다. 로컬/LAN의 `MODEL_STREAM_JSON=true` 연결은 모델 SSE를 재구성하고 기존 스키마·근거 검증을 거친다. 비스트리밍 모델 연결도 앱 SSE의 진행·완성 카드 전달은 사용할 수 있다.
- `singleCallTurns`의 1회 시도 제한과 최종 독립 검토를 유지한다. 스트림이 끊기거나 JSON이 불완전하면 추가 호출로 우회하지 않는다. 미완성 답변·사실을 저장하지 않는다. 문맥상 질문 생략 기능을 제거하지 않았다.

## 관리자 설정 통합

`/admin/models`와 기존 두 프로필의 연결 조회·저장 API를 본 앱에 통합했다. 선택 기능은 기존 `MODEL_SELECTION_ENABLED=true` 설정을 따른다. 주소·모델·키를 암호화된 불변 버전으로 저장하고 새 대화에 고정하며, 기본 모델 선택과 연결 편집은 별도로 저장한다. 키는 조회하지 않고 빈 입력은 기존 키를 유지한다.

초기 환경 프로필의 baseline도 암호화해 보존한다. 여러 앱 시작이 겹쳐도 같은 baseline ID로 수렴한다. 명시적 논리 모델 ID가 저장된 대화는 환경 모델명을 바꾼 재시작 뒤에도 원래 연결을 사용하고, 편집 후 시작한 대화는 해당 불변 버전을 사용한다. 이어가기·불씨·결과 저장도 같은 ID를 해석한다. 모델 ID가 전혀 없는 오래된 대화는 기존 환경 gateway를 사용하는 호환 경로이며 `.env` 자체를 바꾼 재시작까지 고정되는 것은 아니다.

31B 주소·모델·키 변경은 기존 1회 호출 승인을 해제한다. 이번 변경으로 미검증 31B 연결을 자동 승인하거나 12B 운영 설정을 단일 호출로 변경하지 않았다. 제3 API 모델 프로필은 추가하지 않았다.

## 취소·오류·저장 경계

- 인증·CSRF·Origin·입력 검사는 동일하며 초기 오류는 JSON HTTP 응답이다. 스트림 시작 뒤 오류는 원래 `status`·`code`가 담긴 `error` 이벤트다.
- 같은 소유자·대화·버전의 실행은 구독자가 공유한다. 하나가 나가도 다른 구독자가 있으면 계속하며 마지막 구독자가 끊기면 모델을 취소한다. 답변의 저장된 pending은 남아 기존 복구 경로로 이어간다.
- 서버 종료와 DB 조회 사이에 경합이 있어도 구독 등록 경계에서 취소된 작업을 정리한다. 이 검사 중 발견한 신규 실행 경합을 수정했다.
- 각 구독자는 시작 즉시 현재 스냅샷을 받는다. 카드 삭제·검토 후 교체·전체 재시도도 스냅샷으로 반영한다. 15초 heartbeat와 느린 구독자 버퍼 제한을 둔다.
- 브라우저는 UTF-8 문자·SSE 줄 경계가 여러 청크로 나뉜 응답을 처리하고, terminal result 없는 종료를 성공으로 처리하지 않는다. 취소·다른 화면·교체된 요청·다른 버전의 이벤트는 반영하지 않는다. POST 자동 재전송을 추가하지 않았다.

상세 이벤트 계약은 [API 계약](API.md)의 스트리밍 전송 절과 [OpenAPI](openapi.json)를 따른다.

## 적용 및 남은 검증

GPU 서버 접속·작업 금지 지침을 유지했다. SSH·GPU 추론·학습·큐 재가동을 수행하지 않았다. 따라서 이전 인계에 남아 있던 실제 31B 전체 대화의 생략 이유·가명 계약·최종 생성과 DB 저장 검증 및 단일 호출 승인은 이번 작업의 완료 주장에 포함하지 않는다. 현재 31B worker/큐 자체의 원격 토큰 스트리밍 지원을 추가한 것도 아니다.

소스 통합과 앱 SSE 구현은 완료했다. 기존 앱은 재시작하지 않았으므로 관리자 연결 편집과 SSE가 현재 실행 앱에 적용됐다고 안내하지 않는다. 실제 적용 시에는 적용할 소스·DB·연결 설정을 대조하고, 31B 검증은 사용자의 GPU 사용 명시 허용 범위 안에서 별도 실행해야 한다.
