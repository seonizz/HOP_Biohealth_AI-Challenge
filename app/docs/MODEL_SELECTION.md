## 연결 설정

`MODEL_SELECTION_ENABLED=true`이면 관리자 모델 설정 API를 활성화한다. 로컬 주소 `http://127.0.0.1:9000/admin/models`에서 12B·31B를 선택하고 저장한다. 설정은 PostgreSQL `model_selection`에 저장되어 앱 재시작 후에도 유지되며 새 대화에만 적용된다. 일반 대화 생성 API에서 모델 ID를 보내 변경하는 요청은 거부한다. 기존 `MODEL_*` 설정은 12B 프로필이며, `GPU31B_MODEL_*`는 별도의 31B 프로필이다. 31B는 로컬 모델·검토자·인증 정보를 상속하지 않는다. 선택 목록 응답은 ID·표시 이름·설정 여부만 포함하며, 관리자 연결 조회에는 주소·모델명·키 설정 여부도 포함한다. 키 값은 반환하지 않는다. `available`은 설정 여부이며 모델 서버의 실시간 응답 보장은 아니다. 미설정 모델은 선택할 수 없고, 연결 실패 시 다른 모델로 전환하지 않는다.

관리자 페이지와 API는 로컬 루프백 접속·로컬 호스트만 허용하고, 프록시 전달 헤더를 거부한다. 저장은 기존 세션·CSRF·Origin 검사를 모두 통과해야 한다. URL을 숨기는 것만으로 권한을 대신하지 않는다. 이 설정은 개인용 로컬 앱에 한정되며 원격 관리자 접속 기능은 제공하지 않는다.

관리자 화면에서 기존 두 프로필의 API 주소·모델명·키를 편집한다. 빈 키는 기존 값을 유지하며 키 값은 조회 응답에 포함하지 않는다. 외부 주소는 HTTPS, 로컬/LAN 주소는 HTTP도 허용한다. 연결 변경은 기본 모델 선택과 별도로 저장한다.

프로필 ID 또는 불변 연결 버전 ID는 새 대화 생성 시 암호화 상태에 저장한다. 기록에는 실제 모델과 해당 ID를 남기고 불씨·추가 대화에서도 같은 버전으로 해석한다. 최초 프로필 연결은 암호화된 baseline으로 저장해 환경 변경 후 재시작해도 이전 논리 모델 ID가 원래 연결을 사용한다. 연결 편집은 새 불변 버전을 만들며 기존 대화는 이전 버전을 유지한다. 모델 ID가 전혀 없는 이전 대화도 선택 프로필과 구분되는 최초 legacy gateway·원래 검토자·기존 불씨 연결 설정을 암호화 보존하며, 선택 기능이 활성화된 재시작에서 동일한 연결을 사용한다. 프로필이 있는 대화는 해당 연결이 없을 때 오류로 종료한다. 선택 기능이 꺼졌다고 다른 모델로 대신 처리하지 않는다.

## 31B 서비스 연결

검증한 모델은 step5128이며 과거 controlled 모델의 포트나 체크포인트를 재사용하지 않는다. `scripts/serve-gpu31b-queue.mjs`는 자격 검사를 마친 독립 실행 폴더의 큐만 연결한다. API는 Mac 루프백에만 열고 별도 인증 키를 사용한다. 인증 키는 무시된 실행 폴더와 로컬 `.env`에만 저장한다. 형식 제약·스키마 해시·원격 생성 증명 검증을 유지한다. 모델이 중단되면 503을 반환하며 다른 모델로 전환하지 않는다.

서비스는 이번 실행에서 시작한 GPU 프로세스만 사용한다. 기존 큐의 유휴 제한과 작업 종료 제한을 유지하며, 종료 시 소유 GPU 프로세스를 반환한다. 로컬 앱은 계속 실행될 수 있으나 GPU가 반환된 뒤 31B를 사용하려면 새로운 인증·자격 검사를 거친 실행을 연결해야 한다. GPU 재부팅·reset·전역 서비스 설치는 하지 않는다.

## 출력 안정성에서 발견한 문제와 수정

- 단일 호출의 긴급 초안이 일반 모델 오류로 막히던 경계를 수정했다. 이제 승인되지 않은 `safetyReviewPending`에 보관하고 질문을 마친다. 기존 조건부 안전 안내를 표시하며, 최종 결과는 반드시 독립 안전 검토를 통과해야 한다. 보류를 승인으로 표시하지 않는다.
- 중단된 대화의 최종 판단이 비긴급이면 일반 결과를 생성하지 않는다. 검토 결과를 저장하고 보류를 해제해 재로드 때 같은 검토를 반복하지 않는다.
- 가상·연습·익명이라는 표시만으로 질문을 생략하지 않도록 질문 판단 지침을 보강했다. 실제 문맥에 따른 정당한 질문 생략은 유지한다.

## 적용 조건

31B는 가상 상황의 질문 필요성·명시된 이름·전언·위험 부정·현재 긴급 상황·중단 후 긴급 상황을 실제 모델로 확인한다. 질문 호출이1회인지와 로컬 검증을 통과하는지 확인한 후, 저장한 초안에 대한 별도 사후 독립 검토도 실행한다. 사후 검토 호출은 사용자 질문 응답 경로와 구분해 계측한다.

모든 시나리오와 관리자에서 31B를 선택한 새 대화의 질문 진행·최종 생성·기록 API 재조회·암호화 DB의 결과 일치 검사를 통과한 경우에만 31B의 `MODEL_SINGLE_CALL_TURNS=true`를 적용한다. 하나라도 실패하면 31B는 기존 검토를 포함하는 설정을 유지한다. 12B는 이번 31B 결과를 근거로 단일 호출로 변경하지 않는다.
