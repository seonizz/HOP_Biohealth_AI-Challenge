# 독립 검토를 유지하는 호출 최적화

2026-11-01. 로컬 구현과 검증 기록. GPU 서버 접속·배포는 수행하지 않는다. 원문 사례와 출력은 Git에서 제외된 `runtime/`에만 보관한다.

## 목표와 비교 조건

같은 작성 결과와 검토 결정을 입력했을 때 최종 업무 데이터가 동일하도록 중복 호출을 줄인다. 모델을 실제로 다시 실행하면 문구·판단·재시도는 달라질 수 있으므로, 아래 정상 호출 수는 실제 사례의 보장값이 아니다. HTTP POST를 센다. capability GET, 논리적인 검토 항목 수, 토큰 수와 구분한다.

| 구간 | 기존 정상 POST | 최적화 정상 POST | 조건 |
|---|---:|---:|---|
| 일반 최종 결과, O4 | 18 | 8 | 수정·형식 재시도·분할 없음. 14개 논리 검토 유지 |
| 긴급 최종 결과 | 7 | 6 | 기존 긴급 고정 안내 및 상세 생략 계약 유지 |
| O4 미사용 최종 결과 | 26 | 21 | 카드 작성 방식 유지, 검토만 묶음 |
| 블록 답변 처리 | 7 | 5 | 작성 4회 + 상태·질문·안전 검토 묶음 1회 |
| 같은 원문에서 선택 질문 건너뛰기 | 7 | 4 | 검증된 이름 재사용, 작성 3회 + 검토 묶음 1회 |
| 턴 묶음 없이 이름·안전 재사용 | 7 | 5 | 전체 원문·실제 요청·검토자 계약 일치 시에만 적용 |

## 최종 검토 묶음

`final-review-bundle.js`는 각 검토의 원래 입력·스키마·검증 함수를 유지한다. 공통 지시와 정확히 같은 입력 값만 참조로 공유하며, 개별 입력을 복원할 수 있다. 서로 다른 검토의 승인을 다른 검토의 근거로 사용하지 않는다. 작성 요청과 검토 요청은 분리한다.

O4는 카드별 근거·지원 검토 7개, 품질 검토 1개, 전체 검토 3개를 한 요청에 담는다. 분석 검토·계획 검토·상세 발화 검토는 의존하는 생성 단계 뒤에서 별도로 실행한다. 카드가 수정되면 그 카드 검토와 변경 전 품질·전체 검토 결과를 무효화하고 다시 검토한다. 품질 수정도 이전 전체 검토를 무효화한다.

입력 예산을 초과하면 원문을 자르지 않고 검토 묶음을 나눠 실행한다. 형식·JSON·공백 정체·stale 검증 실패가 기존 3회 시도를 소진하면 해당 작업에서 묶음을 끄고 원래 개별 검토 순서로 복구한다. 실패한 묶음·부분 성공 결과의 승인은 사용하지 않는다. 유효한 반려, 전송 오류, 취소를 승인으로 바꾸지 않는다. 같은 작업 재시작에는 복구 상태를 유지하고 새 요청에서는 최적화를 다시 시도한다.

## 턴 검토와 재사용 경계

질문과 상태 블록의 기존 병렬 작성을 유지한다. 턴 검토 묶음은 상태 audit·질문 결정·안전 판단에 각각 기존 검증 함수를 적용한다. 복구 경로에서도 원래 상태 audit 복구, 독립 안전 검토, 질문 생략 규칙을 유지한다.

이름 재사용은 같은 intake의 전체 실제 답변, 추출 요청·스키마·검증 버전, 모델·전송·토큰 정책이 일치할 때만 허용한다. 독립 상태 검토가 승인한 값만 저장하고 재사용 때 다시 검증한다. 원문 정정·의미 있는 미응답·거절 답변도 비교 대상이다. 다른 사용자나 프로세스의 전역 캐시는 없다.

단독 안전 검토 재사용도 전체 실제 원문, 제안된 판단, 실제 검토자의 요청·정책 일치를 요구한다. 턴 검토 묶음 모드에서는 이 캐시를 사용하지 않고 **매번 묶음 안에서 안전을 새로 검토한다**. 묶음의 결과를 단독 검토 요청의 승인으로 잘못 저장하지 않는다.

최종 분석은 동일 원문의 독립 안전 판단을 입력받아 보존한다. 이미 결정된 안전 근거 ID를 다시 모델에게 출력시키지 않고 서버에서 검증된 값을 복원한 뒤 기존 검증을 수행한다. 원문 변경·이전 기록의 출처 스냅샷 누락에는 독립 안전 재검토가 필요하다.

## 설정

| 환경변수 | 기본값 | 적용 조건 |
|---|---|---|
| `MODEL_BUNDLE_FINAL_REVIEWS` | false | relationship_agent, 기존 최종 검토·상세 기능 활성 |
| `MODEL_BUNDLE_TURN_REVIEWS` | false | relationship_agent + combined_blocks |
| `MODEL_REUSE_REVIEWED_NAME` | false | relationship_agent + combined_blocks |
| `MODEL_REUSE_REVIEWED_SAFETY` | false | relationship_agent + combined_blocks, 턴 묶음 비활성 |

8회 최종 경로에는 기존 `MODEL_REUSE_FINAL_DRAFT=true`가 필요하다. `MODEL_SKIP_FINAL_EXTRAS`는 false로 유지한다. 각 옵션은 로컬 `.env`와 Compose에 연결하며 별도 검토 Gateway는 작성용 옵션을 상속하지 않는다. `check-model.js`의 기본 구성 검사는 네트워크 요청 없이 실제 활성 옵션과 비활성 옵션을 구분한다.

실제 검증 완료 후 로컬 `.env`에 최종·턴 검토 묶음, 검토된 이름 재사용과 기존 입력 최적화를 활성화했다. 상세 생략은 false, 단독 안전 재사용은 false로 유지했다. 작성·검토 대상은 기존 localhost 모델을 보존했고 구성 전용 검사를 통과했다. 기존 실행 중인 앱 프로세스는 재시작하지 않았다.

## 실제 실행에서 드러난 검토 누락 보완

v56 로컬 실행은 답변 처리 6회와 최종 처리 11회, 총 17 POST로 상세 발화·암호화 저장·재조회까지 통과했다. 그러나 별도 원문 대조에서 모델 검토가 승인한 카드에도 다음 오류가 남아 추가 수정했다.

- 노력·내면의 정도를 직접 봐왔다고 확정하는 활용형.
- 이용자가 밝히지 않은 무제한 청취·응답 약속.
- 이용자가 필요하다고 판단한 도움을 대상자의 실제 요청·희망으로 승격하는 전제.

새 `guidance-source-attribution.js`와 표현 검증을 기존 `knownSpeechIssues → localCardIssues → repairCard → 독립 재검토`에 연결했다. 모델이 전부 승인한 응답도 해당 경계를 위반하면 수정·재검토하고, 반려된 카드를 먼저 표시하지 않는다. 원문에 없는 문장을 서버가 자동 수정하거나 승인하지 않는다. 실제 요청이 있는 반례, 조건부 제안, 한정된 시간, 피할 예문을 구분한다. 필요·희망 표현 전체를 금지하지 않으며, 공식 질문의 의미와 같은 도움의 보고 범위를 확인하는 제한된 검증이다. 미지원 표현까지 완전하게 판별하는 자연어 검증기는 아니다.

후속 검증은 v56에서 승인된 답변 상태와 원문·생략 상태를 보존한다. 처음 두 차례 최종 전용 실행은 분석·카드를 새로 생성했다. 이후 강조 부사가 있는 방향 오류를 발견해 마지막 실제 분석·초안을 변경 없이 기존 trusted local seed 계약으로 이어받았다. 전체 입력 지문·스키마·근거를 다시 검증하고, 승인 결과는 재사용하지 않으며 모든 독립 검토와 모델 수정·상세 생성·저장을 실행한다. 한 버전으로 처음부터 새로 실행한 결과와 구분한다.

추가 최종 실행에서도 독립 원문 대조가 지원 의사의 주어 역전을 두 카드에서 발견했다. 모델 검토 묶음은 이를 승인했고 기존 표현 검사는 중간 수식어와 소유어 생략형을 놓쳤다. 해당 실행은 8 POST 발행 후 중단·보존했다. 지지 방향 검사를 제한적으로 넓히고 감사, 실제 과거 전언, 제3자 수신자, 피할 예문을 구분하는 합성 회귀를 추가했다. 호출 묶음의 형식 검증 통과와 내용 검토 통과를 같은 것으로 취급하지 않는다.

## 보존되는 기능

전체 원답변·근거 검증·독립 검토·문맥에 따른 선택 질문 생략·상세 발화 저장·암호화 저장·재조회 계약을 유지한다. 재조회는 모델을 호출하지 않는다. 카드 표시·색상·배치와 복사 버튼은 변경하지 않는다. 실패·반려 결과는 최종 승인 기록으로 저장하지 않는다.

## 검증 기록

최종 번들 구현 후 독립 검토에서 발견한 두 복구 결함을 수정했다. 앞 카드의 반려와 후속 검토의 잘못된 형식이 함께 발생해도 원래 수정 순서를 복구하며, 과거 문구 재인용 오류에는 기존 개별 요청의 current-only 복구를 다시 사용한다. 독립 재검토 76개 검사가 통과했다.

전체 앱 회귀 검사 **2,352개 통과, 실패·건너뜀 0개**. 전용 로컬 PostgreSQL을 포함해 암호화 저장·재조회 검사를 실행했다. JavaScript 구문·JSON 검사, Compose 옵션 전달 확인, diff 검사를 통과했다. 턴 묶음의 독립 재검토 **189개 검사**에서 미해결 결함이 없었다.

최적화 첫 실제 실행에서는 이미 답한 항목을 미확인으로 남긴 초안이 반려됐다. 수정 지시의 일괄 삭제 금지와 모두 해결된 항목의 삭제가 충돌해 수정 설명을 미확인 문장으로 옮기는 문제가 확인됐다. 해당 실행은 10 POST 발행 후 중단하고 기록을 보존했다. v56에서 모든 항목이 해결되면 빈 배열을 허용하되 실제 미확인·모름·거절·상충은 보존하도록 명확히 했다. 서버가 항목을 대신 삭제하거나 승인하지 않는다.

최종 로컬 사례 검증은 **완료**했다. 마지막 이어받기 실행은 **11 POST, 같은 generation의 추가 시도 0회, 내용 수정 2 POST**였고 상세 발화 생성·독립 검토·암호화 저장·재조회까지 16개 검사를 통과했다. 저장 결과 전체와 재조회 결과가 정확히 일치하며 재조회 모델 호출은 0회다. 별도 원문 대조에서 최종 카드와 상세의 지정 오류가 남지 않았음을 확인했다.

실제 분석·초안 작성 결과 두 개를 검증 후 이어받았으므로 이 11회를 처음부터 생성하는 경로의 호출 수로 해석하지 않는다. 앞선 답변 처리 6회, 실제 초안 준비 6회, 마지막 11회를 연결한 완료 경로는 **23 POST·동일 단계 추가 시도 1회**다. 실패·중단·내용 재검토까지 포함한 이번 수정 작업의 전체 발행은 **97 POST**다. 이전 저장 결과는 다른 안전 분기의 27회 경로이므로 실제 절감률을 계산하지 않았다. 정상 18→8의 비교는 고정 합성 응답을 사용한 별도 검증이다.

중간 승인 상태의 미확인 범위와 질문 생략 이유에는 근거를 더 정밀하게 구분할 과제가 남았다. 원문 미언급을 명시적 모름으로 설명하는 문제와 최종 카드의 검증 결과를 분리한다. 실제 사례의 전체 출력·비교표·원요청·검사 증거는 Git에서 제외된 `runtime/haeun-call-optimization-20261101/`에 보관한다.
