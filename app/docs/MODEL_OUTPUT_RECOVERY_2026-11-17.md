## 수정한 동작

- 중복 JSON 키가 확인된 combined 응답은 일부도 채택하지 않고 즉시 모든 블록을 새로 생성·검토한다. 중복 키를 지워서 승인하거나 파서가 덮어쓴 값을 사용하지 않는다. 다른 문법 오류는 기존 제한된 재작성 경로를 유지한다.
- `json_object` 모드에도 첫 요청부터 스키마의 객체별 키 배치를 전달한다. 키 배치는 판정 기본값이나 사실 예시를 포함하지 않는다.
- combined 프롬프트에서 `questions`가 객체이고 생략 배열은 `questions.skip` 안에 있어야 함을 명시한다. 키 목록은 실제 스키마에서 가져온다.
- `output.questions`의 객체→배열 자료형 오류가 확인되면 전체 초안을 반복 생성하지 않고 블록 복구로 전환한다. 상태 전체의 스키마·원문 근거가 유효하면 해당 상태만 보존하고 질문 판단 객체를 새로 요청한다. 상태가 유효하지 않으면 상태도 다시 생성한다. 일시적인 연결 실패 중 보존하는 블록도 같은 요청·문맥·스키마·수정 단계의 키와 원문 검사를 다시 통과해야 한다. 이전 검토 승인은 보존하지 않는다.
- 배열을 임의로 감싸거나 누락된 안전·추가 확인·맞춤 질문 결정을 기본값으로 채우지 않는다. 재생성 후 상태·질문·안전의 독립 검토를 유지한다. 형식 통과는 의미 검토 통과가 아니다.
- 일시적인 연결·서버 오류에 대한 operation 재시작은 최대 2회다. 내부 요청의 기존 최대 3회 시도와 별도이므로 총 HTTP 호출 수가 항상 3이라는 뜻은 아니다. 출력 검증 실패로 이 재시작 예산을 다시 열지 않는다.
- timeout은 최초 operation부터 계산하며 재시작·backoff 동안 갱신하지 않는다. 하위 reviewer도 부모의 남은 시간 안에서 실행한다. `timeoutMs=0`은 시간 제한 없음이라는 기존 의미를 유지하지만 재시작 횟수는 제한한다.
- 취소는 복구를 중단한다. 실패한 질문 판단은 성공 처리하거나 결과로 저장하지 않는다. 기존 보류 답변·재요청 계약과 최종 저장 검증은 유지한다.
- 31B의 `singleCallTurns` 경로에서는 블록 재생성·operation 재시작을 켜지 않는다. 질문당 1회 호출 계약을 유지한다.
