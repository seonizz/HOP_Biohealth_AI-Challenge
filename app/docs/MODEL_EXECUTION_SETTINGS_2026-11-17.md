# 모델 역할·질문 실행 설정

사용자 지정(2026-11-17): **질문은 기본 1회, 개별 실행, 범용 모델**을 사용한다. 질문용·검토용 모델을 각각 설정할 수 있고 같은 모델도 허용한다. **최종 카드는 기존 흐름을 유지하며 범용 모델이 생성**한다.

관리자 URL: `/admin/models`. 기존 12B·31B 선택과 범용 모델 연결 아래에 질문 실행 설정을 제공한다. 일반 이용자 화면과 카드 디자인은 바꾸지 않는다.

새 설치의 setup·환경 예시는 `MODEL_SELECTION_ENABLED=true`를 기본으로 사용한다. 이미 명시적으로 비활성화한 환경은 그대로 두며, 해당 환경에서는 이 프로필별 실행 설정을 사용하려면 모델 선택 기능을 켜야 한다.

| 설정 | 동작 |
| --- | --- |
| 질문 1회 — 기본 | 질문 판단 전용 요청 1회. 추가 검토·재생성 호출 없음. 상태 분석은 기존 최종 생성 단계에서 처리 |
| 질문 최대 2회 | 통합 상태·질문 생성 후 통합 독립 검토. 오류·수정·검토 모델을 합쳐 실제 채팅 POST 최대 2회 |
| 단계별 | 상태·질문·검토를 나누어 실행. 기존 제한된 형식 복구·독립 검토 유지 |
| 개별 실행 — 기본 | 독립 작업도 순서대로 실행 |
| 병렬 실행 | 독립적인 상태/질문 생성과 개별 검토 작업을 병렬 실행. 앞 단계 출력이 필요한 작업은 순서 유지 |
| 질문용 모델 | 범용 모델 공유 또는 별도 URL·모델 이름·API 키 |
| 검토용 모델 | 범용 모델 공유 또는 별도 URL·모델 이름·API 키. 질문용과 같은 모델·주소도 가능 |

병렬 설정이 호출 수를 늘리거나 같은 요청을 복제하지 않는다. 1회 모드에는 병렬 분기가 없고, 2회 모드는 생성 결과를 검토해야 하므로 생성→검토 순서다. 실제 병렬 실행은 단계별 모드의 독립 작업에 적용한다. 서로 다른 모델 서버를 연결해도 이 의존성은 같다.

1회·2회는 성공 보장이 아니라 **호출 상한**이다. 모델 응답이 틀렸다고 추가 호출로 상한을 넘기지 않는다. 2회 예산 소진은 `MODEL_CALL_LIMIT`으로 끝나며 검토 통과로 저장하지 않는다. 정상 1회 호출도 독립 검토된 결과로 표시하지 않는다. 단계별 모드에는 앞서 구현한 제한된 자동 복구가 유지된다. 모델 상태·용량을 조회하는 GET은 생성 POST 횟수와 구분한다.

## 저장·연결 계약

- 설정은 프로필별로 암호화한 `model_connections` 불변 버전에 보관한다. 새 대화에만 적용하고 진행 중 대화·기존 기록·이어가기는 원래 버전을 유지한다.
- 처음 적용하는 기본값도 별도 `execution_default` 버전(`profile_id` + `_` + `2` 32개)으로 저장한다. 기존 baseline·legacy 연결은 바꾸지 않는다. 동시 앱 시작은 같은 기본 버전으로 수렴한다.
- 범용 연결을 수정하면 범용 모델을 공유하는 질문/검토 역할은 새 대화에서 새 범용 연결을 따른다. 별도 역할 연결은 그대로 보존한다.
- 역할별 빈 키는 **해당 역할의 기존 키만** 유지한다. 다른 역할이나 범용 모델의 키를 자동 복사하지 않는다. 별도 연결을 잠시 사용하지 않아도 암호화 설정은 보존한다.
- 최종 카드용 gateway와 최종 검토 옵션은 기존 설정을 유지한다. 질문용·검토용 별도 연결이 카드·불씨·이어가기의 모델을 바꾸지 않는다.
- 같은 모델의 두 역할도 호출별 맥락과 검토를 구분한다. 동일 모델 사용을 다른 모델에 의한 평가로 표현하지 않는다.
- 관리자 인증·세션·CSRF·Origin 검사를 모두 적용한다. 응답에는 키 값이 없고, 모델 변경만으로 다른 프로필을 자동 선택하거나 장애 시 다른 모델로 전환하지 않는다.

## API

`GET /api/admin/model-execution`은 `executions` 배열에 두 프로필의 실행 설정과 키 없는 역할 연결을 반환한다. `configured`는 설정 준비 여부이며 서버 가용성이나 실모델 검증 통과를 뜻하지 않는다.

`PUT /api/admin/model-execution/:id` (`local12b` 또는 `gpu31b`):

```json
{
  "question_mode": "single",
  "scheduling": "individual",
  "question_source": "general",
  "review_source": "general"
}
```

`question_mode`: `single | two | individual`, `scheduling`: `individual | parallel`, 두 source: `general | custom`.
별도 역할을 설정하려면 `question_connection` 또는 `review_connection`에 `{base_url, model, api_key?}`를 추가한다. HTTP는 기존 로컬/LAN 범위, 외부는 HTTPS를 사용한다. 변경은 키 없는 메타데이터로 응답한다.

## 검증 범위

엔진 회귀에서 12B 1회, 동일/다른 검토 모델의 2회 상한, 오류·병렬 분기에서도 상한 유지, 개별·병렬 실제 동시성, 취소를 확인했다. API 검사는 실제 로컬 HTTP·격리 PostgreSQL을 사용한다. 질문마다 채팅 POST 1회, 범용 모델 최종 카드 경로, 암호화 저장·기록 재조회 일치를 확인하며, 최종 카드 응답은 합성 대역이므로 실모델 품질 증거와 구분한다.

전체 회귀·화면 확인·실행 적용 결과는 `app/runtime/model-execution-20261117/`에 기록한다. 이전 12B 백그라운드 실험은 당시 동결 소스로 실행되므로 이번 실행 설정의 검증 결과로 사용하지 않는다.

최종 전체 회귀 **3,303/3,303 통과, 실패 0·건너뜀 0**, 격리 검사 DB 삭제 확인. 구문·JSON 검사와 diff 검사 통과. 실제 로컬 앱을 재시작해 동작 소스 해시 일치와 두 프로필의 `single / individual / general / general` 설정을 확인했다. 관리자 브라우저 화면에서도 31B·12B의 설정을 확인했다. 기존 기본 모델 선택(31B)은 유지했다.

최초 재시작은 `.env`의 외부 PUBLIC_ORIGIN 값으로 로컬 실행 제한에 걸렸다. 파일·외부 허용 Origin은 바꾸지 않고 기존 loopback 프로세스 설정을 복원해 재시작을 완료했다. 적용 영수증은 `ACTIVATION.json`이다. 실제 모델 품질·응답 속도는 이번 로컬 회귀의 검증 범위가 아니다.
