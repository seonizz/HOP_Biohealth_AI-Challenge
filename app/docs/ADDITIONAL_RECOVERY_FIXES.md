# 대화·모델 응답·서버 종료의 추가 결함 수정

2026-11-15. 진행 중인 GPU 실험의 소스·프로세스를 변경하지 않고, 현재 앱의 추가 경계 조건을 검토했다. 아래 세 결함을 재현한 뒤 수정했다.

## 확인 질문 뒤 오래된 생략 결정

Q1 답변으로 Q2–Q9를 생략하고 Q10을 표시한 뒤 새 확인 답변을 제출해도 기존 생략 결정이 남았다. 새 모델이 생략하지 않겠다고 응답해도 대화가 곧바로 끝날 수 있었다.

Q10 답변도 일반 답변처럼 기존 생략을 다시 검토한다. 이미 답변했거나 표시된 질문은 새 후보에서 제외하며, 모델은 현재 원문을 근거로 다시 생략할 수 있다. 첫 도움말 재표시, 모름·거절, 종료 요청, Q10의 바인딩·질문 예산은 유지한다. 취소된 미확정 답변은 기존 상태로 복원된다.

근거: `intake-v3.test.js`의 새 6개 검사는 수정 전 실패했고 수정 후 통과했다. 추가 독립 확인에서 기존 답변과 표시된 미응답 질문의 인스턴스도 보존됐다.

## 호출 방식에 따라 달랐던 중복 JSON 키 검사

관계 에이전트 이외의 두 모델 호출 경로는 동일 JSON 키가 여러 번 나오면 마지막 값으로 덮어쓰고 검증기에 전달했다. 이스케이프된 키와 중첩 객체에서도 같은 문제가 재현됐다.

공통 요청 처리에서 중복 키 검사를 기본으로 켰다. 중복 응답은 검증기에 넘기기 전에 거부하고 기존 횟수 안에서 다시 요청한다. 사실·승인 판정·필수 필드를 자동으로 채우지 않는다. 구조 안내도 문법·형식·근거 오류를 구분하도록 바로잡았다.

근거: 수정 전 두 경로 모두 중복 판정을 첫 응답에서 수용했다. 새 4개 검사는 첫 응답을 거부하고 두 번째 유효 응답만 검증기에 전달하는지 확인한다.

## 서버 종료 직전 새 모델 작업 등록

요청이 인증 조회나 대화 읽기에서 대기하는 사이 서버 종료가 시작되면, 기존 실행 목록을 취소한 뒤 새 모델 작업이 등록될 수 있었다. 이 작업은 종료 취소를 받지 못해 정상 종료를 지연시킬 수 있었다.

서버 전체 종료 신호를 각 모델 구독에 연결하고 이미 취소된 새 구독은 작업 시작 전에 중단한다. 다른 정상 구독자가 있는 공유 작업의 취소 규칙은 보존한다. 답변·결과·이어 대화·테스트 실행·안내 요청에 같은 종료 신호를 사용한다.

근거: 인증 조회에서 대기하는 답변·결과 요청과 대화 조회에서 대기하는 답변 요청의 3개 회귀 검사는 수정 전 실패했고 수정 후 모델 호출 0회와 서버 종료 완료를 확인했다.

## 검증 경계

새 임시 PostgreSQL DB에서 전체 **2,791/2,791 통과**, 실패·생략 0개를 확인했다. JavaScript 문법·JSON 정합성 검사도 통과했고 테스트 DB 제거를 확인했다.

전체 회귀 결과는 `app/runtime/additional-defects-20261115T132107/regression-verification.json`과 `app-tests-integration.log`에 기록한다. DB 검사는 새 임시 DB를 사용하고 종료 후 제거한다.

앞서 시작한 GPU 실험 `gpu31b-v3-repair-20261115T130556`은 시작 당시 소스 고정본을 사용한다. 이번 추가 수정은 그 실행에 반영되지 않으며 해당 결과를 추가 수정의 실모델 검증으로 주장하지 않는다. 카드 디자인과 모델 가중치는 변경하지 않았다.

## 추가 수정 포함 재검증 시작

사용자의 재검증 요청에 따라 2026-11-15 13:39:13 KST 현재 수정본으로 새 대화를 시작했다. 전체 회귀 2,791개를 다시 통과한 뒤 별도 소스 고정본·임시 DB를 사용했다. 실행 경로는 `app/runtime/gpu31b-v3-retest-20261115T133609/`이다.

이 실행은 13:44:28 KST 정리까지 종료됐으며, 첫 질문 Q3-01에서 원문 인용 오류 1회와 JSON 문법 오류 2회로 실패했다. 결과 레코드 0건을 확인했으므로 결과 생성·저장 성공이 아니다. worker 종료·GPU 반환·임시 DB 제거는 확인했다. 이후 혼합 오류 복구와 루트 구조 검사 순서를 수정하고 전체 회귀 **2,799/2,799 통과**를 확인했다. 승인된 격리 형식 제한 검증의 상세는 [개선 31B 오류 복구](GPU31B_V3_RECOVERY.md)를 따른다.
