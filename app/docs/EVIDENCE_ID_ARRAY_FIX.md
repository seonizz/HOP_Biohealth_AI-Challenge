# 관계 기억 근거 ID·배열 초과 수정

2026-11-01. 관계 기억 작성 단계의 ID 표현과 배열 한도 안내를 수정했다. 검토·저장·질문 생략·카드 디자인 계약은 유지한다.

## 변경

| 항목 | 기존 | 수정 |
| --- | --- | --- |
| 같은 원문 근거 | 위치·certainty 분기마다 다른 ID | `(subject, question_id, quote)`가 정확히 같으면 요청 안에서 같은 `source_N` ID |
| 재시도 중 후보 축소 | 제거된 후보에 따라 순번이 바뀔 여지 | 단계 호출별 ID 레지스트리를 유지하여 제거된 ID를 다른 원문에 재할당하지 않음 |
| ID 허용 범위 | 분기별 enum | 분기별 원래 enum 유지. 다른 분기에만 있는 근거는 사용할 수 없음 |
| 첫 작성의 배열 안내 | 출력 스키마의 `maxItems` | 같은 스키마에서 추출한 `array_limits` 추가. 그룹 전체 한도와 항목별 evidence 한도 구분 |
| 배열 초과 재생성 | 일반 검증 피드백 | 초과 경로·실제 개수·기존 허용 한도를 `array_count_repair`로 전달 |
| 스트리밍 초과 경로 | `output` | 신뢰하는 스키마 경로에 한해 `output.patient[0].evidence`처럼 위치 표시. 알 수 없는 키는 `output` 유지 |
| 턴 캐시 버전 | `combined-turn-v50` | `combined-turn-v51` |

ID는 요청 내부 표현이다. 서버가 잘못된 ID를 다른 근거로 치환하지 않는다. ID 복원 전 스키마 검증, 복원 후 원래 스키마·원문 검증, 독립 상태·질문·안전 검토를 그대로 거친다. 저장에는 원래 근거 객체를 사용한다.

배열의 상한과 시도 횟수는 늘리지 않았다. 초과 항목을 서버에서 잘라내거나 임의 승인하지 않는다. 모델이 원문과 기존 상한을 기준으로 전체 블록을 다시 작성하며, 마지막 실패에 해당하는 배열 피드백만 전달한다. 입력 원문은 축소·삭제하지 않는다.

## 검증

- 수정 대상 집중 검사: 174개 통과.
- 구현 후 독립 검토: 284개 통과. 발견된 이전 프롬프트 버전 assertion 2곳을 수정하고 재검사했다.
- 재시도 ID 보완 후 독립 검사: 107개 통과. 분기 제거로 ID가 다른 원문을 가리키던 문제를 3개 회귀 검사로 재현하고 수정했다.
- 마지막 전용 임시 PostgreSQL 포함 전체 앱 검사: **2,059개 통과, 실패·건너뜀 0개**.
- JavaScript 구문·JSON 검사 통과.
- 이전 ID 변환기를 임시 복사본에 복원했을 때 핵심 회귀 검사 5개가 실패하는 것도 확인했다.

검사는 ID 공유와 분기별 범위 제한, 잘못된 ID·근거·해석 거절, 배열 초과 재시도와 종료, 스트림 경로 노출 제한, 입력 불변성, 기존 검토와 저장 계약을 포함한다. 모의 출력 검사만으로 실제 모델의 하은 사례 성공을 주장하지 않는다.

실제 사례의 실행 증거는 Git에서 제외한 `runtime/haeun-id-array-fix-20261101/`에 보관한다. 사례 원문과 출력은 추적 문서·테스트에 복사하지 않는다. 모델 요청 대상은 Mac의 `127.0.0.1:11434`로 제한하며 GPU 서버·SSH는 사용하지 않는다.

## 실제 로컬 모델 — 답변 처리

이전 실행과 입력 해시가 같은 29개 답변을 사용했다. 앞선 28개는 모델 판단 없이 입력 파서로 적재하고, 마지막 답변을 실제 앱 API에 제출했다. 따라서 이 검증은 모든 문항에서 모델을 실행한 전체 대화 재현과는 범위가 다르다.

| 항목 | 수정 전 기록 | 수정 후 실행 |
| --- | --- | --- |
| 관계 기억 작성 | ID 분기 혼용·배열 초과로 3회 시도 후 실패 | 첫 시도에 원래 검증 통과 |
| 관계 기억 근거 | 최종 승인되지 않음 | 서로 다른 원문 37개의 ID 일관성 확인; 저장 형식은 원래 객체 |
| 그룹 배열 크기 | 최종 승인되지 않음 | patient 2, supporter 2, relationship 1, unknowns 2 |
| 각 항목 근거 수 | 3개 상한 초과 발생 | 1~3개; 기존 상한 유지 |
| 상태·질문·안전 독립 검토 | 도달하지 못함 | 모두 승인, 저장된 턴 실행 정보의 reviewed 확인 |

수정 후 마지막 답변 처리는 작성 4회와 독립 검토 3회, 총 7회였으며 오류 재시도가 없었다. 수정 전 실패한 6회와 수정 후 성공한 7회는 도달 단계가 다르므로 호출 절감률로 비교하지 않는다.

모델이 선택한 첫 추가 질문은 독립 검토에서도 유지됐다. 사용자가 명시적으로 선택한 “추가 답변 없이 이 선택 질문 건너뛰기”를 실제 답변 API에 제출했다. 빈 `rawText`와 `skipped:true`가 저장됐고, 첨부 문서에 없는 답변은 추가하지 않았다.

건너뛰기 후 제안된 다른 질문은 독립 검토가 이미 답변된 내용으로 판정하여 제외했다. 질문 생략·검토 기능을 유지한 채 상태가 `ready`가 되어 최종 생성으로 진행했다. 이 후속 턴 역시 작성·검토 7회로 완료됐고, 관계 기억의 ID 혼용·배열 초과 재시도는 없었다.

## 최종 생성에서 확인한 추가 보완

초기 최종 생성 실행은 원문에서 확인되지 않은 대상자의 요청을 관계 해석에 추가하여 마지막 검토에서 거절됐다. 검토기의 수정 예문에도 그 행위가 남아 재작성으로 해결되지 않았다. 이 실행의 저장 성공을 주장하지 않는다.

작성·분석 검토·초기/후기 분석 재작성에 요청·동의의 귀속 지시를 추가했다. 상황 공유나 이용자의 바람을 대상자가 실제로 한 요청·동의로 바꾸지 않으며, 직접 인용뿐 아니라 명시적 전언도 유효한 근거로 검토한다. 모름·건너뜀을 거부로 바꾸지 않는다. 검토 예문은 근거가 아니며 모든 절을 원문과 다시 대조한다.

요청 귀속 보완은 `relationship-v3.21-request-attribution`에 반영했다. 이후 실제 검증에서 계획 검토가 `opening_evidence` 인용 객체에 설명 문구를 추가하라고 반복 요구하여 중단됐다. 인용의 관찰·전언이 함께 있다는 사실 자체를 오류로 판정하고, 스키마에 없는 설명을 요구하는 검토 지시 문제였다.

현재 버전 `relationship-v3.22-plan-evidence-review`는 해당 필드가 `{subject,question_id,quote}` 배열임을 명시한다. 원문 인용을 편집하거나 설명·새 키를 추가하라고 요구하지 않으며, 실제로 근거 없는 추측을 선택했을 때만 구체적인 문제 절과 유효한 인용 선택을 요구한다. 현재 오류 없이 앞으로 조심하라는 경고만으로 거절하지 않도록 했다.

스키마, 검토 거절, 저장 게이트, 시도 횟수는 변경하지 않았다. 요청 귀속 독립 관련 검사 103개, 계획 인용 계약 독립 관련 검사 214개와 최신 전체 DB 포함 검사 **2,059개**가 통과했다. 실제 모델 재검증은 같은 승인된 원답변·건너뛰기 상태에서 수행한다.

모델은 긴급 안내 분기를 선택했다. 이 분기의 기존 계약에 따라 상세 발화 단계(`conversation_detail`)는 생성하지 않으며, 일반 안내의 O4·상세 발화 경로를 실제 사례에서 검증했다고 주장하지 않는다. 해당 일반 경로는 전체 회귀 검사 범위에 포함된다. 이번 결과는 기능과 저장 확인이며 임상적 판단의 타당성을 검증한 결과가 아니다.

성공 경로는 마지막 답변 7회 + 승인된 질문 건너뛰기 7회 + 최신 최종 생성 13회 = **27회**다. 개발 중 이전 최종 실행의 4회(중단)·23회(검토 반려)·8회(계획 검토 반려)는 별도이며, 이 작업의 실제 생성 요청 시작 횟수는 총 **62회**다. 27회를 전체 작업 사용량이나 고정 호출 수로 해석하지 않는다. 앞선 28개 답변에서의 모델 호출은 이 검증 범위에 포함하지 않는다.
