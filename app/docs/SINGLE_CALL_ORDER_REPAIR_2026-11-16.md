### V3 재발 확인과 V4 후보

V3에서도 동일 안전 ID 중복이 재발했다. 실제 재시도 요청에 구체적 피드백이 전달됐지만 모델 원출력이 바뀌지 않아 피드백만으로 해결됐다고 볼 수 없다. 원본 4턴도 직접 요청이 이미 있는데 다른 선호까지 질문 범위를 넓혀 `not_needed`를 선택했다. 이 실행은 부적격이 확정돼 현재 소유 모델 요청 후 정리하고 후속 후보로 교체했다(`SUPERSEDED.json`). V3의 최종 생성·저장 성공은 주장하지 않는다. 진행 중 동결본은 수정하지 않았으며, 이후 현재 작업 트리 변경은 V4용이다.

V4는 독립 안전 검토의 근거 배열 대신 각 실제 근거 ID를 고정된 필수 boolean 키로 생성하는 선택 표현을 추가한다. 모델이 작성한 basis/reason과 선택한 ID 집합은 보존하며, 복원 배열은 원문 source 순서다. 임의 배열 순서까지 동일하다는 뜻은 아니다. 논리 입력의 중복을 조용히 제거하지 않고, 중복 raw JSON 키·빠진 키·추가 키·잘못된 boolean·다른 요청 binding·원래 선택 개수 초과를 거절한다. 현재 위험의 유효한 근거와 의미 검토는 기존 validator가 계속 수행한다. 18개 선택 상한을 위해 19번째 후보를 자르지 않는다. 독립 안전 검토만 명시적으로 켜며 audit 압축과 12B 기본 설정은 유지한다.
