# 응답 지연 추가 최적화 — 구현·테스트 기록

2026-11-10(KST). [추가 수정 기획](응답시간_추가단축_수정기획_2026-11-10.md)의 R1~R6-a를 반영한 뒤, 사용자 추가 지시로 **대화 2회·카드 6회 선택 경로와 검토 출력 압축**을 구현했다. 1차 R1~R6-a의 정상 최종 요청은 8회였고, 아래 추가 수정 절은 6회 구성의 검증 결과다. [상위 기획](대화_실시간응답과_카드_10분이내_생성_기획_2026-11-10.md)의 더 작은 질문 결정 전용 경로·최종 4회 후보와는 구분한다.

최신 사용자 지시는 **빠른 경로를 로컬 `.env`에 적용하고, GPU 서버를 건드리지 않고 로컬 모델로 대화부터 카드까지 검증**하는 것이다. 아래 단계별 결과는 당시 기록이며, 최신 적용 설정·추가 수정·전체 흐름 검사는 마지막 절을 따른다. 이 지시 이후 SSH·GPU 진단·추론·학습·설정 변경은 하지 않았다. 과거 허용 시점의 GPU 실측은 역사 기록이며, 이번 추가 수정의 검증은 mock과 Mac 로컬 Ollama만 사용했다.

## 형식 오류와 내용 반려

R2는 중복 JSON 키(escape로 같은 키를 쓴 경우 포함), 절단·파싱 실패, 알 수 없는 최상위 task를 부분 승인으로 처리하지 않는다. 원래 전체 묶음 복구·fallback을 유지한다. 전송·인증 오류와 취소도 승인으로 바꾸지 않는다.

각 task의 원래 validator를 적용한다. 품질은 `improvements`, 카드는 `localCardIssues`와 모델 판정을 함께 소비한다. 부분 결과는 내부의 미해결 검토 상태이고 완료된 승인 묶음이 아니다. 로그에는 `partial_review`로 구분하며 원문·카드·검토 내용은 새 진단 로그에 넣지 않는다.

개별 task 복구도 기존 요청당 최대 3회 범위다. 실패 시 기존 개별 검토 순서로 돌아간다. 새 무제한 내부 루프나 영속 승인 캐시를 만들지 않는다. 기존 `MODEL_TIMEOUT_MS=0`과 바깥 작업 재시작 정책은 유지한다.

독립 코드 검토에서 응답 뒤 모델 계약 지문을 캡처하던 경합을 발견했다. 발행 전에 원문·후보·프롬프트·스키마·validator와 검토자 설정을 캡처하고 응답 직후·실제 소비 시 다시 비교하도록 고쳤다. 같은 상황을 재현하는 영속 회귀를 추가했다. 분석·카드·품질 변경은 종속 승인을 무효화한다.

## 과거 GPU 실측 기록 — 재실행 금지

사용자가 2026-11-10에 이번 테스트의 GPU 서버 사용을 명시적으로 허용하고 공유 SSH 인증을 완료했다. 비밀번호는 사용자 터미널에서만 입력하며 저장하지 않았다. 별도 작업 경로·기존 가상환경·쓰기 제한·GPU 점유 확인을 적용한다.

사용자가 지정한 대상은 **`malssi-gemma4-31b-cards-final-step4723`**다. 원격 체크포인트는 `model_Training/cards31b_fresh_lora_20261031_r1/training/checkpoints/02_card_generation-e001-s000004723`이며, 어댑터 SHA-256은 `65de513ce74a22b4d31b4c85f8d7980629969406c1f1a6296620726ae0526200`, 체크포인트 manifest SHA-256은 `7bb7fcf4a6f843e12458ecb0729a6fbbf8dd89a2899df37165ccb81497aa7a06`다. 컨텍스트 32,768·최대 출력 8,192 토큰 경계를 원문 축약 없이 적용한다. 기존 학습 가중치·설정·코드는 변경하지 않는다.

정확한 모델명을 전달받기 전에 실행한 v11 epoch3 진단은 종료했다. 소유 worker PID 부재·GPU 메모리 11/30 MiB 복귀를 확인했으며, 그 결과를 지정 모델의 속도 근거로 사용하지 않는다.

과거 허용된 테스트는 별도 경로에서 대화 갱신·최종 카드의 합성 입력으로 실행했다. 외부 진단 기한은 대화 180초, 카드 구성별 600초다. 운영 설정의 `MODEL_TIMEOUT_MS=0`을 변경하거나 필수 검토·원문·저장 계약을 줄여 성공 처리하지 않는다. 이 검사는 앱·DB·화면을 포함한 전체 시간이나 p95 검증이 아니다.

위 대화 한 건에서 보고된 입력은 34,175토큰, 출력은 337토큰이며 모든 시도의 usage를 받았다. HTTP 요청 본문 합계는 150,899 bytes다. 단일 합성 입력·GPU 단독 사용에서의 관측이며 대표성·p95를 보장하지 않는다. 준비 72.133초는 별도이고, 실제 앱의 마지막 입력 처리·저장·브라우저 표시는 포함하지 않았다.

모델 내부 계측에서 대화 5회 생성 시간 합은 130.113초였다. 첫 토큰까지의 시간 합은 38.995초, 그 이후 생성 시간 합은 91.118초다. 첫 추론의 TTFT는 21.105초였고, 이후 네 요청도 2.904~5.578초였다. 이 입력 규모에서는 모델 준비 후에도 입력 처리와 출력 생성 자체가 2초를 넘는다. 호출 통합과 함께 필요한 판단만 짧게 출력하는 경로를 실제 모델로 다시 검증해야 한다.

대화 실시간화에는 R1~R6 외에 상위 기획의 작은 질문 결정·독립 검토 2회 경로가 우선 필요하다. 현재 상태·이름·관계 기억을 매 턴 먼저 생성하는 5회 경로의 출력량만 줄여 2초 달성을 주장할 수 없다. 질문의 문맥상 생략·호칭 정정·안전 판단·원문 귀속은 유지해야 한다.

카드 최적화 구성은 분석 22.337초, 분석 검토 6.055초, 전략 40.127초, 전략 검토 4.699초, 본문 127.745초 뒤 전체 검토 묶음에 진입했다. 묶음이 추가 399.008초 안에 완료되지 않아 외부 진단 기한에 `MODEL_CANCELLED`로 취소했다. 발화 상세·최종 독립 검토·기록 저장까지 성공한 결과가 없으므로 10분 완료로 세지 않는다. 먼저 알린 관계 카드 이벤트도 취소 시 reset됐으며 최종 결과로 집계하지 않았다.

이 구성의 요청 본문 합계는 206,824 bytes다. 보고된 usage만 합산하면 입력 27,418·출력 771토큰이지만, 취소된 묶음 1회의 usage는 **알 수 없다**. 이 값을 전체 토큰 합계나 0토큰 처리로 해석하지 않는다. 기존 구성과의 단일 순차 비교는 속도 향상률·채택·p95의 근거로 사용하지 않는다.

과거 테스트의 로컬 종료 기록은 소유 PID 부재, compute 프로세스 없음, GPU 11/30 MiB 복귀를 확인했다. 이후 GPU 금지 지시를 받은 이번 수정에서는 이 로컬 기록만 읽었고 서버에 재접속하지 않았다. 과거의 미완료 검토 출력량·토큰 수는 기록이 없으므로 추정하지 않는다.

## 검토 묶음 추가 단축 — GPU 미사용 로컬 검증

### 확인한 원인과 수정

첫 검토 묶음은 작성기의 호출 한 번으로 바뀐 것이 아니라 **서로 다른 11개 검토의 모든 결과를 한 응답으로 직렬 생성**하는 구조다. 각 claim의 긴 ID·verdict·reason 객체가 카드별 검토와 전체 검토에서 반복된다. 하나의 응답이 늦으면 각 필수 결과를 검증할 때까지 전체 묶음이 대기한다. 과거 실측의 399.008초는 이 묶음이 미완료인 채 기다린 구간이며, 기록되지 않은 출력 토큰이나 내부 정지 원인을 확정하는 수치는 아니다.

다음 변경은 필수 판정을 줄이지 않고 호출·전송 표현을 줄인다.

- **대화 2회:** `combined` 초안 1회 + 상태·조건부 질문·안전의 독립 검토 묶음 1회. 문맥상 질문 생략, 이름 정정, 미확인·안전 검증을 유지한다. 기존 블록 경로와 개별 검토 fallback은 남긴다.
- **카드 6회:** 분석·전략 초안 1회 → 각각의 독립 검토 묶음 1회 → 카드 초안 1회 → 기존 11개 검토 묶음 1회 → 발화 상세 1회 → 상세 독립 검토 1회. 분석을 반려하면 추측 단계의 전략·검토를 버리고 기존 순서로 새로 생성·검토한다. 전략 반려·늦은 분석 반려도 종속 결과를 갱신한다.
- **검토 출력 압축:** 짧은 키·요청에 결속된 판정 코드와 순서로 claim ID를 정확히 복원한다. 모든 audit, approved와 issues, 구체적인 모델 작성 reason·repair는 계속 필수다. 통과 문구를 서버가 만들어 넣거나 이유를 잘라내지 않는다. 누락·중복·위치 교환·다른 분기 코드·이전 요청 지문은 거절한다.
- **압축의 형식 안정성:** 초기 v2는 배열의 `items`를 공유해 입력 비용을 줄였다. 실제 로컬 모델은 서로 다른 claim 위치의 코드를 혼동했다. 최신 v4는 `a0`, `a1`처럼 위치별 객체와 해당 위치의 정확한 enum을 공개 스키마에 넣는다. 입력 비용 일부 증가를 허용하고 형식 오류 재시도를 줄인다. 모든 이유·판정·R2 부분 복구 경계는 유지한다.
- **통합 초안의 근거 ID:** 분석·전략을 묶어도 기존 위치별 원문 허용 범위와 operation ID 레지스트리를 유지한다. 위치 간 ID를 가져오거나 공개 schema/table 변경으로 private 근거를 바꿀 수 없다. 지원하지 않는 자식 스키마는 원래 객체 표현을 유지한다.

주요 수정 파일은 [relationship-turn.js](../app/src/relationship-turn.js), [relationship-agent.js](../app/src/relationship-agent.js), [compact-review-transport.js](../app/src/compact-review-transport.js), [final-evidence-transport.js](../app/src/final-evidence-transport.js)와 Gateway·설정 연결이다. 검사는 `combined-turn-review-bundle.test.js`, `final-six-call.test.js`, `compact-review-transport.test.js`, `final-stage-evidence-transport.test.js`에 보존했다. 기존 최종 흐름 fixture를 공유해 원래 59개 회귀도 그대로 검증한다.

정상 호출 수는 상태가 준비됐고 수정·용량 오류가 없는 경우다. 긴 입력의 분할·개별 fallback, 내용 반려·수정과 마지막 답변 처리까지 2/6회라고 주장하지 않는다. 이번 2회 대화는 **전체 상태 초안 통합**이며 상위 기획의 더 작은 질문 결정 전용 경로 구현으로 표시하지 않는다.

### 초기 v2 합성 전후 비교 — 역사 기록

이 표는 초기 배열 codec 결과다. 현재 v4 및 압축을 끈 실제 `.env` 결과는 마지막 절의 별도 표를 따른다.

실제 Gateway·HTTP 파서·스키마·의미 검증기와 같은 합성 입력을 사용했고, 모든 14개 논리 검토 및 최종 guide·detail 저장 값을 보존했다. 아래 출력량은 **JSON bytes**이며 토큰·실모델 속도 절감률이 아니다.

| 지표 | 이전 → 이번 선택 경로 | 변화 |
| --- | --- | --- |
| 현재 범위별 블록 대화 | 5 → 2 POST | 60% 감소 |
| 기존 통합 대화 | 4 → 2 POST | 50% 감소 |
| 정상 최종 카드 | 8 → 6 POST | 25% 감소 |
| 최종 전체 요청 본문 | 238,437 → 209,014 bytes | 12.34% 감소 |
| 최종 전체 모델 JSON 출력 | 5,446 → 4,146 bytes | 23.87% 감소 |
| 첫 11개 검토 묶음 요청 | 87,998 → 78,567 bytes | 10.72% 감소 |
| 첫 11개 검토 묶음 출력 | 2,927 → 1,984 bytes | 32.22% 감소 |

호출만 합친 중간 안은 출력이 5,723 bytes로 오히려 늘었다. 근거 ID·검토 압축을 함께 적용한 값을 최종 비교로 삼았다. 개별 24-audit codec fixture는 출력 4,399→3,605 bytes, 추가 schema·지시 7,176→3,188 bytes다. 이 마지막 3,188 bytes도 원래 논리 schema 1,050 bytes보다는 크므로, 압축이 언제나 모든 입력을 줄인다고 일반화하지 않는다. 전체 요청 장부에서 비용을 확인한다.

### 선택 설정과 적용 범위

이 선택 경로의 최초 구현 시점에는 기존 서비스 `.env`·모델명·연결 대상·화면 디자인을 변경하거나 재시작하지 않았다. 이후 로컬 `.env` 적용은 아래 최신 절을 따른다. 사용자가 지정한 실모델 대상은 `malssi-gemma4-31b-cards-final-step4723`이며 이번에 호출하거나 대체하지 않았다. 다음은 수정 경로를 선택하는 설정 묶음이다. `combined_blocks` 전용 옵션을 켠 채 모드만 바꾸면 구성 검사가 실패하므로 함께 해제해야 한다.

```dotenv
MODEL_STATE_MODE=combined
MODEL_BUNDLE_TURN_REVIEWS=false
MODEL_REUSE_REVIEWED_NAME=false
MODEL_REUSE_REVIEWED_SAFETY=false
MODEL_BUNDLE_COMBINED_TURN_REVIEWS=true
MODEL_REUSE_FINAL_DRAFT=true
MODEL_BUNDLE_FINAL_REVIEWS=true
MODEL_BUNDLE_ANALYSIS_PLAN=true
MODEL_COMPACT_REVIEW_OUTPUT=true
MODEL_SHARE_REVIEW_SOURCES=true
MODEL_REPAIR_REVIEW_BUNDLE_TASKS=true
MODEL_EXTENDED_FINAL_EVIDENCE_IDS=true
```

새 세 옵션은 기본 false이며 파서·Compose·`.env.example`·`check-model`에 연결했다. 작성기가 지정한 압축 전송은 같은 원래 검토 계약·검증기와 함께 별도 검토 endpoint에도 전달하지만, endpoint·모델·자격·토큰 정책 설정을 바꾸지 않는다. 별도 검토측의 `MODEL_REVIEW_COMPACT_REVIEW_OUTPUT`으로도 선택할 수 있다. 작성측 옵션이 false여도 명시적으로 활성화한 검토측 설정을 덮지 않으며, 이 경우의 실제 요청 형식도 회귀로 확인했다.

### 최초 로컬 검사 결과와 당시 한계

전체 앱 검사: **2,638개 중 2,530 통과·실패 0·건너뜀 108**. JavaScript·JSON 검사와 diff 검사도 통과했다. 실제 PostgreSQL 검사가 필요한 108개는 앞서 설명한 환경 부재로 그대로 건너뛰었다. 추가 근거 위치 간 침범·메타데이터 변조 회귀도 집중 검사에서 통과했다.

Mac `http://127.0.0.1:11434`의 `gemma4:12b`로 합성 원문 검토 **2/2 통과**: 정상 보고 승인 5.582초, 미래 가능성을 과거 완료로 바꾼 주장 반려 8.628초. 실제 앱에서 사용하던 `reasoning_effort=none`과 완성 JSON 수신 후 종료·전체 검증 경로를 사용했다. 완료 JSON을 받은 시점에 종료하므로 usage는 없으며 0으로 집계하지 않았다. 이 경로를 쓰지 않은 첫 진단 시도는 384토큰 한도에서 두 건 모두 미완료였고 실패 기록을 보존했다. 이를 성공으로 계산하지 않았다.

이 두 건은 압축 출력의 복원·판정·반려를 확인하는 간단 테스트다. 대화 전체나 최종 카드 전체, 지정 31B 모델의 속도 검사가 아니다. **이 최초 검사에서는 실시간 2초·전체 카드 600초 달성을 검증하지 않았다.** 이후 실제 대화→카드 검사는 마지막 절을 따른다. 기존 실측의 모델 생성 비용을 고려하면 2회 통합만으로 실시간을 보장할 수 없다. 작은 질문 결정 경로 및 더 짧은 판단 출력에 대한 후속 검증은 GPU 금지 지시를 유지한 범위에서 별도 과제다. timeout·필수 검토를 줄이거나 미완료 카드를 성공 처리하지 않았다.

## 로컬 `.env` 적용·실제 대화→카드 검사 — 최신 단계

사용자의 추가 요청으로 `app/.env`에 대화 2회·최종 6회의 정상 경로를 적용했다. 비밀값을 출력하지 않고 Git에서 제외된 로컬 경로에 권한 0600 백업을 보관했다. 작성·검토 모델은 기존 Mac `http://127.0.0.1:11434/v1`의 `gemma4:12b`를 유지하고 `MODEL_SERVER_GPU_ONLY=false`로 확인했다. GPU 서버·SSH·터널·학습 환경은 접속하거나 변경하지 않았다. 기존 실행 서비스 재시작과 기본 DB URL 변경도 하지 않았다.

현재 활성 설정은 `MODEL_STATE_MODE=combined`, `MODEL_BUNDLE_COMBINED_TURN_REVIEWS=true`, `MODEL_REUSE_FINAL_DRAFT=true`, `MODEL_BUNDLE_FINAL_REVIEWS=true`, `MODEL_BUNDLE_ANALYSIS_PLAN=true`와 R1/R2/R3의 세 옵션이다. 모드가 달라진 기존 블록 전용 옵션·이름/안전 검토 재사용은 해제했다. 적용 뒤 다른 작업에 의해 `MODEL_COMPACT_REVIEW_OUTPUT=false`로 변경된 것을 감지했으며 이 변경을 보존했다. 실제 전체 흐름은 압축을 끈 현재 설정을 사용하며 압축 활성화 성공으로 보고하지 않는다.

실제 로컬 검사 중 발견한 오류를 두 가지 수정했다.

1. 압축 audit 배열은 다음 claim에도 이전 위치 코드를 허용하는 공개 스키마를 가졌다. v2에서는 위치 접두사도 공개하지 않았다. v3에서 접두사를 공개했어도 실제 모델이 다른 위치 코드를 출력했다. v4의 위치별 객체·enum으로 바꾼 뒤 같은 로컬 진단은 **실제 2 POST, 형식 재시도 없이 통과**했다. 오래된 결속·범위 침범·누락·중복은 계속 거절한다.
2. 압축 상태 검토를 재시도할 때 기존 긴 키의 `state,questions,safety` 응답을 요구하던 지시와 압축 `b,o` 스키마가 충돌했다. 압축 전송에서는 현재 스키마에 맞는 재시도 피드백을 유지하도록 고쳤고, 잘못된 첫 응답 뒤 두 번째 요청도 같은 압축 계약을 유지하는 회귀를 추가했다.

공개 스키마·메타데이터만으로 올바른 위치 코드를 만드는 회귀를 포함한 집중 검사 **85 통과·실패 0**을 확인했다. 이 검사는 실모델의 전체 처리시간을 보장하지 않는다. 수정 후 전체 앱 회귀도 새로 실행해 **2,642개 중 2,534 통과·실패 0·DB 의존 108개 건너뜀**을 확인했다. 첫 실행의 로컬 수신 권한 `EPERM`은 별도 실패 로그에 보존하고 로컬 테스트 서버를 허용한 환경에서 재실행했다. JavaScript·JSON 검사, `.env` 구성 검사와 `git diff --check`도 통과했다.

| 합성 정상 최종 흐름 | POST | 전체 요청 bytes | 전체 JSON 출력 bytes | 초기 11개 검토 요청/출력 bytes |
| --- | ---: | ---: | ---: | ---: |
| 기존 경로 | 8 | 238,437 | 5,446 | 87,998 / 2,927 |
| 최신 v4 압축 경로 | 6 | 213,449 | 4,276 | 82,024 / 2,094 |

### 실제 로컬 전체 흐름의 범위와 결과

Mac 로컬 Docker 소켓을 명시하고 이미 설치된 `postgres:16-bookworm` 이미지를 다운로드 없이 사용했다. 이번 작업 전용 컨테이너·스키마·암호화 키를 만들고 HTTP 전체 흐름을 검사한다. 관련 저장·진행 조회·후속 대화·권한·삭제·보존기간 회귀도 이 임시 DB의 테스트별 독립 스키마에서 실행해 **76 통과·실패/건너뜀 0**을 확인했다. 원래 기본 문항 중 이름·바람·관계·상황·감정 **5개**를 사용하며 모델이 고른 추가 질문에도 실제 API로 답한다. 준비 상태·모델 답변을 주입하지 않는다. 기본 29문항 전체나 브라우저 paint, 별도 기관 분류 API 검사는 아니다.

앞선 실행에서는 5개 기본 질문과 1개 추가 질문으로 대화가 완료됐다. 실제 대화 호출은 22 POST, 각 응답은 57.859~228.747초였다. 최종 분석·전략 초안, 각각의 독립 검토, 카드 초안은 통과했지만 초기 11개 검토 도중 테스트 클라이언트의 기본 HTTP 헤더 대기 제한(약 300초)에 연결이 종료됐다. 최종 저장 전 중단했으므로 카드 성공이나 10분 달성으로 집계하지 않았다. 앱·스키마 종료 후 소유 컨테이너가 삭제됐음을 정확한 ID로 재확인했다.

테스트 전용 HTTP 클라이언트를 명시적 취소 기한만 적용하는 로컬 `node:http` 구현으로 바꿨다. 임시 컨테이너 삭제 확인도 제거 진행 중 상태를 기다린 뒤 확인한다. 카드 기능 검사의 외부 진단 기한은 1,200초이며 서비스의 `MODEL_TIMEOUT_MS=0`은 그대로다. 이 진단 기한을 600초 목표 달성으로 해석하지 않는다.
