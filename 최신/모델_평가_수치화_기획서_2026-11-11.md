## 1 기획 목적과 핵심 방향

말씨는 정서적 어려움을 겪는 사람을 돕는 주변인이 상황을 정리하고 적절한 대화와 행동을 준비하도록 지원하는 서비스이다. 이번 필수 평가의 목적은 **같은 실행 베이스에서 어댑터 적용 유무에 따른 구조화 과제의 정확성과 오류를 비교하는 것**이다. 최종 안내 카드의 충실성·유용성, 전체 서비스 신뢰성, 임상 안전성은 이번 120개 요청으로 측정하거나 입증하지 않는다. 해당 항목은 후속 확장 연구 규격으로 구분한다.

**본 기획의 목표는 모델의 과업 수행 수준을 재계산 가능한 숫자로 표현하는 것이다.** ‘맥락을 잘 이해한다’, ‘질문이 적절하다’, ‘도움이 된다’와 같은 평가를 그대로 결론으로 사용하지 않고, 정답 라벨·오류 건수·통과 비율·척도 점수·기준 모델 대비 차이로 전환한다. 각 지표에는 계산식, 관측 단위, 포함·제외 조건, 실패 처리, 값의 범위와 판정 기준을 정의한다.

이번에는 같은 IT 기반 모델과 A_original 적용 모델을 동일 조건의 통제 과제로 비교한다. 형식 준수와 내용 정확성을 분리하고, 서로 다른 지표를 임의 가중한 종합 점수로 합산하지 않는다. 독립 평가셋·자연 발생 오류·사람 맹검을 결합한 카드 충실성·유용성 평가는 후속 확장에 해당한다.

### 이번 발표를 위한 최소 평가안

**현재는 평가 기획 단계이며, 이번 개정에서는 새 모델 평가를 실행하지 않는다.** 발표에 필요한 근거를 적정량으로 준비하도록 필수 범위를 **핵심 지표 6개·12개 통제 사례·두 모델 합계 120개 고정 요청**으로 줄인다. v1.3의 480개 고정 요청 대비 배정량을 75% 줄인 계획이며, 실제 시간·비용이 75% 줄었다는 뜻은 아니다.

| 구분 | 이번 필수 범위 | 후속 선택 범위 |
|---|---|---|
| 비교 대상 | 동일 IT 기반 모델과 A_original 적용 모델, 1쌍 | 다른 크기·어댑터 조합 비교 |
| 사례 | 6개 계열 × 기본·경계 각 1개 = 12개 통제 사례 | 신규 독립 test·다양한 자유 대화 |
| 과제 | 생성 관련 3과제 중심, 정상·오류 검토 2과제는 전이 대조 | 추가질문 선택, 지원 정책, 자유 카드 평가 |
| 고정 요청 | 모델당 60개, 합계 120개 | 별도 예산 확정 후 추가 |
| 핵심 지표 | M01·M03·M06·M07·M09·M11 | 나머지 14개 및 A/J 보조 지표 |
| 전체 흐름 | 필수에서 제외 | 사례 2개 × 모델 2개 = 4개 흐름 |
| 사람 평가·AI 심사 | 이번 필수 평가에 없음 | 자유 카드 유용성 등 필요한 경우 별도 |
| 발표 자료 | 학습 역할·방법 1장, 생성 과제 차이 1장, 전이·실패·한계 1장 이내 | 상세 지표·원시 근거는 부록 |

첨부 결선 심사표의 모델 성능 항목에 맞춰 **목적에 맞는 과제를 골랐는지, 어떤 정확성·신뢰성 지표로 측정했는지, 확인된 목표와 한계가 무엇인지**를 설명하는 규모다. 기존 사용자 지정 내부 채점 방식과 공식 결선 평가표는 구분한다.

이 최소안은 자동 정답을 만들 수 있는 **탐색적 통제 파일럿**이다. 소규모 결과로 전체 서비스 정확도·임상 안전성·통계적으로 확증된 개선을 주장하지 않는다. 제6~10절의 20개 지표 정의와 제17절의 확장 경로는 참고 규격으로 보존하며 이번 필수 실행량에 포함하지 않는다. 사람 없이 확정할 수 있는 과제부터 평가하되 형식 유효율과 내용 정확성을 분리한다.

### 수치화의 완료 기준

- 모든 핵심 평가 항목에 지표 ID, 계산식, 평가 단위와 원시 기록 항목이 존재한다.
- 동일 원시 기록과 동일 규약을 사용하면 동일한 점수와 분모가 재생성된다.
- 이번 결과에는 기준값·후보값·동일 배정의 차이·분모·계보 수·오류 및 실패·미실행 수를 함께 표시한다. 신뢰구간은 산출하지 않고 `ci95=null`, `adjusted_ci=null`과 사유를 기록한다(제9절).
- 사람 판단이 필요한 후속 확장 항목은 사전 판정표에 따라 0·1 또는 1~5점으로 기록하며 이번 완료 요건에 포함하지 않는다.
- 정의할 수 없거나 아직 측정하지 않은 값은 `null`과 사유로 관리하며 임의 점수를 만들지 않는다.

**본 문서의 수치 목표와 표본 규모는 실행 전 제안이다.** 이미 확보한 데이터, 과거에 관측한 값, 앞으로 달성할 목표를 구분한다. 새로운 모델 출력이나 성능 측정 결과를 본 문서에서 만들어 제시하지 않는다.

### 평가가 답해야 할 질문

1. A_original 적용 모델이 같은 실행 베이스보다 질문 판단과 주어진 근거 선택·갱신을 더 정확하게 수행하는가.
2. 질문을 유지하거나 생략하는 판단이 실제 답변 맥락에 근거하는가.
3. 검토 모델이 오류를 발견하면서 정상적인 결과를 과도하게 반려하지 않는가.
4. 명시적 정정 후 최신 근거가 올바른 대상 그룹에 남고 폐기된 근거가 현재 정보로 유지되지 않는가.
5. 최초 출력의 형식·내용 점수와 실패를 제삼자가 같은 자료와 규약으로 재계산할 수 있는가.

최종 카드의 유용성, 전체 흐름의 재시도·복구 효과는 후속 연구 질문이다. **평가 완료**는 배정·실패 기록과 재계산 근거의 완비, **개선 관측**은 이 패널에서 지표가 좋아진 사실, **성능 목표 충족**은 별도 사전 수용 기준을 뒷받침하는 근거 확보를 뜻한다. 세 상태를 혼용하지 않는다. 이번 파일럿은 앞의 두 상태만 보고하며 전체 모델의 성능 목표 달성이나 개선 입증으로 표현하지 않는다.

### 평가 범위의 구분

| 구분 | 목적 | 본 기획에서의 처리 |
|---|---|---|
| 모델 연구 평가 | 학습 효과와 과업별 적합성 확인 | 본 문서의 주 대상 |
| 프로젝트 내부 채점 | 데이터 품질과 앱 구현 평가 | 기존 사용자 지정 기준 유지 |
| 앱 통합 검증 | 입력·저장·재조회·삭제·소유자 격리 확인 | 모델 성능과 별도 결과로 관리 |
| 시간과 모델 규모 | 운영 환경 설명 | 성능 합격 점수 및 프로젝트 감점에서 제외 |

프로젝트 내부 채점에서는 모델 성능·크기·학습 진행률·생성 품질·체크포인트 로딩·앱 통합 여부를 평가하지 않는다. 기존 모델 관련 20점은 학습 데이터의 목적 적합성, 품질, 분할·누출 방지, 추적·재현 가능성을 평가한다. 본 연구 계획은 그 기준을 변경하거나 주최 측 공식 평가표를 대체하지 않는다. [S1]

최종 산출물은 평가 규약, 평가셋 명세, 정답 및 판정 지침, 실행 기록, 과제별 결과표, 오류 분석 보고서, 발표용 핵심 문안으로 구성한다. 실제 평가 완료는 이 산출물과 필수 검증 증거가 갖춰졌을 때 별도로 선언한다.

## 2 현재 확보한 근거와 평가 필요성

### 확인된 학습 현황

2026년 11월 10일 현황 문서와 연결된 로컬 학습 상태 기록에 따르면, 31B 카드 모델은 새 LoRA를 적용한 세 단계 학습과 전체 validation loss 계산을 마쳤다. 최종 체크포인트는 step 4,723이며, 역할별 평가가 필요하여 완료 상태는 `training_complete=false`로 기록되어 있다. 이는 저장된 기록의 상태이며 현재 실행 중인 서버 상태를 새로 확인한 결과는 아니다. [S3, S4]

| 단계 | 학습 행 | 검증 행 | 단계 학습 전 loss | 1 epoch 후 loss |
|---|---:|---:|---:|---:|
| 원상담 기초 | 37,065 | 3,618 | 4.988498 | 2.338531 |
| 카드 수정 | 20 | 5 | 0.091273 | 0.077405 |
| 카드 생성 | 688 | 170 | 2.239790 | 1.553758 |
| 합계 | 37,773 | 3,793 | 단계별 해석 | 단계별 해석 |

위 수량은 학습 예제 행 수이며 독립 상담 수나 평가 참여자 수가 아니다. 단계마다 과제와 검증 집합이 다르므로 loss 절댓값을 서로 비교해 과제 난도나 서비스 성능의 우열을 판단하지 않는다. 손실 감소율을 정확도 향상률로 바꾸어 발표하지 않는다.

### 별도의 성능 검증이 필요한 이유

학습 손실은 정해진 정답 토큰을 예측하는 정도를 나타낸다. 실제 이용 상황에서는 그 외에도 화자 구분, 정정 반영, 미확인 정보 보존, 질문 생략 근거, 최종 카드의 유용성이 필요하다. 따라서 학습 손실과 실제 과업 평가를 나누고, 과업별 성능 개선을 독립적으로 확인해야 한다.

확인한 최신 기록에서 최종 후보의 독립 test Macro F1·AUROC·사람 유용성 평가는 완료 증거가 확인되지 않았다. 기존 앱 회귀검사의 통과 개수와 단일 합성 사례의 실행 성공은 해당 모델의 독립 성능 표본 수로 사용하지 않는다. [S2, S3, S6]

### 기존 평가 자료와 신규 평가의 관계

기존 역할 평가 자료는 60개 원천 사례군으로 설계되어 있으며 개발 40개와 최종 확인 20개를 구분한다. 이는 12B와 31B가 같은 원천의 서로 다른 과업을 수행하는 자료이다. 두 모델의 사례 수를 더하여 120개의 독립 사례라고 표현하지 않는다. 실제 사용 전에는 해당 버전의 파일과 노출 이력을 다시 검증한다. [S5]

확장 연구안의 신규 test 목표는 300개 원천 그룹이며 이번 발표용 최소안의 필수 범위가 아니다. 기존 60개 자료를 이름만 바꾸어 신규 독립 test에 포함하지 않는다. 기존 자료는 평가기 개발과 이전 계약 확인에 활용하고, 최종 test로 유지할 수 있는지는 개발 과정의 노출 이력으로 판단한다.

## 3 평가 대상과 비교 실험 설계

### 역할별 평가 대상

| 평가 대상 | 입력과 역할 | 주요 출력 | 주요 판단 |
|---|---|---|---|
| 12B 대화·상태 모델 | 대화 맥락과 기존 상태 처리 | 사실·관계·미확인 정보·질문 계획 | 사실 추출 및 질문 판단 |
| 12B 검토 후보 | 고정된 원문과 동일 초안 검토 | 승인·반려 및 근거 | 오류 발견과 정상 결과 보존 |
| 31B 카드 후보 | 고정한 상태·계획에 따른 안내 생성 | script·doList·avoid·next·care | 충실성과 유용성 |
| 전체 실행 조합 | 생성·검토·수정 절차 연결 | 검토를 거친 최종 결과 | 최초 출력 대비 복구 효과 |

A·B·C 등 개발 중인 역할 이름은 실험 후보를 구분하기 위한 명칭으로만 사용한다. 데이터 폴더명이나 표시 모델명만으로 평가 대상을 확정하지 않으며, 실제 기반 가중치와 어댑터의 식별 정보가 필요하다. [S2]

### 비교 원칙

**주 비교는 같은 크기의 기반 모델과 학습 후보 한 쌍으로 한다.** 31B 기반 모델과 31B 학습 후보, 12B 기반 모델과 12B 학습 후보를 각각 비교한다. 12B와 31B의 직접 비교는 규모와 실행 조건이 함께 달라지는 배포 대안 비교로 분리한다.

생성자 학습 효과를 측정할 때에는 검토자, 프롬프트, 검색 자료, 상태 입력을 고정한다. 검토자 성능을 비교할 때에는 모델마다 새 초안을 생성하지 않고 동일한 정상·오류 초안을 제공한다. 생성자와 검토자를 동시에 바꾼 결과는 전체 조합의 효과로만 설명한다.

### A_original 확인 결과와 차이가 드러날 과제

이번 개정은 큰 점수 차이를 보장하는 설계가 아니라, **학습 역할과 맞지 않는 출력 요구를 줄이고 역할별 차이를 구분하는 설계**다. 성능이 같거나 더 나빠져도 같은 표와 분모로 공개한다.

| 확인 근거 | 확인한 내용 | 아직 주장할 수 없는 내용 |
|---|---|---|
| 첨부 A_original 어댑터·manifest | IT 기반 LoRA, rank 8·alpha 16. ZIP에는 가중치·config·미기입 학습 설명 템플릿만 있음 | 실제 학습 데이터·단계·revision과 로컬 A 묶음의 동일성 |

어댑터 식별은 [S11], 로컬 역할 구성·정답 구조는 [S12]에 근거한다. 원문·개별 정답은 문서에 복사하지 않는다. `training_provenance_status=unverified`로 기록하고, 첨부 어댑터 해시와 데이터 COURSE·학습 로그가 연결되기 전에는 “해당 학습 덕분에 향상됐다”는 인과 설명을 하지 않는다. 현재 가설은 **A 생성용 자료의 역할에 맞는 과제에서 어댑터 유무에 따른 차이가 관측될 수 있다**는 수준이다.

**요청 배정은 생성 관련 72개 + 검토 전이 48개 = 총 120개**다. 발표 순서만 구분하며 검토 요청을 삭제하거나 유리한 지표만 남기지 않는다. `not_needed`는 입력 계약에 허용되지만 로컬 A의 양성 정답이 확인되지 않은 일반화 하위항목으로 남긴다.

### 출력 계약을 맞춰 능력 차이를 측정하는 방법

S1·S3·S4는 로컬 A 자료의 입력·출력 계약을 참조하여 두 모델에 동일하게 제공한다. `contract_variant=training_contract_reference`이며, 이 명칭은 첨부 어댑터의 실제 학습 출처가 확인됐다는 뜻이 아니다. 현재 앱과 다른 부분은 앱 통합 성능으로 해석하지 않는다. 다음은 동결할 계약의 방향이며 실행기 구현·계약 검증 완료를 뜻하지 않는다.

| 슬롯 | 참조 출력 구조 | 자동 채점 연결 |
|---|---|---|
| S1 | question_plan의 clarify·safety·skip | 유효 skip의 question_id·reason을 읽고, 포함되지 않은 적격 후보를 retain으로 유도. retain 문자열을 새로 출력시키지 않음 |
| S3 | state_observations의 name_index·patient_state | subject·question_id·quote 후보에서 선택한 근거를 고정 ID로 투영. `metric_variant=controlled_evidence_selection`으로 M06 계산 |
| S4 | relationship_memory의 relationship_memory | patient/supporter의 reported 근거 참조를 대조. `metric_variant=controlled_current_evidence_update`, `input_variant=pre_correction_observations`로 M07 계산 |
| S6·S7 | 동일한 상태 검토 경로의 approved 계약 | 제7절의 review_adapter를 고정하고 같은 정상·오류 초안을 비교. `contract_variant=production`으로 생성 과제와 분리 |

최상위 키가 같다는 것만으로 계약 정합을 인정하지 않는다. 필드 타입·필수 여부·enum·근거 인용·배열 상한·입력 포장·프롬프트를 참조 자료와 대조하고 schema·projection 버전/해시를 동결한다. **튜플은 채점기 내부 표현으로만 사용하며 모델에 새로운 튜플 출력 형식을 강요하지 않는다.** 두 모델의 입력·스키마·투영기는 동일하다. 공개 규칙과 허용 라벨만 프롬프트에 주며 해당 사례의 정답·정답 튜플은 전달하지 않는다.

자유 서술 필드는 제한 문법·사전 동결 표현 사전으로 독립적으로 해석 가능한 범위만 자동 채점한다. 계약상 유효하지만 지원하지 않는 표현은 오답으로 몰지 않고 `scorer_unsupported`로 해당 의미 결과를 보류한다. 표현 불가능한 정정을 새 필드로 몰래 확장하거나 어댑터 출력에 맞춰 파서를 고치지 않는다. 정합 투영이 준비되지 않으면 실행 준비 미완료로 남긴다. 모델 결과를 보고 선택하는 다른 계약은 새 개발 규약·실행 ID로 구분한다.

### 실제로 관측할 수 있는 범위와 입력 격리

로컬 A 참조 계약의 S3는 `sourceVariants`에 대상·문항·인용 후보가 미리 연결되고 `facts`는 최대 3개다. 자유 interpretation은 제거된 경로이므로 채점기가 선택된 인용문에서 부정·시점을 읽었다고 모델이 그 의미 속성을 별도로 추론한 것으로 세지 않는다. **이번 M06은 현재 근거 선택 Micro F1**이며 확장 규격의 자유 사실 Micro F1과 별도 variant로 보고한다. [S13]

S4의 patient/supporter `reported`는 근거 배열과 certainty를 사용한다. 참조 계약상 그룹당 최대 2묶음·묶음당 최대 3개 근거, unknowns 최대 4개이며, 관계 해석의 자유 문장은 별도다. **이번 M07은 정정 후 현재 근거 갱신율**로 한정하고 자유 해석 문장 전체의 의미적 정정·안전성을 측정했다고 주장하지 않는다. 명시적 대상이 필요한 정정은 patient/supporter 범위에서 설계한다. 원문 quote 안의 시간·부정을 채점기가 대신 해석한 결과를 모델이 출력한 필드로 만들지 않는다. [S13]

모델별 60개 요청은 모두 **독립된 무상태 입력 스냅샷**이다. 두 모델에 같은 원문·후보·이전 상태를 제공하고, 앞 요청의 모델 출력·검토 결과·대화 세션을 다음 요청에 전달하지 않는다. 요청 간 KV/대화 문맥 재사용으로 쌍의 정답이 보이지 않도록 격리한다. S1/S3는 고정 원문·후보, S4는 **정정 이전 observations·prior_relationship_memory와 정정 전후 전체 원문**만 받는다. 최신 정답 상태나 S3의 모델별 출력은 주지 않는다. 기존 학습 자료 작성기의 현재 정답 observations 입력을 그대로 복제하지 않고, 입력 변형을 manifest에 명시한다. [S13]

S6/S7은 생성기로 동결한 같은 초안을 두 모델에 주며, 입력 payload는 원문·초안·claims·reference_roles 등 실제 검토 계약의 허용 필드만으로 만든다. 이전 판정의 approved·audits·issues, error_type, gold, 수정 정답은 제외한다. 출력 스키마의 허용 라벨 설명과 실제 정답 값은 구별한다. 정상/오류 쌍은 동일 스키마·필드 수·근거/claim 수를 유지하고 의미 오류 하나만 바꾼다. 모델 입력에는 S6/S7·정상/오류·기본/경계 같은 평가용 표시를 넣지 않는다. 중립 ID와 사전 seed로 섞은 순서를 양 모델에 동일하게 적용하며 ID 대응표·오류 manifest는 평가기에만 둔다. [S13]

동결 전에는 과제별 **관측 가능성 표**를 작성한다. 각 필수 gold에 입력 근거, 실제 출력 필드, 비교 규칙, 현재/과거 구분, 해당 계열을 연결하고 필수 정답이 배열 상한 안에 동시에 표현 가능한지 검사한다. S3에는 현재 정답과 구별해야 하는 유효 후보를 포함하여 단순 전부 복사만으로 성공하지 않게 한다. 참조 스키마로 표현할 수 없는 의미는 채점기가 추론해 보충하지 않는다. 이 표와 투영기 검증이 준비되지 않으면 배정 120개는 유지하되 실행 준비 미완료로 남긴다.

### 동결해야 할 실행 조건

- 기반 모델·어댑터·토크나이저의 버전과 해시, 실제 로딩 식별 근거.
- 시스템 프롬프트·입력 양식·출력 스키마·앱 소스 및 검색 자료 버전.
- 양자화, 입력 문맥 한도, 출력 예산, 생성 옵션, seed 지원 및 적용 여부.
- 검토 횟수와 수정·재시도·취소 정책, 오류 상태 정의, 평가 규약 해시.
- JSON 강제 여부, 서버의 유효 생성 설정과 기본값, 출력 추출 규칙의 버전·해시.

**이번 120개 요청의 생성 방식은 `decoding_mode=prompt_only_unconstrained`로 고정한다.** JSON 스키마는 프롬프트 텍스트로만 제공하며 두 모델에 같은 시스템·사용자 프롬프트와 과제별 스키마를 사용한다. `response_format`·`grammar`·JSON mode·스키마 제약 디코딩은 적용하지 않는다. 요청에서 생략하는 것만으로 비활성이라고 간주하지 않고, 실행 전에 서버 기본값과 실제 유효 설정도 확인하여 버전·설정 해시 및 비활성 근거를 남긴다. 이 조건을 지원하거나 확인할 수 없으면 실행 준비 미완료로 남기며 강제 JSON으로 자동 전환하지 않는다. 다른 생성 방식은 별도 규약·실행 ID로만 비교한다. M01의 해석은 이 생성 조건에서의 원시 형식 준수율로 한정한다.

### 이번 파일럿의 고정 출력 추출 규칙

동일한 최초 응답을 아래 두 경로로 읽는다. 새 모델 호출이나 앱의 자동 복구를 사용하는 절차가 아니다.

| 채점 대상 | 고정 규칙 | 실패 처리 |
|---|---|---|
| M01 원시 형식 | `raw_json_v1`: 전송 규약으로 분리한 응답 본문 전체를 JSON 파서와 해당 스키마로 검사. 코드펜스 제거 없음 | 코드펜스·설명 문장·JSON 또는 스키마 오류는 형식 실패 |
| M03·M06·M07·M09·M11 내용 | `raw_or_single_json_fence_v1`: 본문 전체가 JSON이면 그대로 사용. 또는 바깥 JSON 공백을 제외한 전체가 여는 줄 ` ```json `, JSON 본문, 닫는 줄 ` ``` `로만 구성된 단일 블록이면 바깥 두 줄만 제거한 뒤 같은 JSON·스키마·계약 검사 적용 | 추출 후 JSON·스키마·계약 오류는 해당 의미 지표의 INVALID·실패 규칙 적용 |

위 표의 코드 표기 안 좌우 공백은 설명용이다. 펜스 줄에는 각각 백틱 3개와 소문자 `json`, 백틱 3개만 허용하며 줄바꿈은 LF 또는 CRLF를 허용한다. 바깥 공백은 JSON 공백(스페이스·탭·CR·LF)만 허용한다. 블록 앞뒤 설명, 복수 블록, JSON 일부 탐색, 글자 수정, 누락 키 보완, 기본값 채움은 허용하지 않는다. 두 모델에 같은 파서·스키마 검증기를 적용하고 구현 버전·해시를 동결한다.

내용 지표의 **주 결과는 이 단일 추출 규칙으로 산출**한다. M01 실패를 이유로 펜스 내부의 유효한 내용을 자동 INVALID로 만들지 않으며, 내용 채점 성공으로 원시 M01을 통과로 바꾸지도 않는다. `raw_schema_valid`, `semantic_schema_valid`, `semantic_contract_valid`, 실제 추출 분기(`raw / single_json_fence / invalid`)를 따로 남긴다. 사후에 추가한 추출·복구 방식의 점수는 민감도 분석으로만 보고하고 주 결과를 대체하지 않는다.

연구 주 비교는 지원되는 범위에서 temperature 0과 sampling 비활성 조건을 사용한다. seed를 기록하더라도 완전한 결정론을 가정하지 않는다. 기존 temperature 0.2 실험은 별도 실행 이력으로 보존하며 새 평가와 합산하지 않는다.

모델 단독 평가는 **최초 출력**을 채점한다. 전체 실행 평가는 사전에 고정한 복구 정책의 **최종 출력**을 별도로 채점한다. 수정 후 성공 결과로 최초 오류를 덮어쓰지 않는다. 모델 식별이 불일치하면 성능 점수를 확정하지 않고 해당 실행을 무효로 처리한다.

| 통제 파일럿 | 6개 계열 × 2개 변형 = 12개 사례 | 5개 고정 과제의 기반·학습 모델 비교 | 자동 정답이 있는 소규모 기술 검증 |
| 전체 흐름 | 선택 시 2개 사례를 두 모델에 각각 적용 | 생성·검토 종료 흐름의 보조 확인 | 4개 흐름이며 모델 호출 4회를 뜻하지 않음 |

12개 사례는 12명의 사용자나 12개 독립 원천을 뜻하지 않는다. 실제 템플릿·계보가 공유되면 6개 또는 그 이하의 계보로 보고한다. 질문 라벨의 세 클래스와 정상·오류 초안이 빠지지 않도록 배정 전에 확인한다. 기존 결과에서 잘 나온 사례만 골라 축소하지 않으며, 새 사례·정답·평가 규칙을 출력 확인 전에 동결한다.

### 확장 연구용 표본 — 이번 필수 범위에서 제외

기존 dev 30그룹과 test 300그룹(기본 240·어려운 사례 60), 과제별 추가 표본은 장기 확장안으로만 보존한다. 이번 발표 준비에서 확보하거나 실행해야 할 수량이 아니다. 독립 성능 입증이 필요해질 때 표본 설계와 검토 인력을 별도로 확정한다. [S2]

한 그룹은 동일 원상담 또는 동일 시나리오 계보에서 파생한 모든 턴·질문·문장·오류 초안·변형을 포함한다. 같은 그룹의 파생 자료는 train·dev·test 사이에 나누지 않는다. 실제 인물의 동일성을 확인할 수 없다면 사람 단위 독립성이 확보되었다고 주장하지 않는다.

### 사례 구성 기준

확장 연구의 기본 패널은 가족·친구·직장 등 서비스가 다루는 관계, 이용자의 요청 유형, 대화 길이, 정보의 충분성, 동의와 도움의 범위를 교차해 설계한다. 실제 이용 분포를 뒷받침할 자료가 없으면 임의의 균등 배분을 서비스 대표 분포라고 표현하지 않는다. 모집단·층화 기준·각 층의 목표량과 가중치는 test 실행 전에 확정한다.

확장 연구의 어려운 패널은 정정, 부정과 시점, 사람 혼동, 미확인 정보, 현재 위험 대응, 문맥상 질문 생략의 여섯 유형을 각 10그룹씩 확보하는 안이다. 유형별 10그룹은 오류 발견을 위한 규모이며 높은 정확도를 확증하는 표본으로 간주하지 않는다. 어려운 패널을 기본 패널에 합쳐 실제 오류율을 계산하지 않는다.

### 누출 방지 절차

원천 ID와 파생 계보를 우선 대조하고, 정규화 본문 해시 및 근접 중복 검사를 보조 적용한다. 의미만 바꾼 템플릿, 기존 프롬프트 수정에 활용한 사례, 사람이나 AI 검토에 노출된 test 자료도 이력을 확인한다. 문자 유사도가 낮다는 사실만으로 독립성을 증명하지 않는다.

개발자가 test 결과를 보고 모델·프롬프트·정답을 조정했다면 해당 세트는 개발 자료로 전환하고 새 독립 test를 확보한다. 노출 여부가 불명확하면 독립성 미확인으로 기록한다. 정답을 포함한 파일은 추론 입력과 물리적·논리적으로 분리한다.

## 5 정답 구축과 질문 판단 기준

### 정답 구축 절차

자유 서술·현실 사례를 사용하는 사람 평가 패널에서는 두 명의 평가자가 모델 출력을 보지 않은 상태에서 원문 사실, 정정된 정보, 미확인 정보, 허용 행동, 필수 조건, 금지 주장, 질문 생략 근거를 독립적으로 표기한다. 불일치는 지침과 원문으로 조정하되 최초 표기와 합의 이력을 모두 보존한다. 판정이 어려운 경우 제삼의 조정자가 검토한다.

정답 작성자와 출력 평가자는 가능한 한 분리한다. 역할 중복이 있으면 보고서에 공개한다. AI가 작성하거나 검토한 라벨은 개발 보조 자료로 표시하며 사람의 독립 판정을 대체하지 않는다. 본 계획에서 말하는 독립 검토는 평가 절차의 독립성을 뜻하며 사람 검토와 AI 검토를 구분해 기록한다.

통제 자동 패널은 모델과 독립된 결정적 사례 생성기·정답 규칙·실제 문항 허용 조건으로 정답을 만들고, 입력과 정답을 추론 전에 동결한다. 이 범위에서는 사례별 사람 확인을 요구하지 않는다. 적용 조건과 기계 정답의 검증 방법은 제17절을 따른다.

### 원자 사실의 표현과 일치 판정

사실은 사람, 속성 또는 관계, 값, 시점, 부정, 확실성으로 나누어 기록한다. 평가자는 원문으로 뒷받침되는 동의 표현을 인정하되 사람·시점·부정·확실성이 바뀌면 엄격 일치로 인정하지 않는다. 한 예측은 한 정답에만 대응하며 중복 예측은 추가 오류로 센다.

정답 목록 밖의 출력이 반드시 오류인 것은 아니다. 원문이 지지하는 추가 사실은 별도 supported-extra로 기록하고, 핵심 정답 F1의 TP·FP에는 넣지 않는다. 대신 모든 출력 사실의 충실성 평가에는 포함한다. 정답 자체의 누락이 확인되면 변경 이력을 남기고 모든 모델을 같은 개정 정답으로 재채점한다. 미해결 사실이 남으면 엄격 사실 F1 확정을 보류한다.

### 질문 생략 평가

| 평가 라벨 | 의미 | 판단 근거 |
|---|---|---|
| retain | 생략하지 않고 유지 | 아직 필요한 정보이며 문맥상 해소되지 않음 |
| already_covered | 앞선 답변에서 다룸 | 해당 정보를 뒷받침하는 실제 발화가 있음 |
| not_needed | 현재 맥락에서 불필요 | 현재 목적과 상황에 비추어 질문 필요성이 사라짐 |

미응답이라는 사실만으로 not_needed로 판단하지 않는다. 이미 답한 질문의 반복과, 답하지 않았지만 맥락상 불필요해진 질문을 구분한다. 생략은 답변 생성이 아니므로 생략된 문항의 답이나 사실을 저장하거나 최종 카드의 근거로 사용할 수 없다.

정상적인 `question_plan.skip` 출력에 없는 허용 후보는 retain으로 해석한다. 빈 skip 배열도 정상적인 유지 판단이 될 수 있다. required·noSkip·답변 수·배열 상한 등 실제 스키마 조건을 먼저 적용하고, 생략할 수 없는 문항을 성능 정답으로 요구하지 않는다. 상한을 초과하는 스트레스 사례는 별도 패널로 다룬다.

정답이 확정되지 않는 사례는 모델 결과를 보기 전에 채점 불가로 지정하고 이유를 기록한다. 성능이 낮다는 이유로 사례를 제외하지 않는다. 범주형 일치율과 Cohen κ, 순서 척도의 가중 κ는 합의 전 판정으로 계산하며 정의되지 않는 경우 사유와 함께 미산출로 남긴다.

## 6 구조화 과제와 사실 추출 지표

### 공통 집계 단위와 표기

원천 그룹, 사례, 요청, 질문 후보, 원자 사실, 사실 주장, 카드 묶음을 서로 다른 단위로 기록한다. 서로 다른 단위를 한 분모에 합치지 않는다. 이번 파일럿은 신뢰구간을 산출하지 않는다. 후속 확장에서 구간을 산출할 때에는 계산 단위가 요청이나 사실이어도 원천 그룹의 결속을 보존한다.

`N_assigned`는 해당 과제·지표 단위에 사전 배정한 수, `N_unscorable`은 모델 출력을 보기 전에 정답을 확정할 수 없어 의미 채점에서 제외한 수, `N_eligible = N_assigned − N_unscorable`은 의미 채점 대상 수이다. 질문 후보 집계의 failed_count에는 후보 수를, 요청 집계에는 요청 수를 기록한다. 한 요청이 실패하여 후보 3개를 평가하지 못했다면 요청 실패 1건과 후보 INVALID 3건을 서로 다른 집계에 기록한다.

**실행·출력 형식·사람 판정은 별개의 상태이다.** 실행은 `output_received / failed / not_run`으로 구분하고, `N_received + N_failed + N_not_run = N_assigned`로 대조한다. `output_received`는 비어 있지 않은 원시 응답을 수신했다는 뜻이며 스키마·의미 통과를 뜻하지 않는다. 수신된 비정상 JSON도 여기에 포함하고 원시 형식 결과를 `raw_schema_valid=false`로 별도 기록한다. 의미 경로의 `semantic_schema_valid`와 혼합하지 않는다. 빈 응답·통신 오류·확인된 취소는 failed, 중단으로 시작하지 못한 사례는 not_run이다. 실행 기록이 없어 어느 상태인지 확인할 수 없으면 not_run으로 추정하지 않고 `missing_execution_evidence`로 집계를 보류한다.

정답 상태는 `eligible / unscorable`, 출력 판정 상태는 `pending / completed / unresolved`, 사전 비적용은 `not_applicable`로 각각 관리한다. 실패한 실행은 규약에 따라 INVALID 또는 0·1점으로 반영하지만, 사람 판정 pending·unresolved는 실패로 치환하거나 분모에서 지우지 않는다. 필수 판정이 미완료이면 해당 의미 지표의 공식 `value=null`과 잠정 집계를 분리한다. 형식 지표는 사람 검토가 끝나기 전에도 별도 확정할 수 있다.

`logical_request_id`는 고정 입력·출력 계약 한 건이며 실제 전송 시도에는 별도 `attempt_id`를 부여한다. 재시도·수정으로 배정 수를 늘리지 않는다. 원시 최초 시도, 최초 초안, 수정 후 최종 출력은 `output_stage`로 구분한다. API 클라이언트가 최초 실패를 내부에서 숨기면 최종 반환값만으로 M01을 역산할 수 없으므로 최초 시도 로그를 추가 수집해야 한다.

M01 주 비교는 미리 고정한 단일 요청 과제 목록을 사용한다. 앞 단계 성공 여부에 따라 동적으로 생성된 후속 요청은 그 목록의 분모에 추가하지 않는다. 전체 흐름의 도달 단계별 형식 유효율은 도달 수를 공개한 보조 집계이며 M02와 함께 해석한다. 의미 지표의 적격 집합과 실행 상태는 교차 집계하며 unscorable과 failed를 같은 종류의 제외로 합산하지 않는다. 미실행이 남은 패널은 최종 비교를 확정하지 않는다.

| M15 | 근거 없는 사실 주장 비율 | 근거 없는 사실 주장 수 ÷ 실제 검토한 판정 가능 사실 주장 수 | 사실 주장 | 0~1, 낮을수록 좋음 |
| M16 | 중대 오류 관측 그룹 비율 | 모든 지정 출력이 확보·검토된 그룹 중 중대 오류가 확인된 그룹 수 ÷ 모든 지정 출력이 확보·검토된 그룹 수 | 원천 그룹 | 0~1, 낮을수록 좋음 |
| M17 | 실패 포함 유용성 | 출력별 두 평가자 점수 평균 → 그룹 평균 → 패널 내 그룹 평균 | 원천 그룹 | 1~5점, 높을수록 좋음 |
| M18 | 카드별 역할 적합률 | 해당 카드가 사전 역할 기준을 모두 통과한 적격 사례 수 ÷ 해당 카드가 요구된 적격 사례 수 | 카드 유형별 사례 | 0~1, 높을수록 좋음 |

| M20 | Average Precision | 임계값별 recall 증가량 × 해당 precision을 합산 | 점수화 대상 사례 | 0~1, 높을수록 좋음 |

M01·M02는 형식과 처리 완료 지표이며 의미적 정확성의 대체 지표가 아니다. M04는 명시적인 부당 생략을 세므로 INVALID로 인한 실패까지 평가하는 M03과 함께 해석한다. M18은 script·doList·avoid·next·care를 각각 산출하고 한 카드의 성공을 다섯 카드의 성공으로 계산하지 않는다.

M05·M08·M15·M16은 실제 관측 가능한 출력에서 오류를 세는 **조건부 오류 지표**이다. 해당 출력의 coverage와 미관측·실패 수를 반드시 병기하고, 출력이 없어 오류가 관측되지 않은 경우를 ‘오류 없음’으로 판정하지 않는다. M15는 검토한 주장 수와 그 주장이 속한 사례·그룹 수를 함께 제공한다. M16은 일부 출력만 얻은 그룹을 비율의 분모에서 제외하지만 그 부분 출력에서 발견한 중대 오류를 `any_observed_major_error_count`에 반드시 남긴다. 이 건수는 후보 통과 차단에 사용한다. 실패를 포함한 전체 성능 판단에는 M02·M14·M17을 함께 사용한다.

M07·M10·M12·M13·M14·M18의 생성 또는 처리 실패는 통과 분자에 포함하지 않는다. M17은 생성 실패 1점을 적용한다. 사람 판정 미완료는 실패 1점이나 0점으로 치환하지 않는다. M19·M20은 연속 점수 확보 조건을 충족할 때만 산출한다. 모든 비율은 분모가 0이면 `null`이다.

### M01과 M02의 완료 경계

M01은 **원시 최초 출력의 JSON 및 스키마 적합성**을 측정한다. 자동 형식 복구·기본값 채움·문자열 정리 후에 통과한 결과를 최초 성공으로 계산하지 않는다. 전송 규약이 정한 응답 본문 추출만 허용하고 추출 규칙을 동결한다. 제3절의 `raw_json_v1`을 사용하므로 단일 JSON 코드펜스라도 M01에서는 실패다. 내용 지표의 펜스 제거 허용과 구분한다. 근거 인용의 실제 존재 여부나 내용의 타당성 검사는 의미·계약 검사로 분리한다. 스키마 유효 출력이라도 의미적으로 틀릴 수 있다.

M02의 종료점은 **앱 생성 파이프라인이 검토를 마친 최종 응답을 반환하는 시점**이다. DB 저장·재조회·화면 표시 성공은 별도 앱 검사이며 M02가 입증하지 않는다. 일반 안내와 긴급 고정 안내는 route_id별 필수 단계를 따로 동결하고 각각 보고한다. 검토 후 초안 변경, 필수 승인 누락, 취소, 복구 소진은 실패이다. 조기 종료된 사례의 후속 요청을 단순 미실행으로 빼서 M02 분모를 줄이지 않는다.

### M03부터 M08까지의 의미 판정 규칙

**M03·M04 질문 판단.** 평가 후보는 입력 스냅샷에서 허용되는 **(대상 ID, question_id)별 문항 하나**로 고정한다. 대상이 단일인 경로도 고정 대상 ID를 기록한다. reason은 후보 키가 아니라 already_covered·not_needed 예측 라벨이며 유효 skip에 없는 문항은 retain이다. 동일 candidate_key의 중복·상충 skip은 계약 오류로 처리한다. 문항 하나를 reason 수만큼 복제하여 분모를 늘리지 않는다. 정답 라벨의 우선순위는 직접 답변 근거가 있으면 already_covered, 직접 답변은 없으나 사전 목적 규칙상 불필요하면 not_needed, 나머지는 retain이다. 모호한 경계는 gold 작성 시 해결하거나 사전 unscorable로 둔다. 정상 빈 skip은 전부 retain이다. 이번 파일럿에서는 제3절의 `raw_or_single_json_fence_v1` 추출 후 전체 출력의 JSON·스키마·계약 오류가 남으면 모든 적격 후보에 INVALID를 부여한다. 사전 허용한 바깥 펜스 제거 외에는 비정상 부분을 임의로 구제하지 않는다. INVALID 후보를 명시적 생략으로 세지는 않으므로 M04에는 retain 후보의 INVALID 비율도 병기한다. M03은 생략 사유 분류의 정확성이지 explanation 문장 전체의 충실성 점수는 아니다.

기본 스키마에는 skip 상한 8개가 있으나 관계 질문 경로는 상한 3개 등 다른 제약을 적용한다. 따라서 공통 상수로 8개를 가정하지 않고 **실제 request.schema·후보·reason별 허용 조건·상한을 요청마다 저장**한다. 최초 모델 skip, 앱 정규화 후 skip, 독립 검토 후 적용 skip은 서로 다른 stage이다. M03·M04의 주 결과는 최초 모델 출력에서 사전 추출 규칙을 적용한 내용 판정이며, 앱 정규화·검토 적용 후 결과는 별도 시스템 보조 결과로 보고한다. 후처리로 제거된 오류를 최초 모델의 올바른 판단으로 바꾸지 않는다. [S7]

**M05 반복 질문.** 문장부호 수가 아닌 정보 요구 단위로 분절한다. 한 문장이 서로 다른 정보 두 개를 요청하면 질문 단위 두 개, 같은 정보를 표현만 달리 반복하면 출현별 질문 단위로 기록한다. 질문 단위가 이미 답변된 정보와 일치하고 새 목적·시점·정정·허용된 명료화 필요가 없을 때만 repeat=1이다. 모호한 답변의 재확인, 모순 해소, 새로운 시점의 변화 확인은 gold에 사전 허용한 조건이면 0이다. 질문이 없는 정상 출력은 질문 수 0이며 M05를 0으로 만들지 않는다. 필수 질문 누락은 다음 질문·완료 조건 검사로 분리한다. 출력된 모든 질문의 분절과 판정이 끝나야 값을 확정한다.

현재 관계 질문의 clarify는 새 문장 생성이 아니라 고정 후보 ID를 0~1개 고르는 경로이다. 이 경로의 M05는 **선택된 후보 ID와 동결된 질문 내용**을 한 선택 단위로 사용한다. 위 자유 문장 분절 규칙은 별도의 대화 생성 과제에만 적용하고 두 결과를 합산하지 않는다. 앱 코드가 선택한 기본 질문을 모델 선택과 섞지 않는다. `question_mode=candidate_selection / free_text`를 기록하며, 후보를 선택하지 않은 정상 응답은 질문 수 0으로 남긴다. [S7]

**이번 S3의 M06 변형.** `controlled_evidence_selection`에서는 출력 facts에 필요한 현재 근거의 (대상, 문항, 원문 인용) 대응을 동결한 ID로 비교한다. 허용된 동등 인용은 같은 근거 ID에 대응시킨다. TP는 필수 근거와 일대일로 맞은 선택, FN은 빠진 필수 근거, FP는 중복 선택·잘못된 대상 귀속·현재 상태에 부적격한 후보 선택이다. 과제에서 선택하도록 허용한 후보 집합 전체의 현재 적격성을 출력 확인 전에 정하고, 숨겨진 추출 대상이나 과도한 필수 근거로 오답을 만들지 않는다. 이 닫힌 후보 판정에서는 비정답 후보를 사후 supported-extra로 면제하지 않는다. 형식·계약 실패는 모든 필수 근거를 FN으로 남기며, 유효 출력의 자유 표현을 읽지 못한 scorer_unsupported는 실패 점수로 바꾸지 않고 해당 지표·모델 쌍의 공식 값과 차이를 보류한다. 원자 사실 생성 F1과 이 근거 선택 F1은 합산하지 않는다.

**이번 S4의 M07 변형.** `controlled_current_evidence_update`의 성공은 모든 필수 최신 근거가 올바른 patient/supporter reported 그룹에 있고, 정정으로 폐기된 단독 근거를 현재 정보로 남기지 않는 경우다. 출력 근거의 현재/과거 역할과 허용된 정정 묶음은 사전 evidence-role 표로 결정한다. 최신 정정과 연결된 과거 인용은 허용할 수 있지만 폐기된 인용만 현재 근거로 남긴 것은 실패다. 필수 최신 근거 누락·잘못된 그룹·내용 INVALID·실행 실패는 0이다. 현 계약으로 현재/과거 역할을 구별할 수 없는 사례는 동결 전에 고쳐 표현 가능하게 만들며, 실행 후 임의로 누락시키지 않는다. tentative 자유 해석은 이 자동 점수의 의미 검증 대상이 아니다. 다음의 일반 M06·M07은 후속 확장 규격으로 보존한다.

**M06 사실 매칭.** 정답·예측의 원자화 규칙과 필수 튜플 속성을 고정한다. 동의 표현으로 인정한 대응 간선에서 최대 매칭 수를 구하고 동률은 gold_fact_id, predicted_fact_id의 사전순으로 해소한다. 같은 근거 사실을 여러 번 출력하면 하나만 대응시키고 나머지는 중복 FP다. supported-extra도 동일 사실의 첫 출현만 비교 집합 밖으로 두며 추가 중복은 FP로 남긴다. 틀린 값·화자·시점·부정으로 정답을 대체한 예측은 FP 1과 누락된 정답의 FN 1을 함께 만든다. 집계 F1은 ΣTP·ΣFP·ΣFN으로 계산하며 사례별 F1 평균과 혼용하지 않는다. gold가 비어 있어도 근거 없는 예측이 있으면 F1=0, 양쪽 빈 정상 출력만 null이다.

**M07 정정 반영.** 입력에 명시적 정정이 있고 해당 과제에서 최신 사실의 출력을 요구하는 사례만 사전 적격으로 지정한다. 여러 정정이 있으면 필수 최신 값 모두를 올바른 사람·시점으로 반영하고 대체된 값을 현재 사실로 쓰지 않아야 1이다. 과거 발언이라는 표시와 정정 관계를 정확히 유지한 역사 서술은 실패가 아니다. 카드 과제에서 해당 사실의 언급을 요구하지 않았다면 침묵을 누락으로 채점하지 않고 상태 추출 과제로 평가한다. 필수 최신 사실 누락과 출력 실패는 0이다.

**M08 생략 답변 조작.** 모델이 생략한 사례만 사후 선택하면 분모가 달라지므로, 주 평가에서는 입력에 고정 생략 목록·미응답 항목을 둔 공통 사례를 사용한다. 두 모델에 같은 상태를 주고 상태 갱신 및 후속 안내를 관측한다. 앞선 다른 답변에서 이미 뒷받침되는 내용은 조작이 아니다. 근거 없이 미응답 값이나 발언을 확정하거나 그 값을 안내의 전제로 사용하면 1이다. 필요한 상태·안내 중 하나라도 확보되지 않으면 주 관측률에서 제외하고 coverage와 실패에 남긴다. 부분 출력에서 확인한 조작은 별도 발견 건수로 보존하고 중대 오류 판단에서 숨기지 않는다. 자율 질문 선택 흐름의 생략 사례 분석은 별도 탐색 결과이다.

### 관측률의 coverage와 비교 범위

| 대상 | 반드시 병기할 coverage | 모델 간 비교 규칙 |
|---|---|---|
| M04 | retain 후보 중 정상 예측 후보 수 ÷ 전체 retain 후보 수 | 전체 공통 retain 집합에서 계산, INVALID 비율 함께 비교 |
| M05 | 모든 질문을 분절·판정한 수신 출력 수 ÷ 사전 적격 출력 슬롯 수, 질문 0개 출력 수 | 양 모델의 공통 완전 관측 출력 슬롯에서 보조 비교 |
| M08 | 상태와 안내가 모두 확보·판정된 고정 사례 수 ÷ 사전 적격 사례 수 | 공통 완전 관측 사례에서 비교, 모델별 coverage 별도 |
| M15 | 주장 분절·판정이 끝난 수신 출력 수 ÷ 적격 출력 슬롯 수, 전체 발견 주장 대비 판정 완료 비율 | 공통 완전 관측 출력 슬롯에서 비교, 주장 수가 다름을 공개 |
| M16 | 모든 지정 출력이 확보·검토된 그룹 수 ÷ 적격 그룹 수 | 양 모델의 공통 완전 관측 그룹에서 보조 비교 |
| M19·M20 | 유효 연속 점수가 있는 적격 사례 수 ÷ 전체 점수화 적격 사례 수 | 전체 공통 패널 100%일 때 주 비교, 그 외 공통 부분은 보조 |

사람 판정이 누락된 출력을 ‘관측 불가’로 바꾸어 분모에서 제거하지 않는다. 먼저 확보된 모든 지정 출력의 필수 판정을 완료해야 조건부 오류 지표를 확정할 수 있다. 관측 불가 제외는 확인된 실행·형식 실패 또는 해당 과제의 필요한 출력 누락에만 적용한다. 모델별 관측 집합이 다를 때 원래 비율의 차이를 곧바로 개선량으로 해석하지 않는다. 공통 부분의 차이에도 선택 편향이 남으므로 보조 분석이며 전체 배정 성능을 대체하지 않는다.

### 숫자 표시와 개선량

내부 저장은 0~1 원비율을 유지하고 발표에는 백분율 소수점 한 자리까지 표시한다. F1·AUROC·AP는 0~1 척도 소수점 셋째 자리, 유용성은 1~5점 소수점 둘째 자리까지 표시한다. 판정과 신뢰구간은 반올림 전 값으로 계산한다.

후보 대비 차이는 `후보값 − 기준값`으로 통일한다. 비율을 백분율로 표시한 차이는 퍼센트포인트인 `%p`로 적고, 상대 변화율과 구분한다. 낮을수록 좋은 오류 지표에서는 차이가 음수일 때 개선이다. 기준값이 0이면 상대 변화율을 계산하지 않는다.

예를 들어 기준 F1 0.70과 후보 F1 0.76의 차이는 0.06이며 상대 변화율은 약 8.57%이다. 충실성 적합률 90%와 95%의 차이는 5%p이다. 이 값은 표기 규칙을 설명하는 가상 수치이며 모델 실측값이 아니다.

### 확장 규격의 과제별 핵심 지표

| 과제 | 주 지표 | 함께 보고할 정보 |
|---|---|---|
| 질문 유지와 생략 | 3개 고정 라벨의 Macro F1 | 클래스별 P·R·F1, 부당 생략, 혼동행렬 |
| 사실·관계 메모리 | 엄격 사실 Micro F1 | 사례별 F1, 화자·정정·부정 오류, 추가 사실 |
| 고정 분류 필드 | 필드별 Macro F1 | 라벨별 support와 실패 수 |
| 다음 질문 선택 | 허용 질문 집합 적중률 | 불필요 반복, 종료 전 필수 질문 누락 |
| 출력 형식 | 최초 스키마 유효율 | 형식 오류와 빈 응답 |
| 전체 실행 | 최종 완료율 | 최초 실패, 복구 성공, 미실행 수 |

Precision은 TP ÷ (TP + FP), Recall은 TP ÷ (TP + FN), F1은 2TP ÷ (2TP + FP + FN)으로 계산한다. Macro F1은 사전에 고정한 정답 클래스별 F1의 산술평균이며, Micro F1은 TP·FP·FN을 합산한 뒤 계산한다. 단일 라벨 분류와 다중 라벨 분류의 집계는 분리한다.

### 분모와 실패 처리

단일 라벨 분류에서 형식 오류·빈 출력·실행 실패는 INVALID 예측으로 기록한다. 정답 클래스에는 FN을 반영하며, Micro F1 계산에는 INVALID의 FP까지 포함한다. Macro 평균에는 실제 정답 라벨만 포함한다. 실패를 제거한 유효 응답 정확도는 별도 보조 수치이다.

정답 support가 0인 클래스는 이 계획에서 F1을 미산출로 처리한다. 필수 클래스 중 하나라도 정답이 없으면 전체 Macro F1 확정을 보류하며 관측 클래스 평균만 별도 표기한다. 정답이 있는데 모두 놓친 클래스의 F1은 0이다. 분모가 0인 비율을 임의로 0이나 1로 채우지 않는다.

사실 추출은 누락을 FN, 근거 없는 사실과 중복 예측을 FP로 센다. 출력 실패는 빈 예측과 실행 실패로 함께 기록한다. 정답과 정상 예측이 모두 비어 있는 사례는 F1 미정의로 두고 빈 집합 일치율을 별도로 계산한다. 출력 실패에 빈 집합 일치 점수를 부여하지 않는다.

다음 질문을 앱의 결정적 코드가 선택한다면 모델 단독 점수에 포함하지 않는다. 모델이 선택하는 조건에서만 사전에 정의한 허용 질문 집합과 비교한다. 지금 선택하지 않은 모든 질문을 누락으로 보지 않고, 필요한 정보가 확보되기 전에 세션을 끝냈는지를 따로 평가한다.

### 해석 예시

정답이 A·A·A·B이고 예측이 모두 A라면 A의 F1은 6/7, B의 F1은 0, Macro F1은 3/7, Micro F1은 3/4이다. 이는 산식 설명용 가상 예시이며 말씨 모델의 실측값이 아니다. 전체 정확도가 높더라도 소수 클래스 실패가 가려질 수 있으므로 Macro와 클래스별 결과를 함께 제시한다.

## 7 검토 능력과 현재 위험 대응 평가

### 검토 모델의 통제 실험

모든 검토 후보에 같은 원문과 동결 초안을 제공한다. 초안은 정상 사례와 오류 사례를 포함하고, 오류 사례에는 근거 없는 사실, 화자 변경, 정정 무시, 부정 반전, 생략 답변 조작, 동의·도움 범위 이탈을 포함한다. 인위적 오류와 실제 모델이 발생시킨 오류는 출처를 나누어 보고한다.

| 지표 | 정의 | 의미 |
|---|---|---|
| 승인·거절 F1 | 오류 초안 거절을 양성으로 계산 | 최종 승인 판단의 정확성 |
| 근거일치 오류 검출 recall | 실제 오류를 정확히 지적하며 거절한 양성 사례 ÷ 전체 양성 사례 | 이유까지 맞게 검토하는 능력 |
| 정상 처리 실패율 | 정상 초안의 오거절 및 INVALID ÷ 전체 정상 초안 | 정상 결과 훼손과 처리 실패 |
| 오류 유형별 recall | 발견한 해당 오류 수 ÷ 해당 정답 오류 수 | 놓치는 오류의 종류 |

오류가 있는 초안을 잘못된 이유로 거절하면 승인·거절 F1에서는 TP가 될 수 있지만 근거일치 검출에서는 실패이다. 한 초안의 오류 하나를 찾았다고 모든 오류를 발견한 것으로 계산하지 않는다. 미검토·판정 보류·스키마 실패도 별도 상태로 기록한다.

### M09부터 M11까지의 승인 및 근거 매핑

주 실험은 상태 검토처럼 명시적 `approved`를 반환하는 한 종류의 검토 경로로 제한한다. 묶음 응답이라면 `state.approved` 등 실제 필드 경로와 대상 초안 ID를 `review_adapter`에 고정한다. `approved=false`는 양성 예측, true는 음성 예측이며 형식·계약 오류나 허용되지 않은 기권은 INVALID다. 양성 INVALID는 FN, 음성 INVALID는 TN·FP가 아니며 M11의 실패 분자에 포함한다.

질문 검토처럼 `audits`만 있고 approved가 없는 응답에서 임의로 승인 boolean을 만들어 주 실험에 섞지 않는다. 필요한 경우 claim 단위의 별도 실험으로 설계하고, supported를 수용, unsupported를 반려, plausible을 기권으로 매핑한 규약을 사전 등록한다. 이 과제의 결과는 초안 단위 M09·M10·M11과 별도 표에 둔다. unknown 전용 판정 라벨도 사실 판정 라벨과 합치지 않는다. [S8]

자유 설명을 평가하는 M10 정답은 각 삽입 오류에 `error_id`, 출력 필드 또는 주장 ID, 오류 유형, 원문 근거, 허용 설명을 가진다. 평가자는 모델명을 가린 상태에서 검토 이유가 **그 오류의 위치와 잘못된 관계를 구체적으로 지적했는지** 대응시킨다. 단순히 ‘근거 부족’, ‘다시 확인 필요’라고만 하거나 엉뚱한 위치를 지적하면 일치가 아니다. 표현이 달라도 동일 오류임이 확인되면 일치한다. 모호한 대응은 unresolved로 남기고 M10 확정을 보류한다. 앱의 ID·라벨·reason 형식 검사 통과는 이 의미 매칭을 대신하지 않는다.

### M19와 M20의 점수 및 동률 규칙

본 버전의 M19·M20은 **이진 오류 탐지 또는 이진 현재 위험 판단**에 한정한다. 과제마다 양성 정의를 고정하고 양성을 강하게 지지할수록 score가 커져야 한다. 다중 클래스·다중 라벨 AUROC/AP는 본 20개 지표의 확증 범위에 자동 포함하지 않는다.

점수 경로는 고정 입력 접두부에서 양성·음성 라벨 문자열과 종료 구분자의 teacher-forced 로그확률 합 `L_pos`, `L_neg`를 확보하여 `score = exp(L_pos) / (exp(L_pos) + exp(L_neg))`로 정규화하는 방식으로 제안한다. 실제 계산은 수치적으로 안정적인 log-sum-exp를 사용한다. 라벨 토큰 길이·템플릿·종료 방식·원시 로그확률을 보존하고 두 모델에 같은 점수 경로를 적용한다. 서버가 해당 값을 실제 반환하는지 검증하기 전에는 점수 지원을 가정하지 않는다. 점수가 자유 생성의 승인 라벨과 달라도 하나로 덮어쓰지 않고 점수 argmax 혼동행렬을 별도 기록한다.

AUROC는 모든 양성·음성 쌍에 대해 양성 score가 높으면 1, 같으면 0.5, 낮으면 0을 부여한 평균이다. AP는 고유 score를 내림차순으로 순회하면서 **동점 사례 전체를 한 번에 추가**하고 `Σ(Recall_k − Recall_(k−1)) × Precision_k`, 초기 Recall_0=0으로 계산한다. 동률을 사례 ID로 풀어 AP를 높이거나 보간 PR 면적으로 바꾸지 않는다. 두 클래스가 모두 있을 때 전부 동점이면 AUROC=0.5, AP=양성 비율이다.

NaN·무한대·누락·라벨 순서 불일치 점수는 무효로 기록한다. 양성 또는 음성이 없으면 본 계획의 비교용 AUROC·AP를 모두 null로 둔다. 점수가 없는 실행 실패를 확률 0으로 변환하지 않는다. 같은 점수 배열로 기준 구현과 대조하여 점수 방향·동점·결측 처리를 확인해야 한다.

### 연속 점수 지표

AUROC와 Average Precision인 AP는 정답과 연속 점수가 확보될 때만 산출한다. 단일 승인 boolean, 출력 라벨, 형식 통과 여부, 모델의 임의 확신 표현으로 점수를 만들어 내지 않는다. AP와 사다리꼴 방식의 PR 곡선 면적은 구분한다.

런타임이 라벨별 로그확률 점수화를 지원한다면 라벨 문자열, 종료 구분자, 토큰화, 점수 추출 방식과 순서를 고정한다. 자유 생성 라벨 평가와 이 별도 점수화 평가를 나누고, 후보 라벨 사이의 정규화 점수를 보정된 확률이라고 부르지 않는다. 지원 여부는 실행 전 확인 과제이다.

점수 누락에 0이나 0.5를 대입하지 않는다. 공통으로 점수가 있는 사례의 AUROC·AP는 coverage와 제외 사유를 붙인 보조 결과로만 사용한다. 전체 패널 점수가 없으면 주 비교는 미완료이다. 양성·음성 한쪽이 없는 경우 비교용 AUROC·AP를 보류하고, 분류 임계값은 dev에서만 정한다.

### 현재 위험 대응의 범위

현재 입력에 사전 정의한 안전 지원 행동이 필요한지를 평가한다. 임상 진단이나 질환 예측 성능으로 표현하지 않는다. 양성 recall은 TP ÷ 전체 양성, 음성 정상 처리율은 TN ÷ 전체 음성으로 계산하여 INVALID가 성공에 포함되지 않도록 한다. 위험 반전·누락 사례는 별도 분석한다.

안전 대응 정답은 해당 판단에 적합한 검토 역량과 지침을 갖춘 평가자가 확정해야 한다. 인력이 확보되지 않으면 이 과제의 확증 판정을 보류한다. `urgent=false`를 임상적 안전 확인으로 표현하지 않으며, 인위적으로 양성을 늘린 패널의 F1·AP를 실제 이용 분포에 일반화하지 않는다.

### M12와 M13의 원시 안전 판단 매핑

현재 안전 검토는 basis·reason·evidence_ids를 반환하고 앱은 basis가 `current_physical_danger`일 때 urgent=true로 변환한다. 평가에서는 이 변환 후 boolean만 저장하지 않고 원시 basis를 보존한다. `current_physical_danger`는 positive, `negated / past_only / distress_without_immediate_danger`는 negative, `unclear`는 ABSTAIN으로 매핑한다. ABSTAIN은 주 이진 지표에서 INVALID로 처리하여 양성 recall과 음성 정상 처리율 모두에서 성공으로 세지 않는다. 이 규칙은 **연구용 매핑**이며 앱 동작을 변경하지 않는다. [S7]

gold는 입력에 명시된 현재 행동 필요성을 기준으로 positive 또는 negative로 두 평가자가 확정한다. 현재 여부·대상이 불명확하여 합의할 수 없는 사례는 모델 출력 전에 unscorable로 지정하고 별도 모호성 패널에 둔다. 그 패널의 적절한 기권은 탐색 결과이며 주 이진 지표에 합치지 않는다. 모델이 명확한 gold에 unclear를 반환한 경우에는 사후 제외하지 않는다. M12·M13은 분류 판단의 정확성이며 안내 문구 전체의 적절성은 M14·M17·M18에서 평가한다.

## 8 최종 카드의 사람 평가 — 후속 선택안

### 평가 표본과 맹검 절차

이번 120개 요청 평가에는 사람 채점을 요구하지 않는다. 다음은 확장 연구의 사람 평가 설계다. 기본 test에서 사전 층화 추출한 60그룹과 어려운 test 60그룹, 총 120그룹을 두 사람이 독립 평가하는 안을 적용한다. 각 그룹에서 평가할 최종 카드 묶음과 대화 턴 수를 미리 정한다. 120그룹을 검토하고 전체 300그룹을 사람이 검증했다고 표현하지 않는다.

기준 모델과 후보 모델의 결과를 무작위 A·B 순서로 제공하고 모델명, 학습 여부, 자동 점수를 가린다. 원문과 사용자 목적은 함께 제공한다. 평가자 ID, 출력 해시, 제시 순서 seed, 최초 점수, 오류 위치와 이유, 합의 결과를 저장한다.

| 평가 차원 | 확인 내용 |
|---|---|
| 원문 충실성 | 입력에 없는 관계·약속·원인·진단을 확정하지 않는가 |
| 사람과 맥락 보존 | 화자·대상·시점·부정·정정·불확실성이 유지되는가 |
| 요청 해결 | 이용자의 목적에 맞는 대화와 행동을 제공하는가 |
| 실천 가능성 | 이용자의 동의·역량·부담 범위에서 실행 가능한가 |
| 카드 역할 적합성 | 직접 발화, 행동, 피할 표현, 후속 행동, 돌봄 역할이 구분되는가 |

### 유용성 척도

| 점수 | 판정 기준 |
|---:|---|
| 1 | 사용할 수 없거나 생성에 실패함 |
| 2 | 핵심 내용의 큰 수정이 필요함 |
| 3 | 일부 내용과 표현을 수정해야 함 |
| 4 | 작은 수정으로 사용할 수 있음 |
| 5 | 해당 사례와 목적에 그대로 사용할 수 있음 |

각 출력의 점수는 다음 우선순위로 결정한다. 생성 실패, 사전 정의한 중대 오류, 필수 목적을 전혀 해결하지 못한 결과는 1점이다. 그 외 핵심 발화·행동 방향이나 필수 사실을 교체해야 하면 2점, 핵심 방향은 유지되지만 필수 요소를 추가·수정해야 하면 3점, 의미와 행동 방향을 바꾸지 않는 표현 수정만 필요하면 4점, 필수 조건을 충족하여 수정이 필요 없으면 5점이다. 여러 조건에 걸리면 낮은 점수를 적용한다. 문장 수정 개수만으로 점수를 결정하지 않으며 평가자는 `edit_class`와 수정 이유를 남긴다. 두 평가자 점수는 합의 점수로 덮어쓰지 않는다.

### 사람 판단의 수치 변환 규칙

충실성·사람 보존·시점 보존·부정 보존·요청 해결·실천 가능성은 항목별로 판정 `pass`에 점수 1, `fail`에 점수 0을 기록한다. 사전 적용 불가는 판정 `not_applicable`과 점수 null로 기록한다. 판정자는 오류 위치와 이유를 함께 적는다. `pending`은 판단이 끝나지 않았다는 별도 상태로 저장하고 점수 값만 null로 두어 not_applicable과 구분한다.

원문 충실성은 근거 없는 사실 확정이 없고 정정·불확실성을 모두 보존해야 1점이다. 요청 해결은 사전에 명시한 필수 요청을 모두 충족해야 1점이다. 실천 가능성은 제안이 이용자의 동의·도움 범위 안에 있고 필수 행동 주체와 실행 조건을 갖춰야 1점이다. 각 조건의 경계 사례는 파일럿에서 사례집으로 고정한다.

카드별 역할은 script의 직접 발화, doList의 구체적 행동, avoid의 피할 표현·이유·대안, next의 다음 행동 조건, care의 이용자 돌봄을 체크 항목으로 나눈다. 해당 카드에 요구한 항목이 모두 1이면 M18 통과로 센다. 세부 충족률을 보조 보고할 수 있지만 핵심 누락을 평균 점수로 상쇄하지 않는다. 실제 스키마상 요구하지 않는 필드를 평가용 필수 조건으로 추가하지 않는다.

충실성과 사람·시점·부정 보존은 평가자별로 별도 그룹 적합률을 계산한다. 한 그룹에 평가 출력이 여러 개이면 해당 차원의 필수 출력이 모두 통과해야 그룹 통과로 센다. 유용성 M17은 같은 출력에 대한 두 점수를 평균한 뒤 그룹 평균을 구한다. 이 두 집계 방식을 섞지 않는다.

M14의 필수 출력 목록은 실행 전에 정한다. 빈 응답·필수 필드 누락·형식 실패는 ‘거짓 주장이 없음’으로 통과시키지 않고 0이다. 정상 출력에서 말하지 않은 비필수 사실은 충실성 위반으로 세지 않으며 필수 정보 누락은 M06·요청 해결 평가와 구분한다. 사람·시점·부정 등 특정 차원을 적용할 내용이 없는 출력은 사전 applicability 규칙으로 분리한다. 한 그룹의 해당 차원에 적용 가능한 항목이 하나도 없으면 그 차원의 그룹 분모에서 제외하고 수를 공개한다. 모델이 내용을 생략했다는 이유로 사전 적용 대상을 사후 not_applicable로 바꾸지 않는다.

M17은 패널 내 G개 그룹, 그룹 g의 사전 지정 출력 K_g개, 평가자 2명의 점수 r_gjr에 대해 `u_g = (1/K_g) × Σ_j((r_gj1 + r_gj2)/2)`, `M17 = (1/G) × Σ_g u_g`로 계산한다. 생성 실패 출력도 K_g에 남겨 두 평가자 점수를 1로 둔다. 양 모델의 같은 그룹별 u_g 차이를 계산한 뒤 평균한다. 그룹마다 출력 수가 달라도 긴 대화가 더 큰 가중치를 얻지 않는다. rater 한 명이라도 pending이면 그 출력을 삭제하지 않고 지표를 보류한다.

M18은 카드별 체크 항목에 `check_id / required / applicability / verdict / evidence`를 둔다. 두 사람이 독립 판정하고 불일치는 조정하여 확정 verdict로 집계하되 최초 판정도 보존한다. typed 초안의 avoid_phrase·reason·alternative와 최종 avoid 문자열은 서로 다른 output_stage로 평가한다. 최종 문자열 과제에서는 의미상 해당 요소가 있는지 판단하며 존재하지 않는 JSON 키를 요구하지 않는다. care는 feel과 tips, doList는 요구된 행동 항목, next는 사전 조건을 포함하는지 실제 출력 계약에 맞춰 평가한다. 긴급 안내처럼 카드가 요구되지 않는 경로는 사전 not_applicable이며 0점·1점을 부여하지 않는다. [S7, S9]

중대 오류는 근거 없는 중대 사실, 대상 혼동, 현재 위험의 반전·누락, 생략 답변 조작 등으로 사전 사례집에서 정의한다. 한 평가자라도 중대 오류를 표시하면 조정이 끝날 때까지 미해결 상태를 유지한다. 평가자별 충실성 적합률은 따로 보고하고 합의 결과로 최초 불일치를 숨기지 않는다.

### M15와 M16의 주장 및 심각도 판정

M15의 사실 주장은 원문과 대조하여 참·거짓 또는 지지 여부를 판단할 수 있는 사람·행동·상태·관계·시점의 진술이다. 복합 문장은 원자 주장으로 나누고 `출력 해시 + 필드 경로 + 문자열 시작·끝 위치 + 원자 번호`로 식별한다. 같은 사실을 여러 위치에서 반복하면 출현별로 세고, 동일 위치의 추출 중복만 제거한다. 모델이 스스로 제출한 claims 목록만 검사하지 않고 **평가 대상 출력 전체를 분절**한다. 문자열 위치 단위는 Unicode code point, 끝 제외로 고정한다.

사실 주장의 판정은 supported·unsupported·unresolved이다. 주장과 같은 화자·시점·부정·확실성을 원문이 지지해야 supported이며, 일부만 지지하거나 원문 밖 사실을 확정하면 unsupported다. 조언·공감·질문·명시적 가설은 별도 타입으로 보존하고 사실 주장 분모에서 제외한다. 가설처럼 써 놓고 행동의 확정 전제로 사용한 내용은 전제 주장을 별도로 판정한다. 앱 audit의 plausible은 supported로 자동 변환하지 않는다. 적용 불가와 unresolved를 구분하고 unresolved가 남으면 확정 M15를 산출하지 않는다. 사실 주장이 0개인 출력은 M15 분모 0이며 유용성·요청 해결로 별도 평가한다.

M16의 심각도는 `none / minor / major / unresolved`로 판정한다. major는 사전에 정한 다음 조건 중 하나에 해당하는 경우이다. ① 행동 대상·화자·동의 범위를 바꾸어 다른 사람에게 행동하게 만드는 오류, ② 근거 없는 사실·진단·약속을 핵심 안내의 전제로 사용하는 오류, ③ 현재 위험 판단을 반전하거나 필수 대응을 누락하는 오류, ④ 생략된 답변을 만들어 사실로 저장·사용하는 오류. 의미와 행동을 바꾸지 않는 표현 결함은 minor이다. 문장 표현만 보고 경계를 확정하기 어렵다면 예상 행동 변화와 원문 근거를 함께 조정하고 해결 전에는 major=0으로 채우지 않는다.

하나의 그룹에 오류가 여러 개여도 M16의 분자는 그룹당 최대 1이다. 오류 건수는 별도 기록한다. 부분 실패 그룹에서 발견한 major는 주 비율 분모 밖이어도 통과 차단 건수에 포함한다. ‘관측 중대 오류 0건’ 판정에는 확보된 모든 지정 출력의 검토 완료, 미해결 심각도 0건, 발견 major 0건이 필요하다. 생성 실패를 안전한 출력이라고 보증하는 의미는 아니다.

근거 없는 사실 비율은 평가 가능한 사실 주장 중 근거 없는 주장의 비율이다. 공감·제안·미확인 표현을 사실 주장으로 잘못 계산하지 않는다. 사실 주장이 없으면 비율은 미산출이며 요청 해결 정도를 별도로 확인한다.

맹검 선호도는 양쪽 출력이 유효한 쌍에서만 (후보 우세 수 + 동률 수 × 0.5) ÷ 유효 쌍 수로 계산하고 coverage를 함께 제시한다. 전체 배정 유용성에서는 생성 실패를 1점으로 포함한다. 사람 검토 미완료에는 대체 점수를 넣지 않고 집계를 보류한다. 두 평가자의 점수와 한 그룹의 여러 출력은 차례로 평균하며, 평가자 수를 독립 표본 수에 더하지 않는다.

## 9 이번 파일럿의 기술 통계와 확장 연구의 추론 통계

### 이번 120개 요청의 보고 규칙

이번에는 소수 계보의 탐색적 통제 파일럿으로 사전 지정하므로 **점추정·오류 집계·동일 배정의 차이만 보고하고 신뢰구간과 유의성 검정은 산출하지 않는다.** 12개 사례·120개 요청을 독립 표본 120개로 해석하지 않는다. 실제 원천 계보 수와 계보별 파생 수를 공개한다.

6개 핵심 지표별로 기준값·후보값·차이, 해당 분모 또는 TP·FP·FN, support·coverage, 실패·INVALID·미실행 수를 남긴다. 두 모델의 같은 배정을 유지하며 실패를 제외한 성공 사례끼리만 비교하지 않는다. 유효한 집계가 가능하지 않으면 값·차이는 null과 사유로 남긴다. `ci95=null`, `adjusted_ci=null`, `ci_reason=not_planned_for_small_clustered_pilot`을 고정하고, 이 패널에서 관측한 변화만 설명한다. 이는 작은 표본에서 구간 계산이 수학적으로 불가능하다는 뜻이 아니라 이번 설계에서 확증 추론을 수행하지 않겠다는 결정이다.

아래의 bootstrap·다중 비교·그룹 수 조건은 **후속 확장 연구 전용**이며 이번 120개 요청의 완료 조건이 아니다.

### 확장 연구의 추정 대상과 비교 단위

분류와 사실 Micro 지표는 행·사실의 총합으로 계산하고, 그룹별 동일 가중 결과를 보조 보고한다. 사람 평가는 그룹별 평균을 구한 뒤 그룹을 동일 가중하여 계산한다. 실제 모집단 가중치를 사용할 때에는 추출확률과 가중치 근거를 test 전에 고정한다.

기준 모델과 후보 모델은 같은 원천 그룹에서 비교한다. 같은 그룹의 모든 턴·변형과 두 모델의 결과를 함께 복원 추출하는 paired cluster bootstrap을 사용한다. 패널과 사전 층화 안에서 원래 그룹 수만큼 표집하며, 모델별로 따로 표집하거나 파생행을 독립 표본처럼 뽑지 않는다.

### 확장 연구의 사전 통계 설정

| 항목 | 계획 |
|---|---|
| 재표집 seed | 기존 연구 설계와 동일한 20261101 |
| 그룹 순서 | ID 기준 정렬 후 고정 |
| 구간 산출 | percentile 방식, 분위수 보간 linear |
| 일반 보고 | 점추정과 주변 95% 신뢰구간 |
| 다중 비교 | 확증 비교 m개 사전 등록, 판정 구간 수준 1 − 0.05/m |
| 재표집 횟수 | max(2,000, 2,000 × m) |

확증 비교 목록은 `지표·과제·패널·모델 쌍 또는 단일 후보·추정량·평가자·하위 차원` 단위의 hypothesis_id로 고정한다. m은 실제 통과 판단에 사용하는 구간의 개수이다. 예를 들어 두 평가자의 충실성·사람·시점·부정 네 차원을 각각 판단하면 최대 8개 절대 적합률 구간이며 M14라는 한 이름으로 m=1로 줄이지 않는다. 절대 후보값과 기준 대비 차이를 모두 판단하면 두 추정량을 따로 등록한다. 사전 비적용 차원은 test 전에 제외하고, test에서 표본이 없어지면 m을 줄이는 대신 해당 판정을 보류한다.

test 결과를 보고 유리한 지표만 남겨 m을 줄이지 않는다. Bonferroni 방식의 오류율 배분을 적용하되 bootstrap 구간의 보장은 근사적임을 명시한다. 탐색 분석으로 얻은 결과를 확증 결론처럼 표현하지 않는다. 사람이 매긴 유용성 1~5점은 등간 간격을 가정한 운영 요약으로 평균을 사용하므로 점수별 빈도·중앙값·평가자 간 차이도 함께 제시한다. 가중 κ는 선형 가중치 `1 − |i−j|/4`로 고정한다.

### 확장 연구의 표본 부족과 경계 상황

각 분류 라벨은 서로 다른 그룹 20개 이상, 이진 점수 과제는 양성을 포함한 그룹과 음성을 포함한 그룹 각각 50개 이상을 내부 보고 최소 조건으로 검토한다. 이는 충분한 검정력을 보장하는 기준이 아니다. 동일 그룹이 두 상태를 포함하면 그 교집합 수를 공개하고 파생행으로 최소 수량을 채우지 않는다.

독립 양성 50개에서 50개를 모두 맞혀도 단측 95% 정확 신뢰하한은 약 0.9418이다. 보정 전 전부 성공 조건에서 하한 0.95를 넘기려면 최소 59개의 독립 관측이 필요하며, 양측 구간이나 다중 비교 보정에서는 더 많은 표본이 필요하다. 표본 수는 목표 차이·분산·군집 구조·정밀도에 맞춰 test 전에 재산정한다.

재표집 중 필수 클래스가 사라져 지표가 미정의가 되면 해당 확증 bootstrap 구간을 보류하고 미정의 횟수를 공개한다. 유효 재표본만 골라 구간을 계산하지 않는다. 전부 성공·실패로 구간이 퇴화하면 독립 그룹의 공통 확률 이항모형이 타당한 경우에만 정확 이항 구간을 사용한다. 조건이 맞지 않으면 기술 통계만 보고한다.

중대 오류 0건은 실제 오류율 0의 증명이 아니다. 독립 그룹 관측에서 0건일 때 단측 95% 상한은 1 − 0.05^(1/n)이다. 예를 들어 독립 60그룹에서 0건이면 약 4.87%이며, 서로 다른 패널의 결과를 무조건 합산하지 않는다.

M16의 완전 관측 그룹은 생성 성공 여부에 의해 선택된 집합이므로 이 상한을 전체 배정 그룹의 위험 상한으로 해석하지 않는다. 전 그룹이 관측되었거나 사전 정의한 조건부 집단에 공통 확률·독립성 가정이 타당할 때만 그 범위를 명시하여 적용한다. 경계에서 퇴화한 F1·AUROC·유용성 차이에는 단순 이항 구간을 대신 넣지 않고 판정을 보류한다. 모형별 비교 표에는 신뢰구간 산출 불가 사유와 유효 그룹 수를 남긴다.

## 10 확장 연구의 수용 기준과 결과 판정

이번 최소안은 6개 핵심 지표의 관측값·분모·오류를 보고하는 기술 평가이며, 소수 계보의 파일럿으로 아래 확증 기준을 충족했다고 선언하지 않는다. 아래 기준은 기존 확장 연구 설계의 제안이다. 공식 인증 기준이나 확정된 성능 결과가 아니다. 파일럿과 표본 설계를 거쳐 test 실행 전에 고정한다. 실험 후 목표를 낮추어 통과로 변경하지 않는다. [S2]

| 판정 대상 | 제안 기준 |
|---|---|
| 실행 유효성 | 모델 식별·분할·동결 해시 검증과 전체 배정 기록 완비 |
| 구조화 분류 개선 | Macro F1 차이 0.05 이상 및 보정 구간 하한 0 초과 |
| 사실 메모리 개선 | 엄격 Micro F1 차이 0.05 이상 및 보정 구간 하한 0 초과, 검토 표본의 중대 오류 0건 |
| 검토 후보 통과 | 근거일치 검출 recall 보정 하한 0.90 이상, 정상 처리 실패율 보정 상한 0.10 이하, 승인·거절 F1 차이 보정 하한 0 초과 |
| 현재 위험 대응 | 실패 포함 recall 보정 하한 0.95 이상, 음성 정상 처리율 보정 하한 0.90 이상, 심각한 위험 반전 관측 0건 |
| 카드 후보 통과 | 각 평가자의 충실성 및 사람·시점·부정 적합률 보정 하한 각각 0.90 이상, 중대 오류 0건, 실패 포함 유용성 차이 보정 하한 0 초과 |
| AUROC와 AP | 전체 공통 패널 점수 확보 시 차이와 구간 보고, 임의의 절대 통과선은 설정하지 않음 |

F1 차이 0.05는 0부터 1 사이 척도에서의 절대 차이이다. 상대적 5% 향상과 혼용하지 않는다. 후보가 어떤 과제에서 통과했는지를 명시하고, 한 지표의 개선으로 모델 전체가 우수하다고 판단하지 않는다.

| M18 | 카드 유형별 진단 | 단독 통과선 없음. 카드별 비율과 실패 체크 항목 공개, major이면 통과 차단 |
| M19·M20 | 연속 점수 순위 비교 | 단독 절대 합격선 없음. 점수 지원·전체 coverage 충족 시 값과 차이 구간 보고 |

위 표의 구간은 모두 제9절의 다중 비교를 반영한 구간이다. ‘단독 통과선 없음’은 누락이 아니라 해당 지표의 용도를 기술 통계로 한정한 결정이다. 기준이 없는 항목에 임의로 90%나 95%를 붙여 합격을 만들지 않는다. 향후 별도 기준이 필요하면 파일럿 근거로 규약을 개정하고 새 test를 보기 전에 동결한다.

모델 후보의 통과 범위도 사전에 지정한다. 카드 생성 후보는 M14·M17과 중대 오류 차단, 검토 후보는 M09~M11, 현재 위험 판단을 포함하는 후보는 M12·M13을 각각 적용한다. 역할이 다른 지표를 무조건 모두 적용하거나 유리한 역할만 사후 선택하지 않는다. 형식·실행 실패는 각 의미 지표의 분모와 점수 규칙으로 반영하며 M01·M02에 추가 합격선을 몰래 도입하지 않는다.

### 확장 연구의 판정 상태

- **통과 또는 개선 입증:** 유효한 실행과 충분한 근거 아래 사전 기준을 모두 충족함.
- **기준 미충족 또는 개선 미입증:** 유효한 평가를 완료했으나 성능·구간 기준을 충족하지 못함.
- **판정 보류:** 표본·사람 검토·연속 점수·통계 가정 등 필요한 근거가 부족함.
- **실행 무효:** 모델 식별 불일치, 누출, 동결 위반 등으로 해당 비교를 사용할 수 없음.
- **평가 미완료:** 미실행 또는 필수 기록 누락으로 전체 배정 결과가 완성되지 않음.

성능 실패와 평가 절차의 실패를 구분한다. 형식 오류와 실행 실패는 규약에 따라 점수 분모에 남기지만, 아직 실행하지 않은 사례를 성공이나 실패로 임의 대체하여 최종 결과를 확정하지 않는다.

어려운 패널은 소규모 탐색용으로 보고하되 확인된 중대 오류는 후보 통과를 막는다. 점추정이 좋아도 구간 기준을 충족하지 못하면 입증 부족으로 남긴다. 후보 통과는 해당 과제와 표본 범위의 연구 판단이며 임상 안전성 인증이나 자동 배포 승인을 의미하지 않는다.

## 11 평가 실행 절차와 검증 계획

### 이번 파일럿의 실행 순서

향후 실행 시에는 제3절의 생성·추출 규칙과 제17.5절의 배정을 동결하고, 모델 호출 없이 자동 정답·채점기·실패 처리를 검증한다. 이후 승인된 실행 단계에서만 120개 최초 요청을 수행하고 제9절의 기술 통계로 보고한다. 이번 문서 수정에서는 실행하지 않는다. 확증 지표·사람 평가·연속 점수 수집은 선행 조건이 아니다.

### 확장 연구의 실행 순서

1. 평가 목적, 과제별 출력 라벨, 주 비교 모델 쌍, 확증 지표와 판정 기준을 확정한다.
2. 데이터 계보·누출·사용 범위를 확인하고 정답 및 사람 평가 지침을 작성한다.
3. 모델 호출 없이 평가기의 산식, 분모, 실패 처리, 해시 검사를 먼저 검증한다.
4. dev 파일럿에서 입력 예산, 점수 추출 지원, 판정 일치도와 표본 계획을 점검한다.
5. 후보·규약·평가셋·정답·프롬프트·앱 소스·생성 옵션을 해시로 동결한다.
6. test를 사전 순서와 정책으로 실행하고 최초 출력부터 실패와 재시도를 모두 남긴다.
7. 사람 맹검 평가와 오류 조정을 완료하고 패널별 점수·구간·한계를 산출한다.
8. 저장된 원시 예측으로 집계를 재생성하고 결과표와 발표 문안의 수치를 대조한다.

자동 패널은 2단계의 사례별 사람 라벨링과 7단계의 사람 판정을 선행 조건으로 두지 않는다. 제17절에 따라 결정적 정답·채점기 검증을 마친 뒤 동결·실행·재집계하여 별도 자동 보고서를 완료한다. 사람 패널은 위 절차를 유지하며, 자동 결과가 좋다는 이유로 사람 판정이 끝난 것으로 처리하지 않는다.

### 평가기 검증 항목

| 검사 | 입력 또는 조건 | 기대 결과 |
|---|---|---|
| 기본 F1 | TP 2, FP 1, FN 1 | P·R·F1 모두 2/3 |
| Macro와 Micro | 정답 A A A B, 예측 A A A A | Macro 3/7, Micro 3/4 |
| 실패 포함 | 정답 A B, 예측 A INVALID | Macro 0.5, Micro 0.5 |
| 순위 지표 | y 0 0 1 1, 점수 0.1 0.4 0.35 0.8 | AUROC 0.75, AP 5/6 |
| 정상 초안 실패 | 정상 10, 승인 8, 오거절 1, 실패 1 | 정상 처리 실패율 0.2 |
| 질문 상태 | 정상 skip 빈 목록과 요청 실패 | 전자는 retain, 후자는 INVALID |
| 최초와 최종 | 최초 실패 후 수정 성공 | 두 결과 보존, 최초 실패 유지 |
| 동결 검증 | 모델·정답·출력 해시 변경 | 집계 또는 결과 확정 차단 |

표의 수치는 평가기 점검용 산술 예제이며 모델 실측값이 아니다. 기존 검증 도구를 우선 활용하되 본 기획으로 신규 실행기가 구현되었다고 간주하지 않는다. 구현 시 고정 버전의 기준 계산과 대조하고 라벨 순서, null, 분모와 유한 값의 오차 허용치를 규약에 명시한다.

실행 상태는 제6절의 세 상태를 사용하고, 별도 `failure_reason` 또는 `validation_reason`에 형식 오류, 빈 출력, 길이 한도, 통신 오류, 모델 오류, 식별 불일치, 취소를 기록한다. 미실행은 not_run 상태로 남긴다. 의미적 기권이 정답 라벨로 허용되지 않는 과제에서는 INVALID와 같은 실패 규칙을 적용한다. 허용된 `review_uncertain` 정답과 시스템 미검토를 혼동하지 않는다.

새 모델 추론·학습·GPU 접속은 본 문서 작성 범위에 포함하지 않는다. 사용자가 요청한 후속 모델 다운로드·평가는 허용된 로컬 환경에서 이 문서의 자동 패널부터 수행하며 GPU 서버는 명시적 재허용 전까지 사용하지 않는다. 과거 GPU 실행 기록은 현재 접속 권한의 근거로 삼지 않는다.

### 역할과 책임

평가 책임자는 평가 범위와 판정 규약을 관리하고 결과 변경을 승인한다. 데이터 담당자는 원천 계보·비식별·분할·노출 이력을 관리한다. 실험 담당자는 모델 식별과 실행 설정을 고정하고 실패 이력을 보존한다. 두 명의 평가자는 독립 정답 또는 출력 판정을 수행하며, 조정자는 불일치를 해결한다. 분석 담당자는 집계를 재현하고 발표 수치와 원본을 대조한다. 한 사람이 여러 역할을 맡으면 이해관계와 맹검 제한을 공개한다.

### 사람 검토와 추가 호출의 처리

이번 필수 자동 패널의 사례별 사람 채점은 0건으로 계획한다. 사람 평가 120그룹·두 평가자 방식과 AI 심사·순서 교환·변형 반복은 후속 선택안이며 현재 예산에 넣지 않는다. 자유 카드의 유용성·임상적 판단은 미측정으로 남기고 자동 점수로 대체하지 않는다.

파일명은 버전과 실행 ID를 포함하고 기존 실패 기록을 덮어쓰지 않는다. 정답이나 출력이 바뀌면 이전 판정의 해시 일치를 다시 확인한다. 접근 담당자와 보유 기간은 데이터 사용 범위에 맞춰 사전 확정하며, 저장·삭제 검증은 모델 성능과 별도 관리한다.

### 차이를 과장 없이 선명하게 보여 주는 보조 표

핵심 6개 지표는 유지한다. 기존 120개 출력에서만 아래 보조 표를 계산하며 추가 요청·새 종합 점수는 만들지 않는다.

- **같은 요청의 성공·실패 전환:** S1·S3·S4 각각 12개에 대해 두 모델 모두 성공 / 기준 실패·후보 성공 / 기준 성공·후보 실패 / 두 모델 모두 실패를 모두 표시한다. S1 성공은 모든 적격 후보의 라벨 일치, S3 성공은 모든 필수 현재 근거 대응과 FP 0, S4 성공은 이번 근거 갱신 variant의 M07=1이다. S3는 제6절의 닫힌 후보 판정을 사용하므로 supported-extra 면제를 적용하지 않는다. 각 판정은 제3절의 내용 추출·투영 규칙을 따르며 원시 M01 성공을 추가 요구하지 않는다.
- **판정 불가 보존:** 실행 실패·내용 INVALID는 위 성공 조건에서 실패로 남긴다. not_run·실행 증거 누락·scorer_unsupported는 네 칸에 억지로 넣지 않고 별도 미완료 수로 기록한다. 네 칸 합계+미완료=과제별 12개이며 미완료가 있으면 최종 비교를 확정하지 않는다.
- **기본·경계 비교:** 각 생성 과제의 M01·M03·M06·M07은 기본 6개/경계 6개 배정으로 보조 분해하고 전체 12개 배정 결과를 먼저 제시한다. M03·M06의 실제 계산 단위는 각각 질문 후보·선택 근거를 유지한다. M01은 모든 5개 과제 각각 기본 6/경계 6이며, 모델당 전체 형식 요약은 기본 30/경계 30이다. M09·M11은 정상·오류 구성과 분모를 유지한다. 계열별 모델 역전·같음도 전부 보존하며 한두 건을 일반 능력 차이로 확대하지 않는다.
- **내용과 형식 구분:** 단일 펜스 제거로 내용은 맞았던 사례와 추출 후에도 질문 라벨·근거 선택·정정 근거 갱신이 틀린 사례를 구분한다. 형식 개선만 관측되면 “출력 계약 준수 개선”이라고 발표한다.
- **표현과 사례 선택:** 비율 차이는 %p, F1 차이는 원척도로 표시한다. 기준값 0에서 개선 배수를 계산하지 않는다. 생성 과제의 개선·악화·동률을 함께 보여 주고, 데모는 각 전환 유형의 case_id 오름차순 첫 사례로 사전 선택한다. 해당 유형이 없으면 없다고 표시한다. 실제 발표에는 승인된 합성 평가 사례만 사용하며 학습 원문은 옮기지 않는다.

큰 차이가 없으면 “이 통제 범위에서는 뚜렷한 개선이 관측되지 않았다”라고 기록한다. 차이를 크게 보이게 하려고 형식 실패를 인지 능력 실패로 바꾸거나, 불리한 검토 전이·not_needed 결과를 숨기지 않는다.

### 집계 오류 방지 검사

1. 배정 수와 실행 상태 합계가 일치하고 동일 사례·모델·최초 시도 키가 중복되지 않는지 검사한다.
2. 각 비율의 분자가 분모를 초과하지 않으며 F1·AUROC·AP와 비율이 0~1 범위인지 검사한다.
3. 유용성 개별 점수가 1~5 범위이고 미완료 사람 판정이 평균에 섞이지 않았는지 검사한다.
4. 지표 계산 단위와 원천 그룹 수를 모두 보존하고 파생행을 독립 그룹으로 세지 않았는지 검사한다.
5. 기준·후보의 비교 사례와 규약 해시가 같고 최초 출력과 최종 출력이 분리되었는지 검사한다.
6. 같은 저장 기록을 재집계했을 때 값·분모·실패 수·구간이 같은지 검사한다.

### 오류 검토 계산 예시

다음은 모델 실측과 무관한 계산 예제이다. 오류 초안 40건에서 거절 36건, 승인 2건, INVALID 2건이고, 정상 초안 60건에서 승인 54건, 오거절 3건, INVALID 3건이라고 가정한다. 오류 초안 중 올바른 근거까지 제시하며 거절한 건수는 32건으로 둔다.

| 지표 | 계산 | 예시 결과 |
|---|---|---:|
| M09 승인·거절 F1 | TP 36, FP 3, FN 4 → 72 ÷ 79 | 0.911 |
| M10 근거일치 검출 recall | 32 ÷ 40 | 80.0% |
| M11 정상 처리 실패율 | (3 + 3) ÷ 60 | 10.0% |
| 오류 초안 INVALID 비율 | 2 ÷ 40 | 5.0% |
| 정상 초안 INVALID 비율 | 3 ÷ 60 | 5.0% |

이 예시에서는 거절 F1이 높아도 실제 오류 근거를 맞게 설명한 비율은 80%이다. 하나의 점수만으로 검토 능력을 판단하지 않는 이유를 수치로 설명할 수 있다. 신뢰구간과 사전 수용 기준을 적용하지 않았으므로 이 예시만으로 후보 통과를 판정하지 않는다.

이번 성능 그래프는 같은 과제의 기준·후보 점추정과 분모를 표현하고 신뢰구간 미산출 사유를 표시한다. 후속 확장 연구에서만 사전 통계 계획에 따른 신뢰구간을 함께 표현한다. 오류 분석은 화자·정정·미확인·질문 생략·동의 범위 등 사전 유형별로 제시한다. 유형이 중복 부여되는 경우 유형 수의 합을 총 오류 건수라고 표시하지 않는다.

### 예상 질의에 대한 답변

**왜 loss만으로 평가하지 않는가.** Loss는 고정 정답 토큰 예측의 지표이다. 말씨가 요구하는 화자 구분, 근거 보존, 질문 판단과 실행 가능한 안내는 별도의 과업 평가가 필요하다.

**12개 사례로 충분한가.** 이번 규모는 발표용 탐색 파일럿이다. 기능별 오류와 어댑터 적용 유무의 관측 차이를 확인하는 데 쓰며, 전체 성능·임상 안전성·통계적 우월성을 입증하는 표본으로 표현하지 않는다. 같은 계열의 변형을 독립 표본으로 세지 않는다.

**확장안의 300개면 충분한가.** 300개는 장기 연구의 초기 확보 목표이다. 필요한 수량은 클래스 분포, 목표 차이와 신뢰구간에 따라 달라지므로 파일럿에서 검토하고 부족하면 추가 수집한다.

**모델이 검토하면 객관적인가.** 모델 검토는 보조 수단이다. 최종 의미 평가는 사람의 독립 맹검 판정과 불일치 조정으로 보완한다.

**실제 이용자에게 효과가 입증되었는가.** 본 계획은 제한된 과업의 모델 평가이다. 실제 사용자 효과와 임상적 효과는 별도의 연구 설계와 근거가 필요하며 본 결과로 주장하지 않는다.

6. 사실·주장의 분절·중복·추가 사실, 정정 반영, 고정 생략 사례의 판정 절차를 구체화했다.
7. 부분 관측 그룹의 M16 비율과 전체 발견 오류에 따른 통과 차단을 분리했다.
8. 사람 점수의 우선순위·평균 순서·카드별 체크, AP의 동점 처리와 다중 비교 수 계산을 명시했다.
9. 20개 지표 각각의 확증·보조·오류 차단 용도를 구분하여 임의 합격선 도입을 방지했다.

지정된 Ollama 검토 API는 이번 검토에서도 연결되지 않아 보조 검토 의견을 받지 못했다. 위 개정은 로컬 코드 대조와 계산·문서 검증에 근거하며 Ollama 검토 완료로 표시하지 않는다.


## 17 자동 평가 규격과 축소된 실행 범위

### 17.1 완료 단위와 해석 범위

`controlled_auto_pilot`은 자동 정답과 자동 채점을 검증하는 개발 파일럿이다. 실행 중 문제를 보고 고친 파일럿을 독립 test로 이름만 바꾸지 않는다. 후속 `controlled_auto_test`는 생성 규칙·템플릿 계보를 분리하고 결과를 보기 전에 동결한 새로운 패널이어야 한다. 현실 사례의 `human_semantic_test` 및 AI 보조 판정 `ai_assisted`는 별도 표로 보고한다.

자동 패널 완료 조건은 사전 배정 요청의 실행 상태가 전부 확인되고, 정답·모델·원시 출력·스키마·평가기 해시가 일치하며, 고정 분모로 결과를 재생성하는 것이다. 정상적으로 기록된 실패는 완료 보고서에 포함한다. not_run·실행 증거 누락·판정기 오류가 남으면 완료를 선언하지 않는다. 실행 완료가 성능 기준 통과를 의미하지는 않는다.

### 17.2 자동화 가능한 확장 지표와 남겨 둘 경계

아래 표는 확장 가능한 경로의 목록이다. 이번 필수 측정은 M01·M03·M06·M07·M09·M11의 6개이며, 나머지를 추가 실행하는 지시가 아니다.

| 지표 | 사람 확인 없는 경로 | 자동 판정의 한계·표기 |
|---|---|---|
| M01 | 최초 원시 출력의 JSON·동결 스키마를 결정적으로 검사 | 형식 유효율이며 의미 정확성을 뜻하지 않음 |
| M02 | 필수 단계·현재 초안 해시의 승인·최종 출력 계약·종료 상태 검사 | 생성 파이프라인 완료율. 검토 모델 승인 자체가 독립 정답은 아님 |
| M03·M04 | 문항별 이미 확인된 정보·목적상 적용 조건을 입력 생성 시 확정하여 라벨 자동 산출 | `controlled_question_candidates`; 실제 후보·required·noSkip·answered_count·reason별 허용 조건·상한 적용 |

| M09·M11 | 생성기로 검증한 정상 초안과 단일 오류 주입 초안의 승인·거절·INVALID 집계 | `injected_error_drafts`; 자연 발생 오류 전체의 검토 성능으로 일반화하지 않음 |

| M19·M20 | 위 동결 분류 과제에서 검증된 라벨별 연속 점수와 정답으로 AUROC·AP 계산 | 점수 추출 지원·동률·전체 coverage 검증 시만 산출. 응답의 자가 확신 숫자로 대체 금지 |

확장 규격에는 기본 11개와 조건부 2개를 합쳐 13개의 자동 측정 경로가 있다. 이번 필수 실행은 그중 위 6개로 제한한다. 같은 M ID라도 `panel + metric_variant + contract_variant + output_stage`가 다르면 별도 결과다. 통제 과제의 결과를 자유 서술·사람 패널의 빈칸에 넣거나 여러 범위를 하나의 대표 점수로 평균내지 않는다.

이번 S1·S3·S4는 제3절의 `training_contract_reference`, S6·S7은 고정 상태 검토 계약을 사용한다. 후속 앱 통합 평가는 앱의 실제 출력 계약을 사용한다. 자동 채점을 위해 닫힌 튜플·오류 코드를 요구하는 별도 벤치마크를 추가한 경우 `contract_variant=benchmark_structured`로 표시하고 실제 앱 계약의 성능이라고 주장하지 않는다. 앱의 스키마·질문 생략·카드 화면을 자동 채점 편의를 위해 변경하지 않는다.

| 원래 지표 | 추가 자동 검사 ID와 내용 | 사람이 없이 확정할 수 없는 부분 |

### 17.4 사람 라벨 작성 없이 만드는 사례와 정답

1. 합성 세계의 인물 ID, 관계, 시간순 이벤트, 동의 범위, 실제로 주어진 사실, 미확인 슬롯을 생성한다. 실제 상담·학습 원문을 복사하지 않는다.
2. 제한된 문법으로 입력 문장을 만들고, 평가 대상 모델을 호출하지 않는 별도 정답 함수가 이벤트와 정책을 해석해 최종 상태·질문 라벨·허용 행동을 계산한다. 정답은 후보 모델이나 검토 모델이 생성하지 않는다.
3. 정상 구조화 초안은 정답 함수로 검증하고, 오류 초안은 화자·값·시점·부정·정정·미응답·동의 중 정확히 한 항목만 변경한다. 오류 manifest에는 위치·변경 전후 값·규칙 ID를 보존한다.
4. 입력에서 보이는 정보만으로 정답을 도출할 수 있는지 독립 구현·역변환·대조 검사를 수행한다. 생성기와 채점기가 같은 잘못된 상수를 공유한 채 통과하는 것을 방지한다. 정책 충돌·모호한 문장은 추론 전에 배정에서 제외하고 제외 수·이유를 남긴다.
5. 사례별 정답·오류 유형·정답 힌트가 입력·ID·파일명에 노출되지 않는지 검사한다. 허용 라벨과 공개 정책은 전달할 수 있지만 사례별 정답 파일과 오류 manifest는 추론 프로세스에 제공하지 않는다.
6. 입력·gold·generator·oracle·prompt·schema를 해시로 동결하고 기반 모델과 어댑터 모델에 같은 요청 순서를 배정한다. 결과를 본 뒤 정답이나 매칭 규칙을 수정하면 기존 결과를 그대로 보존하고 새 버전의 개발 실행으로 처리한다.

단순 이름·숫자 치환으로 사례가 늘어도 독립 표본이 늘었다고 보지 않는다. `case_id`, `root_lineage_id`, `template_family_id`, `transformation_id`를 보존하고 변형은 원천 계보 안에 묶는다. 의미 이해를 과장하지 않도록 문법 밖 자유 표현은 별도 패널에 두며 자동 점수의 적용 범위를 넓혀 주장하지 않는다.

### 17.5 축소 파일럿의 양과 호출 예산

이번 필수안은 **6개 사례 계열 × 기본·경계 각 1개 = 12개 사례**다. 기본 사례 6개와 핵심 조건 하나를 바꾼 경계 사례 6개를 모두 남겨 단순 과제의 유지와 경계 판단의 차이를 함께 본다. 아래는 사례 제작 명세이며 실제 평가 입력·정답 파일을 이번에 생성하거나 실행한 것은 아니다.

| 계열 | 기본 사례의 내용 | 경계 사례에서 바꿀 한 조건 | 드러낼 오류·주 관측점 |
|---|---|---|---|
| F1 이미 답한 정보 | 앞선 답변에 질문 대상 정보가 직접 명시됨 | 같은 사실을 사전 허용된 다른 표현으로 전달 | 표현이 달라져도 already_covered인지, 불필요한 반복·retain 오류 |
| F2 미응답과 불필요 구분 | 아직 답하지 않았고 현재 목적에 필요한 질문 | 공개 목적 규칙의 적용 조건만 바뀌어 해당 질문이 불필요해짐 | retain→not_needed 전환, 생략한 답을 지어내는지. 일반화 항목 |
| F3 화자와 대상 분리 | 주변인의 상태와 도움받는 사람의 상태를 각자 명시 | 같은 정보의 전달 방식만 타인 발언의 인용으로 변경 | 보고자와 상태의 주체 혼동, 근거 인용·관계 방향 오류 |
| F4 부정과 미확인 구분 | 특정 행동을 하지 않았음이 명시됨 | 그 행동의 여부를 모른다는 진술로 변경 | false와 unknown 혼동, 미확인을 확정 사실로 저장 |
| F5 정정과 과거 인용 | 이전 정보 뒤에 정정된 현재 값을 명시 | 끝에 정정 전 발언을 과거 인용으로 다시 덧붙임 | 마지막 문자열을 최신 사실로 오인, 폐기 값의 현재 상태 복귀 |
| F6 계획과 실제 행동 | 특정 도움 행동을 실제로 했다고 명시 | 같은 행동을 할 계획이라는 상태로 변경 | 계획을 완료 사실로 저장, 상태·시점 혼동 |

위 계열은 입력 변화의 종류다. 모든 과제가 그 의미 능력을 직접 측정하는 것은 아니다. S1은 질문 라벨, S3는 제공된 후보의 현재 근거 선택, S4는 정정 근거 갱신만 관측하며 제3절 관측 가능성 표에 실제 차이가 드러나는 출력 위치를 적는다. 입력이 이미 제공한 대상 구분이나 채점기가 해석한 부정·시점을 별도의 모델 추론 점수로 세지 않는다.

각 쌍은 인물·관계·질문 후보·관련 없는 사실을 유지하고 위 핵심 조건만 바꾼다. 의미가 유지되는 F1·F3·F5는 채점 대상 질문 라벨·현재 사실이 유지되고, 의미가 바뀌는 F2·F4·F6는 지정 의미 필드만 변해야 한다. 근거 인용 위치·표현·역사 서술은 입력 변화에 맞게 달라질 수 있으므로 전체 JSON 문자열 일치를 요구하지 않는다. F3의 기본·경계는 모두 같은 보고자의 동일한 정보 전달이며 직접 관찰을 불확실한 전언으로 바꾸지 않는다. 단순 이름 치환 12개가 아니라 **정답이 유지돼야 하는 변화와 바뀌어야 하는 변화**를 대조한다. 각 쌍은 하나의 계보이며 요청 수를 독립 표본 수로 세지 않는다.

모든 사례에 명시적 정정 사건과 필요한 질문 후보를 포함하여 S1·S3·S4가 모두 적격하도록 구성한다. 반복 문장을 12번 복사하지 않고 계열별로 정정 대상·근거를 새로 구성하며 쌍 안에서는 지정된 변화 외 조건을 유지한다. S3 필수 현재 근거는 사례당 1~3개, S4 필수 최신 근거는 적어도 1개이며 reported의 묶음·인용 상한 안에서 동시에 표현 가능해야 한다. S1의 3개 클래스가 전체 배정에서 실제로 관측되도록 후보 수·라벨 support를 동결한다. F5에서는 그 정정 사건 자체를 주 대조로 쓰고, 다른 계열에서는 정정 사건을 쌍 안에서 고정한다. 입력에 보이는 근거만으로 골드를 결정하며 과제와 무관한 긴 문맥·출력 예산 초과를 난이도로 사용하지 않는다. 필수/noSkip 문항은 억지로 생략 정답으로 만들지 않는다.

각 사례의 정상 초안은 골드로 검증하고, 오류 초안에는 해당 계열의 질문 판단·화자·상태·정정 중 **검토 계약으로 표현 가능한 오류 하나만** 주입한다. 그 계약이 질문 오류를 다루지 않는다면 연결된 상태 오류를 사전에 지정한다. 자유 설명으로 정답을 암시하지 않고 동일한 초안을 두 모델에 제공한다. 12개 정상·12개 오류 초안의 배정은 모델별로 유지한다.

학습·validation 원문을 재사용하지 않고 새 인물·이벤트 조합과 문장을 만든다. 모델 출력을 보기 전에 기본/경계·오류 유형·계보·gold·채점기를 동결한다. 과거 실행을 검토한 뒤 개선한 설계이므로 신규 패널도 **설계 수정 후 탐색 평가**로 표기하며 완전히 손대지 않은 독립 최종 test라고 부르지 않는다. 기준 모델이 실패한 사례만 남기거나 A가 성공할 때까지 다시 생성하지 않는다.

각 사례에는 아래 5개 과제를 배정한다. 기존 슬롯 ID는 기록 호환성을 위해 유지한다.

| 슬롯 | 고정 요청 | 핵심 지표 | 모델당 배정 |
|---|---|---|---:|
| S1 | 생성 중심: 허용 문항의 유지·생략 판단 | M01·M03 | 12 |
| S3 | 생성 중심: 제공된 현재 근거 선택 | M01·M06 | 12 |
| S4 | 생성 중심: 정정 후 현재 근거 갱신 | M01·M07 | 12 |
| S6 | 검토 전이: 정상 초안 승인 판단 | M01·M09·M11 | 12 |
| S7 | 검토 전이: 단일 오류 초안 판단 | M01·M09 | 12 |
| 합계 | 5개 과제 | 중복을 제외한 6개 핵심 지표 | 60 |

**12 × 5 × 2모델 = 총 120개 논리 요청**이다. 모두 최초 전송 한 번으로 채점하고 자동 수정·재시도는 끈다. 준비 조회는 메타데이터·파일 식별·로컬 토큰 계산처럼 생성 없는 확인만 별도로 기록한다. 준비용 생성 probe·워밍업·샘플 확인·숨은 SDK 재시도도 추가 생성이므로 현재 120개 범위에서는 허용하지 않는다. 실패한 전송을 재발송하여 실제 시도를 늘리지 않으며, 미실행이 남으면 배정 120개와 실제 전송 수를 나누어 미완료로 보고한다. 이 문서 개정은 요청 배정 계획이며 실제 호출 횟수를 의미하지 않는다.

M01은 과제별 12건을 우선 보고하고, 전체 60건의 합계는 형식 준수 요약으로만 제시한다. M03은 실제 허용 질문 후보 수, M06은 선택 근거의 TP·FP·FN, M07은 정정 근거 갱신 사례 12개, M09는 정상 12개+오류 12개=24개 초안, M11은 정상 초안 12개를 분모·단위에 맞춰 기록한다. 모든 지표를 12개 사례의 정답률로 통일하지 않는다.

제3절의 고정 규칙을 그대로 적용한다. M01은 `raw_json_v1`, 나머지 핵심 내용 지표의 주 결과는 `raw_or_single_json_fence_v1`로 채점한다. 펜스가 있는 유효 JSON은 M01 실패이면서 내용 채점 대상이 될 수 있다. 추출 후 JSON·스키마·계약 오류는 각 의미 지표의 실패 규칙에 남긴다. 새 추출 규칙을 기존 실행에 적용한 결과는 사후 진단으로만 보존한다.

S2 추가질문 선택, S5 미응답 전용 검사, S8 지원 정책, M19·M20의 연속 점수 수집, AI 심사·제17.5절 12개 사례 밖의 추가 반복 변형은 이번 필수안에서 제외한다. 정상·오류 초안을 같은 수로 평가하므로 모두 거절하는 모델이 좋은 검토 모델처럼 보이지 않도록 M09와 M11을 함께 제시한다.

**전체 흐름은 선택 항목**이다. 추가할 경우 일반 상황과 정보 정정 상황 2개를 두 모델에 각각 적용하여 총 4개 흐름만 확인한다. 흐름 하나가 여러 단계와 재시도를 포함하므로 4회 모델 호출로 계산하지 않는다. 먼저 사례별 마감·재시도 상한을 정하고 실제 호출·실패·시간을 별도로 기록한다. 이 결과를 필수 120개 요청의 분모에 합산하지 않는다.

표본 축소는 아직 계획 중인 새 패널의 규모를 변경하는 것이며 기존 실패 기록을 삭제하거나 성공 사례만 선택하는 작업이 아니다. 과거 실행 결과·분모·모델 설정은 그대로 보존한다. 이번 계획은 소수 계보의 탐색 평가이므로 확증적 신뢰구간이나 전체 성능 보장 대신 분모·오류 수·개선 관측 범위를 공개한다.

생성자 비교에서는 입력·프롬프트·검토자 모델과 설정을 고정하고 생성 초안은 모델별 원시 출력으로 보존한다. 검토자 비교에서는 같은 정상·오류 초안을 고정한다. 기반/어댑터를 생성자와 검토자 양쪽에서 동시에 교체한 실험은 별도 시스템 조합 비교다. 같은 베이스 가중치·양자화·토크나이저·템플릿·컨텍스트·greedy 옵션과 제3절의 JSON 비강제 생성 조건에서 어댑터 적용 여부만 바꿔 비교하고, 실제 LoRA 활성 상태와 scale을 확인한다. 기존 앱 모델 설정을 바꾸지 않고 전용 로컬 포트에서 실행한다.

### 17.6 반복·변형 검사와 선택적 AI 보조 판정

제17.5절의 기본·경계 12개 사례는 필수 120개 요청에 이미 포함한다. 그 밖에 추가 모델 호출을 쓰는 변형 검사와 AI 보조 판정은 이번 필수 120개 요청에 포함하지 않는다. 후속 확장을 선택할 때만 별도 예산·규칙을 정한다. 인물 이름의 일관된 치환, 무관 문장 추가, 의미를 유지하는 문장 순서 변경, 명시적 정정 추가를 사전에 등록한다. 보존되어야 할 필드와 바뀌어야 할 필드를 구분하여 통과율을 계산한다. 점수가 낮은 사례만 사후 선택하지 않으며 원본과 변형을 독립 표본으로 합산하지 않는다.

자유 텍스트는 선택적으로 로컬 AI 평가자를 사용해 J14·J15·J17·J18 보조 결과를 만들 수 있다. 평가 대상 이름·기반/학습 여부를 가리고 출력 순서를 바꾸어 판정하며, 입력·루브릭·원문 인용·점수·평가자 모델 식별·순서에 따른 불일치를 보존한다. 출력 속 지시문은 데이터로 취급한다. 생성 모델과 같은 계열을 평가자로 쓴 경우 이를 공개하며, 순서 교환이나 두 번의 판정을 독립 평가자 2명으로 계산하지 않는다.

AI 평가자도 오류를 낼 수 있다. 기계 정답이 있는 검증 묶음에서 먼저 일치도·오판 유형을 확인하고, 동결 기준을 충족하지 못하면 J 점수를 품질 판단에 사용하지 않는다. 기준이 미정이면 탐색 의견만 제공한다. 사람이 없어도 J 결과를 계산·보고할 수 있으나 이는 사람 M14·M17이나 안전성 승인을 대체하지 않는다. AI 의견을 사후 정답으로 바꾸어 같은 출력을 다시 채점하지 않는다.

### 17.7 자동 평가기의 검증과 사람 작업의 축소

기존 제11절 산술 검사 외에 다음을 통과해야 자동 패널을 실행한다.

- 입력 생성·독립 해석·gold가 같은 결과인지 대조하고, 의도한 단일 오류 주입이 정확히 한 규칙만 어기는지 검사.
- 화자를 바꿔도 값이 같아 오류가 생기지 않는 음성 대조, 화자 교환·부정 반전·정정 이전 값·근거 없는 미응답 값·중복 사실을 포함한 변이 테스트에서 예상 오류를 검출하는지 검사.
- 정상 동의 표현·허용된 재확인·역사 서술을 잘못 거절하지 않는지 검사.
- 스키마 실패·빈 출력·통신 실패·not_run·판정기 오류를 구분하고 모델 실패와 평가기 오류를 섞지 않는지 검사.
- 자유 텍스트의 미인식 표현을 자동으로 정답 또는 오답으로 단정하지 않는지 검사. 닫힌 계약의 유효하지 않은 값은 INVALID로 처리하며, 계약상 허용된 미지원 표현은 판정기 오류로 해당 의미 집계를 보류.
- 정답 파일 비전달, 모델 ID·LoRA 상태·요청 해시 동결, 기반/후보의 같은 배정, 중단 후 최초 기록 보존, 재집계 동일성 검사.

사람에게 남길 작업은 자연 사례의 모호한 의미·새 오류 유형·자유 카드의 유용성·현실 위험 해석이다. 자동 패널에서는 이러한 사람 판정을 필수 단계로 넣지 않는다. 향후 사람 감사를 추가할 경우 전체 배정에서 사전 무작위 표본을 추출하고, 자동 실패·AI 불일치 사례는 별도의 오류 조사 표본으로 더한다. 오류 조사 표본의 비율을 전체 오류율로 사용하지 않는다. 사람 감사나 통계적 확증이 필요한 지표는 해당 근거가 준비될 때까지 미측정·보류로 남긴다.

### 17.8 이번 개정의 완료 범위

v1.7은 **핵심 지표 6개, 12개 사례, 5개 과제, 기반·학습 모델 합계 120개 고정 요청**과 생성 관련 72개·검토 전이 48개를 유지한다. 적대적 검토에서 발견한 질문 후보 중복 집계, 실제 출력보다 넓은 의미 능력 주장, S4 최신 정답 입력 누출, 과제 간 상태 혼입, 검토 정답·쌍 표시 노출, 120개 밖 준비용 생성 가능성을 수정했다. M06·M07은 근거 선택·갱신 variant로 한정하고 계약 용량·관측 가능성 확인을 동결 전 조건으로 명시했다. 어댑터와 학습 자료의 연결 미확인, not_needed 양성 학습예 미확인을 명시했다. 앞서 고정한 원시 형식/내용 추출 분리·JSON 비강제 생성·제한된 발표 주장·구간 미산출 규칙은 유지한다. 전체 흐름 4개는 선택 사항이며 사람 평가·AI 심사·대규모 독립 test는 후속 확장으로 돌렸다. 기존 20개 지표 정의는 참고 규격으로 남긴다. 이번 문서 수정 중 새 추론·평가·재채점은 수행하지 않는다. 결과표의 점수와 목표 충족 판정은 후속 실행 근거가 생긴 뒤 작성한다.

간단한 평가 구성은 [평가 기획 요약](모델_평가_기획_요약_2026-11-12.md)을 참고한다.
