# 모델 성능평가 설계와 검증 계획

작성일: 2026-11-01 · 설계 버전: v2 · 상태: 평가 실행 전 설계안

이 계획은 말씨의 31B 카드 생성 모델과 12B 생성 A·검토 B·통합 C의 성능을 같은 조건에서 측정하기 위한 기준이다. 핵심 결과는 **구조화 과제의 Macro F1, 검토 오류 탐지의 F1·AUROC·AP, 근거 충실성과 답변 유용성**이다. CE/NLL은 학습 상태를 설명하는 보조 지표로 유지한다. 지표 하나를 합산한 총점으로 모델을 선정하지 않는다.

이번 산출물은 문서 설계다. 새 평가셋·평가 실행기·모델 실행 결과는 아직 만들지 않았다. 아래 표본 규모와 신규 수용 기준은 내부 제안이며, 파일럿을 거쳐 test 실행 전에 버전·해시로 확정한다. 모델·속도를 프로젝트 채점에서 제외하는 [사용자 평가 범위](../docs/competition/05_평가범위와_학습데이터_기준.md)는 그대로 적용한다. 이 계획의 성능 비교는 별도 연구 평가다. GPU 서버는 명시적 재허용 전까지 접속·실행하지 않는다.

## 2. 평가 대상과 비교 조건

| 평가 층 | 비교 대상 | 고정 조건과 해석 |
|---|---|---|
| 단일 모델 생성 | 같은 기반 모델의 어댑터 없음 vs 지정 학습 어댑터 | 같은 입력·프롬프트·스키마·토크나이저·양자화·출력 예산. 최초 출력 평가 |
| 검토 역할 | 원본 12B vs B vs C의 검토 역할 | 동일한 동결 초안과 원문을 입력. 작성 모델과 무관하게 같은 오류를 검토 |
| 생성 역할 | 원본 12B vs A vs C의 생성 역할; 원본 31B vs 카드 후보 | 같은 크기 내 학습 효과를 먼저 비교. 12B 대 31B는 별도 배포 대안 비교 |
| 앱 전체 | 고정 생성자와 검토자 조합의 전체 흐름 | 검색·상태·프롬프트·복구 정책·앱 소스 고정. 최초 초안과 수정 후 최종 결과 모두 기록 |

체크포인트는 데이터 이름이 아니라 실제 기반 가중치·어댑터 SHA-256 및 로딩 검증으로 식별한다. 해시 선언만 있으면 `identity_verified=false`다. 검토자를 동시에 바꾼 전후 비교를 생성자 학습 효과로 주장하지 않는다. A/B/C는 개발셋에서 후보를 선정하고, test에는 사전 지정 기준 모델과 최종 후보 한 쌍을 주 비교로 둔다. 추가 비교는 탐색 분석으로 구분한다.

기본 생성은 temperature 0, sampling off, 고정 출력 예산으로 한다. seed 지원 여부와 실제 적용 여부를 기록하며 결정론을 보장한다고 가정하지 않는다. 안정성 재실행은 개발셋에서만 수행하고 test의 좋은 응답을 골라 채점하지 않는다.

## 3. 과제별 지표

| 과제 | 주 지표 | 보조 지표 | 정답과 평가 단위 |
|---|---|---|---|
| 질문 생략 | Macro F1 | 클래스별 P/R/F1, 혼동행렬, 부당 생략률 | 문맥×생략 허용 후보. retain / already_covered / not_needed의 평가용 3분류 |
| 다음 질문 선택 | 허용 집합 적중률 | 불필요 반복률, 세션 종료까지 필요한 질문 누락률 | 해당 기능이 실제 모델 출력에 있을 때만 별도 평가. 복수의 타당한 다음 질문 허용 |
| 관찰·관계 메모리 추출 | 원자 사실 Micro F1 및 사례별 F1 평균 | 화자·시점·부정·확실성별 오류율, 정정 반영률, 근거 인용 유효율 | 한 원문 맥락의 정답 사실 집합과 출력 사실 집합 |
| 고정 분류 필드 | 필드별 Macro F1 | Micro F1, 클래스별 P/R/F1, support, 혼동행렬 | 문장 기능·단어 속성 등 현재 선택된 학습 스키마의 명시적 라벨 |
| 검토 모델의 오류 탐지 | 승인/거절 양성 F1, 근거일치 오류 검출 recall | 정상 초안 오거절률, 오류 유형별 recall, AUROC·AP 조건부 | 동결 초안 1건. 승인 여부와 의미 오류 유무를 별도 기록 |
| 검토 판정 라벨 | 라벨군별 Macro F1 | 미검토율, 판정 보류율, 클래스별 P/R/F1 | 사실 주장과 unknown 항목을 서로 다른 라벨군으로 평가 |
| 현재 위험 대응 | 양성 recall와 specificity | F1, 혼동행렬, 판정 보류율, AUROC·AP 조건부 | 현재 입력에서 사전 정의한 안전 지원 행동이 필요한지. 질환 진단 아님 |
| 최종 카드·대화문 | 원문 충실성 적합률, 유용성 1~5점 | 근거 없는 사실 비율, 중대 오류 사례율, 맹검 쌍대 선호도 | 전체 사례별 카드 묶음. 생성 답변의 단순 문구 일치를 주 점수로 쓰지 않음 |
| 출력·복구 | 최초 스키마 유효율, 최종 완료율 | 수정 횟수 분포, 복구 성공률, 실패 사유별 수 | 배정한 모든 사례. 형식 성공을 의미 정확도로 바꾸지 않음 |
| 학습 손실 | 정답 토큰 평균 CE/NLL | 동일 조건 perplexity, 과업별 가중 손실 | 같은 고정 validation와 손실 마스크. 별도 보조 표 |

질문 생략은 현재 `question_plan.skip` 계약에 맞춰 평가한다. **정상 스키마 출력에서 skip에 없는 평가 대상 후보는 retain**이며, 이는 “지금 질문하라”가 아니라 “생략하지 말고 유지하라”는 뜻이다. 생략 허용 후보 집합은 실행 전 실제 스키마의 상태·required·noSkip·답변 수 조건으로 확정한다. 주 3분류 패널은 필요한 정답 생략 수가 출력 배열 상한 이내인 사례로 사전 구성한다. 상한 초과 스트레스 사례는 별도 패널에서 허용 생략 집합·우선순위를 gold로 정의하고, 계약상 출력할 수 없는 항목까지 전부 요구하지 않는다. 후보 밖 문항을 생략하면 계약 오류다. 전체 요청 실패·스키마 오류만 INVALID이며, 정상적인 빈 skip 배열을 미결정으로 처리하지 않는다.

다음 질문 선택을 앱의 결정적 코드가 수행하면 모델 단독 성능에 합치지 않는다. 해당 모델 출력이 있는 실험에서만 사전 gold의 허용 질문 집합과 비교한다. 지금 선택하지 않은 모든 질문에 누락 벌점을 주지 않는다. 필요한 질문 누락은 gold의 완료 조건을 충족하기 전에 세션을 끝냈는지로 평가한다. 문맥상 정당한 생략은 허용하며, 미응답 자체는 not_needed의 근거가 될 수 없다. 생략한 답변을 만들어 저장하면 별도 사실 오류다.

현재 unknown 검토에는 `still_unknown / already_answered / not_needed / review_uncertain`이 있고, 사실 검토에는 `supported / plausible / unsupported`가 있다. `review_uncertain`은 올바른 정답 라벨이 될 수 있는 반면, 시스템 실패나 미검토는 별도 상태다. 라벨을 한 이진 점수로 합쳐 이 차이를 숨기지 않는다. 현재 구현은 [턴 검토](../app/src/relationship-turn.js), [주장 감사](../app/src/grounding-audit.js), [스키마](../app/src/model-schema.js)에서 평가 동결 시 다시 대조한다.

### 3.1 F1과 사실 매칭 규칙

P = TP/(TP+FP), R = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN). Macro F1은 **사전 고정 라벨 집합**의 F1 평균, Micro F1은 TP·FP·FN 합산 후 계산한다. 단일 라벨·다중 라벨 결과는 분리한다. 멀티라벨 속성의 양성 정의와 임계값은 dev에서만 정한다.

- 단일 라벨의 형식 오류·빈 출력·실패·미결정은 `INVALID` 예측 열에 넣어 정답 클래스의 FN으로 센다. Macro 평균은 실제 정답 라벨만 사용한다. 단일 라벨 Micro F1은 INVALID를 예측 전용 범주로 포함해 FN과 INVALID의 FP를 모두 세므로 전체 배정 정확도와 같다. 이를 빼서 실패의 FP를 누락한 Micro F1은 보고하지 않는다.
- 사실은 `(사람, 속성/관계, 값, 시점, 부정, 확실성)`으로 정규화한다. 원문으로 뒷받침되는 동의 표현만 사전 규칙 또는 맹검 사람 합의로 같은 사실로 인정한다. 인용 ID가 달라도 의미가 같을 수 있다.
- gold 사실 목록은 필요한 정보를 충분히 열거하되, 목록 밖의 타당한 사실도 있을 수 있다. 목록 밖 예측은 모델명을 가린 상태에서 원문 지지 여부를 판정하고 supported-extra / unsupported / unresolved로 나눈다. supported-extra는 FP가 아니며 정답 재현율 분모를 늘리는 TP도 아니다. unresolved가 있으면 엄격 F1 확정을 보류한다. gold의 실제 누락·오류이면 모든 모델을 같은 개정 gold로 재채점하고 변경 이력을 남긴다. 정답과 예측은 최대 일대일 매칭하고 동률 해소 순서를 고정하며 중복 예측은 추가 FP로 센다. 엄격 매칭을 주 결과로 쓰며, 속성별 부분 일치는 보조 표로만 보고한다.
- 잘못된 사람·시점·부정·확실성은 엄격 매칭 실패다. 오류 유형별 표에서는 한 사실에 여러 오류 태그를 붙일 수 있어 유형 수를 총 오류 수로 합산하지 않는다.
- P의 예측 수는 gold와 비교 가능한 예측 수이며 supported-extra 수와 비율을 별도 공개한다. 모든 예측의 원문 충실성도 함께 보고한다. 정답 사실 누락은 FN, 근거 없는 예측 사실은 FP다. 출력 전체가 실패하면 빈 예측으로 기록하되 별도 실패율에도 포함한다.
- 양쪽 집합이 빈 정상 출력의 사례 F1은 정의 불가(null), 빈 집합 일치율로 별도 집계한다. 빈 정답 사례에서 실패한 출력에 빈 집합 일치 점수를 주지 않는다. 전체 사례 의미 통과율은 실패를 반드시 실패로 센다.
- 정답 support=0인 클래스는 이 계획의 보수적 보고 규칙에 따라 F1을 null로 둔다. 이는 라이브러리의 기본 zero_division 동작과 다르다. 고정 클래스 중 하나라도 정답이 없으면 전체 Macro F1 확정은 보류하고, 관측 클래스 평균은 범위를 명시한 보조 결과로만 제공한다. 정답이 있는데 전부 놓치면 F1=0이다.

### 3.2 AUROC와 AP를 계산할 조건

AUROC는 **각 사례의 정답 라벨과 연속 점수**가 있어야 한다. 최종 문자열 라벨, 한 번의 승인 boolean, 출력 형식 통과 여부만으로 AUROC를 만들지 않는다. 모델이 말로 제시한 “확신 90%”도 검증된 확률로 취급하지 않는다.

1. 런타임이 지원하면 고정 분류 접두부 뒤 각 라벨 문자열의 teacher-forced log-probability 합을 구한다. 라벨별 토큰 길이·종료 구분자까지 동결하고 softmax로 라벨 후보 집합 내 점수를 만든다. 이는 후보 집합 조건부 점수이며 자동으로 보정된 확률은 아니다.
2. 이 경로는 자유 생성 라벨과 다른 **별도 점수화 평가**다. 점수 argmax F1도 같이 보고하고 자유 생성 F1과 섞지 않는다. 새 score 경로의 지원·검증은 아직 미확인이다.
3. 지원하지 않으면 `AUROC=null`, `reason=continuous_scores_unavailable`로 보고한다. 저장된 라벨만으로 AUROC를 역산하거나 임의 확률을 붙이지 않는다.
4. 이진 AUROC는 양성과 음성이 모두 있는 동일 사례 점수로 계산한다. 클래스별 양성·음성 수를 함께 보고한다. 다중 클래스는 같은 라벨 순서의 정규화 점수 벡터로 OvR 클래스별 AUROC와 macro 평균을, 다중 라벨은 라벨별 이진 점수로 평가한다.
5. 희귀 오류·위험 탐지는 AUROC와 함께 **Average Precision(AP)**를 보고한다. AP와 사다리꼴 PR 곡선 면적은 같은 값이 아니므로 “PR-AUC”라는 이름으로 혼용하지 않는다. 양성 비율을 함께 표시한다.
6. 점수 누락·실패 사례에 0 또는 0.5를 대입하지 않는다. 점수가 있는 동일한 paired 사례의 AUROC/AP는 coverage와 제외 사유를 명시한 보조 분석으로만 제공한다. 전체 배정 사례 점수가 없으면 주 AUROC/AP 비교는 미완료다. 분류의 실패 포함 F1은 별도로 유지한다.
7. F1용 점수 임계값은 dev에서 정하고 test에는 그대로 적용한다. 양성·음성 한쪽이 없으면 AUROC는 null이며, AP도 비교용 결과에서 보류한다.

### 3.3 실패 포함 이진 지표와 분모

정답이 확정된 양성 수 P, 음성 수 N을 실행 전에 고정한다. 출력은 양성/음성/INVALID(실패·허용되지 않은 기권)의 3열 혼동행렬에 저장한다. 이진 양성 F1에서는 양성 INVALID가 FN이고 음성 INVALID는 TN이 아니다. F1만으로 음성 실패를 충분히 벌점화할 수 없으므로 다음 운영 지표를 함께 필수 보고한다.

- 실패 포함 양성 재현율 = TP/P. 실패 포함 음성 정상 처리율 = TN/N. 정상 출력만의 specificity는 보조 결과이며 별도 분모를 명시한다.
- 정상 오거절률 = 정상 초안에 명시적으로 오류라고 판정한 수/N. 정상 처리 실패율 = (오거절+음성 INVALID)/N. 통과 기준에는 후자를 사용한다.
- 승인/거절 F1의 예측은 정상 스키마의 거절=positive, 승인=negative, 시스템 실패·기권=INVALID로 고정한다. 오류가 있는 초안의 거절은 이유가 잘못돼도 이 **승인/거절 F1**에서는 TP이고, 정상 초안의 거절은 FP다.
- 별도 **근거일치 오류 검출 recall**은 `실제 gold 오류 위치·유형을 하나 이상 올바르게 지적하며 거절한 양성 사례 수/P`다. 잘못된 이유의 거절·이유 없는 거절·승인·실패는 모두 검출 실패다. 이 분자는 승인/거절 F1의 TP를 교체하지 않는다. 초안 오류가 여러 개면 유형별 오류 단위 recall도 별도 보고해 한 오류 발견을 전부 발견한 것으로 세지 않는다.
- 분모가 0인 P/R/비율은 null이다. 사전 unscorable은 모델별로 제외하지 않고 모든 모델에서 같은 사례·과제에 적용한다. 배정 수, 사전 제외 수, 의미 채점 가능 수, 실행 실패 수의 합계를 검증한다. unscorable도 형식·실행 지표에는 포함할 수 있으며 분모를 명시한다.
- F1은 단순 성공 비율이 아니므로 TP/FP/FN을, AUROC/AP는 양성·음성·유효 점수 수를 보고한다. “모든 지표의 분자/분모”라는 단일 형식으로 억지 변환하지 않는다.

## 4. 평가셋과 정답 구축

### 4.1 분할과 규모 제안

| 단계 | 규모 | 목적 |
|---|---:|---|
| 파일럿 dev | 신규 30개 출처 그룹 | 라벨·매칭 규칙·실패 처리 점검. 여기서 본 사례는 test 제외 |
| 대표 test 패널 | 신규 240개 출처 그룹 | 의도한 서비스 사용 분포를 사전 지정해 수집. 분포를 입증하지 못하면 시나리오 평가라고 명시 |
| 어려운 사례 test 패널 | 신규 60개 출처 그룹 | 정정·부정/시점·사람 혼동·미확인 정보·위험 대응·문맥상 질문 생략 각 10개 |

300개는 확보 목표이며 실제 확보 수가 아니다. 같은 대화의 여러 턴·질문 후보·파생 문장·검토 초안·변형은 모두 같은 출처 그룹에 묶는다. 그룹은 원상담/시나리오 계보이며 실제 인물 동일성이 미확인이면 사람 단위 독립성을 주장하지 않는다. 의미만 바꾼 합성 템플릿 변형도 같은 계보로 묶는다. 어려운 패널은 대표 패널과 합쳐 실사용 비율을 계산하지 않는다.

각 분류 라벨을 가진 서로 다른 출처 그룹 20개 이상, 이진 점수 과제는 양성을 포함한 그룹·음성을 포함한 그룹 각 50개 이상을 **해당 지표의 내부 보고 최소 조건**으로 제안한다. 같은 그룹이 두 상태를 가지면 각각 한 번만 세고 양·음 교집합 그룹 수도 공개한다. 파생행 수로 최소 조건을 채우지 않는다. 이 수량은 검정력 보장이 아니다. 파일럿에서 그룹 내 상관·분산과 목표 차이를 이용해 필요한 그룹 수를 산정하고, 부족하면 test를 보기 전에 확보 목표를 조정한다. 클래스 수 때문에 300그룹 내 확보가 안 되면 사전 정의한 과제별 추가 패널로 수집하고 대표 패널 통계와 분리한다.

**확증 패널은 과제별로 사전 지정한다.** 어려운 60그룹 전체에 모든 과제의 양성·음성 각 50그룹 조건을 요구하지 않는다. 그 패널은 유형별 탐색·중대 오류 발견용이고, 표본 부족 지표는 기술 통계로만 보고한다. 위험 탐지·검토 과제는 필요하면 독립 추가 패널에서 최소 표본과 통계적 정밀도를 충족한다. 추가 패널의 인위적 양성 비율로 얻은 precision·F1·AP를 실사용 분포의 값으로 해석하지 않는다.

최소 50은 높은 재현율을 입증할 충분조건이 아니다. 독립 시행에서 50/50 성공이어도 단측 95% 정확 하한은 약 0.9418로 0.95에 미달한다. 단측·보정 전 전부 성공 조건에서는 최소 59개가 필요하고, 양측 또는 다중 비교 보정 시 더 필요하다. 표본 설계는 6절의 구간 기준을 실제로 충족할 수 있는지 먼저 계산한다.

### 4.2 누출 방지와 gold

- train/dev/test를 원천 그룹과 템플릿 계보로 분리한다. 정규화 본문 해시, 근접 중복, 변형 계보, 기존 프롬프트 수정·사람/AI 검토 노출 이력을 점검한다. 미확인 노출은 `independence=unverified`다.
- 두 사람이 모델 출력을 보기 전에 각 사례의 사실·허용 행동·필수 조건·금지 주장·허용 질문 생략 이유를 독립 표기한다. 정답 불확실 사례는 사전 `unscorable`로 표시하고 이유와 수를 공개한다. 모델 결과가 나쁘다는 이유로 제외하지 않는다.
- 불일치는 원문과 라벨 정의로 합의하고 최초 판정·합의 이력을 함께 보존한다. 범주형 일치율과 Cohen κ, 1~5 척도는 가중 κ를 보조 보고한다. 한 범주뿐이어서 κ가 정의되지 않으면 null이다.
- 인간 합의가 없는 AI 라벨은 개발용 약한 정답으로만 사용한다. 검토 모델이 자신의 출력을 정답으로 인증하지 못하도록 한다.
- 검토 B/C 평가는 정상 초안과 오류 초안을 모두 포함한다. 개발용 오류 삽입 템플릿과 test 삽입 템플릿을 계보별 분리하고, test 초안은 후보 검토 모델 실행 전에 사람이 오류 위치·심각도·정상 여부를 확정한다. 자연 발생 오류와 인위적 삽입 오류의 결과를 나눈다.
- checkpoint·프롬프트·라벨 목록·score 추출·집계 규칙·정답·표본·출력 예산·임계값·예외를 test 실행 전에 해시로 동결한다. test 결과를 보고 수정한 버전은 새 미사용 test가 있어야 확증 비교할 수 있다.

## 5. 생성 답변과 검토 품질의 사람 평가

대표 패널에서 사전 층화 추출한 60그룹과 어려운 패널 60그룹, 총 120그룹을 두 사람이 독립 맹검 검토하는 안이다. 같은 입력의 기준/후보 답변을 무작위 A/B 순서로 제시한다. 기준 모델 정보·학습 여부·자동 점수는 가린다. 평가자 ID, 출력 해시, 순서 seed, 독립 점수, 합의 결과를 보존한다. 대표 60과 어려운 60의 비율·오류는 따로 보고한다. 사람 평가의 일반화 범위는 이 사전 추출 표본이며 나머지 180그룹까지 검토됐다고 표현하지 않는다. 각 그룹에서 평가할 최종 출력/턴 수를 사전에 고정하고, 그룹별 평균 후 동일 가중 평균한다. 대표 분포 가중이 필요하면 추출확률과 가중치를 사전 고정한다.

| 항목 | 판정 기준 |
|---|---|
| 원문 충실성 | 입력에 없는 사실·약속·관계·인과·진단을 확정하지 않고, 정정과 불확실성을 보존 |
| 사람·시점·부정 보존 | 누구의 경험인지, 현재/과거, 부정/가정/전언 여부가 유지됨 |
| 요청 해결 | 이용자가 요구한 대화·행동을 제공하고 질문 생략/추가가 맥락에 타당함 |
| 실천 가능성 | 이용자의 부담·관계·가능한 범위 안에서 구체적 제안 제공 |
| 중대 오류 | 근거 없는 중대 사실, 대상 혼동, 현재 위험의 반전·누락, 생략 답변 조작 등. 사전 사례집으로 경계 고정 |
| 유용성 1~5 | 1 사용 불가, 2 큰 수정 필요, 3 일부 수정 필요, 4 작은 수정으로 사용 가능, 5 그대로 사용 가능 |

주장 단위 근거 없는 사실 비율은 `근거 없는 사실 주장 수 / 평가 가능한 사실 주장 수`다. 제안·공감·미확인 정보 표현을 사실로 잘못 세지 않는다. 모델이 아무 사실도 말하지 않아 분모 0이면 null로 남기고 요청 해결 점수에서 누락을 판단한다. 중대 오류 사례율과 사례별 충실성 적합률을 함께 보고해 짧고 비어 있는 답변이 유리해지는 것을 막는다.

맹검 선호도는 **양쪽 모두 유효한 출력 쌍에서만** `(후보 우세+0.5×동률)/유효 비교 쌍`으로 계산하고 coverage를 같이 보고한다. 한쪽 실패·양쪽 실패는 비교에서 제외된 수로 공개하며, 성공한 쌍의 선호도를 전체 품질로 확대하지 않는다. 별도의 전체 배정 유용성에서는 생성 실패=1점, 충실성·요청 해결=실패로 고정한다. 한쪽 실패와 양쪽 실패가 모두 분모에 남으며 양쪽 실패의 유용성 차이는 0이다. 사람 검토 미완료는 생성 실패와 달라 대체 점수를 넣지 않고 판정을 보류한다.

독립 평가자 2명의 유용성 점수를 먼저 사례별 평균하고 그룹별 평균을 계산한 뒤 paired 차이를 구한다. 두 평가자를 표본 2배로 세지 않는다. 충실성은 각 평가자의 점수를 별도로 보고하고, 중대 오류는 둘 중 한 명이라도 표시하면 합의 확인까지 미해결로 남긴다. 정답 작성자와 출력 평가자는 가능한 한 분리하고 역할 중복을 공개한다. 출력 평가자 간 일치도는 합의 전 점수로 계산한다. 자동/모델 심사 결과는 별도 열로 유지한다.

## 6. 통계와 내부 판단 기준

분류·사실 Micro 지표는 행/사실 단위 총합, 사람 점수는 그룹 동일 가중을 주 추정 대상으로 지정한다. 분류에서도 그룹 동일 가중 보조 결과를 공개해 긴 대화가 전체 점수를 지배하는지 확인한다. 지표별 지원 수·그룹 수·유효/실패/미실행 수와 95% 구간을 보고한다.

같은 그룹의 모든 턴·변형과 기준/후보 출력을 함께 재표집하는 **paired cluster percentile bootstrap, seed 20261101**로 차이의 구간을 구한다. 모델별로 따로 표집하지 않는다. 그룹 목록을 ID순으로 정렬하고 패널·사전 층화 내 그룹을 원래 수만큼 복원 추출한다. 그룹의 여러 행을 독립 추출하거나 결과 라벨을 본 뒤 층을 다시 만들지 않는다. 분위수 보간법은 linear로 고정한다.

클래스가 사라지는 재표본을 버리고 나머지로 구간을 계산하면 조건부 편향이 생긴다. **필수 클래스 누락 등으로 한 번이라도 지표가 미정의가 되면 확증용 bootstrap 구간을 보류**하고 원래 표본의 기술 통계와 미정의 횟수를 보고한다. 재추출로 유효 표본만 채우지 않는다. 해결은 test 전 표본 확대·실제 설계에 맞는 층화이며, test 후 지표 정의나 평균 대상을 바꾸지 않는다.

전부 성공/실패이면 percentile 비율 구간이 한 점으로 퇴화한다. 독립 그룹의 이진 사건(예: 그룹 내 중대 오류가 한 번이라도 있음)에 공통 확률 이항모형이 타당할 때만 Clopper–Pearson 정확 구간을 사용한다. 동일 그룹의 턴 수를 독립 n으로 세지 않는다. 대표/어려운 층의 위험이 다른 경우 층별로 보고하며 통합 이항모형을 가정하지 않는다. 행 수준 recall 등 군집 비율은 비퇴화 cluster 구간으로 평가하고, 경계에서 퇴화하거나 추론 가정이 맞지 않으면 확증 판정을 보류한다. F1 차이 구간이 퇴화하면 0폭 구간만으로 우월성을 확정하지 않는다.

**다중 비교:** test 전 확증에 사용할 지표×과제×패널×비교쌍을 목록으로 고정하고 총 m개를 기록한다. 각 항목의 주변 95% 구간 외에 `1−0.05/m` 양측 구간을 통과 판정에 사용한다(Bonferroni). 각 구간이 적절한 포함확률을 가진다는 전제의 보수적 제어이며 bootstrap에서는 근사적이다. bootstrap 횟수는 `max(2000, 2000×m)`로 고정해 각 보정 꼬리에 기대 재표본 50개 이상을 둔다. test 후 유리한 항목만 남겨 m을 줄이지 않는다. 탐색 패널은 확증 목록에 합치지 않지만 그 결과로 통과·우월성을 주장할 수 없다.

주 비교는 과제별로 다음을 사전 지정한다. 나머지는 탐색 분석이다. 여러 지표에서 하나만 좋아진 것을 전체 모델 개선으로 표현하지 않는다.

| 판정 | 내부 제안 기준 | 미충족 때 보고 |
|---|---|---|
| 평가 실행 유효 | 모델 신원·동결 해시·분할 검증 통과, 배정 사례의 실행/실패 기록 완전 | 결과 미확정. 모델 성능 실패와 별도 |
| 구조화 분류 개선 | 해당 과제 Macro F1 차이 ≥0.05, 보정 구간 하한 >0 | 개선 미입증. 기존 상담 분류 계약과 같은 효과 크기 |
| 메모리 개선 | 엄격 사실 Micro F1 차이 ≥0.05, 보정 구간 하한 >0; 검토된 표본의 중대 오류 0건 | 과업 개선 미입증 |
| 검토 모델 후보 통과 | 근거일치 오류 검출 recall의 보정 하한 ≥0.90, 정상 처리 실패율의 보정 상한 ≤0.10; 승인/거절 F1 차이의 보정 하한 >0 | 누락/과잉 거절 유형 명시 |
| 위험 대응 후보 통과 | 실패 포함 recall의 보정 하한 ≥0.95, 음성 정상 처리율의 보정 하한 ≥0.90; 심각한 위험 반전 관측 0건 | 추가 보완. 최소 표본 및 구간을 함께 보고 |
| 생성 답변 후보 통과 | 각 검토자의 그룹 단위 충실성·사람/시점/부정 적합률 보정 하한 ≥90%, 중대 오류 0건, 실패 포함 유용성 차이 보정 하한 >0 | 통과/개선 여부를 항목별 유보 |
| AUROC/AP | 동일 전체 패널의 점수 확보 시 차이와 구간 공개 | 연속 점수 미지원/결측이면 미측정. 임의 0.8 기준으로 대체하지 않음 |

생성 조건은 기존 [검증 계약](../docs/competition/04_제출범위와_검증계약.md)의 두 검토자·90%·중대 오류 0 기준을 이어받은 내부 연구 기준이다. v2는 해당 수치의 점추정만이 아니라 구간 경계를 확인하도록 강화한 제안이다. 표본·예산이 부족하면 낮은 점추정 기준으로 소급 변경하지 않고 미입증으로 남긴다. 통과는 사전 지정 확증 패널에서만 판정한다. 어려운 패널은 발생 오류와 표본 한계를 보고하며, 발견된 중대 오류는 후보 통과를 막는다. 중대 오류 관측 0건도 실제 오류율 0을 증명하지 않는다. 독립 그룹 이진 관측일 때만 단측 95% 상한 `1-0.05^(1/n)`을 보조 표시한다. 임상 안전성 인증이나 자동 배포 승인으로 해석하지 않는다. 처리시간·모델 크기·학습 진행률은 이 성능 판단의 점수에 넣지 않는다.

## 7. 실행 순서와 실패 처리

1. **과제 동결:** 현재 스키마·프롬프트와 학습 과제를 대조한다. 옛 6종 행동 라벨을 현 앱 출력에 억지로 적용하지 않는다. 대상 checkpoint와 기준 모델, 역할별 매핑을 지정한다.
2. **데이터 검사:** 그룹 누출·표본·gold·동의/사용 범위·test 노출 이력을 검증한다. 학습용 패키지에서 test가 제외돼 있는지 해시로 확인한다.
3. **평가기 검증:** 8절의 계산·실패·독립성 검사를 모두 통과시킨다. 여기서는 모델 호출이 필요 없다.
4. **dev 파일럿:** 허용된 로컬 환경에서 기준/후보를 돌려 정답 정의·score 경로·예산·임계값을 확정한다. 다른 로컬 모델의 결과를 31B 후보 결과로 대체하지 않는다.
5. **test 단일 실행:** 모든 사례를 고정 순서/seed로 배정하고 최초 시도부터 기록한다. 원본 점수 평가에는 자동 수정 결과를 덮어쓰지 않는다. 시스템 평가는 동결한 복구 정책의 마지막 결과를 별도 저장한다.
6. **맹검 검토 및 집계:** 최초/최종 출력, 모델 단독/앱 전체, 대표/어려운 패널을 분리 집계한다. 미실행은 실패와 구분해 남기고 최종 비교는 모든 배정 기록이 완성된 뒤 확정한다.
7. **재현과 보고:** 원시 예측만으로 집계를 재생성하고 독립 계산값과 대조한다. 후보 채택은 이 결과와 남은 오류를 검토한 뒤 별도 결정한다.

실패 상태는 `format_error`, `empty_output`, `length_limit`, `transport_error`, `model_error`, `identity_mismatch`, `not_run` 등을 고정한다. 신원 불일치는 해당 실행의 효력을 없애며 누락을 숨기지 않는다. 모델의 의미적 기권은 `ABSTAIN`으로 기록하고 coverage·기권 포함 성능을 함께 보고한다. 주 출력에 보류 라벨이 없는 과제에서는 ABSTAIN은 정답 클래스 FN이다. 품질이 나쁘다는 이유로 재생성해 최초 결과를 교체하지 않는다.

## 8. 평가 방법 자체의 검증 계획

아래는 구현 후 통과시켜야 할 검사다. v2에서 추가한 사례도 현재는 계산·계약 검증 명세이며 실행기 구현 완료가 아니다. 이 문서 작성으로 통과했다고 간주하지 않는다.

| 검사 | 입력 또는 조작 | 기대 결과 |
|---|---|---|
| 이진 지표 산술 | TP=2, FP=1, FN=1, TN=2 | P=R=F1=2/3, specificity=2/3 |
| Macro와 Micro 구분 | 정답 A,A,A,B; 예측 A,A,A,A | F1 A=6/7, B=0; Macro=3/7, Micro=3/4 |

| 잘못된 거절 이유 | 오류 초안 2건 중 올바른 이유 거절1·틀린 이유 거절1, 정상 초안2건 중 승인1·거절1 | 승인/거절 TP=2 FP=1 FN=0 F1=0.8; 근거일치 검출 recall=1/2; 정상 처리 실패율=1/2 |

| 사실 매칭 | 중복 예측, 화자 변경, 부정 반전, 빈 집합 | 일대일 매칭·추가 FP·속성 오류; 빈 실패에 통과 점수 없음 |
| 질문 생략 | 앞선 답변으로 불필요한 미응답 질문 vs 필요한 미응답 질문 | 전자는 생략 허용, 후자는 누락 오류; 둘 다 답변 조작 금지 |
| 검토 능력 | 정상 초안, 근거 없는 사실, 타당한 unknown, 잘못된 정정 | 정상 오거절과 오류 놓침 각각 검출; unknown 전용 라벨 적용 |
| 맹검·누출 | 모델명 노출, 같은 계보의 train/test 변형, 정답을 모델 입력에 혼입 | 평가 사전검사 실패 |
| 재시도·결측 | 최초 실패 후 성공, 미실행 1건, 중복 실행 ID | 최초/최종 분리; 미실행이면 미완료; 중복 집계 거절 |
| 재현·통계 | 같은 로그 재집계, 순서만 변경, 같은 bootstrap seed | 동일 점수·구간; 그룹 ID 정렬·paired 결속·보정 m 유지 |
| 변조 검출 | gold·prompt·checkpoint·출력 해시 한 개 변경 | 동결 불일치로 결과 확정 거절 |

수작업 예제와 별개로, 고정 버전 scikit-learn의 F1·AUROC·AP를 기준 구현으로 교차 계산한다. 단일 라벨 Micro의 INVALID 포함 라벨 집합과 Macro의 실제 정답 라벨 집합을 각각 전달하고, 프로젝트의 support=0 보류 규칙은 라이브러리 반환 후 별도 적용한다. 유한 값은 절대 오차 1e-10 이내, null/분모/라벨 순서는 정확 일치를 요구한다. 이 라이브러리는 향후 구현 선택이며 이번 문서 작업에서 새 의존성을 설치하지 않는다. 통계 구간은 seed·재표집 그룹 인덱스·유효 횟수를 보존한다.

## 10. 구현 착수와 완료 조건

현재 완료 범위는 기존 근거 확인과 평가 설계 문서다. 다음 단계는 **과제별 라벨 매핑·gold 지침 확정 → 평가기 및 산술 회귀검사 → dev 파일럿 → 동결된 독립 test → 사람 검토와 재현 보고**다.

문서 작성 단계에서 로컬 참조 링크의 존재, 표·코드 블록·절 구조를 검사했고, 8절의 AUROC=0.75·AP=5/6·Macro F1=3/7 예제를 별도 산술로 확인했다. 이는 향후 평가기 전체 검증이나 실제 모델 평가 완료를 의미하지 않는다.

평가 완료에는 해당 과제의 충분한 gold, 고정 모델 신원, 모든 배정 사례의 기록, 필요한 연속 점수, 사람 평가 완료, 집계 교차 검증이 필요하다. 점수 경로가 없는 환경에서도 F1·사실 추출·사람 품질 평가는 진행할 수 있으나 AUROC는 미측정으로 남는다. GPU 재허용·미사용 test 확보·사람 정답 검토가 필요한 단계는 그 조건이 갖춰지기 전 완료로 표시하지 않는다.

## 11. 지표 정의 참고자료

- [SciPy bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html): 재표집과 퇴화 분포의 한계.
- [SciPy 정확 비율 구간](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats._result_classes.BinomTestResult.proportion_ci.html): Clopper–Pearson 구간.
- [statsmodels 다중 검정](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html): Bonferroni 보정. 이 함수는 p값 보정용이며 본문의 구간 보정은 같은 오류율 배분 원리를 적용한 설계다.
- [scikit-learn F1 score](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.f1_score.html): averaging과 클래스별 집계.
- [scikit-learn ROC AUC score](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html): 연속 점수, 다중 클래스와 다중 라벨 입력 조건.
- [scikit-learn 임계값 선택](https://scikit-learn.org/stable/modules/classification_threshold.html): dev에서 임계값 선택 후 test에 고정.
- [scikit-learn 확률 보정](https://scikit-learn.org/stable/modules/calibration.html): 정규화 점수와 보정된 확률의 구분.
- [scikit-learn Average Precision](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html): AP 정의와 보간 PR 면적의 차이.

표본 규모와 내부 통과 기준은 위 라이브러리가 보증하는 표준값이 아니라 이 프로젝트의 평가 설계안이다.

## 12. v2 검토와 남은 확정 사항

2026-11-01 재검토에서 질문 스키마와 평가 매핑 불일치, INVALID의 Micro·음성 분모 누락, 작은 패널의 불가능한 최소 표본 조건, 실패 쌍의 선호도 해석, 불완전 gold의 FP 오판, 미정의 bootstrap 폐기와 다중 비교 누락을 보완했다. 모델 출력이나 앱 코드는 변경하지 않았다.

실행 전에는 과제별 실제 라벨·평가 허용 후보, gold 사실의 범위와 동의 표현 매칭, 확증 패널·m·표본수, 독립 그룹 정의, 점수 추출 지원을 확정해야 한다. 사람 검토 인력과 미사용 표본 확보 여부는 아직 미확인이다. 따라서 문서의 모순 보완과 실제 평가 착수 가능 판정은 구분한다.

보완 후 별도 검토에서 위 차단점 해소를 확인했다. 로컬 산술·문서 검사 14항목(F1, INVALID 포함 Micro, 거절과 근거일치 탐지 구분, 실패 분모, 유용성, 정확 비율 하한, 최소 표본 계산, AUROC 방향·동률, AP, 링크·절·공백·표 열 수)이 통과했다. 지정 Ollama 검토 API는 응답 시간 초과로 결과를 얻지 못했다. 따라서 별도 검토와 산술 검증은 완료했지만 Ollama 검토 완료로 기록하지 않는다.
