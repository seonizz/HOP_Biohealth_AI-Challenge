# 말씨 LLM 분류 출력 자동 검증

이 부록은 원본 31B·원본 12B·학습 후 31B의 **행동 분류 출력 형식·종료 상태·실제 토큰·출력 라벨 건수**를 원시기록에서 검증하는 방법이다. 형식 유효율은 분류 정확도가 아니며, 출력 라벨 분포는 모델이 생성한 코드의 관측 건수다. 의미상 적절성·상담 품질·안전성은 이 지표로 입증하지 않는다.

작성일: 2026-10-09. 현재 BASE12 공개 합성 회귀 31건(28개 상황 그룹)의 생성과 자동 집계를 완료했다. [최신 결과](outputs/presentation_automatic_20261009T132307Z/comparison.md) · [JSON](outputs/presentation_automatic_20261009T132307Z/metrics.json) · [CSV](outputs/presentation_automatic_20261009T132307Z/local_measurements.csv) · [재계산 코드](outputs/presentation_automatic_20261009T132307Z/verify_measurements.py) · [검증 결과](outputs/presentation_automatic_20261009T132307Z/verification.json).

같은 고정 원시파일에서 집계값을 재현할 수 있다는 뜻이며, 미래 생성 실행에서도 같은 결과가 나온다는 보증은 아니다. 환경에 따라 달라지는 응답 시간·처리속도·메모리는 발표 지표에 포함하지 않는다.

**모델 조건**

| 조건 | 모델 | 현재 상태 |
|---|---|---|
| `BASE31` | Gemma 4 31B IT · 학습 adapter 없음 | 동일 사례 출력 미수집 |
| `BASE12` | `google/gemma-4-12B-it`의 Ollama `gemma4:12b` · MLX NVFP4 | 로컬 생성·기계적 집계 완료 |
| `FT31` | Gemma 4 31B IT + 본학습 완료 adapter | 완료 증거·동일 사례 출력 미수집 |

BASE12 digest는 `c7597fc90b86aff6965317f37dd5465402284e26382d9b4bf2dfe3ef1491f4b6`이다. 로컬 배포 manifest의 해시이며 Google 원본 revision 연결은 미확인이다. Apple M5 32 GiB / Ollama 0.40.0 / MLX에서 실행했다.

BASE31/FT31은 같은 기반 가중치·tokenizer·채팅 템플릿·양자화 설정을 사용한다. FT31에는 본학습 완료 증거와 adapter 해시가 필요하며, 시험 학습·용량 검사 adapter는 사용하지 않는다. BASE12는 자체 tokenizer·템플릿과 배포 digest를 기록한다.

**출력 계약**

허용 행동 코드는 `ASK_CFI`, `CLARIFY`, `SUPPORT`, `SUPPORT_LIMITED`, `SAFETY_SUPPORT`, `END`다. 기존 행동 프롬프트를 그대로 사용한다. 출력 앞뒤 공백만 제거한 뒤 허용 코드 1개와 정확히 일치하는지 검사한다. 설명에서 코드를 추출하거나 여러 코드를 하나로 고치지 않는다.

선택 과제인 주제 출력의 허용 코드는 `ANXIETY`, `DEPRESSION`, `ADDICTION`, `OTHER`이며 현재 비활성이다. 허용 코드의 출력 빈도만 세고, 사례에 맞는 코드였는지는 판정하지 않는다.

**사례 고정과 실행**

1. `case_id`, `source_group_id`, 입력·사례 목록 해시, 생성 전 배정 N과 제외 사유를 기록한다. 같은 그룹의 변형을 서로 독립적인 표본처럼 해석하지 않는다.
2. 현재 시점까지의 대화만 입력에 넣는다. 미래 발화·평가 메모를 넣지 않는다. 실제 train/dev와의 중복 점검 및 개발용·공개 합성 범위를 기록한다.
3. 비교 조건은 같은 사례·의미상 동일 프롬프트·출력 예산을 사용한다. 각 tokenizer 길이를 실행 전에 검사하고 공통 예산 초과 사례는 전 조건에서 사전 제외한다. 출력 이후 사례를 제외하지 않는다.
4. 기본은 조건·사례당 첫 시도 1회다. 오류·timeout·형식 오류·길이 소진·누락은 전체 배정 N에 남긴다.
5. 원문 대화는 한 개의 직렬화된 사용자 메시지 자료로 전달한다. 대화 내부 명령을 시스템 지시문으로 승격하지 않으며 입력 변환을 조건 간 고정한다.

현재 결과는 공개 합성 회귀 자료이며 독립 test·실제 서비스 분포를 대표하지 않는다.

**생성 설정**

| 항목 | 공통 목표 / BASE12 실제 설정 |
|---|---|
| 샘플링 | 결정적 생성 목표 / Ollama `temperature=0` |
| 사고 모드 | 비활성 / `thinking=false` |
| 생성 예약 | 32토큰 |
| 전체 예산 | 입력 직렬화 + 생성 예약 ≤ 4,096토큰 |
| 배치·동시성·seed | 1 / 1 / 3407 |
| 종료 | 강제 EOS·추가 stop string 없음; 실제 종료 사유 기록 |
| 반복 | 조건·사례별 첫 시도 1회 |

실제 런타임별 설정과 해시를 남긴다. `do_sample=false`, `num_beams=1`은 지원하는 런타임의 공통 목표이며 Ollama에 전달된 옵션으로 주장하지 않는다. 입력 자르기를 허용하지 않는다. tokenizer가 다르면 토큰 수의 의미도 달라지므로 토큰 수만으로 모델 간 성능을 비교하지 않는다.

**자동 집계**

| 지표 | 계산 |
|---|---|
| 배정·실행 수 | 고정 사례 목록의 N과 연결된 첫 실행 기록 수 |
| 형식 유효율 | 정상 종료하고 단일 허용 코드를 출력한 건수/N×100 |
| 오류·형식 오류·길이 소진·누락 | 상태별 건수와 N 대비 비율 |
| 실제 토큰 | API 반환 입력·출력 토큰 합계·최소·최대 |
| 출력 라벨 분포 | 형식 유효 출력에서 코드별 관측 건수; 0건 코드 포함 |

미실행이 있으면 부분 결과로 표시한다. 오류·timeout·형식 오류·길이 소진·미실행을 N에서 빼지 않는다. 종료 사유와 실제 출력 해시를 함께 확인하며 정상 종료와 형식 유효를 구분한다.
