검증일: 2026-10-09 · 대상: 현재 학습용 3종 v1과 말씨 에이전트 사례 v2

- **범위 밖:** 비선정 원문 100만여 문장 전체의 의미 재라벨링, 전문가 검수, 실제 LLM 학습·응답 평가, 새 패키지 설치·외부 API 호출은 수행하지 않았다.

## 4. 말씨 본학습을 막는 사항

### M01. 학습 목표에 맞는 정답이 없다 — 사실·높은 확신

기존 세 단위의 입력은 `text`, 타깃은 `labels_multihot`이다. 3,131행 모두 현재 에이전트 스키마의 `prefix`, `target_response`, `decision`, `perspective`를 갖고 있지 않다. 상담 텍스트 안에는 상담사 발화가 있지만, 이를 말씨가 가족·주변인에게 제공할 승인된 답변으로 분리·검토한 것은 아니다.

별도 설계 사례 9개는 모두 합성 예시이며 `illustration_only`, `training_allowed=false`, `legacy_unverified`다. 실제 감사 결과 적격 0개, 내보내기 거절이며 출력 디렉터리도 생성되지 않았다.

**판단:** 질환 관련 텍스트를 분류하도록 학습하는 것만으로는 필요한 질문 선택, 질문 중단, 말 예시, 행동 안내, 거절 대응을 가르쳤다고 볼 수 없다. 파일을 chat JSONL로 포장하거나 승인 플래그만 바꾸는 것으로 해결되지 않는다.

### M02. 주변인 서비스에 필요한 주체·관계·행동 주석이 없다 — 사실·높은 확신

현재 문장 1,646개는 모두 `speaker=내담자`다. 상담사 응답 문장 학습셋이 아니다. 관계, 현재 요청, 도움받는 당사자, 사용자의 직접 관찰과 전언, 시점, 다음 행동, 대화 전략은 활성 분류 자료에 감독 정보로 연결되지 않았다.

표본에서 본인 경험, 제삼자 경험, 과거 상태와 현재 호전, 물질 사용을 부정하는 내용이 각각 확인됐다. 가족과의 연락·희망·관계 회복처럼 말씨에 필요한 내용은 ‘기타’에도 있다.

**판단:** 원문 내담자를 보호자로 바꾸거나, 과거·제삼자·부정 표현을 현재 사용자의 상태로 취급하는 변환은 적합하지 않다. 원천을 유지하면서 주변인 관점이 확인되는 사례를 선별하고, 각색을 한다면 새로 만든 사실과 원문 근거를 분리해야 한다.

### M03. 같은 네 가지 라벨이라도 의미와 신뢰도가 다르다 — 사실·높은 확신

| 단위 | 실제 타깃 의미 | 확인된 검토 상태 |
| --- | --- | --- |
| 상담 | 원본 class에 따른 코호트 | 새로 독립 판정한 진단이 아님 |
| 문장 | 문장에 표현된 정서·경험·물질 관련 주제 | 사람 검증 0/1,646. 독립 AI 재검토 표기 205/1,646, 약 12.5% |
| 단어 | 독립 어휘 의미·주제 단서 | 사람 검증 0/378. 기존 승인 단어의 독립 AI 재검토 출처 49개, 대기 단어 AI 검토 출처 329개 |

상담과 문장은 원천 상담 679개를 공유한다. 활성 상담과 원천 ID로 연결된 문장 1,643개 중 775개는 상담 코호트와 라벨 집합이 다르다. 이는 서로 다른 과제의 차이이며, 그 자체를 오류로 집계하거나 한 라벨로 덮어쓰면 안 된다.

예를 들어 흡연하지 않는다는 문장이나 술 관련 장소 이름도 중독 ‘주제’ 라벨에 들어간다. 이 계약에서는 가능하지만, 이를 사람의 중독 여부로 해석하면 잘못된 감독 정보가 된다. 원본 정의 미확정 수치 점수 역시 임상 강도·위험 점수로 바꾸지 않는다.

### M04. 통합 분할 전 원천 연결을 보완해야 한다 — 사실·높은 확신

단어 378개 전부에 원천 상담·대상자 연결이 없다. 어휘군 기준 분할은 되어 있지만 상담 단위의 학습·평가 독립성과 같지 않다.

**이번에 추가 확인한 사항:** `demo_01_observation_needed`의 입력과 목표 답변이 `demo_03_enough_after_answer`의 과거 대화와 정확히 연결된다. 같은 합성 시나리오의 연속인데 `source_root_ids`는 서로 다르다. 현재 둘 다 예시 split이라 실제 train/validation 누출은 없다. 그러나 향후 분할 전 동일 시나리오 계보로 묶어야 한다. 코드가 선언된 원천 ID를 검사한다고 해서 그 선언의 누락까지 자동 발견하는 것은 아니다.

문장과 상담 출력의 연결 예외 4개는 원천 손실이 아니었다. 3개는 같은 split·그룹의 동일본문 상담을 중복 제외한 경우이고, 1개는 코호트 공개 발화 전체를 상담 입력에서 제외한 경우다. 각각 보존된 대응 본문을 확인했다.

### M05. 서비스 범위와 데이터 분포가 충분히 입증되지 않았다 — 사실과 판단

문장 후보 2,400개 중 2,160개, 즉 90%는 우울·불안·중독 표현을 우선 검색한 후보였다. 최종 기타는 185/1,646, 약 11.2%다. 이 비율은 실제 서비스 이용자의 요청 분포가 아니다. 생성 학습에서는 공감, 관계 조율, 질문·거절, 보호자 부담과 경계 설정을 기타라는 이유로 더 줄이면 안 된다.

중독 라벨 문장 584개에 대한 중복 허용 키워드 진단은 다음과 같다.

**판단·중간 확신:** 음주·흡연 중심의 주제 자료로 도박·디지털 문제를 겪는 가족에 대한 안내까지 충분히 학습됐다고 볼 수 없다. 설계 사례 9개에 여섯 행동 코드가 모두 있더라도 관계·목적·하위 주제·위기 여부·대화 단계의 범위를 충족한 학습셋은 아니다. 설계 입력도 1개 또는 3개 메시지뿐이다.

### M06. 문항 양식에 의존하는 분류 가능성은 남는다 — 관찰 사실, 영향은 미확인

원문에서 확인한 문항형 표현 6종 중 2종 이상을 포함한 상담이 117건이며, 그중 107건은 불안 코호트다. 선택한 불안 상담 표본에서도 문항 낭독과 숫자 응답을 직접 확인했다.

이는 기존에 제거한 모집 코호트 공개 216개 발화와 다른 종류의 단서다. **현재 모델이 실제로 이 단서에 의존했다는 인과 증거는 없다.** 일반 대화 내용보다 문항 양식으로 분류하는지 확인하려면 해당 표현을 통제한 별도 비교 평가가 필요하다. 이번에 원문을 삭제하거나 라벨을 변경하지 않았다.

### M07. 실제 모델 학습 입력과 배치가 검증되지 않았다 — 사실·높은 확신

상담 입력 길이는 중앙값 23,223자, 최대 56,589자다. 모두 8,192자를 넘지만 **문자 수를 토큰 수로 환산하거나 특정 모델의 초과율로 해석할 수 없다.**

현재 도구에는 prefix 제한, 승인에 묶인 행 해시, 입력·이전 assistant·패딩의 손실 제외 기능이 있다. 그러나 선택한 기반 모델의 토크나이저, 채팅 템플릿, 실제 토큰 길이·배치·학습기 연결은 검증되지 않았다. 구조화된 상태 갱신 정답은 현재 학습 목표 출력에 포함되지 않으며 런타임 상태 갱신기도 미구현이다.

**판단:** 모델을 정한 뒤 전체 사례를 실제 템플릿으로 인코딩하고 목표 토큰 손실·길이 처리·작은 학습 배치를 확인해야 한다. 상담 전체를 항상 입력으로 넣으면 미래 발화가 섞이므로, 생성 학습에는 현재 사용자 턴까지 잘라 별도 목표 답변을 연결해야 한다.

### M08. 이용 근거·개인정보·응답 평가의 실제 완료 증거가 없다 — 사실과 미확인

현재 생성 사례의 원천 및 질문은행 레지스트리 10항목은 모두 미확인이다. 실제 안전 전문 승인 사례와 검증된 지역 자원도 없다. 이는 사용권 위반을 발견했다는 뜻이 아니라, 현재 프로젝트의 승인 조건을 충족하는 증거가 없다는 뜻이다.

활성 3,131행의 이메일·한국 휴대전화·주민등록번호 형태 정규식 탐지는 각각 0건이었다. 대체표기는 상담 1,101행과 문장 117행에 있었다. 이름·주소·간접 식별·서식이 다른 연락처까지 확인한 것은 아니므로 개인정보 제거 완료 판정은 하지 않는다. 주석 코드의 privacy 체크박스도 실제 검토를 대신하지 않는다.

공개 회귀 30개 집단·34개 실행 단위는 전부 미실행이다. 실제 모델 응답 평가 0개, 통과율은 null이다. 공개 개발용 사례를 독립 최종 평가셋으로 사용해서도 안 된다.

## 5. 기존 점수로 알 수 있는 것

저장된 TF-IDF/Naive Bayes 기준모델의 macro-F1은 상담 0.5535, 문장 0.7584, 단어 0.6213이다. 기존 실행 결과를 읽어 확인했으며 이번 작업에서 재학습한 수치는 아니다.

이 점수는 상담 응답의 도움 정도·사실성·안전성 점수가 아니다. 별도 test 분할도 없다. 상담 validation 117행은 관찰 대상자/그룹 23개에서 나온 것으로, 117명의 독립 사용자 평가라고 해석하면 안 된다. 실제 인물 ID의 완전한 유일성 역시 미확인이다.
