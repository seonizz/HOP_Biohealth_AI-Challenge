# 선별 전후 대표성과 검토 대기열

2026-10-16 · 원천·후보는 변경하지 않고 집계와 검토 입력을 준비했다. 모델 실행·성능·속도는 평가하지 않았다. **대표성 한계의 위치를 확인하고 검토 대기열을 준비했으며, 편중을 해소하거나 사람 정답을 확보한 것은 아니다.**

## 동일한 원천 순서로 비교한 결과

상담사로 매핑된 연속 발화를 하나의 응답 블록으로 센다. 초기 두 단계의 블록은 SFT 허용 행과 다르며, 상담·사람 수와 합산하지 않는다. 위치는 `target_end_ordinal / max(1, original_turn_count - 1)`이다. 분모는 선별된 행 수가 아니라 해당 원상담 전체 발화 수다. 전반부는 0.5 이하, 마지막 1/4은 0.75 초과다. 실제 상담 시간·임상 단계·회복 여부를 나타내지 않는다.

| 단계 | Train | Validation | 전체 블록/행 | 전반부 | 전반부 비율 | 마지막 1/4 |
|---|---:|---:|---:|---:|---:|---:|
| 로컬 적재 전체 1,462상담 | 179,518 | 22,829 | 202,347 | 101,396 | 50.11% | 50,675 |
| 현재 release 모집단 1,107상담 | 134,667 | 16,389 | 151,056 | 75,691 | 50.11% | 37,833 |
| 원본 SFT 휴리스틱 허용 | 40,652 | 5,322 | 45,974 | 24,936 | 54.24% | 9,497 |
| 내용·노출 기준 허용 | 40,415 | 4,289 | 44,704 | 24,222 | 54.18% | 9,266 |
| 현재 4,096 길이 후보 | 15,512 | 1,724 | 17,236 | 17,092 | **99.16%** | **1** |

**해석:** 같은 원천의 전체 접두부를 보존하는 조건에서 길이 선별 후 전반부 집중이 크게 늘었다. 후보에서 train 전반부는 15,371/15,512(99.09%), validation은 1,721/1,724(99.83%)로 v7 관찰과 일치한다. 마지막 1/4은 train 1행, validation 0행이다. 이 결과는 길이 기준을 임의로 완화하거나, 접두부를 잘라 후반부를 추가하거나, 보류 자료를 자동 승인할 근거가 아니다. 후반부 과업을 별도로 정의·작성·검토할 필요를 보여준다.

로컬 전체에는 문자열이 아닌 `paragraph_text` 2,855개를 포함한 **354상담**이 있다. 기존 적재는 원값을 `raw_json`에 보존하고 검색용 text를 빈 문자열로 유지한다. 원천 해시와 이 기존 적재 계약을 확인했다. 이 상담들은 현재 release 모집단과 후보 밖에 있으며 검토 큐에서도 제외했다. 전체 모집단 표에는 이런 기존 빈 문자열 블록도 포함되므로 1,107상담 표와 함께 해석한다. 큐에서 제외된 해당 상담의 상담사 블록은 51,159개다. 두 모집단 차이 355상담의 모든 제외 사유를 이 집계로 새로 판정하지 않는다.

아래 코호트는 원천의 `class`다. 새로 진단하거나 개인별 임상 상태를 검증한 값이 아니다. 행 단위 집계이므로 긴 상담이 더 큰 비중을 갖는다.

태그는 기존 `source_selection_audit.PATTERNS`를 그대로 재사용했다. 질문·지지·종료와 비슷한 표면 표현을 탐색하기 위한 것이며, 의미 검토를 마친 행동 정답은 아니다. 한 행이 여러 태그를 가질 수 있어 열 합은 행 수와 다르다.

후보의 종료 유사 표현 122개는 성공적인 종료 행동이나 실제 상담 후반부 122개를 뜻하지 않는다. 원천 단계·표현·실제 과업을 구분한 검토가 필요하다. split별 4분위·코호트·태그·고유 상담·그룹 수는 [원문 없는 로컬 집계](../../outputs/private/finals_source_review_20261016/summary.json)에 있다.

## 준비한 검토 작업

split × 원천 코호트 × 위치 4분위 × 선별 상태 × 대표 휴리스틱 태그의 **관찰된 검토 가능 층 391개**에서 각 1개씩 선택했다. 대표 태그 우선순위는 ending → support → question → other이며, 원래 중복 태그도 보존했다. 층마다 아직 선택되지 않은 원천 그룹·상담을 우선하고 ID 순서로 정하므로 입력 순서와 관계없이 재현된다. 새로운 집단의 유병률·서비스 성능을 추정하기 위한 무작위 표본은 아니다.

| 검토 위치 | 요청 수 |
|---|---:|
| 현재 후보 | 78 |
| 내용 허용이나 길이로 보류 | 114 |
| 내용·노출 보류 | 59 |
| 원본 SFT 휴리스틱 보류 | 127 |
| release 밖의 원문 문자열 확인 자료 | 13 |
| 합계 | **391** |

요청은 **298상담·180원천 그룹**에서 왔다. 큐는 원문 접두부·관찰된 상담사 응답·원래 화자·원문 위치·선별 사유·해시를 보존하며 전부 `review_pending`, `training_allowed:false`, `human_verified:false`다. 원천 상담사 응답은 주변인 지원 정답으로 승인하지 않았다. 기존 문장 주석 파이프라인의 `{context,context_hash}` 형식으로 **391개 오프라인 입력**을 준비했고, 별도로 **6개 주변인 과업 작성 요청**을 만들었다. 작성 요청의 정답·작성자·승인은 모두 비어 있다. [정답 작성·검토 계약](결선_데이터_검토계약_2026-10-16.md)에 기존 게이트와 불일치 처리 방법을 연결했다.

원래 문장 라벨 정의는 여전히 unresolved다. 새 사람 결정·사람 승인 정답은 **0건**이다. 큐를 준비했다는 사실로 정의·의미·사용 권한·임상 검토를 완료 처리하지 않는다.

## 입력·노출 이력과 재현

DB 전체 해시와 frozen 입력을 기존 `source_sft.load_inputs`로 확인했다. 기존 `evaluation_history.audit_history`로 실제 원천·내용 선별 재계산·길이 장부·후보 원본 행 바이트·사용 이력을 준비 전후에 검증했다. source/candidate 파일과 split은 수정하지 않았고 DB 크기·수정 시각도 동일했다. 파일별 해시와 입력 연결은 [manifest](../../outputs/private/finals_source_review_20261016/manifest.json)에 있다.
