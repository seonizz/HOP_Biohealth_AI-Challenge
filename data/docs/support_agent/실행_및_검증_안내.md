# 말씨 데이터·평가 실행 안내

2026-10-09 2차 적대적 검증까지 반영한 로컬 코드다. [2차 수정 결과](말씨_2차_검증_수정_결과.md)에 반례·정상 대조군과 실행 근거를 기록했다. 새 의존성, 모델 다운로드, 외부 AI 호출은 없다. 아래 명령은 저장소 루트에서 실행한다.

## 1. 생성 학습 데이터 감사와 내보내기

```sh
python3 -m counseling_pipeline.agent_training audit \
  --cases docs/support_agent/agent_cases.design.v2.jsonl \
  --source-registry docs/support_agent/source_use_registry.json \
  --output outputs/private/malssi_round2_20261009/agent_data_audit.json
```

현재 9개 행은 기존 합성 설계 예시를 변환한 자료다. 응답을 새로 승인하지 않았고 원래 예시도 보존했다. `structure_passed=true`와 `eligible_count=0`이 함께 나온다. 구조 통과를 학습 준비 완료로 해석하지 않는다.

변환 시 `demo_04_previous_words_unclear`의 `CLARIFY`에 붙어 있던 `Q16` 참조를 제거했다. Q16은 주변 사람이 권한 방법에 관한 질문이며, 사용자가 앞서 한 말을 확인하는 문항의 ID가 아니다. 변경 전 값과 이유는 해당 행의 `migration.field_corrections`에 남겼다.

원본에서 다시 변환하려면 기존 결과를 덮어쓰지 않고 새 경로를 지정한다.

```sh
python3 -m counseling_pipeline.agent_training migrate-design \
  --cases docs/support_agent/design_examples.jsonl \
  --output /tmp/malssi_design_migrated.jsonl
```

학습 내보내기의 필수 조건은 다음과 같다.

- `training_allowed=true`, 학습 또는 검증 split, 가족·주변인 관점.
- 현재 입력과 같은 prefix를 대상으로 작성했다는 주석 기록.
- 정확한 사례 해시에 연결된 독립 검토: 검토자, 시각, 기준 버전, 판단 이유와 항목별 검사.
- `risk_tags`, 안전 주행동, `safety_guidance`, `safety_subjects` 중 하나라도 안전 필요를 나타내면 관련 전문 검토와 안전 정책 버전.
- 원천별 사용 허용 범위의 검증 기록과 증거 파일 해시. 과거 대화·목표 응답·각색에서 사용한 자원의 목록, 버전·내용 해시·사용 위치 및 이용 근거도 필요.
- 모든 통제 가능한 보조학습·평가 경로의 원천/split 명세. 다른 경로를 사용하지 않는다면 그 사실을 확인하고 빈 명세를 제공한다.

검토 레코드의 최소 필드는 `case_id`, `case_sha256`, `status`, `reviewer_id`, `reviewer_type`, `reviewed_at`, `rubric_version`, `rationale`, `checks`다. 검사 항목은 `agent_training.REVIEW_CHECKS`에 있다. 사례 내용이나 split을 바꾸면 해시가 바뀌므로 이전 승인이 적용되지 않는다. 승인·거절 기록이 충돌하면 자동으로 마지막 기록을 채택하지 않고 제외한다.

`source_use_registry.json`은 원천 ID를 키로 사용하는 사전이다. 검증된 항목에는 `status=verified`, `local_training_allowed=true`, `verified_by`, `verified_at`, `evidence_path`, `evidence_sha256`이 필요하다. 증거 경로는 사전 파일의 디렉터리를 기준으로 해석한다. 현재 항목은 미확인 상태이며, 필드 채우기만으로 권리 검토를 실제 수행한 것이 되지는 않는다.

현재 사례 스키마는 `malssi-agent-case-v2`다. 모든 사례에 `resource_dependencies` 목록을 넣는다. 자원을 쓰지 않았으면 빈 목록이며, 사용했다면 `resource_id`, `version`, `content_sha256`, `used_in`을 기록한다. `used_in`은 `prefix`, `target`, `adaptation` 중 해당하는 위치의 목록이다. 해당 자원의 이용 근거 레지스트리에 기록된 버전·내용 해시와 일치해야 한다. 독립 검토의 `checks.resource_dependencies`도 필수다.

질문은행 문구를 과거 대화나 목표 응답에서 재사용하면 현재 행동이 SUPPORT여도 검사한다. 알려진 전체 문구와 충분히 구체적인 완결 문장의 정확한 재사용은 공백·유니코드 정규화 후 탐지하며, 메시지를 나눈 재사용도 검사한다. 의미를 바꾼 각색이나 외부 자원의 누락까지 자동 발견한다고 보장하지 않는다. 작성자 목록과 독립 검토가 필요하다. 공통 질문은행·정책·템플릿은 `resource_dependencies`에, 상담과 파생 사례의 연결은 `source_root_ids`에 기록한다. 공통 자료 사용만으로 무관한 상담의 split을 합치지 않는다.

기존 `agent_cases.design.jsonl`은 v1 이력으로 보존했다. v2 이행에는 자원 목록과 새 사례 해시에 묶인 검토가 필요하므로 기존 승인을 자동 승계하지 않는다. 현재 v2 설계 예시 9개 역시 학습 허용은 0개다.

외부 노출 명세는 JSONL이며 각 행에 `source_root_ids`와 `split`을 넣는다. 여러 상담을 섞은 사례는 모든 원천 ID를 기록한다. 원천이 같은데 split이 다르거나 원천을 추적할 수 없는 행은 오류다. 기존 단어 분할을 원천 독립적인 생성 평가 분할로 자동 간주하지 않는다.

실제 승인 자료가 준비된 뒤 사용하는 명령 형식:

```sh
python3 -m counseling_pipeline.agent_training export \
  --cases /absolute/path/cases.jsonl \
  --reviews /absolute/path/reviews.jsonl \
  --source-registry /absolute/path/source_use_registry.json \
  --exposures /absolute/path/all_other_training_and_evaluation_exposures.jsonl \
  --output /absolute/path/new_release
```

승인 자료가 0개면 오류로 종료하며 빈 파일을 학습 완료물로 만들지 않는다. 내보내기는 기존 디렉터리도 덮어쓰지 않는다. 자료의 승인 상태는 실제 검토 사실을 반영해야 한다. 코드는 검토자 신원·자격의 진위를 인증하지 못한다.

## 2. 입력 시점과 손실 마스크

`prepare_prefix`는 지정한 사용자 턴까지의 발화만 반환한다. `annotation-view` 명령은 주석자에게 기존 정답·행동·미래 내용을 숨긴 입력을 만든다. 과거 설계 예시는 당시의 열람 범위 증거가 없어 `legacy_unverified`로 보존했다.

```sh
python3 -m counseling_pipeline.agent_training annotation-view \
  --cases docs/support_agent/agent_cases.design.v2.jsonl \
  --output /tmp/malssi_annotation_views.jsonl
```

모델 입력에는 고정 서비스 지시와 현재까지의 원문 대화만 직렬화한다. 주석자가 만든 목적·상태 요약, 검토 내용, 정답 행동은 입력에 넣지 않는다. 목표 assistant 출력에 다음 행동, 응답 구성 요소, 질문 ID, 사용자에게 보여줄 응답을 넣는다.

`load_training_release`는 내보낸 파일·행·승인·split 해시를 검사하고 `(rows, manifest)`를 반환한다. `build_token_batch`는 이 manifest를 필수 인자로 받아 직렬화된 행을 다시 검사하므로 로딩 뒤 목표 응답이 바뀌어도 거절한다. 모델별 채팅 형식에 맞춘 인코더를 인자로 받으며 사용자 입력과 이전 assistant 발화, 패딩은 `-100`으로 가리고 마지막 목표 assistant에만 손실을 적용한다. 길이가 넘으면 조용히 자르지 않고 거절하며 여러 사례를 이어 붙이지 않는다.

현재 테스트 인코더는 합성 토큰을 사용한다. **실제 기반 모델의 토크나이저·채팅 템플릿·학습 배치는 아직 검증하지 않았다.** 모델별 어댑터 검증과 실제 토큰 수 측정은 기반 모델 선정 후 필요하다.

## 3. 응답 정책과 평가의 범위

[응답 정책](response_policy.json)은 `primary_action`과 `response_components`를 구분한다. 지원하면서 필요한 확인 질문을 함께 하는 응답을 표현할 수 있다. 질문의 필요 이유, 제한된 지원의 한계, 안전 우려의 주체를 별도로 기록한다. 모름·거절·정정과 여러 사람의 상태를 다루는 규칙도 명시했다.

정책은 주석·검토 기준이며 실제 모델의 준수를 증명하지 않는다. 현재 런타임 상태 갱신기, 운영 로그 접근 통제, 삭제 전파, 지역별 긴급 자원과 전문 승인 절차는 완성되지 않았다. 구조 검사를 통과해도 이 항목들이 검증됐다고 표시하지 않는다.

회귀 시험은 [평가 프로토콜](evaluation_protocol.json)과 [시험 사례](adversarial_cases.jsonl)를 사용한다. 실제 생성 결과와 해당 결과에 연결된 독립 검토가 없으면 미실행 또는 검토 대기다. 자동 구조 검사와 상담 응답의 의미·안전성 평가는 분리한다.

평가 프로토콜 v2는 집단마다 실행 단위가 있어야 하며, 선언된 집단 종류·실행 ID·미래 변형 구성을 검사한다. 조건별 확정 실패는 다른 조건의 불확실성과 함께 보존한다. 같은 조건에 대한 실패/통과 의견 충돌은 미확정으로 남는다. T30의 JSON 비교는 불리언과 숫자를 구별하고 객체 키 순서는 무시한다. 프로토콜 해시가 바뀌었으므로 이전 프로토콜에 묶인 검토는 재사용할 수 없다.

## 4. 검증 명령

기존 분류 패키지 전체 감사는 다음과 같이 실행한다. `--independent-only`는 개별 분류 무결성만을 통과 조건으로 사용하며 통합 생성 학습 준비를 승인하지 않는다. 이 옵션을 빼면 전체 경로 게이트가 미충족인 현재 자료는 종료 코드 1을 반환한다.

```sh
COUNSELING_PYTHON=/Users/chihun/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
"$COUNSELING_PYTHON" -m counseling_pipeline.release_audit \
  데이터셋/학습용_3종_v1_20261009 \
  --database outputs/private/corpus.sqlite \
  --independent-only \
  --output outputs/private/malssi_round2_20261009/release_audit.json
```

분류 입력을 읽을 때는 동결 패키지의 기존 로더 대신 검사 경로를 사용한다.

```python
from counseling_pipeline.release_audit import load_checked_unit
X, y, weights, rows = load_checked_unit("데이터셋/학습용_3종_v1_20261009", "sentence", "train")
```

미실행 평가 상태를 집계하거나 실제 실행·검토 기록을 입력하는 명령:

```sh
python3 -m counseling_pipeline.agent_evaluation \
  --output outputs/private/malssi_round2_20261009/adversarial_evaluation.json
python3 -m counseling_pipeline.agent_evaluation --template /tmp/malssi_records.jsonl
# 실제 실행과 독립 검토 후 작성한 기록에 사용:
# python3 -m counseling_pipeline.agent_evaluation --records /absolute/path/records.jsonl --output /absolute/path/report.json
```

전체 Python 테스트는 기존 NumPy가 설치된 런타임에서 실행한다.

```sh
COUNSELING_PYTHON=/Users/chihun/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
"$COUNSELING_PYTHON" -m unittest discover -s tests -v
```

일반 `python3`에 NumPy가 없으면 일부 기존 테스트가 건너뛰어진다. 이 결과를 전체 검사 통과로 보고하지 않는다. 모델 출력 평가와 코드 회귀 테스트의 결과도 각각 기록한다.
