## 1. 입력과 수정 전 재현

- [사용자가 제공한 2차 보고서 원본](말씨_2차_적대적검증_원본_2026-10-09.md)을 별도로 보존했다.
- 제공 재현 ZIP의 SHA-256은 `ef3cd3cd29e2570c883a556ad940647c220bedf49fea6a2a40b73a2e42f3c70d`다. 선언된 178개 payload의 해시를 확인했다.
- 기존 검증 ZIP을 별도 폴더에 풀고 첨부 실행기를 실행했다. 기존 105개 테스트와 8단계 실행 결과가 제출 버전의 예상 종료 코드와 일치했으며 원본 payload 77개는 바뀌지 않았다.
- 합성 반례의 승인·자격·사용 허가·모델 응답은 인공 입력이다. 실제 전문가 승인이나 사용권 검토로 채택하지 않았다.
- 수정 전 결과: `outputs/private/malssi_round2_20261009/before/reproduction_summary.json` 및 그 하위 분야별 결과. 현재 수정 근거: [검증 요약 JSON](remediation_round2_verification.json).

문장·단어 단위는 원천 상담 한 건에서 여러 행이 나올 수 있다. F04의 전체 상담 유일성 규칙을 이들 행에 그대로 적용하지 않는다. 생성 후보 수·보류 수 등 다른 단계의 건수를 최종 내보내기 건수와 억지로 같게 만들지도 않는다.

F05의 자동 탐지는 알려진 질문은행의 정확한 문구 재사용에 한정된다. 의미를 바꾼 각색, 임의의 짧은 조각, 목록에 없는 외부 자원의 출처까지 자동으로 알아내지는 못한다. 작성자의 자원 목록과 내용에 묶인 독립 검토를 함께 요구하며, 이를 출처 완전성이나 법적 허가의 자동 인증으로 표현하지 않는다.

## 3. 버전과 파일 변경

- `counseling_pipeline/agent_training.py`: 사례 v2, 자원 목록·사용 위치·버전·해시, 안전 검토 조건, 주장·안전 주체 검사.
- `counseling_pipeline/agent_evaluation.py`: 조건별 집계, 집단 구성 검증, 타입을 보존하는 T30 비교.
- `counseling_pipeline/release_audit.py`: 상담 원천 유일성과 manifest 건수 대조.
- `counseling_pipeline/evaluation_audit.py`: 실제 수치화 폴더 기준 매핑 경로.
- 관련 기존 테스트 4개 파일과 `tests/test_agent_training_round2.py`에 반례·정상 대조군을 반영했다. 전체 테스트 수는 105개에서 129개로 늘었다.
- [실행 안내](실행_및_검증_안내.md), 서비스 계약·준비 상태·응답 정책, 평가 프로토콜과 현재 데이터셋 포인터를 갱신했다.

현재 사례는 `malssi-agent-case-v2`, 평가 프로토콜은 `malssi-public-regression-v2-20261009`다. 기존 v1 사례는 이력으로 보존했으며 최신 설계 사례는 `agent_cases.design.v2.jsonl`이다. 사례 내용과 프로토콜 해시가 바뀌므로 기존 승인·검토를 자동 승계하지 않는다. 실제 사용권 레지스트리는 여전히 미확인 상태다.

## 5. 아직 완료하지 않은 범위

말씨에 실제로 승인된 생성 학습 사례와 실제 모델 응답 평가는 이번에도 추가되지 않았다. 실제 전문가의 안전 정책 검토, 원천·질문은행 이용 근거, 기반 모델 토크나이저·배치 검증, 운영 상태 갱신·개인정보 처리와 모델 비교 평가는 남아 있다. 단어 378개의 원천 상담 연결이 없어 통합 학습·평가 경로 게이트도 계속 미통과다.

다음 검증 ZIP에는 현재 코드·테스트·문서와 수정 전후의 검사 근거를 넣는다. 원본 상담 DB·실제 상담 텍스트 JSONL·NPY/NPZ는 제외한다. 따라서 수신자는 합성 반례와 코드 검사를 재현할 수 있지만, ZIP만으로 실제 3,131행의 재계산을 독립 재현할 수는 없다. 그 결과는 로컬에서 수행해 기록한 증거로 구분한다.
