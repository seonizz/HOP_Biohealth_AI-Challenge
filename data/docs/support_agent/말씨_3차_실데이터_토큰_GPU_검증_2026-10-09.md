## 2. 추가로 발견해 반영한 내용 노출

## 3. 실제 Gemma 템플릿과 마지막 응답 손실

고정 템플릿 SHA-256은 `845f1ee48e39fc942fe190da9df6a1c5db229e17a96ea08966ad1c9274e73d1b`다. 이 템플릿은 완성된 assistant 메시지의 직렬화와 비사고 모드의 생성 접두 구간이 다르다. 후자는 빈 thought 채널을 포함하므로 단순한 native full/prefix 비교는 **45,974행 모두 불일치**했다.

`gemma4_token_validation.py`에서 공식 생성 접두 구간에 공식 완료 응답을 역할 경계로 연결하는 명시적 직렬화 경로를 추가했다. 목표 문장 검색으로 위치를 추정하지 않는다. 원본 메시지 객체는 그대로 두며 템플릿의 경계 공백 정리는 별도로 기록한다. 이 경로는 고정한 템플릿 해시에만 허용한다. [Gemma 비사고 모드 설명](https://ai.google.dev/gemma/docs/capabilities/thinking)

검증 결과:

- **45,974행 모두** 실제 토큰화, 생성 접두 토큰의 정확 일치, 마지막 목표에만 라벨 부여, collator의 입력·라벨·attention 및 패딩 검사를 통과했다. 과거 assistant, user, system과 패딩의 라벨은 `-100`이다.
- 라벨을 미리 shift하지 않는다. 설치된 causal loss API의 loss를 수동 1회 shift 계산과 수치 비교하고 무시된 위치의 gradient가 0임을 확인했다. 이 수치 대조는 설치된 loss API fixture이며 Gemma의 fused loss 전체를 별도 수식으로 재구현한 검사는 아니다.
- 같은 목표의 반복, 과거 assistant 여러 개, 첫 발화가 assistant인 경우, 제어 토큰, 불리언 마스크, 목표 절단·초과 길이, 패딩을 회귀 검사했다. 실제 자료 중 첫 역할이 assistant인 행도 38,192개가 성공했다.
- packing과 암묵적 truncation은 거부한다. `assistant_only_loss`만 켜서 과거 assistant까지 감독하는 경로를 사용하지 않는다. [TRL 손실 범위 문서](https://huggingface.co/docs/trl/sft_trainer)
- 비용을 줄이기 위해 1,069개 상담별 최장 예시의 공식 템플릿을 검증한 뒤, 모든 짧은 예시가 정확한 메시지 prefix일 때만 직렬화를 재사용했다. **각 행의 실제 토큰화와 경계·collator 검사는 생략하지 않았다.** 기존 행별 경로의 8,768행 통계도 재사용 경로와 같았다.
- Transformers **5.19.0과 실제 Unsloth 환경의 5.17.0에서 각각 전수 실행**했다. 45,974행의 통계·경계 결과가 완전히 같았다. 두 환경의 전체 token/label 배열 일치는 길이 256~16,384의 대표 7행에서 별도 확인했다. 모든 행의 배열을 두 버전 사이에서 저장·직접 비교했다고 주장하지 않는다.

자유 생성에는 마지막 정답을 제외한 `prefix_text`만 사용한다. 이번에는 실제 자유 생성의 품질을 평가하지 않았다. [전수 검사](../../outputs/private/malssi_round3_20261009/remote/tokenizer_training_env/audit.json), [버전 대조](../../outputs/private/malssi_round3_20261009/remote/tokenizer_cross_version_equivalence.json)

검증 전체에서 성공한 순전파·역전파는 **10회**이며 7,670토큰 예시는 첫 실행에서 OOM으로 중단됐다. 이후 별도 실행으로 정확히 4,096토큰인 예시를 다시 확인했다. 성공한 loss와 LoRA gradient는 유한했고 gradient 410개 텐서가 0이 아니었다. LoRA 가중치 해시는 각 실행 전후 같았고 옵티마이저 step은 0회였다.

4,096 예시의 501.2토큰/초를 후보 Train의 총 토큰량에 단순 적용하면 1회 순회가 약 **17시간**이다. 이는 실측 전체 학습 시간이 아니며 속도·메모리 여유·하루 내 완료를 보장하지 않는다. 옵티마이저 상태 메모리도 할당하지 않았으므로 **4,096의 실제 전체 학습 적합성은 미검증**이다. 7,670 OOM을 모든 31B 설정의 불가능성으로 일반화하지도 않는다.

| 문장·단어 역할 | 문장은 문맥 복원·사례·품질/중복 검사, 단어는 연관 표현 탐색으로 유지 | 보조 예측 과제·가중치의 검증; 이번 생성 손실에는 혼합하지 않음 |

길이만 이유인 보류에는 질문 휴리스틱 22,586개, 지원 휴리스틱 2,658개, 종료 휴리스틱 175개가 포함됐다. 태그는 중복될 수 있으며 사람 승인 수량이 아니다. 길이 규칙을 무조건 없애거나 AI 표본만 보고 일괄 승격하지 않았다. 상세 표와 근거는 [selection audit](../../outputs/private/malssi_round3_20261009/selection_audit.json)에 있다.

이번에 수행하지 않은 것은 실제 SFT 업데이트, B0/B1 성능 비교, 자유 생성 평가, 모델 자체 이력의 다턴 회복 평가, 임상·전문가 전수 승인, 원천 이용 조건의 법적 확정이다. 24개 감정/HOP 주석과 합성 초안의 승인 상태를 바꾸지 않았다. 현재 후보의 `model_training_authorized=false`, `hop_readiness=false`, `optimizer_fit=unknown`도 유지한다.

## 7. 검증·재현 자료

전체 로컬 회귀 테스트 **250개 통과**. 독립 검토에서는 원본 45,974행을 다시 대조하여 출력 17,236행의 원본 JSONL 바이트·순서·ID·split 보존, 보류 재유입 0행, 압축·비압축 SHA와 길이 제한을 확인했다. 새 선별/출력 관련 24개 테스트는 일반 실행과 `python -O` 모두 통과했다.

핵심 코드는 `source_selection_audit.py`, `source_admission.py`, `gemma4_token_validation.py`, `token_admission.py`, `scripts/malssi_tokenizer_audit.py`, `scripts/malssi_gpu_validation.py`다. 실패/중단 로그와 성공 로그를 함께 보존했다. `remote/tokenizer_full`은 성능 개선을 위해 8,768행에서 중단한 최초 시도이며 완료 근거는 `remote/tokenizer_training_env`다.

로컬 회귀 검사:

```sh
python -m unittest discover -s tests -v
```

기존 전체 테스트는 NumPy가 설치된 Python이 필요하다. 새 토큰·선별·출력 단위 테스트는 표준 라이브러리 fixture를 사용한다. 원본 데이터와 실제 모델을 포함한 재현에는 기존 v1 데이터·서버 체크포인트가 별도로 필요하다. ZIP은 체크포인트, 12GB DB, 기존 892MiB 전체 3종 자료를 중복 포함하지 않는다.

새 출력 폴더를 지정해 후보를 재생성한다:

```sh
python -m counseling_pipeline.token_admission \
  --release 데이터셋/말씨_원본상담_SFT_v1_20261009 \
  --admission-policy outputs/private/malssi_round3_20261009/admission_policy.json \
  --admission-rows outputs/private/malssi_round3_20261009/admission_rows.jsonl.gz \
  --tokenizer-audit outputs/private/malssi_round3_20261009/remote/tokenizer_training_env/audit.json \
  --row-lengths outputs/private/malssi_round3_20261009/remote/tokenizer_training_env/row_lengths.jsonl.gz \
  --output outputs/private/malssi_round3_reproduced --cap 4096 --export-source-rows
```

실제 서버 실행 명령·가상환경 freeze·정확한 파일 지문은 검증 묶음에 포함했다. 보고서의 수치와 코드 검사는 현재 산출물에 한정되며 앞으로 다른 모델 revision, 템플릿, packing, 길이, LoRA/optimizer 설정을 쓰면 해당 경계를 다시 검증해야 한다.
