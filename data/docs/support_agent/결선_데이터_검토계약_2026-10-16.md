# 주변인 목적 정답 작성·검토 계약

2026-10-16 · 상태: **과업·검토 절차 정의 및 대기열 준비. 사람 승인 정답은 새로 만들지 않음.**

현재 17,236행은 원래 내담자 맥락에서 상담사의 다음 발화를 학습하기 위한 후보다. 원문 대응과 분할 검증이 통과해도, 가족·친구에게 첫마디·행동·자기돌봄을 안내할 정답이 확보됐다는 뜻은 아니다. 원천의 내담자를 보호자라고 바꾸거나 원래 상담사 발화를 주변인 지원 정답으로 이름만 바꾸지 않는다.

## 작성할 과업과 정답 단위

기존 [응답 정책](response_policy.json), [agent_training](../../counseling_pipeline/agent_training.py)의 `malssi-agent-case-v2`와 6개 행동 코드를 사용한다. 새 작성 요청 6건은 로컬 `agent_authoring_requests.jsonl`에 있으며 `prefix`, `target_response`, 작성자·검토는 비어 있는 `authoring_pending`이다. 이 요청 파일은 학습 사례 파일이 아니며 exporter에 전달하지 않는다.

| 주목적 | 입력에 있어야 할 근거 | 정답 작성·검토 기준 |
|---|---|---|
| `ASK_CFI` | 답에 따라 지금 제안할 도움이 달라지는 누락 정보 | 기존 질문은행 Q01~Q17 중 한 질문과 필요 이유. 이미 모름·거절한 내용을 반복하지 않음 |
| `CLARIFY` | 주체·시점·실제로 한 말 등 결정에 필요한 모호함 | 질문은행 밖의 필요한 확인 한 개. `question_id:null`, 추측을 사실로 채우지 않음 |
| `SUPPORT` | 이용자의 목표와 알고 있는 장면, 당사자 의향·반응의 확인 범위 | 이용자가 건넬 구체적 첫마디, 가능한 행동, 본인의 부담·경계 중 요청에 맞는 구성. 동의·거절 선택 보존 |
| `SUPPORT_LIMITED` | 모름·공개 거절·부족한 정보 | 확인할 수 없는 점을 밝히고 아는 범위의 말·행동을 제안. 모름을 치료·위험 부재로 해석하지 않음 |
| `SAFETY_SUPPORT` | 누구의 현재 위험인지, 전언·부인·과거와 현재의 구분 | 별도로 승인된 안전 정책과 자격 근거가 있는 전문가 검토 필요. 준비만으로 안전 절차·연락처를 승인하지 않음 |
| `END` | 이용자의 종료 의사와 남은 위험 맥락 | 새 질문·과제 없이 종료. 급박한 위험과 함께 나타난 경우 기존 응답 정책의 우선순위 적용 |

사례 하나는 **사용자 발화로 끝나는 보이는 접두부와 바로 다음 응답 하나**다. 정답의 판단에 미래 발화·기존 결과·원상담 전체의 결론을 사용하지 않는다. 문장별 오프라인 주석에 포함되는 인접/미래 발화는 이 접두부에 복사하지 않는다. 주장마다 주체·시점·출처·상태와 원문 문자 위치를 남긴다. 원천 코호트·키워드 태그를 진단이나 의미 정답으로 사용하지 않는다.

## 정답 출처와 분할

- 실제 주변인 대화를 사용할 때는 그 관점이 입력 자체에서 확인돼야 한다. `observed_source_dialogue`와 모든 원천 root·group·split·허용 근거를 기록한다.
- 원천에서 새 상황을 구성하면 `adapted_from_source`와 모든 원천 연결을 남긴다. 구성한 부분을 관찰 사실처럼 표시하지 않으며, 기존 원천의 역할·분할·정답 파일을 수정하지 않는다.
- 독립 창작은 `synthetic_scenario`와 별도의 합성 root를 사용한다. 원천 상담을 복사한 뒤 synthetic으로 바꾸지 않는다. 기존 설계 예시는 illustration 상태를 유지한다.
- 실제 사용한 질문은행·외부 정책 등은 `resource_dependencies`에 버전·내용 SHA-256·사용 위치를 선언한다. 기존 `source_use_registry`의 증빙 파일·해시·검증자·시각·허용 범위를 확인해야 한다.
- 원천 root가 연결된 파생물은 기존 split을 유지한다. 개발 노출을 이름 변경이나 재압축으로 지우지 않는다. 검토 대기열 준비 자체의 데이터 선별 이력도 기록한다. 독립 test로 승격하지 않는다.

## 검토자 판정과 불일치 처리

1. 작성자는 보이는 접두부와 그 해시에 결합해 사례를 작성한다. 작성 완료 전 `training_allowed:false`를 유지한다. `validate_case`와 `annotation-view`로 형식·원문 위치·미래 제외를 확인한다.
2. 작성자와 다른 실제 검토자가 같은 접두부에서 먼저 독립 판단한 뒤 정답과 비교한다. 관점, 사실·근거, 접두부만 사용, 행동 적합성, 자율성·경계, 안전·범위, 실행 가능성, 개인정보, 자료 출처의 **9개 기존 `REVIEW_CHECKS`**를 모두 판정한다. 기록에는 실제 신원, 역할, 시간대가 있는 시각, rubric 버전, 근거, 전체 case SHA-256을 남긴다.
3. 역할 전환, 미래 의존, 근거 없는 사실, 강압·감시, 의학적 단정, 해결되지 않은 권한·출처는 보류 또는 거절 사유다. 위험 태그·안전 행동은 자격 근거와 안전 정책 버전이 있는 `domain_expert`가 검토해야 한다. AI 검토는 사람 승인으로 기록하지 않는다.
4. 두 검토자의 판정이 다르면 원래 의견과 근거를 로컬 append-only 기록에 모두 보존하고 보류한다. 실제 조정 담당자가 원문과 쟁점을 다시 확인한다. 사례를 수정하면 해시가 바뀌므로 재검토한다. 기존 `eligibility_reasons`는 같은 해시에 복수 최종 판정을 넣으면 `ambiguous_review_decision`으로 보류한다. exporter의 `--reviews`에는 논쟁 기록을 숨겨 덮어쓰는 대신, 별도 의견 이력에 연결한 **해시당 하나의 최종 조정 판정**을 전달한다. unresolved/uncertain은 approved가 아니다.
5. 검토 통과와 사용 권한 근거가 모두 생긴 후에만 검토 대상 사례의 학습 허용 여부를 확정하고, 그 최종 내용·메타데이터·허용 플래그를 포함하는 해시로 승인을 다시 결합한다. 기존 `audit`와 `export --exposures`를 통과해야 학습 파일이 생성된다.

`agent_dataset.py`의 AI draft 경로는 합성 시나리오와 별도 AI 검토를 전제로 한 실험용 경로다. 실제 상담의 주변인 역할 전환이나 독립 사람 승인 게이트를 우회하는 데 사용하지 않는다.

## 준비된 검토 대기열 사용

[로컬 준비 폴더](../../outputs/private/finals_source_review_20261016/)에는 다음이 있다. 발화·ID·원문 위치는 Git 제외 경로에만 보관한다.

| 파일 | 용도·현재 상태 |
|---|---|
| `source_review_queue.jsonl` | 원문 내 상담사 응답과 미래 없는 접두부, 원래 화자·분할·원천 해시, 선별 위치·사유를 묶은 층화 검토 요청. 모든 행 `review_pending`, 사람 승인·학습 허용 false |
| `annotation_batch.jsonl` | 기존 `annotations.context`가 만든 `{context,context_hash}` 입력. 같은 corpus의 sentence ID로 기존 import 흐름에 연결 가능. 인접/미래 발화가 포함되는 오프라인 용도 |
| `agent_authoring_requests.jsonl` | 위 6개 주변인 과업의 작성 대기 요청. 정답·작성자·승인은 없음 |
| `summary.json`, `manifest.json` | 원문 없는 선별 전후 집계, 파일 SHA-256, 입력 결합과 완료 상태 |
| `evaluation_history_events.jsonl`, `evaluation_history.json` | 기존 사용 이력을 보존하고 이번 선별의 개발 노출을 추가한 검증 기록 |

현재 수치 라벨 사전은 `scale_status:unresolved`다. 기존 문장 주석 jobs도 `definition_unresolved`이며 실제 생성·검증·사람 결정은 0건이다. 따라서 준비한 annotation context를 수치 정답으로 수용하거나 `ai-batch`의 정의 게이트를 해제하지 않는다. 공식 의미를 확인한 별도 버전의 정의가 생긴 뒤 기존 `prepare-ai`/generation/verification/human import 절차를 따른다. 기존 확정 라벨이나 실제 AI 실행 기록을 새로 만들지 않았다.

현재 완료는 비교 가능한 집계·검토 입력·재현 경로다. 실제 사람 검토, 주변인 정답 작성, 안전 전문가 판정, 사용 범위 증빙은 외부 완료 근거가 남은 항목이다. 이 문서는 해당 항목의 점수 회복이나 임상 타당성을 주장하지 않는다.
