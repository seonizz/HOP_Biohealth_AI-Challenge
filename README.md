# 말씨 개인 시연 백엔드

`seonizz/HOP_Biohealth_AI-Challenge`의 최신 프론트 `feat/column-full-text`, 커밋 `9fbd159340fe0231feee08f70c341e86b2c2f074`을 기존 PostgreSQL·학습 모델 API 연동에 적용했습니다. 이전 프론트 기준은 `feat/columns-interactive`의 `aa144758fdcece6a01a69d9e0507d51e9dc1a9ff`입니다. 로그인 화면이나 새 서비스 기능은 추가하지 않았습니다.

## 실행

Docker Desktop이 실행된 상태에서:

```sh
npm ci --ignore-scripts
npm run setup
# 레퍼런스의 비공개 학습 모델 키를 서버용 .env로 가져오기
npm run setup -- --trained-model-key /absolute/path/to/trained_model_api/runtime/api_key
docker compose up -d --build
```

[말씨 열기](http://127.0.0.1:9000). 기본 API 포트는 9000, 로컬 PostgreSQL 포트는 5433입니다. 학습 모델은 SSH 터널의 `http://127.0.0.1:18080/v1`로 호출합니다. Mac의 Docker에서는 `http://host.docker.internal:18080/v1`을 사용하도록 설정합니다. API 키는 `.env`에만 저장되고 브라우저에 전달되지 않습니다. SSH 터널은 모델 API 레퍼런스의 `connect.py`로 준비하며 기존 연결이 있다면 그대로 사용합니다.

`npm run setup`은 기존 `.env`를 덮어쓰지 않습니다. `--trained-model-key` 또는 `--model-env`를 지정할 때 모델 설정만 갱신합니다. 생성한 `.env`의 DB 암호와 `CONTENT_KEY`를 보관해야 기존 데이터를 다시 읽을 수 있습니다. 이전 Ollama 12B를 사용할 때는 `npm run setup -- --model-env /absolute/path/to/client.env`로 전환합니다.

```sh
# 상태 확인: 비밀값을 포함하는 docker compose config 출력은 피합니다.
docker compose ps
# 종료: 데이터 볼륨은 보존됩니다.
docker compose down
```

개발 중에는 PostgreSQL만 Docker로 실행하고 API를 Node.js 24.14 이상 24.x로 실행할 수 있습니다.

```sh
docker compose up -d postgres
npm start
```

## 대화와 내부 상태

1. 브라우저별 익명 세션을 만듭니다. 이메일·회원 가입은 요구하지 않습니다.
2. 기존 UI의 30개 문항과 보충 질문을 PostgreSQL에 최초 한 번 넣고 DB에서 읽습니다. 조건부 분기, 후속 질문과 첫 문항까지 반복해서 되돌리기를 서버에서 처리합니다. 후속·보충 질문에서도 본 질문으로 돌아갈 수 있습니다.
3. 답변 원문과 선택한 보기, 건너뛰기, 후속 답변을 PostgreSQL에 먼저 저장합니다.
4. 모델이 현재 상태와 이전 메모리를 읽고 JSON으로 상태 메모리·이름 인덱스·질문 계획을 반환합니다. 원문 인용과 대상 구분을 검증한 변경만 저장하고, 추출한 이름을 채팅 제목과 질문에 반영합니다.
5. 마지막에 누적 상태를 읽어 기존 결과 카드에 필요한 첫마디·해볼 행동·피할 표현·다음 단계·주변인 자기돌봄을 생성합니다. 결과와 전체 대화 기록을 저장합니다.

당사자 정보와 앱 이용자의 감정·부담은 별도 필드로 관리합니다. 답변은 사용자의 보고이며 임상적으로 확인된 사실이 아닙니다. 내부 `patient_state`의 요약·해석은 모델 생성물입니다. 서버는 인용이 현재 답변의 실제 부분 문자열인지, 대상과 문항이 일치하는지 검사하지만 의미의 임상적 타당성을 인증하지 않습니다. 임의 질환 점수는 계산하지 않습니다. 결과의 분류는 기존 칼럼 연결용이며 진단이 아닙니다.

기본 질문·보기는 최신 프론트와 같으며 이름은 필수 입력이고 별도 이름 후속 질문을 사용하지 않습니다. 기존 상담의 질문 버전과 관리자가 수정한 문항은 유지합니다. [질문 관리 안내](docs/QUESTIONS.md)의 로컬 명령으로 문구·보기·순서·사용 여부를 수정하거나 문항을 추가·삭제할 수 있습니다. 새 상담에 즉시 반영되며 진행 중·완료된 상담은 질문 스냅샷을 보존합니다. 모델은 답변에서 이미 설명한 질문을 근거와 함께 건너뛸 수 있습니다. 답변이 5개 이상 쌓이면 안내에 필요하지 않은 선택 질문도 건너뛸 수 있습니다. 이름·전하고 싶은 말·조건부 분기 기준 질문은 유지하며 필수 질문은 이미 설명된 경우만 건너뜁니다. 건너뛴 질문에는 사용자 답변을 생성하지 않고 결정과 근거를 따로 저장합니다. 되돌리면 그 단계 이후의 결정도 복원됩니다.

학습 모델 API는 `response_format`과 `reasoning_effort`를 지원하지 않으므로 JSON 생성 지침과 서버 검증을 사용합니다. `temperature:0`, `stream:false`, 상태 정리 최대 2,048토큰·최종 가이드 최대 4,096토큰과 1,800초 제한을 적용합니다. 최종 가이드는 직접 건넬 말 5~8문장, 행동·주의·자기 돌봄 목록 각각 3~4개, 다음 대화와 이용자 마음의 구체적인 설명을 요청합니다. 분량은 생성 목표이며 실제 내용에 따라 달라집니다. 2026-10-10 확인한 운영 API는 기본 출력 예약 256토큰, 최대 입력 65,536토큰·출력 4,096토큰·합산 69,632토큰입니다. 이 값은 실행 중인 서버 설정이며, 별도 합산 65,536토큰 계획의 적용을 뜻하지 않습니다. 서버는 전체 원문을 보존하고 모델에는 제한된 문맥과 검증된 이전 상태를 전달합니다. 일시적인 연결 오류·혼잡은 짧게 기다린 뒤 자동 재시도하고, 생성 응답의 형식·근거 검증 실패는 수정 지침을 추가해 다시 생성합니다. 문맥 예산 초과는 입력 구성을 한 번 줄여 재시도합니다. 이 복구들은 상태 또는 최종 가이드 생성당 합계 최대 3회 요청과 공통 제한 시간 안에서 수행하며, 인증 오류나 제한 시간이 지난 요청은 반복하지 않습니다. 검증되지 않은 답변을 성공으로 저장하지 않습니다. 이름은 실제 이름 입력과 후속 답변에서만 추출합니다. 이전 Ollama 연결에서는 [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)의 JSON Schema를 사용합니다.

전송한 글은 즉시 작성창에서 비우고 사용자 말풍선과 대기 표시를 먼저 그린 뒤 요청합니다. 재시도에는 캡처한 원문을 사용합니다. 자동 복구 후에도 모델이 실패하면 원문 답변은 서버의 대기 상태와 버전 이력에 남으며, 같은 질문에서 재시도할 수 있습니다. 화면은 연결·응답 확인·시간 초과를 구분해 안내합니다. 운영 로그에는 요청 ID와 오류 단계·시도 횟수·상태 코드·처리 시간 같은 진단 정보만 남기며, 대화 본문·모델 출력·인증 키는 기록하지 않습니다. 모델 응답 검증이 성공해야 다음 질문으로 진행합니다. 실패한 답변을 수정하면 대기 답변을 교체하고, 같은 입력을 재시도하면 답변을 중복 추가하지 않습니다. 최종 결과 생성 실패는 결과를 꾸며 저장하지 않고 기존 대화 화면에서 재시도할 수 있습니다.

## 기존 UI 기능

시작·서비스 소개·대화·결과·내 기록·칼럼의 6개 화면을 유지합니다. 단일/다중 선택, 직접 입력, 단독 보기, 필수 입력, 건너뛰기, 후속 질문, 되돌리기, 문장 복사, 두 번 눌러 기록 삭제, 공통 내비게이션, 칼럼 분류·안 읽음·담음 필터, 읽기 완료, 글자 크기와 이전/다음 읽기, 대화 종료 확인, 응원 문구, 결과 생성 로딩과 카드 등장 애니메이션을 지원합니다. 최신 프론트에서 제거된 오늘의 글·다른 글 뽑기·말씨 정원은 화면에서도 제외했습니다.

칼럼은 GitHub 최신 프론트에 포함된 10편의 목록·요약·원문 링크와 9편의 본문을 사용합니다. 본문이 없는 1편은 원래 UI대로 요약을 표시합니다. 새 기사 수집은 하지 않았습니다. 요청에 따라 익명 세션과 개인 시연용 서버 저장을 설명하는 문구는 UI에서 제거했습니다. 브라우저 쿠키를 지우면 해당 기록에 다시 접근할 수 없고, 다른 브라우저와 동기화되지 않습니다.

## 저장 구조와 검증

- `questions`: 질문 문구·보기·순서·대상·조건·후속 질문.
- `browsers`: 익명 토큰의 해시와 세션 정보.
- `intakes`: 대화 진행 상태·원문 답변·모델 메모리.
- `patient_states`: 현재 당사자/주변인 문맥과 모델 내부 메모리.
- `patient_state_revisions`: 답변·정정·모델 변경의 버전 이력.
- `records`: UI 결과 카드와 전체 대화 기록.
- `column_states`: 읽음·담음 상태.

상담·상태·이력·결과는 AES-256-GCM으로 암호화합니다. PostgreSQL 데이터는 Docker 이름 있는 볼륨에 저장합니다. 브라우저에는 접근용 쿠키만 두고 상담 내용은 저장하지 않습니다. 세션은 기본 30일로 만료되지만 검증용 서버 기록은 남습니다. 기존 UI에서 기록을 명시적으로 삭제하면 연결된 대화와 상태 이력도 삭제합니다.

서버에 저장된 전체 원문·모델 상태·버전 이력·결과를 검증하려면 로컬에서 `npm run export:verification`을 실행합니다. 비공개 `runtime/server-verification.json`에 복호화한 자료를 저장합니다. 이 파일은 Git과 웹 제공 대상에서 제외됩니다. 다른 브라우저나 쿠키 삭제 후에도 서버 자료를 이 방식으로 확인할 수 있습니다.

현재 공개 앱 주소는 `https://s-macbook-pro.tail85b0de.ts.net`입니다. `.env`의 `ALLOWED_ORIGINS`에 이 정확한 Origin을 지정해 기존 Funnel을 통한 앱 요청을 허용합니다. 모델 API 호출 주소는 로컬 `18080`이며 브라우저는 모델 키를 받지 않습니다.

```sh
npm run check
npm test
# 생성한 로컬 .env의 DB에 격리된 임시 테스트 스키마를 생성/제거
npm run test:integration
```

`npm test`는 `TEST_DATABASE_URL`이 없으면 PostgreSQL 테스트를 건너뜁니다. 모든 저장 검증은 `npm run test:integration`으로 실행합니다. 테스트에는 합성 데이터만 사용합니다.
